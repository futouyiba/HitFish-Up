# 任务：把「展开时下方行自动让位」接进 canonical 总图（方案二落地）

## 背景

`fcf-system-map/` 是 **FCF Canonical System Map（中鱼机制总图）**：JSON 是事实源、
`.drawio` 是确定性构建产物、官方 pinned viewer 是消费面。

图有**七条行带**，每行可折叠。当前用的是**方案一**：行带高度固定、展开只向右延伸，
所以下面的行永不被推动。代价是折叠时行带里空着（用一块大的「封面块」填住缓解）。

**方案二已经有人验证过了**（报告在 `align/dynlayout/REPORT-dynamic-layout.md`）：
draw.io 的布局引擎**确实能在 viewer 里跑**，触发条件是「任何一次完成的编辑事务」——
不是"加载"也不是"折叠"。所以**不需要新动词**，现成的 `hide`/`show`/`toggle` 点击即触发重排；
重排范围恒等于那个带 `childLayout` 的容器，容器外的兄弟块不动。确定性也达标。

**本任务：把它接进 canonical。** 这不是能力验证（已做完），是落地。

## 先读这两份

1. `align/dynlayout/REPORT-dynamic-layout.md` —— 已完成的验证报告与探针
2. `fcf-system-map/README.md` —— 地图的硬约束（尤其「骨架冻结」那节）

## 目标

让**行与行之间**具备动态让位能力：展开某一行时，它下方的行下移；折叠时收回。
即：把「七条行带」放进一个带 `childLayout` 的容器里，由布局引擎维护它们的纵向间距。

**范围限定**：先只做**行这一层**（七条行带之间的让位）。行带**内部**的分层展开
（通道分组、L2 细节）先保持现状，不要一起改——一次只动一层。

## 必须处理的三件事（报告里已点明）

### 1. 重叠检查会对嵌套容器 FAIL
`build/validate.py` 的顶点重叠检查目前允许两类重叠：**同一 slot 的互斥可见性**、
以及**真包含**（外层是内层祖先）。若你改用真容器，容器会压住子块——先确认它已被
上面的「真包含」规则覆盖；若覆盖不了，改它是**一次治理事件**：说明理由、改完在
commit message 里写清楚，并确认其余检查（页面容纳、骨架漂移）不受影响。

### 2. builder 必须吐「已是 stack 不动点」的坐标
否则**首次点击时整批行会跳**（布局引擎第一次跑才把间距归位）。
即：`build_diagram.py` 吐出的行 y 坐标，必须与布局引擎算出来的**首轮结果一致**。
验证方法：打开页面，点任意一行折叠/展开，**其它行不应整体跳一下**。

### 3. 骨架护栏不受影响，但别踩
`build/freeze_skeleton.py` 的指纹只读 `graph.json`，不看 `.drawio`，所以本任务
**不应该**触发骨架漂移。如果你发现必须改 `graph.json` 的拓扑，停下来先问。

## 建议的形态

报告里推荐：**标题与内容作为并列 stack 子块交错排**（`probe-tc.drawio`）。
标题永不隐藏，所以既不错位也一直可点。这在 canonical 里的对应物是：
每行的「行标签 / 封面块」与「行内容」——但注意现在封面与行标签**共用同一锚点**、
靠 `slot` 互斥（见 `graph.json` 里 `collapsible` 行的 `slot` 字段）。

## 交付

1. **可运行的改动**（builder + 校验器如有需要），提交到分支 `fcf-map-canonical`
2. 一段简短的说明：你用了哪种容器层次、首轮不跳是怎么保证的、
   以及**方案一与方案二能否共存**（比如只有部分行用动态让位）
3. **实测证据**：折叠/展开前后各行的 y 坐标；连续两次展开同一行的确定性

## 约束（务必遵守，与上一份任务书相同）

- **不要开发新的画图平台 / Web App。**
- 保持**确定性构建**：同 source 两次构建逐字节一致。
- 每格必须有**中文**（校验器会拦）。
- **不要**改 `graph.json` 的拓扑；若必须，先停下来问。
- 骨架基线冻结在 `skeleton.baseline.json`；本任务不应触发它。
