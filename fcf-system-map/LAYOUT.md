# 版面设计原则（方案二：容器包纳 + 动态让位）

这份文档记录**版面是怎么定下来的**，以及**为什么是这样**。内容语义在 Notion 的
《FCF R0 Canonical Map Content Ledger》；这里只讲版面。

> 一句话：这张图是**由容器包纳关系算出来的**，不是手工摆坐标摆出来的。
> `layout.json` 声明"谁包着谁、谁排在谁旁边"，`build_diagram.py` 把它算成几何，
> viewer 的布局引擎在每次点击后维护间距。

---

## 1. 为什么从方案一换成方案二

**方案一**：每行占一条固定高度的行带，展开只向右延伸，下方的行永不被推动。
好处是任何位置永不移动；代价是**折叠时行带里空着**，要用一块大"封面块"填住。

**方案二**：七行放进一条垂直容器链，展开一行时下方的行自动下移，折叠时上移。
没有空档。

换过来的**代价**是每次点开/收起都有整体位移 —— 这是方案二的定义特性，不是缺陷。
Design Owner 拍板接受。

---

## 2. 两条硬规则（都是实测出来的，不是文档说的）

这两条决定了整个版面能长成什么样。探针与数据见 `align/dynlayout/REPORT-dynamic-layout.md`。

### 规则一：引擎**从不重算水平容器的高度**

`mxStackLayout` 对垂直栈只写高度、对水平栈只写宽度。所以：

> **重排只能沿「垂直容器的连续链」向上传播。链上出现一个水平容器，重排就断在那里。**

**推论**：凡是"展开时要推动下方"的东西，都必须是**垂直容器里的兄弟**。
水平容器只用来做"并排"，而且它的高度在发射时就被钉死。

这就是为什么**行三与派生环境场不能做成横向并排**（那会切断行三的重排链），
改成：行三保持垂直、用容器样式上的 `marginLeft` 整行右缩让出左边 gutter，
派生环境场用 `movable=0` 钉在 gutter 里（不进栈、不计入行高，但随行三移动、随行三收起）。

### 规则二：宽度只能有**一个来源**

垂直容器会把**每个**子块宽度撑满（引擎的 `fill`），而 `fill` 和 `resizeParent`
由同一个开关（`transparentBounds`）控制 —— 关掉 `fill` 就连自动算高一起关掉，
重排也就没了。

于是：水平容器一律 `resizeParent=0`、按父容器内宽发射。**不允许两边都写宽度** ——
那样发出来的坐标不再是引擎首轮的不动点（独立复核实测过：同一个容器在 824 与 1336
之间来回跳）。

## 3. 折叠语义

- 每个可折叠容器有一个**标题条**，是它的第一个子块、**常驻可见**，带一条 `toggle` 动作。
- **折叠 = 只留标题条。** 收起后容器高度恰为 `标题高 + 2×border`；下方的行按
  **恰好等于本行高度变化**的位移让位；展开精确复原。
- 标题条必须常驻可见，是因为**栈布局在"一个可见子块都没有"时不会重排父容器** ——
  那样收起后会留一条空档。
- 隐藏一个容器 id 会**级联**到它的子孙，所以 toggle 只需要列顶层 id；
  但**边不是容器的子孙**，必须显式列进 payload。
- 被侧钉（`movable=0`）的子块**不参与级联**，要单独列进 toggle ——
  否则它会挂着压在下一行上（这条是独立复审核抓到的真 bug）。

---

## 4. 版面语汇：两条轴各表一件事

> **横向 = 类别并列（互不相干的多路）　竖向 = 执行顺序（自上而下）**

这条是 Design Owner 反复对齐后定下来的（白板草图）。任何一块版面，
先问"这几样是并列的，还是先后发生的"，再决定放横排还是竖排。

**反例（犯过的错）**：把"三种因子"竖着堆、把"每类的执行步骤"横着排 —— 正好反了，
读起来既不像并列也不像顺序。

## 5. 通道一的形态（其余通道的样板）

通道一（空间分布权重）是全图唯一有细展开的，其余四条短得多。它的形态：

```
空间分布权重                       ← 标题条（可折叠，180×24）
┌─────────────┬─────────────┬─────────────┐
│ 核心因子     │ 次要因子     │ 忽略因子     │   ← 横向：三种类别并列
│ ■ ▲         │ ⬡ ●         │ ⬢（虚线）    │   ← 形状即因子语言，不写名字
├─────────────┼─────────────┼─────────────┤
│ 鱼的栖息地动态偏好                          │
│ 门控         │ （无门控）    │ （无后续）    │   ← 竖向：各自的执行顺序
│ 满足→核心条件结果│ 次要因子计算 │             │
│ 不满足→失败路径 │ （得亲和系数）│             │
│ 条件判断失败  │             │             │
│ 核心因子计算  │             │             │
└──────┬──────┴──────┬──────┴─────────────┘
       └──────┬──────┘            ← 各路算完汇聚（边）
   环境权重系数聚合
       ↓
   环境系数下限            ←—— 门控判断失败的那条边也接到这里（不通过不必另起一路）
       ↓
   环境权重聚合 = 基础机会强度 × 环境权重系数
       ↓
   该通道的值 → 烘焙求解器
```

**几个决定及其理由**：

- **门控（菱形）只有核心因子有。** 次要因子不做门控，直接算亲和系数；
  忽略因子往下**什么都不做**（所以它那一列只有因子 + 形状）。
- **形状用矢量图标，不写名字。** ○ □ △ ⬡ ☆ 本来就是形状，写"方块/三角/六边形"
  等于把图形翻译成文字再让人翻回去。图标是 `layout.json` 里的 `{"icon": ...}`。
- **"环境系数下限"这个框的位置比较靠下是**对的** —— 它发生在聚合之后。
  门控判断失败时**不另起一路**，而是从"条件判断失败"拉一条边**接到这个框上**。
- **汇聚用边表示，不用容器表示。** 容器只能表达"包纳"，表达不了"多路合流"；
  合流是流向，属于边。

## 6. 已知代价与限制

| 项 | 说明 |
|---|---|
| 整图偏高 | 全展开约 1300 × 2450；通道一因为三列各自的执行步骤比较长，行二一个人占掉约 1300px |
| 每次改方块名字都要重冻骨架 | `fingerprint()` 把 `labels` 算进骨架，改名 = 骨架漂移。要不要把标签从指纹里摘出去，是治理决定，尚未做 |
| 水平容器只装"不再展开"的东西 | 规则一的直接后果，不是可以绕的 |
| 收缩到标题条后页面留白 | 图例钉在页面底部，收起一层后图例前会留一段空白；换来的是页面高度不跳 |

## 7. 想改版面时改哪里

| 想改什么 | 改哪里 |
|---|---|
| 谁包着谁、谁排在谁旁边、顺序 | `layout.json` 的包纳树 |
| 间距、内边距、缩进、标题条尺寸 | `layout.json` 顶部的 `border/spacing/titleH/titleW/leafH`，或单个容器的同名键 |
| 某一带均分宽度 | 容器上加 `"even": true` |
| 某个子块自己定宽 | 该子块上写 `"w": N` |
| 某节点留在模型里但**不画** | `"skip": true`（如已删除的 SYS，现用不着） |
| 形状、配色、字号、标题条样式 | `build_diagram.py` 的 `KIND_STYLE` / `TITLE_*` / `CONTAINER_STROKE_BY_DEPTH` |
| 折叠时收起哪些 cell | 由包纳树自动推出（容器的非标题子块 + 相触的边），不用手写 |
| 合流、跨层流向 | `graph.json` 的 `edges` |

**改完必须跑**：

```bash
python3 build/build_diagram.py && python3 build/validate.py
```

校验器会拦住：确定性问题、committed 产物过期、重命名动了几何、顶点重叠（只在**渲染
出来**的方块之间比，所以隐形的方块不会误报）、面外溢出、scope 归类漏项、骨架漂移。

**几何必须与引擎首轮结果一致**（"首次点击不跳"），这一点校验器不看 ——
改完版面请在 viewer 里点一下确认没有整体位移。
