# 版面设计原则（方案二：容器包纳 + 动态让位）

这份文档记录**版面是怎么定下来的**，以及**为什么是这样**。内容语义在 Notion 的
《FCF R0 Canonical Map Content Ledger》；这里只讲版面。

> 一句话：这张图是**由容器包纳关系算出来的**，不是手工摆坐标摆出来的。
> `layout.json` 声明"谁包着谁、谁排在谁旁边"，`build_diagram.py` 把它算成几何，
> viewer 的布局引擎在每次点击后维护间距。

---

## 1. 为什么从方案一换成方案二

**方案一**：每行占一条固定高度的行带，展开只向右延伸，下方的行永不被推动。
好处是任何位置永不移动；代价是**折叠时行带里空着**，要用一块大"封面块"填住。

**方案二**：七行放进一条垂直容器链，展开一行时下方的行自动下移，折叠时上移。
没有空档。

换过来的**代价**是每次点开/收起都有整体位移 —— 这是方案二的定义特性，不是缺陷。
Design Owner 拍板接受。

## 2. 引擎行为（都是实测出来的，不是文档说的）

探针与数据见 `align/dynlayout/REPORT-dynamic-layout.md`。这几条决定了整个版面能长成什么样。

### 规则一：引擎**从不重算水平容器的高度**

`mxStackLayout` 对垂直栈只写高度、对水平栈只写宽度。所以：

> **重排只能沿「垂直容器的连续链」向上传播。链上出现一个水平容器，重排就断在那里。**

**推论**：凡是"展开时要推动下方"的东西，都必须是**垂直容器里的兄弟**。
水平容器只用来做"并排"，而且它的高度在发射时就被钉死。

这就是为什么**行三与派生环境场不能做成横向并排**（那会切断行三的重排链），
改成：行三保持垂直、用容器样式上的 `marginLeft` 整行右缩让出左边 gutter，
派生环境场用 `movable=0` 钉在 gutter 里（不进栈、不计入行高，但随行三移动、随行三收起）。

### 规则二：宽度只能有**一个来源**

垂直容器会把**直接子块**的宽度撑满到容器内宽 —— 但**只撑直接子块**。
实测：`C:W:R2.C1.A1`（贴边壳）被引擎撑到 `1220`，而壳里那个 260 宽的方块纹丝不动。

于是有两条配套做法：

- **想让一个方块真的通栏** → 用 `"fill": true` 让它当垂直容器的**直接子块**，
  发射宽度就写成容器内宽（发射值 = 引擎首轮值，首次点击不跳）。
- **想保住方块自己的宽度** → 让它在**贴边壳**里（`wrap()` 自动加的那层
  `border=0、不画边`的水平容器）。壳被撑满无所谓，块在壳里按自身宽度放，
  加 `"center": true` 就在壳里居中。

> 这条是"板式怪"的根因：汇聚漏斗（`C:C1/AGG`）有 1240 宽，而它的几格当年是
> 260 宽的叶子、左对齐 —— 一列宽框里挂着一串窄块，全贴在左边。
> 规则二定清楚之后，改 `fill` / `center` 就解决了。

另外**水平容器一律 `resizeParent=0`、按父容器内宽发射**：两边都写宽度的话，
发出来的坐标不再是引擎首轮的不动点（独立复核实测过：同一个容器在 824 与 1336 之间来回跳）。

## 3. 折叠语义

- 每个可折叠容器有一个**标题条**，是它的第一个子块、**常驻可见**，带一条 `toggle` 动作。
- **折叠 = 只留标题条。** 收起后容器高度恰为 `标题高 24 + 2×border 10 = 44`；
  下方的行按**恰好等于本行高度变化**的位移让位；展开精确复原（实测零漂移）。
- 标题条必须常驻可见，是因为**栈布局在"一个可见子块都没有"时不会重排父容器** ——
  那样收起后会留一条空档。
- 隐藏一个容器 id 会**级联**到它的子孙，所以 toggle 只需要列顶层 id；
  但**边不是容器的子孙**，必须显式列进 payload。
- 被侧钉（`movable=0`）的子块**不参与级联**，要单独列进 toggle ——
  否则它会挂着压在下一行上（这条是独立复审核抓到的真 bug）。

## 4. 版面语汇：两条轴各表一件事

> **横向 = 类别并列（互不相干的多路）　竖向 = 执行顺序（自上而下）**

这条是 Design Owner 反复对齐后定下来的（白板草图）。任何一块版面，
先问"这几样是并列的，还是先后发生的"，再决定放横排还是竖排。

**反例（犯过的错）**：把"三种因子"竖着堆、把"每类的执行步骤"横着排 —— 正好反了，
读起来既不像并列也不像顺序。

## 5. 通道一的形态（其余通道的样板）

通道一（空间分布权重）是全图唯一有细展开的，其余四条短得多。
2026-09-23 按 Design Owner 给的参照 SVG（`计算逻辑图.html`）重排成下面这个形态。

```
空间分布权重                                   ← 标题条
鱼的栖息地动态偏好                              ← 通道入口：参与每个因子的计算
┌───────┬───────┬───────┬───────┬───────┐
│核心因子A│核心因子B│次要因子A│次要因子B│ 忽略因子 │  ← 每个因子一条窄竖列
│  ⬡ 蓝  │  ⬡ 蓝  │  ● 绿  │  ● 绿  │ ▭ 灰虚线 │     形状=类别，名字写在框上
├───────┼───────┤       │       │       │
│ ◇门控 A│ ◇门控 B│       │       │       │  ← 只有核心因子有门控
├───────┼───────┼───────┼───────┤       │
│亲和度计算│亲和度计算│亲和度计算│亲和度计算│ ✗ 无门控·无亲和计算·无聚合线│
└───┬───┴───┬───┴───┬───┴───┬───┘       │
    └───┬───┴───┬───┘       │           │
        ↓       ↓           │           │
   ┌────┴───────┴───────┐   │           │
   │ 环境聚合（容器标题）  │   │           │
   │  核心贡献 │ 次要贡献  │   │           │
   │     原始环境系数     │   │           │
   └─────────┬──────────┘   │           │
             ↓              │           │
        ◇ 是否背景鱼 ←───────┴───────────┘（门控失败绕过整个聚合，直接到这里）
        │ 是          │ 否
   ┌────┴────┐  ┌────┴─────┐
   │是｜背景鱼│  │否｜非背景鱼│
   └────┬────┘  └────┬─────┘
        └─────┬──────┘
              ↓
        最终环境系数
              ↓
    最终合成 ← 基础机会强度
              ↓
      （返回：空间分布权重）                      ← 圆头 = 通道结束
```

**几个决定及其理由**：

- **每个因子一条窄竖列**（照参照 SVG）。四个参与计算的因子各占一列，列内自上而下
  是它自己的求值链；忽略因子那列只有因子本身 + 一行说明。
- **形状代表类别，名字写回框上**（2026-09-23 改）：⬡ = 核心 / ● = 次要 /
  虚线圆角 = 忽略。因此「核心因子 / 次要因子 / 忽略因子」三个**分类头节点退场**了
  —— 形状已经表达类别，再挂一个分组框是重复。
  > ⚠️ **这条推翻了更早的「形状=因子身份、不写名字」**（那是 2026-09-17 的定法）。
  > 两套不能并存：形状要么标识**类别**、要么标识**个体**。
- **每个核心因子各自一个门控** —— Notion 清单原话「各影响因素 / 各习性组
  **各有自己的**门控」。门控的两个配置是鱼的可接受水温边界
  （`temp_accept_min` / `temp_accept_max`）。
- **失败支路绕过整个聚合**，直接汇进那个**统一**的背景鱼判断；判断的「是 / 否」
  两支各自写明门控失败与通过时取什么值。
- **聚合展开成 核心贡献 / 次要贡献 / 原始环境系数** 三格。只写中文名与一句白话，
  **不写公式**（`CoreProduct = Π CORE Fit` 这类留在文档里）。
- **返回通道结果用 end 图形**（圆头胶囊，`kind: "end"`）。
- **汇聚用边表示，不用容器表示。** 容器只能表达"包纳"，表达不了"多路合流"；
  合流是流向，属于边。

**顺带修掉的两个已废术语**：原来的「环境权重系数聚合」「环境权重聚合」里的
「环境权重」是**已废弃术语**（现行统一术语是「空间分布权重」，见 README §2），
改成「环境聚合」「最终合成」——正好与参照 SVG 的用词一致。

**一个版面上的取舍**：四条「亲和度计算」到聚合的路，和两条门控失败的路，
都要挤过聚合框。做法是把「环境聚合」从**整行横框**改成**聚合容器的标题条**
（`role: title` + `w: 120`）——它一收窄，线就从它旁边过去了。见 §6.5。

### 5.1 这一版踩到的三个坑（都实测过）

- **`hexagon` 的 `size` 是比例、不是像素。** 写 `size=26` 等于 26 倍斜角，轮廓自己
  折成**蝴蝶结**（不是六边形）。必须配 `fixedSize=1;` 才是像素。
  探针：并排渲 7 个候选（`perimeter=hexagonPerimeter` / `hexagonPerimeter2` /
  `direction=east` / `mxgraph.basic.hexagon` / `shape=poly` / `fixedSize=1` / 不带 size），
  只有后两个是正经六边形。
- **「亲和度计算」不要做成因子那种形状。** 它一开始误用了因子的 `kind`
  （`fcore`/`fsec`），于是核心 B 的那个渲染成蓝色六边形 —— 它是普通过程框。
- **菱形装不下长说明。** 门控原本带「鱼的可接受水温边界（temp_accept_min / max）」
  一整句，文字溢出菱形、盖住左右邻居。改成 `214×104` + 短说明「可接受水温边界」；
  `temp_accept_min / max` 这两个参数名留在 Notion 清单里。

## 6. 边的走位

### 6.1 层级关系不画线

**结构边（行 → 顶层块）已删除。** 容器嵌套已经把"谁包着谁"画出来了；
那 27 条线里行一/行五/行六/行七那几条中心连中心，正好横穿各自行内的方块
（如 行六→鱼侧透传 穿过 抽鱼和生成）。删掉这一层是本图最大的一笔"少挡内容"。

### 6.2 出入口约束对**平行四边形无效**

`graph.json` 的边可以写 `exit`/`entry`（`N/S/E/W` + 四角 `NW/NE/SW/SE`）。
实测：**圆角矩形、立方体认；`kind=data` 的平行四边形不认** ——
写 `exit: "W"` 它照样从方块正中往下扎。所以：

- 一行之内、只用圆角矩形/立方体的短边 → 写 `exit`/`entry` 就够了；
- **起点或终点是平行四边形** → 用下面的走廊绕行。

（这个 viewer build 里 `exitX/exitY` 数值也一样不被平行四边形采纳；换
`edgeStyle` 也不动。这是实测结论，不是猜测 —— 探针脚本见 `align/dynlayout/`。）

### 6.2b 四角入口（`NW`/`NE`）会打回折

汇聚处常想给两条线各钉一个角（两条都进同一个框，最后一段就不会重叠）。但实测：
**当源在目标正上方时，`entry=NW/NE` 会让路由器打一个小回折** ——
下去 → 横走 → **又倒回来往上** → 再下去，整条边多出 2 个点、一段 28px 的折返。

⇒ 只有源头离得远、回折不明显时才用四角；**源在目标正上方时一律用 `N`**，
宁可让两条线的最后一段重叠（重叠比回折好看）。

> 顺带一个不是我们造成的现象：**平行四边形（`data`）**端点之间的边会出现同样的
> 28px 回折 —— 那就是 §6.2 那条"平行四边形忽略 exit/entry"的症状，绕不过去。

### 6.3 跨行长边：走廊绕行

在 `graph.json` 的边上写：

```json
{"from": "R2.C1", "to": "R5", "type": "DATA_FLOW", "route": "left", "lane": 2}
```

- `route: "left" | "right"` → 构建器算出页面左/右空白走廊的横坐标
  （**不写死**：左 = `8 + lane*9`，右 = `页右缘 + 12 + lane*9`），
  在源与目标的中心高度各放一个途经点，线就沿走廊直上直下。
- `lane` → 同侧多条长线各占一条平行车道，不叠在一起。
- `via: "S"` → 先纵向挪出自己那条横带再横穿。同一横带里的邻居会挡住直着出去的路
  （行一的「投放与强度」要往右走，正撞上右边的「习性配置的构成」）。

实测：修完全部跨行长边后，**逐段 polyline 与全部渲染方块求交 = 0 处**。

### 6.4 跨模块的边锚在**模块**上（折叠不断线）

**问题**：折起一行之后，从这行内部发出的边全都不见了 —— 所有大模块看起来互相断开。

**先答一个factual问题：draw.io 有没有"折叠时把边提升到容器"的原生功能？** 没有。
两层源码都读过：mxGraph 核心的 `foldCells`/`cellsFolded` 只做 `setCollapsed` /
`swapBounds` / `extendParent` / `constrainChild`；draw.io 自己对 `foldCells` 的覆盖
只加了"把折叠容器提到最前"和"重排父容器尺寸"。**两层都不碰边**。

**然后是一条更硬的规则**（读 `mxGraph.updateSelection` 的祖先遍历 + `isCellVisible`
得出）：**一个 cell 只有在「它的所有祖先都没被折叠」时才可见。**
推论很干脆 —— **能扛住任意折叠组合的锚点，只有最外层模块（行）本身**。
任何更深的东西（叶子、通道容器）都会被"折叠它的祖先"一起带走。

所以：**跨模块的边一律锚在模块的标题节点上**（`R2`、`R5`…）。标题节点**永远可见**
（折叠只隐藏容器的非标题子块），所以折起来线就从折叠后的标题条出发，展开就从模块
边框出发 —— **不需要任何新机制**，把 `graph.json` 的 `from`/`to` 换成模块 id 就行。

配套两条：

- **两侧都撞成同一对就合并。** `DEF→响应` 与 `Cue→响应` 重锚后都是 `R3→R4`，
  而校验器禁止重复边对；合并成一条、用标签承载原意（`派生环境场 + Cue 吸引元素`）。
  这也更贴近 Notion 的说法（响应模块"两路输入"）。
- **例外：指向模块内部的"导航边"保持精确。** `DEF → 通道入口`（标签"展开通道 1"）
  不重锚 —— 它的用途就是**指进**某个模块内部，那个模块被折起来时它本来就该消失。

**实测验收**（浏览器里逐行折叠，问"9 条模块边还剩几条"）：

| 操作 | 可见语义边 | 9 条模块边 |
|---|---|---|
| 全展开 | 31 | 9 |
| 折叠行二 | 12 | **9** |
| 折叠行三 | 29 | **9** |
| 折叠行四 / 五 / 六 / 鱼侧动态参数 | 31 | **9** |
| 全部复原 | 31 | 9（行七纵坐标精确复原） |

**代价**（Design Owner 已知情并选择接受）：

- 展开态多出一组**页边总线**（左/右空白里各几条平行长线）；模块级边从"就近的短箭头"
  变成"走页边再上来"。
- 模块级的边**丢掉了"具体是哪个内部节点发出的"**。如 `R2→R5` 不再显式说明是
  「空间分布权重」在喂圆桌抽鱼，只能靠行内关系推出来。

> 另一条曾被考虑的方案是**孪生提升边**（给每条跨界边再发一条 `模块标题→外部端点`，
> 折叠时显示）：能保住精度，但 toggle 的 cell 列表在发射时就写死了，外层容器那次翻转
> 会连带翻掉子孙的边与孪生边，**嵌套折叠互相污染**（先折通道 → 再折行 → 展开行，
> 通道仍是折的，但它的提升边被带回了隐藏态）。这个方案是**有状态**的，上面那条不是。

### 6.5 穿过列间缝隙（`route: "gap"`）

有些边**两侧都被堵死**，只剩列与列的缝可走。通道一里那个典型：核心 B 的门控要把
「门控失败」送出去，可**往下走撞自己那一列下面的「亲和度计算」**，**往左走撞核心 A
的门控**（两者同一行）。

`route: "gap"` 就是为这种情形加的：它把走线钉在**源所在那一列**的左缘减半个间距处
（缝宽正好是 `spacing`，所以那是缝的中心）。缝的横坐标**由版面算出来**，不写死 ——
列宽、间距、列序变了它跟着变。

> 同一条边也可以先纵向挪开再横穿（`via: "S"`，留白可用 `gutter` 逐边调）。
> 三种绕行方式按"两侧还剩多少空"选：`route: left/right` 走页面边廊、
> `route: gap` 走列间缝、`via: S` 先出自己那条横带。

## 7. 已知代价与限制

| 项 | 说明 |
|---|---|
| 整图偏高 | 全展开约 1340 × 2600；行二一个人占掉约 1200px（通道一 662 + 鱼侧动态参数） |
| 每次改方块名字都要重冻骨架 | `fingerprint()` 把 `labels` 算进骨架，改名 = 骨架漂移。要不要把标签从指纹里摘出去，是治理决定，尚未做 |
| 走廊是"算出来"的，不是引擎给的 | 引擎不做避障（OrthConnector 只管首尾两段），长边必须靠 `route` 显式指定；版面对长边的走向没有自动保证，靠碰撞检查兜底 |
| 跨模块的边锚在模块上 → 展开态多出页边总线 | §6.4 的代价。换来的折叠不断线是 Design Owner 明确要的 |
| 水平容器只装"不再展开"的东西 | 规则一的直接后果，不是可以绕的 |
| 收缩到标题条后页面留白 | 图例钉在页面底部，收起一层后图例前会留一段空白；换来的是页面高度不跳 |

## 8. 想改版面时改哪里

| 想改什么 | 改哪里 |
|---|---|
| 谁包着谁、谁排在谁旁边、顺序 | `layout.json` 的包纳树 |
| 间距、内边距、缩进、标题条尺寸 | `layout.json` 顶部的 `border/spacing/titleH/titleW/leafH`，或单个容器的同名键 |
| 某一带均分宽度 | 容器上加 `"even": true` |
| 某个子块通栏 | 该子块上写 `"fill": true` |
| 某个子块自己定宽 / 居中 | 该子块上写 `"w": N` / `"center": true` |
| 某节点留在模型里但**不画** | `"skip": true`（如已删除的 SYS，现用不着） |
| 把一个节点画成矢量图形 | `{"node": "X", "icon": "square"}`（`ICON_SHAPES` 里加新图标） |
| 形状、配色、字号、标题条样式 | `build_diagram.py` 的 `KIND_STYLE` / `TITLE_*` / `CONTAINER_STROKE_BY_DEPTH` |
| 边从哪边进出 | `graph.json` 边的 `exit`/`entry`（见 §6.2 的限制） |
| 跨行长边怎么绕 | `graph.json` 边的 `route` / `lane` / `via` |
| 折叠时收起哪些 cell | 由包纳树自动推出（容器的非标题子块 + 相触的边），不用手写 |
| 合流、跨层流向 | `graph.json` 的 `edges` |

**改完必须跑**：

```bash
python3 build/build_diagram.py && python3 build/validate.py
```

校验器会拦住：确定性问题、committed 产物过期、重命名动了几何、顶点重叠（只在**渲染
出来**的方块之间比，所以隐形的方块不会误报）、面外溢出、scope 归类漏项、骨架漂移。

**校验器不看的两件事**，改完版面要手工确认：

1. **几何必须与引擎首轮结果一致**（"首次点击不跳"）—— 在 viewer 里点一下标题条，
   看有没有整体位移。
2. **边不许穿过方块** —— 在浏览器里取每条边的 `absolutePoints`，逐段与全部渲染方块求交。
