# Proposal C｜机械操控暴露：可计算指标与最小聚合

状态：Working Closure / Candidate。不是 Current，不是生产参数。

## 1. 结论

第一版不尝试识别“真实猎物运动模式”，也不直接给钓组配置一个固定的“自然度”。

目标收窄为：

> 从实际运行数据中识别当前呈现是否暴露出明显的“被玩家和钓线持续机械操控”的痕迹。

钓组结构只决定这种痕迹**容易不容易出现**；最终评价尽量基于当前实际运动和玩家手法。

原先候选的四项：

```text
持续拖拽程度
输入同步程度
高张力占比
被动运动占比
```

不建议平级保留。

第一版收敛为三个核心量：

```text
持续受控约束度 C
输入直传度 S
释放自由度 F
```

其中：

- “持续拖拽”与“高张力占比”合并到 `持续受控约束度`，避免重复计权；
- `输入直传度` 只表达玩家动作是否直接传到拟饵，不单独等于异常；
- `释放自由度` 表达一次主动操控结束后，拟饵是否还能脱离直接控制继续产生运动 / 漂移 / 衰减；
- 最终形成 `机械操控暴露度 E_mech`，再交给后续警惕 / 风险路径消费。

---

## 2. 为什么不能用“钓组刚性”直接给自然度

若直接：

```text
钓组越直连
→ 自然度越低
```

会把玩家手法几乎全部吃掉。

同一个高直连钓组：

```text
持续绷线猛拖
→ 可以非常机械

轻拉 → 松线 → 等待 → 再轻拉
→ 可以明显降低机械痕迹
```

反过来，一个天然解耦较强的钓组，如果玩家始终高速、绷紧、持续拖动，也可以产生明显机械感。

因此：

```text
钓组结构
→ 影响运动传递条件

玩家操作
× 钓组结构
× 当前环境 / 物理结果
→ 实际呈现

实际呈现
→ 机械操控暴露
```

钓组名称本身不直接进入最终风险成本。

---

## 3. 运行时最小输入

第一版优先消费游戏已经容易获得或可从现有运动状态推导的量。

记：

```text
U(t) = 当前主动操控强度，归一化到 [0,1]
T(t) = 当前线张力或等价受力约束强度，归一化到 [0,1]
V(t) = 拟饵实际速度
D_pull(t) = 当前线 / 玩家牵引方向（若可得）
```

`U(t)` 不要求绑定某个具体输入设备。它可以由当前系统已有的收线、竿尖驱动、主动牵引等事实合成。

若某一输入当前运行时不可得，应显式标记缺口，不得用钓组类型静默伪造“实测值”。

## 4. 指标一：持续受控约束度 C

### 4.1 它回答什么

> 当前拟饵在多大比例的时间里，被玩家主动牵引 + 线张力共同持续约束着运动？

这比单独统计“高张力占比”更合理。

高张力本身可能来自：

- 水流；
- 重物下沉；
- 障碍；
- 其它非主动操控原因。

只有和主动操控、运动方向共同成立时，才是“机械拖拽”的强证据。

### 4.2 最小工作公式

在一个短评价窗口 `W` 内，定义：

```text
Active(t) = 1, if U(t) > U0
Taut(t)   = 1, if T(t) > T0
```

若牵引方向可得，再定义运动与牵引方向的一致性：

```text
Align(t)
= clamp(
    dot(normalize(V), D_pull),
    0,
    1
  )
```

然后：

```text
ConstraintEvidence(t)
= Active(t)
  × Taut(t)
  × Align(t)
```

若当前没有可靠的 `D_pull`，第一版可以退化为：

```text
ConstraintEvidence(t)
= Active(t) × Taut(t)
```

窗口内基础占比：

```text
C_occ
= mean_W(ConstraintEvidence)
```

为了区分：

```text
0.5 秒连续拖拽
```

和：

```text
5 次很短、彼此分开的轻触
```

建议再记录：

```text
C_run
= longest_continuous_constraint_duration / W
```

第一版聚合可先用：

```text
C
= 0.7 * C_occ
+ 0.3 * C_run
```

`0.7 / 0.3` 只是 Working seed；核心语义是“占比为主、连续性为辅”。

### 4.3 玩家手法会改变它

同一钓组：

```text
持续绷线收 / 拖
→ C 高

短促轻拉 + 放松
→ C 下降
```

因此它保留玩家操作差异。

## 5. 指标二：输入直传度 S

### 5.1 它回答什么

> 玩家施加一次明显动作后，拟饵是否几乎同步、直接地做出对应运动？

它衡量的是“输入传到拟饵有多直接”，不是“这个动作是否自然”。

一次急窜、抽动本身完全可能是合法的猎物状态，因此：

```text
S 高
!= 自动风险高
```

只有它长期稳定成立，同时缺少释放自由时，才构成较强机械操控证据。

### 5.2 事件式计算优先于复杂相关模型

第一版不需要做完整时序机器学习。

检测显著操控事件：

```text
player_event_i
```

例如 `U(t)` 的明显上升沿或脉冲。

对每个事件，在 `0 ~ tau_max` 内寻找拟饵对应的显著运动响应，例如：

```text
速度变化
加速度变化
沿牵引方向的运动变化
```

记录响应延迟：

```text
tau_i
```

单事件直传分：

```text
s_i
= 1 - clamp(tau_i / tau_max, 0, 1)
```

若事件后没有找到有效响应：

```text
s_i = 0
```

窗口直传度：

```text
S_raw = mean(s_i)
```

但必须加入证据充分度：

```text
Q_sync
= clamp(valid_event_count / N_ref, 0, 1)

S
= Q_sync * S_raw
```

这样一次孤立抽动不会因为“刚好立即响应”就把整段窗口判成高机械暴露。

### 5.3 为什么不用“相关系数直接判异常”

完整相关 / 互相关虽然可以做，但第一版存在几个问题：

- 玩家输入和拟饵运动可能有不同量纲；
- 连续收线会天然得到很高相关；
- 一次有效急窜也可能得到高相关；
- 需要额外处理窗口、滤波和相位。

事件延迟更容易解释、调试和验证。

## 6. 指标三：释放自由度 F

### 6.1 它回答什么

> 玩家主动施力结束后，拟饵是否仍能脱离直接控制继续产生一段自己的运动？

这正是倒钓、卡罗琳娜等解耦结构可能产生优势的地方，但最终评价的是实际结果，不是钓组标签。

### 6.2 为什么不简单用“被动运动占比”

“被动运动占比”方向是对的，但直接统计整段时间会混入大量无意义停顿。

更稳的是围绕**释放事件**计算：

```text
主动操控结束
→ 看后续短时间内拟饵是否还有非直接受控运动
```

### 6.3 最小工作公式

检测每次主动操控从高到低的释放事件：

```text
release_event_i
```

在释放后的短窗口 `Delta_release` 中，计算：

```text
PassiveMotion_i
= integral(
    motion_amount(t)
    × RelaxedControl(t)
  )
```

其中：

```text
RelaxedControl(t) = 1
if U(t) < U_relax
and T(t) < T_relax
```

`motion_amount` 可以先用经过上限裁剪的速度 / 位移量，不要求复杂物理解释。

同时记录释放前主动阶段的运动量 `DrivenMotion_i`，做相对归一化：

```text
f_i
= PassiveMotion_i
  / (PassiveMotion_i + DrivenMotion_i + epsilon)
```

窗口内：

```text
F = mean(f_i)
```

如果当前窗口没有任何释放事件：

```text
F = Unknown / NotObserved
```

不要因为“没看到释放”就直接写成 `F=0`。

### 6.4 它保留钓组差异和玩家差异

同一个钓组：

```text
一直绷紧
→ 几乎没有释放样本

主动操控后给松线
→ 可能出现明显 F
```

不同钓组在同样玩家手法下，也可能因为结构差异形成不同 `F`。

因此两类差异都保留。

## 7. 高张力占比为什么不再单独进入最终评分

高张力是重要原始信号，但不应该成为第四个独立处罚项。

原因：

```text
高张力
+ 主动操控
→ 已经进入持续受控约束度
```

如果再单独：

```text
+ HighTensionPenalty
```

就会对同一次持续拖拽处罚两遍。

因此第一版：

```text
高张力占比
→ Explain / telemetry 保留
→ 作为 C 的输入
→ 不独立进入机械操控暴露
```

## 8. 最小聚合：机械操控暴露度

三个指标不是简单相加。

原因：

- `C` 与 `S` 有相关性；
- `S` 高本身不一定异常；
- `F` 更像对“机械直传”的反证 / 缓解证据；
- 一次合法抽动不应因高直传被处罚。

第一版建议：

```text
DirectLock
= S * (1 - F)
```

语义：

> 玩家输入高度直传，而且释放后几乎没有自己的运动。

再与持续受控约束合成：

```text
E_mech
= C
  + (1 - C) * DirectLock
```

结果天然位于 `[0,1]`。

解释：

- `C` 已经很高时，持续拖拽本身足以成为主要机械暴露；
- `C` 不高，但输入始终直接传递且缺少释放自由，也会提高机械暴露；
- `F` 高可以降低 `DirectLock`，但不能抹掉已经发生的长时间持续拖拽；
- 单次抽动因为 `Q_sync` 低，不容易单独把 `S` 推高。

如果 `F` 当前不可观测，不能静默取 `0`。该分支应使用明确的降级契约，例如只输出 `C` 与 `S`，并标记机械操控暴露未完整解析；是否允许仅用 `C` 做生产降级，需要后续单独裁定。

## 9. 典型策略故事

### A. 持续高速绷线拖动

```text
C 高
S 高
F 低
→ E_mech 高
```

### B. 高直连钓组，但玩家细腻操作

```text
短促操作
+ 主动释放
+ 有明显松线 / 自由阶段

→ C 低
→ F 提高
→ 即使 S 不低，E_mech 仍可明显下降
```

玩家手法没有被钓组结构吃掉。

### C. 卡罗琳娜 / 倒钓式解耦呈现

若真实运行结果确实表现为：

```text
持续约束少
输入响应不完全直传
释放后仍有较多运动
```

则自然得到：

```text
C 较低
S 较低或中
F 较高
→ E_mech 低
```

不需要给钓组类型硬编码奖励。

### D. 解耦钓组被玩家持续猛拖

如果实际表现变成：

```text
C 高
```

即使结构本身有自由度：

```text
E_mech 仍然会升高
```

所以钓组只提供能力，不保证结果。

## 10. 与其它 Response 机制的边界

`E_mech` 只回答：

> 当前呈现暴露出多强的机械操控痕迹？

它不回答：

```text
这个目标像不像某类猎物
当前状态是否诱发攻击
轨迹是否难预测
鱼是否追得上
玩家是否覆盖了更多搜索空间
```

因此：

- 急窜可以提高攻击触发；
- 急转可以增加轨迹预测困难；
- 高速可能增加追赶负担；
- 只有当这些动作同时形成持续操控、直传锁定、缺乏释放自由时，才通过本页增加机械操控暴露。

---

## 11. 数据可得性与降级

第一版每个指标必须记录来源：

```text
Measured      实际运行数据直接得到
Derived       从实际运行信号推导
AuthoredPrior 人工 / 钓组结构先验
Unknown       当前无法可靠得到
```

优先级：

```text
Measured / Derived
> AuthoredPrior
> Unknown
```

但 `AuthoredPrior` 不能冒充实测。

若未来某些实际运行量拿不到，可以用钓组结构提供“预期直传 / 预期释放自由”的先验，但必须在 Explain 中明确来源，并允许后续真实数据覆盖。

## 12. 当前裁定

第一版冻结以下 Candidate 方向：

```text
持续拖拽 + 高张力
→ 合并为持续受控约束度 C

输入是否直接传到拟饵
→ 输入直传度 S

操控结束后是否仍有自己的运动
→ 释放自由度 F

DirectLock = S * (1 - F)

E_mech
= C + (1 - C) * DirectLock
```

这是一套低成本、可解释、保留玩家手法差异的 Working 机制。

当前仍需通过实现侧确认：

- `U(t)` 当前运行时能由哪些已有输入稳定构成；
- 是否已有可用线张力读数；
- 是否能取得牵引方向；
- 拟饵速度 / 位移是否稳定可读；
- `tau_max / Delta_release / U0 / T0` 等阈值的测试标定。

在这些输入验证完成前，本页不声明生产参数已经闭合。
