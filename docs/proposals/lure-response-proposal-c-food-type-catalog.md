# 方案 C｜食物类型目录与猎物评价假设（候选 v0.1）

日期：2026-11-05  
状态：**Candidate / 待 Owner 审核**；不是生产类型表，不替代已合并的 Proposal C 契约。  
基线：本文按创建时 main `2eab977f950d34473e9d6d1f702f695716180a69` 的设计包整理。食性档位使用 2026-11-05 已合并的 `tier-v2`；圆桌接口仍遵守 2026-11-04 的 `空间分布权重 × 适配系数`，不把 `L × C` 写成最终圆桌公式。

## 1. 本轮先收口的事

1. 采用**食物类型（Food Type）**作为鱼的基础食性评价键。一个饵类型 / 装配可以显式声明一个或多个可表达的食物类型，各自有独立的表达支持度。
2. **不建立“群体猎物”对象。** 例如 Blob Fly 可以直接声明它试图表达“小型浮游甲壳动物”，以既有外观、呈现与水层事实形成表达支持度；不模拟一群具体水蚤。是否真的有效由玩家策略与呈现验证决定，声明本身不自动等于支持度 1。
3. 食物类型与**猎物当前状态**分开。受伤、逃窜、移动、停顿、正常/异常姿态，及尺寸、生活史阶段、加工形态，均不自动成为新的食物类型。
4. 食物目录一次列全；**目录存在不等于每种都要编写独立运动解释器**。只有同一食物类型下的运动/姿态解释确实购买可区分的玩家策略时才单独配置规则。
5. 下文是用于游戏求值的**工程分组**，不是声称这些名称是天然互斥的生物分类学阶元。若实际食性证据需要更细的差异，应有具体鱼种、玩法和来源依据后再改表。

## 2. 食物类型目录（18 项候选）

| ID | 食物类型（中文） | 包含或代表的食物 | 路亚姿态解释的需要 |
|---|---|---|---|
| `FINFISH` | 鱼类 | 小鱼、鱼苗、鳗形鱼；整鱼/鱼块的身份源一致，加工形态另记 | 是，优先已有“小鱼解释器” |
| `SHRIMP_KRILL` | 游泳型虾状甲壳动物 | 河虾、海虾、磷虾等；这是形态/玩法归组，磷虾并非生物学上的真虾 | 是，按具体拟饵决定是否拆规则 |
| `CRAYFISH_LOBSTER` | 小龙虾与龙虾类 | 淡水小龙虾、海洋龙虾 | 是，优先已有“小龙虾解释器” |
| `CRAB` | 蟹类 | 河蟹、海蟹、软壳蟹 | 需要时配置横移/触底表达 |
| `MICRO_CRUSTACEAN` | 小型浮游甲壳动物 | 水蚤、桡足类及同类微型食物 | 不要求逐只姿态；可用静态或呈现证据 |
| `AQUATIC_INSECT_IMMATURE` | 水生昆虫幼体 | 蜉蝣若虫、石蛾幼虫、摇蚊幼虫、蜻蜓稚虫、蛹 | 飞蝇/小型拟饵有独立策略时配置 |
| `INSECT_ADULT` | 成虫及落水昆虫 | 蜉蝣成虫、蝗虫、甲虫、蝉等 | 是，表层漂浮、挣扎等可分别解释 |
| `WORM_LEECH` | 蠕虫与水蛭 | 蚯蚓、水蚯蚓、沙蚕、水蛭 | 软虫、飞蝇或真饵需要时配置 |
| `MOLLUSK_SHELL` | 螺贝类软体动物 | 螺、蚌、蛤蜊、贻贝 | 多用于食性/底钓；姿态解释按需 |
| `CEPHALOPOD` | 头足类 | 鱿鱼、墨鱼、章鱼 | 海钓拟饵有相应泳姿时配置 |
| `AMPHIBIAN` | 两栖动物 | 蛙、蝌蚪、蝾螈 | 是，优先已有“蛙解释器”；不同生活史状态按需区分 |
| `EGG_ROE` | 动物卵 | 鱼卵、其它可食卵 | 不按“鱼苗”计算；可用静态呈现 |
| `ALGAE` | 藻类与附着生物膜 | 浮游植物、丝状藻、底栖藻、附着生物膜 | 一般不需要路亚运动解释器 |
| `AQUATIC_PLANT` | 大型水生植物 | 水草、嫩茎叶等 | 一般用于食性/天然饵 |
| `PLANT_SEED_FRUIT` | 籽实、果实和谷物 | 玉米、谷粒、种子、落水果实 | 多用于台钓/浮钓/底钓 |
| `DETRITUS` | 有机腐屑 | 可被摄取的分解有机碎屑、底层腐屑 | 不要求路亚运动解释器；整块鱼肉仍记鱼类与加工形态 |
| `OTHER_SMALL_VERTEBRATE` | 其它小型脊椎动物 | 鼠、蛇、蜥蜴等较少见的拟饵对象 | 特殊拟饵需要时配置；不可当通用匹配 |
| `OTHER_INVERTEBRATE` | 其它无脊椎食物 | 水母、海胆、海参、海葵等未单列对象 | 扩展位，不可把任意未识别物默认计入 |

**分类边界：**浮游动物是生态生活方式，和甲壳类存在交叉。本表为配置采取明确归属：水蚤/桡足类归微型浮游甲壳动物，磷虾暂归游泳型虾状甲壳动物；如有证明两者食性价值差异的具体需求再拆。鱼卵独立于鱼肉；游动/受伤/停顿、当前大小、活饵/死饵/鱼块是**状态或形态**而非食物类型。拟饵商品大类（米诺、亮片、软虫）、饵料原料（鱼粉、虾粉）与诱味化学线索不是上述食物类型的同义词。

## 3. 机制假设与证据边界

### 3.1 采用“仿佛在评价猎物”的计算模型，不声明鱼脑先后顺序

```text
一份实际呈现 / 同一份可复核事实
    ├─ 分类型解释：可以被当成哪些食物（支持度）
    │      └─ 分类型状态：当前游动、停顿、逃逸样等
    ├─ 通用追赶事实：速度、有效机会（由各自 owner 消费）
    └─ 独立风险线索：终端钓组等

按每一种已支持食物类型：
    食物价值（该鱼种、体型、食性档位）
    + 有准入的额外攻击诱因
    - 追赶成本
    - 有依据的风险成本
    - 摄食意愿门槛
    → 出手余量 → 0~1 条件响应 × 该类型支持度
同一物理目标的已解析替代解释取 max
→ 最终适配系数 C
```

**这是一种求值依赖图，不是脑内时序图。** 鱼可能凭大小、运动、明暗对比等简化线索快速启动捕食/避让，无须先形成完整物种身份；警戒反应也可能早于明确猎物识别。“先识别合法猎物再算一切”如果实现成普遍硬门槛，会错误屏蔽仅凭部分线索可攻击的拟饵。

### 3.2 必须保留的边界

- `PreySupport` 回答该解释有多少证据，不是分类概率；饵上写有 `FoodType` 是可评价范围声明，不自动设 `PreySupport=1`。
- `FoodValue` 按鱼种 × 食物类型读取基础亲和，再消费 `tier-v2` 的一档内食性偏移与独立的尺寸偏好；`Poor=0` 不等于 `Reject`，只有声明不可接受时才触发独立硬边界。
- 同一种呈现允许多种候选解释，分别完整评价后按现行 sibling 规则取 `max`，不把支持度归一化成“猎物分类概率”。
- 速度、停顿可以改变猎物状态、追赶负担和机会，但不因此增加匿名奖励或把同一代价重复计权。风险线索不能凭 `1 - PreySupport` 生成。
- 不能明确归入已支持食物类型的物体，当前摄食路线可能无结果。金属亮片、强闪光、振动或非摄食攻击是否需要独立路线，属于**尚未闭合的设计问题**，不能用“任意物体 = 通用猎物”填补。
- 圆桌当前接口为**空间分布权重 × 适配系数**；机会量 `L` 的并入方式仍由对应设计分支处理，不能在此重写为最终 `L×C`。

## 4. 能否构成有效模型：以反例和策略区分验收

以下是**必须能陈述期望、记录实际输出的受控案例**，不是“已经通过”的实验。对每个案例同时比较：简化基线模型（按饵类型给鱼种直接匹配）与本模型（分类型支持 + 食物价值 + 状态/成本）。

| 案例 | 锁定不变项 | 只改变什么 | 需要验证的机制差异 |
|---|---|---|---|
| 同款米诺 | 鱼况、操作与拟饵事实 | 捕食鱼的食性亲和 | 食物价值变，猎物支持度不被鱼偏好反写 |
| 同一软饵模拟小鱼与小龙虾 | 鱼种和装配 | 近底慢拖 vs 中层游动 | 两套解释排序可能翻转，不按类型数量加分 |
| 蛙饵静止与游动 | 鱼种、外观、水层 | 原子姿态及前史 | 静止仍可有效，不能只靠 Trigger |
| 浮游动物 Blob Fly | 食物类型固定为微型浮游甲壳动物 | 形态/水层/停留事实 | 无需“群体对象”也能形成有依据的支持；不会自动满支持 |
| 亮片闪光但缺明确身份 | 鱼况、其它事实 | 视觉刺激 / 身份证据 | 若无法形成合法解释应暴露边界，不能偷生通用奖励 |
| 同款饵快搜与慢停 | 鱼侧食物偏好 | 速度/时间事实 | 追赶和 Opportunity 分别改变；不出现重复奖励 |
| 当前食性改变 | 鱼种、拟饵、体型 | `DietTierShift` 一个档以内 | 只修改相应类型价值；新档位使用 `tier-v2` |
| 猎物难认且终端钓组显眼 | 同一鱼况 | 猎物证据 vs 风险 cue 各改一次 | 支持不足与风险独立，不能“低支持→高 Suspicion” |
| 无明确猎物，但实际发生攻击 | 现有解释器集合 | 非摄食路线可用性 | 明确是否属当期不覆盖范围；不凭猜想补出新的摄食公式 |

**收敛原则：** 如果本模型比“饵类型×鱼种偏好 + 速度成本”这条更简单的基线不能稳定购买至少一种明确、可解释、玩家能操作的策略排序差异，应删掉带不来区别的子类型/评价维度，而不是继续增加参数。任何数字阈值在取得受控反馈前不得写成生产值。

## 5. 当前明确已定、尚未闭合

- **本轮候选已整理：**食物类型 18 项；不要求群体实体；尺寸、状态、加工形态与食物身份分开；一个饵可支持多个食物类型；鱼侧的价值判断不能反写猎物解释。
- **现行已合并的设计约束：**2026-11-05 食性偏好锚点 `Poor/Marginal/Good/Preferred = 0/0.25/0.60/1.0`，食性偏移在一档以内，`tier-v2`；圆桌接口 `空间分布权重 × 适配系数`。
- **仍需 Owner 审核：**目录的拆分颗粒度及特殊海洋食物的归属；何种食物类型要注册独立动态解释规则；无法归类的强刺激是否需要独立摄食/非摄食路线。
- **仍需生产证据：**各鱼种对应食物类型的基础亲和；装配到食物类型的表达证据和强度；具体类型是否带来独立可学习策略。
