# 方案 C：按猎物类型分层解释与评价路亚呈现

状态：独立设计提案，沿本轮对话继续推导；不是生产规范，已有首轮局部条件规则与案例推导，尚无方案C的完整公式或实现。  
方案B：[线索支持、呈现状态与鱼的响应](lure-feeding-target-interpretation.md)。方案B的原型、数值和失败记录继续保留，不在本文件中改写。

本轮集中推导“1实际呈现 → 2猎物解释”，工作版本见第26节；输入来源与T尾／Jig扩展表见第27节。前文第9～25节保留探索过程与局部候选；其中早期支持档位、部位细节与规则示例不应与第26节拼接成一套同时生效的算法。该工作版本仍为方案C候选，不是Owner已采纳的生产规范。

## 1. 为什么单独提出方案C

方案B用有限的类型支持规则、共同状态距离，以及激励相乘后扣除行动代价的形式，快速做出了可执行探针。轨迹推算暴露了状态切换的响应跳变，也让我们重新检查：不同猎物的解释与鱼侧评价，是否被过早压成了一套共同计算形式。

方案C保留“同一呈现可以支持多种猎物解释”的方向，先展开每类猎物自身的判断逻辑，以及解释、状态、捕获评价和摄食评价之间的关系。共同接口可以统一，内部判断机制不必相同。

方案B的 B=H×S×p×F×g 中各符号确实是相乘。方案C不继承统一乘法、最近状态距离、固定状态激励倍数，也不默认继承跨路径max。需要共用的规则，待案例推导后逐项确认；不能把方案B的数值结果当作方案C已经成立的证据。

## 2. 暂定主线

以下是讨论所需的语义节点，不是五个已经冻结的数据结构，也不要求实现成五个严格串行模块。

| 节点 | 回答的问题 | 暂定输出 | 主要边界 |
|---|---|---|---|
| 实际呈现 | 接收者可感知到什么？ | 轮廓、大小、物理特性、运动过程、水层、反光、振动等事实 | 商品名称不直接指定猎物身份；未观测不补零 |
| 猎物解释 | 各种猎物解释分别得到多少支持？ | 按猎物类型组织的支持map及依据 | 不因鱼更爱吃某食物，就把饵解释成该食物 |
| 类型条件下的呈现状态 | 如果按这种猎物理解，它当前表现如何？ | 正常移动、停留、失衡表现、逃窜表现等中间判断 | 状态定义与证据可以随猎物类型不同 |
| 鱼侧评价 | 对当前这条鱼，食物价值如何、捕获要求如何、是否愿意行动？ | 捕获评价与摄食评价，必要时再细分 | 可得程度与摄食意愿分开；不提前合成匿名总分 |
| 响应 | 这些评价如何激发行动？ | 各猎物解释下的响应，以及后续聚合 | 响应强度不反写目标身份；尚不等于中鱼概率 |

实际运动过程同时向猎物解释、呈现状态和捕获要求提供输入。不能先只凭静态外形永久定类，再禁止运动参与解释。相同事实可以有不同作用，但同一后果不能在多处重复扣罚或加分。

鱼种的感官差异可以影响可获得的线索；食物偏好、摄食意愿和运动能力不能代替线索证据。当前先讨论感知事实已经提供的情况，不在此冻结感官模型。

## 3. 猎物支持map

本轮保留一个显式的中间结果，例如：

```text
小型饵鱼：0.9
甲壳类：  0.5
蛙类：    0.0
```

这只是说明输出形态的示意值，不是已算出的结果。

暂定含义是“该解释获得的支持程度”。各项不要求加起来为1；也尚未规定它等于响应保留比例，或必须与后续响应相乘。0.9与0.5的尺度、跨类型可比性、证据组合及校准方式均待推导。

不同类型允许不同判断机制，例如必要线索、若干充分组合、条件规则、连续匹配或时序模式。不能先规定所有类型必须使用同一组维度与距离，再去填不同中心。

确认没有支持的分支可以停止后续计算。缺失事实或尚未覆盖的规则不等于0。低支持阈值的裁剪属于后续决策：需要说明是否可能丢掉重要响应，不能仅凭方便设一个统一阈值。未决分支如何影响最终输出也需明确，不自动照搬方案B的全局阻断规则。

## 4. 类型、运动与状态各放在哪一层

| 例子 | 适合放置的层次 |
|---|---|
| 小型饵鱼、甲壳类、蛙类 | 猎物类型，最终粒度待定 |
| Shad等更细猎物类别 | 可能的子类型；需要证明确实购买了不同判断或响应 |
| 米诺 | 若指拟饵商品类别，属于呈现来源；若指自然猎物类群，需另行定义 |
| 贴底爬行、水面游动 | 运动与环境关系，参与解释和状态判断 |
| 走停、抽停 | 一段实际运动序列，不直接获得固定响应倍率 |
| 失衡、疑似受伤、惊恐逃窜 | 依赖证据的状态解释，不是直接观测事实 |
| 速度、加速度、离底距离 | 呈现事实或提取特征，不必再包装成一个语义系数 |

不能把“蛙类”与“贴底爬行”作为同一层的平行猎物项。也不能把父类小鱼与其子类Shad重复当成两个独立响应机会；层级与去重方式尚待确定。

呈现状态不必是唯一标签，也不必各状态之和为1。比如“失衡表现”与“快速位移”可能同时成立；哪些状态互斥、哪些可共存，应由每类判断机制说明。

## 5. 鱼侧评价先分清两件事

### 捕获评价

猎物状态与实际几何提出了什么行动要求？鱼当前的速度、转向、加速等能力能否满足？由此得到对这条鱼而言的可得程度。

速度慢不必然更可得：位置、遮挡、逃逸路线和鱼的当前状态都可能改变结论。具体需要哪些输入，由首批案例推导，不先把所有可能因素列成必填字段。

### 摄食评价

鱼是否吃这类猎物、当前食物偏好与diet shift如何、这份食物的价值如何、当前feeding motivation是否支持行动？

食物偏好与feeding motivation保持不同含义。方案B的摄食动机专题可以作为候选参考，但其中的sigmoid、时段偏移与近期负荷公式并未因引用而自动成为方案C规则。

两种评价最后可以存在条件关系。例如容易捕获不代表想吃，很想吃也不代表愿意承担任何行动要求。大小也可能同时改变食物价值与捕获要求；若如此，应分别说明两条作用，而不是重复乘一个大小系数。

## 6. 从哪一端开始推

采用“最小语义约定 → 具体机制与案例 → 所需数据 → 下一案例修订”的循环。机制推导在前，完整数据契约在后；不先列完所有节点的字段，也不长期只画框架。

先约定每个节点回答什么、哪些含义必须分开。例如支持不等于偏好，可得不等于意愿，未知不等于零。接着推一个实际判断，写出条件、运算或明确比较结果；算不出来的地方标为缺口。只有当某项数据被规则实际读取、影响案例判断时，才把它提升为候选字段。

每轮形成一条小而完整的切片：输入事实、判断依据、中间结果、鱼侧变化、响应差异。允许早期数值是假设，但必须能检查；不能只留下函数签名，或为了得到预期排序事后随意改参。

### 首个切口：猎物解释到呈现状态

首批设计对象改为“小型饵鱼、小龙虾、蛙类”。先推小型饵鱼与小龙虾，用明确形态与同一Tube的不同呈现检查类型支持和状态判断；首版规则形成后立即加入蛙类，检查水面与停留逻辑。具体首轮推导见第8～12节；规则归属与配置展开见第13～17节。

首轮要回答：

1. 哪些线索足以支持该猎物解释，哪些仅用于判断状态？
2. 动作不匹配时，是支持减弱、状态改变，还是规则尚未覆盖？不能一概跳成另一猎物。
3. 同样处于停顿，近期运动与实际浮沉分别改变什么中间判断？
4. 各类型确实需要不同规则的地方是什么，哪些事实提取可以共享？

同一Tube的下落与近底移动在第一组案例中就参与检验多类型支持，防止把结构做成“一种饵只对应一种猎物”。

解释与状态的首版机制成立后，再固定同一份呈现，分别改变鱼的能力、偏好、feeding motivation，推捕获评价和摄食评价。最后才决定响应如何组合，以及跨类型的结果怎样聚合。上游案例需要的字段同步整理，不等到所有机制完成才补数据说明。

## 7. 首轮验收与未决问题

首轮至少应能检查以下结果：

- 同一呈现不因鱼的食物偏好变化而被重新解释。
- 明显鱼形饵仅因触底不会自动变成甲壳类；动态证据仍可支持本来就有依据的其他解释。
- 蛙类水面停留可以是合法呈现，不预设静止必然失效；异常水层如何影响支持与状态由规则明确。
- 抽后停顿与长期静止在证据充分时可以不同；缺失历史不伪装成已知没有动作。
- 状态与类型名称有具体规则支撑，不能只靠标签附赠倍率。
- 所需数据均能对应到某条实际判断，未知与已知零能够区分。

尚未裁定：猎物分类粒度、支持值尺度、各类型判断机制、状态集合及时间窗口、feeding motivation的具体参与方式、捕获评价公式、响应映射、跨类型聚合，以及后续行动与咬口结算。

本提案依据为当前项目对话及仓内方案B的推导与失败记录。猎物示例和机制建议属于设计假设，不作为新取得的生物学证据。

## 8. 路亚猎物范围与首轮选择

先整理六个主要家族；这是工作分类，不是完整生物分类，也不是已经冻结的六个计算通道。

| 猎物家族 | 包含哪些对象 | 需要检验的判断差异 |
|---|---|---|
| **鱼类** | 小型饵鱼、较高体型的小鱼、底栖鱼、细长鱼等 | 轮廓、摆动、反光；游动、悬停、下落、失衡等呈现 |
| **甲壳类** | 虾、小龙虾、蟹等 | 身体与附肢线索；游动、爬行、弹跳、逃逸与底部关系 |
| **两栖类** | 蛙、蝌蚪等 | 不同发育形态；水面、水下运动与停留 |
| **蠕虫、水蛭类** | 蚯蚓、水生蠕虫、水蛭等 | 柔软细长的形态、弯曲、蠕动、漂移等 |
| **昆虫类** | 水生幼虫、若虫、成虫，以及落水陆生昆虫 | 发育阶段、漂流、上浮、水面挣扎等差异 |
| **头足类** | 鱿鱼、章鱼等 | 海水路亚中的躯体、触腕与运动呈现 |
| **特殊猎物，暂作扩展** | 鼠、幼鸟、蜥蜴等 | 特定鱼种与场景下的较大猎物呈现 |

表中特殊猎物暂作扩展。浮游生物、鱼卵、贝类、植物等不是不存在，而是未列入本轮主动拟饵的优先设计集。后续兼容其他钓法时还需按目标范围补充，不能把这个表当作所有鱼的完整食谱。

第一组选择小型饵鱼与小龙虾，原因是既有不同的线索和行为，又有同一Tube用于两种模拟的现实案例。蛙类排在下一组，用于检验框架是否过度依赖游动或触底。

资料入口：

- [Minnesota DNR：大口黑鲈](https://www.dnr.state.mn.us/minnaqua/speciesprofile/largemouthbass.html)：列出食性随成长从浮游动物、水生昆虫转向小龙虾与鱼类，以及多种自然钓饵。
- [TPWD：Red Drum](https://tpwd.texas.gov/huntwild/wild/species/reddrum/)：鱼、虾、蟹仿生呈现的应用，说明海水扩展不能把所有甲壳类直接等同小龙虾。
- [Rapala：轻型Jig用途](https://blog.rapala.com/vmc/new-vmc-jigs-help-anglers-match-the-hatch/comment-page-1/)：拟饵覆盖水生昆虫、甲壳类与饵鱼。
- [Nomad：Striped Bass拟饵](https://www.nomadtackle.com/pages/striped-bass-lures)：包含Squidtrex等鱿鱼呈现。
- [Shaw Grigsby的Tube案例](https://www.bassmaster.com/how-to/news/be-a-better-tube-fisherman/)：同一Tube用于小鱼与小龙虾模拟，螺旋下落用于伤鱼呈现。

上述钓饵用途不等于测得鱼的识别机制。下面的条件、支持档位和解释边界均为方案C新提出的设计假设。

## 9. 首轮机制：有明确类型线索与只有部分线索时，走不同路径

本轮先处理接收者已获得的呈现事实。为了讨论判断机制，人工样例明确给出可见轮廓、可见柔性部分和实际运动；尚未实现从Mesh、材质、动画到线索的提取。下面使用的“明确鱼体轮廓”“前部成对粗大突出部分”等，是人工标注的可辨认证据，不是商品类别，也不是已经完成生产定义的字段。

这一步输出两个有范围的猎物支持项：小型饵鱼与小龙虾。其他家族尚未评价，不隐含它们为零。

### 支持值口径

本轮暂用三个人工档位，让案例能够明确比较：

| 数值 | 约定含义 |
|---:|---|
| 0.40 | 有部分类型线索，但单凭它仍缺乏区分力 |
| 0.75 | 部分类型线索与特定运动／环境形成一组支持组合 |
| 0.90 | 有本轮认可的较明确类型轮廓线索 |
| 0 | 所有本轮适用路径都已检查，均未提供支持 |

这些数值不是分类概率、整体逼真度或激励保留比例，不能直接乘入响应。0.90也不表示整体呈现九成像真实猎物：它可以同时伴随“有鱼体轮廓，但动作解释未闭合”。跨类型的0.90暂时只共用档位说明，尚无严格校准意义。

档位间距是设计占位；这一轮真正检验的是路径成立条件与输出排序，不声称算出了自然相似度。

### 小型饵鱼：首轮三条支持路径

| 路径 | 条件同时成立 | 支持 |
|---|---|---:|
| 较明确轮廓 | 可辨认的鱼体轮廓 | 0.90 |
| 柔性组合的动态解释 | 可见细长柔性部分／裙丝；主体在离底下落中表现出连续螺旋或侧向飘落 | 0.75 |
| 部分线索 | 可见细长柔性部分／裙丝，但尚未满足上面的运动组合 | 0.40 |

首轮只注册以上路径，不把普通下沉或任意反光直接判为小鱼。其他有效小鱼线索仍待补充。第二条根据Tube用途提出候选组合，不代表所有有丝状部分的螺旋物体在生物上都像伤鱼。

### 小龙虾：首轮三条支持路径

| 路径 | 条件同时成立 | 支持 |
|---|---|---:|
| 较明确轮廓 | 紧凑主体、前部成对粗大突出部分，以及可见的腹尾分区共同构成小龙虾轮廓 | 0.90 |
| 柔性组合的近底解释 | 可见细长柔性部分／裙丝；接近或接触底部；发生近底拖行或间歇位移，且柔性部分发生可见展开变化 | 0.75 |
| 部分线索 | 可见细长柔性部分／裙丝，但尚未满足上面的近底组合 | 0.40 |

完整轮廓只是其中一条充分支持路径，不是所有小龙虾解释的必要条件。没有完整螯、足或腹尾结构的裙饵，仍可经其他路径获得支持。

“接近底部”单独不提供小龙虾支持。也不把所有甲壳类收进本条规则：虾的游动、蟹的运动另需推导。

### 同类路径怎样组合

同一类型的多条路径是在提出替代证据，本局部候选暂取最强的已成立档位，不按路径数量相加。这里的取大只用于线索支持；不等于决定跨类型响应也取max。

任何未观测的必要条件都保留未决。若已有0.40路径成立，但决定能否升到0.75的运动事实缺失，则只知道支持至少为0.40，不能把最终值写成已解析0.40。如何编码这种未决结果，待数据契约整理。

## 10. 首轮案例：相同运动不能替代不同的类型证据

以下人工样例都明确提供本轮所需事实。名称只帮助阅读；判断实际读取表中的特征。为隔离机制，鱼形、小龙虾形样例均没有额外裙丝等其他支持线索。

| 呈现事实 | 小型饵鱼支持 | 小龙虾支持 | 为什么 |
|---|---:|---:|---|
| 明确鱼体轮廓，水中匀速游动 | 0.90 | 0 | 鱼体路径成立；没有本轮小龙虾线索 |
| 同样鱼体轮廓，贴底拖行 | 0.90 | 0 | 触底与拖行不能替代小龙虾路径需要的轮廓或柔性线索 |
| 明确小龙虾轮廓，近底间歇移动 | 0 | 0.90 | 小龙虾轮廓路径成立 |
| 同样小龙虾轮廓，被快速拉到离底位置 | 0 | 0.90 | 本轮仍有类型证据；动作是否合理需下一层判断 |
| 无明确鱼／小龙虾轮廓的Tube，柔性部分可见，螺旋下落 | 0.75 | 0.40 | 小鱼动态组合成立；小龙虾只保留部分线索 |
| 同一Tube，近底拖行且柔性部分展开变化 | 0.40 | 0.75 | 小龙虾近底组合成立；小鱼保留部分线索 |
| 同一Tube，离底悬停，已知近期无相关运动 | 0.40 | 0.40 | 两类均只有部分线索，本轮不强制选一个 |
| 同一Tube，运动历史未提供 | 未决，至少0.40 | 未决，至少0.40 | 不能用缺失历史代替“已知未运动” |

这些0只表示本轮规则集未提供支持，不等于证明鱼绝不把它解释成该猎物。若识别出其他可用线索，应补规则与反例，不靠偏好去补身份。

本轮出现的机制差异是：小鱼动态路径读取离底下落的轨迹形态；小龙虾动态路径读取底部关系与近底位移。它们不是对同一个统一运动距离换一组中心值。

## 11. 支持之后，下一层具体输出什么

同一份输入事实可以再次用于状态解释，但本轮不把支持值乘以“状态像不像”再重算一次相似度。支持与状态回答不同问题。

| 已支持的解释与事实 | 首轮可以输出的状态描述 | 仍不能直接推断 |
|---|---|---|
| 小鱼解释；持续稳定游动 | 稳定游动表现 | 鱼一定喜欢该速度 |
| 小鱼解释；短促位移后停止，历史已知 | 短促位移后停留；记录距停止多久 | 仅凭抽停确认受伤或惊恐 |
| 小鱼解释；螺旋／侧向飘落 | 下落中有非直线轨迹；可作为失衡样态的候选依据 | 已证明生物学受伤，或应该附赠固定倍率 |
| 小龙虾解释；近底拖行／间歇位移 | 近底移动；接触是否持续、是否离底可分别描述 | 所有移动越慢越好 |
| 小龙虾解释；离底快速拉动 | 离底快速位移，类型证据仍保留 | 自动判为逃逸；需进一步看方向、历时等证据 |
| 任一解释；当前停住但历史缺失 | 当前静止，历史状态未决 | 当作长期静止或“抽后停留” |

首轮先把状态中有依据的运动关系与时序关系写明。是否进一步形成失衡、逃窜等语义状态，必须追加证据规则。不能为了输出状态名而直接赋予0.8等系数。

尚不计算鱼侧的可得程度、摄食意愿或响应。这样可以保留一个重要反例：类型支持很强，但当前运动不协调、状态尚未解释，或者对某条鱼而言很难捕获。三者不再被同一支持标量包办。

## 12. 本轮得到的数据需求及下一步

规则实际用到了以下少量信息；这是需求清单，不是冻结schema：

| 信息 | 被哪条判断使用 | 尚需明确 |
|---|---|---|
| 可见主体轮廓与突出部分关系 | 两类的明确轮廓路径 | 人工标记或几何提取的口径、遮挡后的可见程度 |
| 可见柔性部分／裙丝 | 两类的部分线索及组合路径 | 可辨认尺度、材料与运动如何影响接收者侧可见线索 |
| 与底部的间距、接触 | 小龙虾近底组合 | 参照尺度、接触记录与时间范围 |
| 一段实际位移轨迹 | 下落、螺旋、拖行和短促位移后停留 | 采样、观察窗口与几何判据 |
| 记录是否完整 | 区分已知无事件与历史缺失 | 上游如何声明有效历史范围 |

主要缺口有三项：

1. 当前0.40／0.75／0.90是按证据档位赋值，不能冒充连续特征已推得的精确相似度。需要把轮廓强弱与运动组合的成立程度具体化，并检查支持尺度。
2. 轨迹的“螺旋”“近底移动”等仍需可检查判据，不能仅凭动画或操作名称赋标签。下一小步先展开Tube的下落与近底移动各需要什么事实、什么条件，不先添加响应倍率。
3. 已有线索是否真能区分猎物、组合是否过宽，需要更多对照案例。蛙类作为第三类紧接着加入，不能等两类框架固化后再兼容。

第9～12节为首轮条件规则的纸面推导。第14～17节补充配置示例，并对人工特征值执行了条件判断核算；尚未实现从轨迹提取特征的方案C识别器，也未运行生物识别或玩法效果验证。方案B的原型运行结果不计为本轮验证。

## 13. 待裁定：规则归属、饵侧配置与共享粒度

本节记录新的架构问题，不把上一轮回答中的分工建议当作已定结论。第9～12节是条件规则的案例草稿，尚不能证明规则应存放在哪一层，也不确定可复用的数据结构已经足够。

### 问题本身

Tube与裙饵都可能支持小鱼和小龙虾解释。需要确定：它们评价同一种猎物时，是否共用规则、只共用部分机制，还是需要各自的规则或参数？答案会直接决定配置表、规则引用关系和运行时计算，不能仅以“证据相同就共用”结束讨论。

### 已提出的候选，均待比较

| 组织方式 | 数据与逻辑的大致归属 | 必须检验的问题 |
|---|---|---|
| 按猎物类型 | 饵提供共同特征；每种猎物用自己的规则读取 | 共同特征是否丢掉了Tube与裙饵的重要差异？是否需要越来越多的专用特征？ |
| 按饵类型 | Tube、裙饵等各自评价可支持的猎物 | 是否重复维护小鱼／小龙虾规则？是否导致同样呈现因饵名不同而得到不一致结果？ |
| 按饵类型×猎物类型 | 每一对配置自己的评价规则或参数 | 能否表达真实差异，同时控制组合数量和配置成本？ |
| 按呈现机制共享，组合引用 | 将可复用机制与具体配置分开，由饵和猎物关系选择或组合 | 哪些机制确实可共享，如何证明组合有足够表达力，而不是换名字隐藏重复？ |

上一轮“猎物类型拥有多条证据路径、饵提供实际线索”的建议对应第一种为主、允许共享子机制的方向。它目前只是候选，不能直接据此冻结schema。

### 饵上配什么，同样尚未裁定

“明确类型线索／多样化类型线索”不必然适合做互斥枚举：同一饵可能同时具有较明确的鱼体轮廓和支持其他解释的柔性部分。但是否仍需要辅助的作者配置、多个猎物呈现配置或规则引用，应与上述组织方式一起比较。

饵侧数据可以由策划标注或配置，不要求先实现Mesh到线索的自动识别。需要明确的是每个配置值代表什么、参与哪项判断，以及它是物理／感知特征的近似，还是直接指定最终解释。不能用“实际呈现”四个字掩盖尚未解决的取值来源。

### 下一轮用同一组案例比较

1. 固定相同操作，比较Tube与带拖尾裙饵：差异先体现在哪些实际呈现数据上？
2. 对同一种小鱼解释，两种饵各自需要哪些条件与参数？逐项列出可共享与不可共享部分。
3. 再对同一种小龙虾解释重复比较，检验是否仍能使用同一套组织方式。
4. 若输入相同却声称必须得到不同结果，说明缺少了什么特征、历史或上下文；若选择用饵类型做代理，明确代理依据和适用边界。
5. 用鱼形硬饵与后续蛙类检查扩展成本，比较每种组织方式新增数据、规则与例外的数量。

架构裁定前应至少给出一版具体配置示例与计算过程，使差异能落在字段、引用关系或规则上。不能先裁定存放层级，再事后将所有反例塞进例外项。

## 14. 展开四个组合：不同在哪里

以下比较一件Tube装配与一件“裙丝Jig＋鱼形软拖尾”装配，不代表所有Tube或所有Jig。形态标记是策划对具体装配的人工配置，运行时还需考虑实际可见程度。物理与动画在本轮直接提供运动记录。

| 装配×猎物 | 可提供的证据 | 首选判断路径 | 需要绑定的对象 |
|---|---|---|---|
| Tube×小型饵鱼 | 本样例没有明确鱼体轮廓；有后部柔性条束 | 部分柔性线索；实际出现侧向下落时再检查动态组合 | 主体／整饵轨迹、后部条束 |
| 鱼形拖尾裙饵×小型饵鱼 | 头部与拖尾形成可辨认鱼体轮廓，同时有柔性部分 | 轮廓路径；满足条件时也可检查与Tube共用的下落路径 | 装配后轮廓、整饵轨迹、裙丝 |
| Tube×小龙虾 | 无明确小龙虾解剖轮廓；有后部柔性条束 | 近底移动与条束展开形成组合 | 整饵轨迹、底部关系、后部条束 |
| 鱼形拖尾裙饵×小龙虾 | 本样例不配置明确小龙虾轮廓；裙丝提供部分线索 | 近底移动与裙丝展开形成组合 | 整饵轨迹、底部关系、裙丝 |

因此，四个组合既不是四份完全独立算法，也不是只把同一组原始值交给一个万能评分式：

- 小鱼与小龙虾使用不同的证据组合。
- 两件饵对小鱼可以使用不同的主要路径；也可以共享其中一条路径。
- 两件饵对小龙虾暂时可以共用近底组合逻辑，但读取不同部位的变化。
- 饵的装配、配重与物理特性先改变实际轨迹；同样的操作指令并不保证产生同样的呈现。

后两条是不同的差异来源。不能把“Tube更容易产生某轨迹”与“该轨迹更支持某解释”重复配置成两份奖励。

## 15. 一版可供比较的配置形式

当前更值得继续检验的候选是：猎物侧保存可复用的规则集；具体装配为“装配×猎物”配置规则集引用和部位绑定。规则内部可以调用不同机制，暂不做允许任意写表达式的规则语言。

这意味着承认一层明确的二者关系配置。不是仅有一张猎物规则表，也不要求每个二者关系都新写算法。

| 配置对象 | 保存什么 | 本轮例子 |
|---|---|---|
| 装配描述 | 部件、装配后形态标记、物理／动画来源 | Tube主体与后部条束；Jig头、裙丝与鱼形拖尾 |
| 猎物规则集 | 该猎物有哪些支持路径、路径条件与默认参数 | 小鱼轮廓／柔性下落；小龙虾轮廓／近底附属部分运动 |
| 装配×猎物绑定 | 使用哪个规则集、各规则读取哪个部位或组合 | Tube读取rear_bundle，裙饵读取skirt |
| 运行时呈现 | 当前及窗口内的可见轮廓、轨迹、底部关系、部位运动 | 本次是否真的下落、触底和展开 |

示意配置如下。字段名只用于比较结构，尚未冻结为生产contract：

```yaml
tube_rig:
  prey_bindings:
    small_baitfish:
      rule_set: small_baitfish_v0
      outline_source: tube_body
      flexible_source: rear_bundle
      trajectory_source: whole_rig
    crayfish:
      rule_set: crayfish_v0
      outline_source: whole_rig
      appendage_source: rear_bundle
      trajectory_source: whole_rig

jig_with_fish_trailer:
  prey_bindings:
    small_baitfish:
      rule_set: small_baitfish_v0
      outline_source: assembled_head_and_trailer
      flexible_source: skirt
      trajectory_source: whole_rig
    crayfish:
      rule_set: crayfish_v0
      outline_source: whole_rig
      appendage_source: skirt
      trajectory_source: whole_rig
```

本例两件饵没有使用不同阈值。若之后确有差异需要按二者关系配置参数，可在绑定中显式引用参数组；必须说明对应了哪个可检查差异，不能仅凭饵名加一个隐形系数。

更换拖尾后，应更新装配轮廓及相应绑定，不能因为仍叫“裙饵”就永久保留鱼体支持。没有提供某种绑定只表示尚未评价或尚未实现，不自动证明该猎物支持为零。

### 与其他组织方式的具体比较

| 组织方式 | 四组合如何表达 | 本轮判断 |
|---|---|---|
| 只有猎物规则＋全局特征 | 把所有部位差异提前压成共同特征，再由两个规则集评价 | 可以实现；但部位选择与特征含义可能藏在上游，仍须明示这些关系 |
| 每种饵独立算法 | Tube、裙饵各自返回两个支持结果 | 可以实现；本例近底组合与部分小鱼路径会重复维护 |
| 四组合各自独立算法 | 四个组合拥有各自的规则正文 | 表达力充分；本例没有证据支持四份正文都必须不同 |
| 猎物规则集＋二者关系绑定 | 两个规则集、四个绑定，规则可共享 | 本轮优先候选；差异可定位到路径、部位或参数，仍需其他猎物验证 |

这不是靠计数证明架构最优：关系绑定仍可能随饵与猎物组合增加，配置成本没有凭空消失。只有当同一规则确实被多个组合复用时，共享才有收益。

## 16. 使用这套结构实际核算

为让结构可检查，先采用固定1秒观察窗，所有历史均完整。长度参照L为该装配的参考长度。人工样例直接提供以下特征值，本轮未实现特征提取：

| 特征 | 本例口径 |
|---|---|
| 明确轮廓标记 | 当前绑定对象可辨认的对应类型轮廓，布尔值；不是饵名 |
| 柔性部分可见 | 当前绑定的条束／裙丝可辨认，布尔值 |
| 下落量 | 窗末相对窗初向下位移的正值除以L |
| 侧向范围 | 窗内水平投影轨迹的最大两点间距除以L |
| 近底时间比例 | 窗内离底间距不大于0.5L的累计时长除以1秒 |
| 水平路程 | 窗内水平运动路程除以L |
| 展开变化 | 绑定柔性部分的可见展开宽度最大值减最小值，再除以L |

本轮条件：

```text
小鱼轮廓路径：
  明确鱼体轮廓 → 0.90

柔性下落路径：
  柔性部分可见 AND 下落量≥1 AND 侧向范围≥0.5 → 0.75

小龙虾近底路径：
  柔性部分可见 AND 近底时间比例≥0.70
  AND 水平路程≥0.5 AND 展开变化≥0.15 → 0.75

柔性部分线索：
  可见 → 0.40
```

两类仍分别具有自己的明确轮廓路径。下面两件装配都没有明确小龙虾轮廓，因此该路径为已知未成立。每类取自身已成立路径的最高支持档位，尚不计算响应。

这是对首轮近底组合的细化：只有接近底部且移动还不够，本轮加上可见柔性部分的展开变化。这样“读哪个部位”开始实际改变计算。这个新增条件是待检验假设，不是已有资料证明的必要条件。

| 人工呈现 | 鱼体轮廓 | 下落量／侧向范围 | 近底比例／水平路程／展开变化 | 小鱼支持 | 小龙虾支持 |
|---|---|---|---|---:|---:|
| Tube侧向下落 | 无 | 2／0.7 | 0.1／0.8／0.20 | 0.75 | 0.40 |
| Tube近底移动，条束张合 | 无 | 0／0.1 | 0.9／1.2／0.25 | 0.40 | 0.75 |
| 鱼形拖尾裙饵离底游动 | 有 | 0／0.1 | 0.1／2.0／0.10 | 0.90 | 0.40 |
| 同裙饵近底移动，裙丝张合 | 有 | 0／0.1 | 0.9／1.2／0.30 | 0.90 | 0.75 |
| Tube近底移动，条束几乎不展开 | 无 | 0／0.1 | 0.9／1.2／0.03 | 0.40 | 0.40 |
| 同裙饵近底移动，裙丝几乎不展开 | 有 | 0／0.1 | 0.9／1.2／0.03 | 0.90 | 0.40 |

例如，第二行Tube绑定rear_bundle，读到近底比例0.9、水平路程1.2、展开变化0.25，三个门槛全部成立，小龙虾路径给0.75。第五行只把该部位的展开变化改为0.03，组合不成立，只留下0.40。裙饵绑定skirt，同一算法读到的部位事实不同，但无需复制判断正文。

第四行同时支持小鱼与小龙虾不是计算冲突，也不因小鱼支持更高而删除小龙虾解释。后续如何响应仍待推导。

上述六行已经按所列条件执行数值核算。它验证的是示意配置和条件能给出所写结果，不验证阈值合理性或鱼类识别准确率。

## 17. 本轮架构结论与尚未解决的问题

本轮建议采用“猎物规则集＋装配×猎物绑定”作为下一轮工作结构，尚不作为生产裁定。规则组织在猎物一侧；饵与猎物之间有明确的配置关系，负责选择、绑定和必要参数引用。新机制是否属于某个猎物规则集或值得共享，应由实际复用情况决定。

这比“统一放在猎物类型上”多了一项明确承诺：饵侧不能只有一组来源不明的像鱼／像虾分数，还要知道每种解释具体读取哪些对象、使用哪些路径。也不要求先做自动几何识别；人工形态标记与曲线来源可以作为早期实现。

仍有四个实质缺口：

1. 柔性部分本身支持两类的0.40仍过宽，需要检查假阳性与缺失的关键形态。不能因配置结构清楚就把它当成已成立的生物机制。
2. 当前“下落量＋侧向范围”并不能区分螺旋／失衡与普通斜向下降。它只是可执行的下落组合占位，不可直接输出“受伤小鱼”；应补轨迹反例后决定是否需要转向、摆动或姿态信息。
3. 固定1秒窗口与阈值尚未验证，启动、停止、长时间静止及窗口边界可能改变结果。不能沿用方案B的轨迹测试作为本方案通过。
4. 蛙类的首轮检查已加入第18～21节。现有节点暂能容纳，但绑定需要明确部位组、环境参照与时间关系；尚不能据此宣称覆盖所有蛙类或所有猎物。

第13节列出的架构问题仍作为比较依据保留；第14～17节是本轮给出的具体候选与计算展开，不把候选推荐记为Owner已采纳的最终决定。

## 18. 加入蛙类：先覆盖两种真实呈现与一件抽象对照

本轮的frog只指有四肢形态的蛙类呈现，不包含蝌蚪，也不把整个两栖家族冻结成一套规则。第18～21节的腿部差异只用于检查架构表达能力，不据此增加首版饵分类或必填字段。是否值得实现，须先证明会改变玩家选择或鱼侧评价。主体推导从第22节继续，暂不读取腿部伸收。先比较两种明确蛙形装配：

- 裙丝腿空心蛙：短身、蛙形主体，后部两组裙丝；不要求解剖学完整的实体腿。
- 实体腿蛙：明确蛙形主体与左右实体腿，运动时可呈现伸展与收回。

另外增加一件人工“短身、双后束、没有明确蛙体轮廓”的抽象装配。它用于检查不完整形态能否通过组合证据获得蛙类支持，不声称对应某款商品或已经证明鱼会这样识别。

资料依据：

- [LIVETARGET Popping Frog](https://mustad-fishing.com/livetarget/us/products/fph)同时使用裙丝腿、水面侧向运动与浮水设计，说明不能把实体后腿作为所有蛙类解释的必要条件。
- [Lunkerhunt Pocket Frog](https://lunkerhunt.com/products/pocket-frog)描述收线时腿伸展、停顿时腿收回的实际设计，为身体运动与部位伸收的时序关系提供用途样例。
- [Randall Tharp的蛙饵操作](https://majorleaguefishing.com/bass-pro-tour/randall-tharp-the-fine-points-of-frogging-tackle-part-2/)包含持续运动、停顿再启动，以及随条件改变停顿的做法，不支持“只有运动才是有效蛙类呈现”或“停顿越长越好”。
- [SPRO蛙饵比较](https://www.spro.com/blogs/spro-and-gamakatsu-add-to-stable-of-bass-elite-series-pros/spro-flappin-frog-65-vs-bronzeye-frog-65-vs-bronzeye-pop-60)区分持续腿部运动、walking与popping等用途。不是所有蛙饵都必须满足同一个蹬腿周期。

这些是产品行为与钓手用途依据，不是鱼脑分类实测。下面的支持档位与阈值继续属于人工假设。

### 蛙类有自己的证据路径

| 路径 | 条件 | 暂定支持 |
|---|---|---:|
| 明确蛙体轮廓 | 当前装配有可辨认的蛙体线索；裙丝腿或实体腿均可 | 0.90 |
| 后部成对结构的部分线索 | 紧凑主体＋两个可辨认、空间上分开的后部对象组 | 0.40 |
| 表层伸收组合 | 部分线索成立，且实际表层位置、身体位移与后部伸收满足下述时间组合 | 0.75 |

不设“任何柔性部分都给蛙类0.40”的规则。普通Tube的单一后部条束不能仅由配置者任意切成两半，就当作两个后部对象组；分组必须对应可见的空间结构。裙饵的环状裙丝也不自动成为蛙的后腿线索。

明确轮廓路径不要求当前运动。蛙形饵停住时仍有类型证据。它被拉入水下时，也不能仅因失去水面条件就改写成小鱼或把蛙类支持自动清零；本轮只有表层组合的额外支持不再成立，水下状态的解释另行处理。

## 19. 蛙类可选精细路径涉及三种关系

### 绑定部位组，而非只绑定一个对象

小龙虾近底组合读取一个条束／裙丝对象即可。蛙类组合可能要读取两个对象组之间的关系，实体腿和裙丝腿是不同的几何来源，但都能绑定到“左右后部组”这两个角色。

### 绑定环境参照

需要知道主体相对当前局部水面的距离，不能用固定世界高度代替水面。水面关系是运行时环境输入，不应在饵上配置一个永久为真的“水面饵”字段。

### 绑定身体与部位的时间关系

只记录最大展开幅度还不够。“移动时伸展、停住后收回”与“先收回、后来停住、再展开”可能有相同幅度和路程，但时间关系不同。需要能读取相关过程的顺序，不能统一缩成一个近期动作残留量。

示意配置：

```yaml
hollow_frog_with_skirt_legs:
  prey_bindings:
    frog:
      rule_set: frog_v0
      outline_source: assembled_body
      rear_group_sources: [left_skirt_bundle, right_skirt_bundle]
      trajectory_source: whole_rig
      environment_sources:
        water_surface: local_water_surface
      history_sources:
        body_motion: whole_rig_history
        rear_motion: rear_groups_history

frog_with_solid_legs:
  prey_bindings:
    frog:
      rule_set: frog_v0
      outline_source: assembled_body
      rear_group_sources: [left_leg, right_leg]
      trajectory_source: whole_rig
      environment_sources:
        water_surface: local_water_surface
      history_sources:
        body_motion: whole_rig_history
        rear_motion: rear_groups_history
```

二者引用同一个蛙类规则集，但不要求所有路径都成立。裙丝腿蛙的轮廓路径成立，不意味着其后部运动一定能通过实体腿式伸收组合。

规则应按路径声明所需输入：明确轮廓路径不要求后部动作历史；伸收组合才要求相应历史。若已有0.90轮廓支持，缺少只能提供最高0.75的路径事实不会改变已解析的类型支持，但状态层仍可能缺少历史。不能为了统一输入结构，让所有猎物与所有路径都强制读取同一套字段。

## 20. 蛙类条件核算与反例

继续使用人工支持档位，不计算捕获、feeding motivation或响应。完整记录窗口暂为1秒。表层定义为主体参考点距当前局部水面不超过0.5L；表层时间比例用累计时间计算。

表层伸收路径的局部条件：

```text
紧凑主体 AND 两个可辨认的后部对象组
AND 表层时间比例≥0.70
AND 左右后部组各自伸展幅度≥0.15L
AND 左右后部组各自随后收回幅度≥0.15L
AND 顺序成立：
    身体移动阶段发生伸展，身体停住后发生收回
→ 支持0.75
```

伸展与收回指后部对象组相对主体的纵向可见延伸变化，分别测量，不能用一个最大宽度替代。主体朝向变化、裙丝遮挡和可见程度需要上游明确；尚未自动提取。是否移动与停止在本例由已知的实际运动区间提供，不能直接把玩家“停收线”当作饵已停止。

该路径只是一种受具体产品用途启发的组合，不是所有自然蛙游泳的必要定义。此轮没有把walking或popping直接等同蹬腿，也没有在它们未通过这条路径时判整体失效。

| 人工呈现 | 蛙类支持 | 类型条件状态／原因 |
|---|---:|---|
| 明确裙丝腿蛙，水面静止 | 0.90 | 表层停留；无需持续蹬腿来维持类型证据 |
| 明确实体腿蛙，移动后收腿停留 | 0.90 | 表层移动后停留，可记录收腿过程；不因此在类型支持上重复加分 |
| 抽象短身双后束，水面静止 | 0.40 | 只有部分形态线索，表层静止不自动补成明确蛙形 |
| 同抽象装配，表层比例0.9，左右均伸展0.25L、随后收回0.20L，顺序成立 | 0.75 | 形态＋环境＋时序组合成立 |
| 同抽象装配，幅度与路程相同，但伸收与身体运动的顺序不成立 | 0.40 | 幅度相同不能代替时间关系 |
| 普通Tube，水面漂移；已知没有明确蛙形及分开的后部对象组 | 0 | 本轮全部蛙类支持路径均未成立 |
| 鱼形拖尾裙饵，水面晃动；已知没有明确蛙形及分开的后部对象组 | 0 | 水面与扰动单独不能提供本轮蛙类支持 |
| 明确蛙形，水下停住 | 0.90 | 类型线索保留；水下停留与其后续仿生评价另行处理 |
| 抽象短身双后束，动作历史缺失 | 未决，至少0.40 | 无法判断能否通过0.75的组合，不能补零 |
| 明确蛙形，动作历史缺失 | 0.90 | 类型支持已由最高档位闭合；历史状态仍未决 |

上表条件已执行核算；前五种、Tube、裙饵、水下蛙形与历史缺失例均按条件得到所列结果。这里的0依旧只表示本轮路径未提供支持，不能外推为排除一切蛙类识别。

状态层至少分别保留：表层／水下情境、当前移动／停留、已知的移动—停留过程及距转换多久、部位是否有伸收过程。它们可以并存，不用唯一的“游动蛙／停留蛙”标签包办。相同0.90类型支持下仍可有不同状态，再交给后续鱼侧评价。

## 21. 加入蛙类后，对框架作什么判断

暂时无需增加新的顶层判断节点：实际呈现 → 猎物解释 → 类型条件状态 → 鱼侧评价 → 响应仍能表达本轮案例。若采用上述精细路径，“装配×猎物绑定”需要能表达以下内容；这些先列为可选能力，不要求每件饵、每条路径都配置：

| 原先未明确的内容 | 蛙类检查后的要求 |
|---|---|
| 只举了绑定一个部位的例子 | 能绑定部位组，并读组间与相对主体的关系 |
| 底部关系作为普通输入，参照来源未写清 | 明确环境参照来源，支持底部、水面等不同参照 |
| 只有当前值或窗口极值 | 能读取事件顺序、部位与身体运动的对应关系 |
| 看起来有一套共同必填输入 | 各规则路径声明自己需要的输入，缺失处理依赖具体路径 |

本轮更支持“可共享规则集＋具体装配绑定”的候选：裙丝腿与实体腿不必各复制一套frog算法；同一规则集又可以包含不同证据路径。但它要求规则内部有真正的条件与时序机制，不能只是多一张权重表。

尚未解决：成对后部结构的弱支持是否过宽、可见性与遮挡如何处理、窗口与阈值的连续性、蛙在草垫／岸边等情境的解释、不同蛙形饵的其他有效运动路径，以及状态如何进入鱼侧评价。先前方案B的状态跳变问题没有因为换了规则组织方式就自动解决。

类型支持、类型条件状态与鱼侧评价的下一步推导见第22～25节。腿部差异暂不进入该算例。

## 22. 从蛙类状态进入鱼侧评价：先去掉不影响判断的细节

裙丝腿与实体腿的差异不是当前主体设计的必备分界。只有当其实际运动会改变解释、操作策略或鱼侧评价，才值得付出配置与实现成本。前文将其细化为部位组与伸收时序，是表达能力的压力测试，不是首版要求。

本轮固定：蛙类支持S_frog=0.90，大小与食物价值相同；鱼认识这类食物且已注意到当前目标。支持0.90不再乘入本轮计算，也不作为新的0.90概率。支持程度怎样参与完整响应仍是独立未决问题。

先只用主体轨迹、相对位置与鱼侧状态，展开三种呈现：

| 呈现 | 状态层实际输出 | 不直接赋予的含义 |
|---|---|---|
| 持续表层移动 | 相对水面位置、实际速度方向、持续时间 | 不直接判为惊恐逃窜或更吸引 |
| 移动后表层停留 | 当前速度接近零；已知此前移动；距停住多久 | 不直接加“移后停留bonus”，也不证明鱼已经追上 |
| 下沉 | 向下速度、当前深度与方向、相对鱼的位置 | 不凭下沉判受伤或失真，也不自动降低类型支持 |

“异常下沉”先还原成可观测的下沉事实。是否异常、失衡或与蛙的自然行为不协调，需要另有证据规则，本轮不拿这个词直接加减响应。

三种呈现可以保留独立事实，不强制互斥单标签。离开水面、向下移动与短促动作后停止也可能在同一过程内先后或同时出现。

## 23. 捕获评价：先算要求，再比较鱼的能力

本轮用二维直线局部任务，作为机制隔离算例。水面高度为0、向上为正。鱼位于(0,-0.20m)，饵当前位于(0.30m,0)，相对位置r=(0.30,0.20)m。

假设鱼可立即以固定上限速度c朝任意方向直线行动，目标在预测期间保持当前速度v。最早接触时间tau满足：

```text
||r + v × tau|| ≤ c × tau
tau = 满足该条件的最早非负时间；若不存在则本任务不可拦截
```

这是能力需求算例，未包括加速、转向、遮挡、捕获半径、动作准备或目标变速。c是真正的本例运动速度上限，不是方案B中用来换算代价的V。两者不能混用。

取c=0.60m/s，三种速度为：

| 当前呈现 | v，m/s | 最早接触时间tau |
|---|---|---:|
| 表层沿水平远离鱼 | (0.40,0) | 1.605秒 |
| 表层停留 | (0,0) | 0.601秒 |
| 从表层向鱼所在深度下沉 | (0,-0.15) | 0.538秒 |

停留的结果可直接核对：sqrt(0.30²+0.20²)/0.60=0.601秒。另两项按同一接触条件求解。这里不配置“游动蛙捕获系数”“停留蛙捕获系数”或“下沉蛙捕获系数”；轨迹先改变行动要求。

下沉在本例更快接近鱼所在深度，因此更容易接触。不能据此规定下沉更优。两个反例：

- 同样0.40m/s，若表层运动方向改为朝鱼，tau=0.405秒，比停住更容易接近。速度更快不必然更难捕获。
- 若饵已在鱼下方，令r=(0.30,-0.20)m，还以0.15m/s继续下沉，tau=0.716秒，比同位置静止的0.601秒更久。下沉效果依赖几何位置。

鱼侧能力改变时也不改写目标状态。将c降至0.25m/s，远离移动在本例不可拦截；停留tau=1.442秒，向鱼深度下沉tau=1.203秒。变化发生在捕获评价，蛙类支持仍为0.90。

## 24. 摄食意愿怎样接进来：限制愿意投入的行动，而非改写能力

在目标身份、食物价值和注意状态均固定的前提下，给出一版局部行动响应候选：

```text
H∈[0,1]，为已解析的feeding motivation
T_willing = 2秒 × H

若H=0，或本任务不可拦截：
    R_local = 0
否则：
    R_local = max(0, 1 - tau/T_willing)
```

T_willing表示这条鱼在本候选里愿为这份固定食物投入的行动时间预算。最大2秒及线性对应关系都是人工假设，不是生物标定，也不是对全体猎物或所有响应统一规定的公式。食物价值变化如何改变预算，尚未展开。

H不进入接触时间tau，不改变身体速度c。该公式只演示“捕获要求与愿意投入的程度”如何产生条件响应，不是方案B的激励系数全部相乘。R_local是固定食物、已注意目标的局部行动分数，不是最终摄食响应或咬口概率；状态额外刺激与跨解释聚合尚未计算。

| c | 当前呈现 | tau | H=1，预算2秒 | H=0.5，预算1秒 |
|---:|---|---:|---:|---:|
| 0.60m/s | 表层远离移动 | 1.605秒 | 0.198 | 0 |
| 0.60m/s | 表层停留 | 0.601秒 | 0.700 | 0.399 |
| 0.60m/s | 向鱼所在深度下沉 | 0.538秒 | 0.731 | 0.462 |
| 0.25m/s | 表层远离移动 | 不可拦截 | 0 | 0 |
| 0.25m/s | 表层停留 | 1.442秒 | 0.279 | 0 |
| 0.25m/s | 向鱼所在深度下沉 | 1.203秒 | 0.399 | 0 |

例如，高能力鱼面对表层停留，tau=0.600925秒，H=0.5使预算为1秒，R_local=1-0.600925=0.399075。该鱼的能力没有变，降低的是它愿意投入的程度。

这些结果按接触方程与所列响应候选执行核算。它们只显示本套人工假设的后果，不证明响应曲线真实或体验合理。若任务要求并不应以时间代表、或者摄食意愿不应按这一方式作用，应替换这一局部机制，不要求其他猎物服从它。

## 25. 移后停留为什么可能有效，以及还缺哪一块

本轮先得到一个无需额外奖励的作用：移动结束后，目标当前行动要求改变，可捕获窗口因此改变。若鱼在移动过程中已经接近，新的相对位置还会进一步影响tau；必须输入那份真实位置，不能凭“移后停留”标签假装鱼已经接近。

同时应明确以下边界：

1. 若两份目标当前身份、大小、位置和运动相同，鱼也已同样注意它们，那么“刚才移动过”不必然额外提高本轮捕获分数。长期静止与移后停留在该局部机制中可以相等。
2. 运动是否吸引注意、让鱼持续关注或增加某类摄食刺激，是另一条有待定义的作用。需要接收者侧信号与鱼的当前状态，不能由“移后停留”直接推断鱼已被激发。本轮将其固定，避免凭空赠送历史加分。
3. 下沉是否表现出受伤、惊恐或动作不协调，不能由捕获容易程度反推。此类状态若有证据，应明确它改变摄食评价的哪一项，不能再重复结算已经通过tau体现的运动要求。
4. 不能将时间序列的R_local直接相加、逐帧独立抽签或全程取最大值，就称为整次操作的中鱼概率。行动持续与机会结算仍未闭合。

本轮因此收敛出三种不同的中间结果：猎物解释保留类型支持；呈现状态保留运动、空间与历史事实及有依据的语义解释；鱼侧将这些事实转成捕获要求与行动投入的权衡。它们分别可检查，不再由“某状态更好”的一个固定倍率包办。

下一步优先推“状态对摄食刺激的独立作用”是否有需要、需要什么证据；如选择处理注意与持续关注，先明确它在当前模型中是已给定鱼侧状态、代理变量还是需要模拟的过程，再推时间上的行动响应。腿部精细结构不作为这一步的前置条件。

## 26. 1实际呈现到2猎物解释：本轮工作版本

### 26.1 明确这一步到底计算什么

输入是当前这件饵实际提供的呈现，以及用于解释这件装配的配置；输出是对各猎物类型的解释支持map。

支持表示“这份呈现有多少依据可以按该猎物理解”。它不是完整仿真逼真度、食物价值、喜欢程度、可得程度或咬口概率，也不要求所有项之和为1。

这一步不读取diet shift、feeding motivation、鱼的追赶能力或食物偏好。接收者的感官能力如果需要参与，应该先影响能得到哪些呈现事实；本轮先固定这些事实已可辨认，不实现感官模型。

类型解释较明确、但动作状态不协调，两者可以同时出现。因此运动未满足某条增强路径，不会自动抹掉已经存在的明确类型支持，也不会自动改成另一个猎物。

### 26.2 输入拆成两部分，不能把取值来源藏起来

**第一部分：装配×猎物的解释配置。**它在第2步被查入，不是第1步已经输出了一份最终猎物map。

首版不做从Mesh自动识别猎物。策划为某件具体装配配置形态支持基值b，以及允许使用的动态解释路径。此前一概认为饵上不宜配置“像鱼程度”过于绝对：配置一个有明确含义的形态支持基值是可行的，只要不把它当作本次完整解释结果。

b是对当前装配可提供的形态证据的人工近似，配置时应说明依据，例如“明确鱼体轮廓”“柔性尾轮廓但无明确鱼体”“紧凑蛙形主体”。这些依据暂由策划判断；不能宣称已经通过一套未实现的视觉算法算出。

**第二部分：实际呈现数据。**读取真正发生的轨迹与环境关系，不读取玩家按了哪个操作按钮。最少包括本轮路径实际需要的长度参照、位置轨迹、底部／水面参照，以及可选部位变化。

形态配置与运行时事实分别负责不同内容：前者近似这件装配能提供的类型线索，后者说明本次是否真的出现了某种组合。换拖尾应更新装配配置；抛到不同位置、改变操作则主要更新运行时事实。

本轮示例固定形态线索可见、可辨认。遮挡、水色、距离导致的线索丢失尚未计算，不能声称b已自动反映这些效果。

### 26.3 具体配置长什么样

```yaml
tube_rig:
  interpretations:
    small_baitfish:
      shape_support: 0.40
      routes:
        - pattern: falling_sway
          support_ceiling: 0.75
          trajectory_source: whole_rig
    crayfish:
      shape_support: 0.40
      routes:
        - pattern: bottom_appendage
          support_ceiling: 0.75
          trajectory_source: whole_rig
          appendage_source: rear_bundle
    frog:
      shape_support: 0
      routes: []

jig_with_fish_trailer:
  interpretations:
    small_baitfish:
      shape_support: 0.90
      routes: []
    crayfish:
      shape_support: 0.40
      routes:
        - pattern: bottom_appendage
          support_ceiling: 0.75
          trajectory_source: whole_rig
          appendage_source: skirt
    frog:
      shape_support: 0
      routes: []

  interpretations:
    frog:
      shape_support: 0.90
      routes: []
```

本例Tube与裙饵的frog条目已明确评价为“当前规则无支持”。clear_frog_rig未列出的小鱼、小龙虾条目则尚未评价，不能把它们当成零。不能将绑定缺省等同排除。

这些b与ceiling都是人工设计值，尚未标定。鱼形拖尾的0.90针对这件装配的形态，不是整个裙饵类别的永久分数。

只配置了一种猎物不意味着只能模拟一种猎物。可配置多个解释项；不同解释可引用相同或不同的pattern。也不再要求先配一个互斥的“明确／多样化”类型标签；解释项的结构和结果自然体现其单一或多重支持。

### 26.4 解释路径怎样实际计算

每条路径输出自己的匹配值f∈[0,1]。它只回答该条组合出现了多少，不直接等于某种猎物的最终支持。不同pattern可以读取不同事实、使用不同判断机制；不把所有猎物放进统一的几维距离。

为使本轮能够运行条件核算，先给出两条路径。它们是机制假设，不是经过验证的自然识别规则。

设sat(x)=min(1,max(0,x))，观察窗为已知完整的1秒，L为装配参考长度。

**小鱼的下落偏摆路径falling_sway**

```text
D = 向下净位移/L
W = 窗内轨迹偏离“起点到终点直线”的最大垂直距离/L
f_fall = min(sat(D), sat(W/0.50))
```

向下净位移取非负值。起终点重合时偏离量暂按距起点最大距离定义；若D=0，该路径结果仍为0。直线斜向下落的W=0，不能仅因横向位移较大就通过偏摆路径。

该路径支持“有偏摆的下落呈现”，不直接输出受伤、濒死或惊恐标签。实际哪些偏摆具有小鱼解释意义仍需后续反例检验。

**小龙虾的近底附属部分路径bottom_appendage**

```text
B = 离底间距≤0.50L的累计时间/1秒
X = 窗内水平路程/L
O = 绑定柔性部分的展开宽度变化范围/L

f_bottom = min(
    sat((B-0.20)/0.50),
    sat(X/0.50),
    sat(O/0.15)
)
```

三个量必须共同提供支持，取min是本条路径的连续AND候选，避免一项很强就无限补偿另一项缺失。Tube读取rear_bundle，裙饵读取skirt；规则正文共用。没有对应部位的装配不能通过虚构O来满足该路径。

该路径不要求整体速度越慢越好。速度对捕获要求的作用留给后面处理。O也可先由动画曲线或人工代理产生，不以实现细致软体物理为前置条件。当前O尚未接入生产数据；前文数值是人工样例。第27节给出具体来源候选和缺失时的处理。

这两条路径使用了相同的部分基础算子，但条件结构和输入不同；以后可以加入离散条件、时序关系或其他机制，不要求每种猎物都使用min，也不要求每件饵复制算法。

明确蛙形在本轮只使用b=0.90，暂不添加动态增强路径。持续移动、移后停留与下沉不改变这份已明确的类型支持，其差异进入第3步状态。此前蛙的精细伸收路径保留为探索候选，不是本工作版本的必做项。不是每类猎物都必须用相同数量的运动规则。

### 26.5 从路径匹配到猎物map

本轮选择以下局部组合规则：

```text
某类型的形态支持：b
动态路径j的支持上限：u_j，要求b≤u_j≤1
动态路径匹配：f_j

路径完整支持：s_j = b + (u_j-b) × f_j
该类型支持：S_k = max(b, s_1, s_2, ...)
```

此处乘法只做“从基值到该路径上限”的线性插值，不是方案B的激励系数相乘。max只组合同一类型的替代证据，不决定第5步怎样聚合响应。

这套规则的明确后果是：

- 路径完全不匹配时保留b，不凭动作不匹配自动更换猎物类型。
- 部分匹配提供部分增强，避免前文只用0.40／0.75硬跳档。
- 同一条证据被重复登记不会抬高结果。
- 多条证据的协同若确有需要，必须明写为一条联合路径，不能靠路径数量相加。
- b=0的解释项仍可能有动态路径，必须先评价动态路径，不能先按b=0剪掉。只有本次最终S_k=0且所需判断完整时，才可跳过该类型的后续评价。
- 当前没有负证据压低b的机制。严重不协调的运动如何处理，先交给状态；若以后需要否定类型身份，须增加具体依据，不偷偷塞一个通用惩罚。

模式上限与b相同时，动态路径不会改变类型支持，无需为这一步额外读取它。其事实仍可在第3步状态评价中有用。

### 26.6 同一组事实的逐步计算

以下仅在已配置并覆盖的三类范围内讨论。取Tube与裙饵的数据，D、W、B、X、O口径如上：

| 呈现 | D | W | B | X | O | 小鱼S | 小龙虾S | 蛙S |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Tube弯曲下落 | 2 | 0.40 | 0.10 | 0.8 | 0.20 | 0.680 | 0.400 | 0 |
| 同Tube直线斜落 | 2 | 0 | 0.10 | 0.8 | 0.20 | 0.400 | 0.400 | 0 |
| 同Tube近底移动、条束张合 | 0 | 0.10 | 0.90 | 1.2 | 0.25 | 0.400 | 0.750 | 0 |
| 同Tube近底移动、条束弱张合 | 0 | 0.10 | 0.90 | 1.2 | 0.03 | 0.400 | 0.470 | 0 |
| 鱼形拖尾裙饵近底移动、裙丝张合 | 0 | 0.10 | 0.90 | 1.2 | 0.30 | 0.900 | 0.750 | 0 |

第一行的小鱼路径：

```text
f_fall = min(sat(2),sat(0.40/0.50)) = 0.80
S_fish = 0.40 + (0.75-0.40)×0.80 = 0.68
```

第四行的小龙虾路径：

```text
f_bottom = min(1,1,0.03/0.15) = 0.20
S_crayfish = 0.40 + (0.75-0.40)×0.20 = 0.47
```

因此第一行输出可以为：

```text
small_baitfish: Resolved, support=0.68
crayfish:       Resolved, support=0.40
frog:          Resolved, support=0
```

明确蛙形装配的水面移动、移后停留、下沉，frog均为0.90；未配置评价的其他类型保留未覆盖状态。所有结果不按类型归一化，也不选择唯一赢家。

上述数值已按所列公式执行核算。D/W/B/X/O仍是人工输入，尚未实现从原始轨迹提取；因此这是完整局部运算而非完整生产识别器。W替换了前文的简单水平范围，避免将普通斜落直接当作偏摆；旧表不能与本表混用。

### 26.7 缺失、裁剪与输出责任

每个解释项至少输出状态与支持；Explain可带b、命中路径及其贡献，帮助检查配置与计算。不要求新增独立的业务节点。

- 已知完整：输出Resolved与S_k。
- 必要事实缺失且可能改变最终S_k：输出Unknown；例如已知b=0.40、可能达到0.75的路径未决，可以说明当前范围为[0.40,0.75]，不能用0.40冒充已解析最终值。
- 未配置且未评价：标记未覆盖，不能输出已知零。
- 对应所有路径均已评价且S_k=0：才是本轮规则下的已知无支持。
- 若未决路径的最大可能结果也不超过已知最大支持，不必阻止该类型支持闭合，但它的状态事实仍可能未知。

首版先只裁剪已解析S_k=0的类型，不引入任意低支持阈值。Unknown怎样影响完整响应，超出本步范围；这里的责任是不要把未知丢成零。

### 26.8 本轮明确的分工与剩余边界

配置单元是具体装配×猎物，保存b、路径引用、上限与必要来源绑定。机制实现可以按猎物规则集组织，也可以在有实际复用时共享pattern；不为每种商品写专属函数，不要求每种猎物用同一公式。

来源绑定可以默认整饵。只有规则实际读取了某个局部特征，才增加对应部位引用；首版不因架构允许就强迫所有饵配置腿、组、相位等细节。

本轮已推清取值来源、两条动态路径、局部组合、输出map与缺失处理。未推清的是参数是否适当、形态支持怎样配置得一致、更多动态路径是否必要，以及可见性与真实信号生产。这些是本机制的验证与扩展工作，不能声称已经获得鱼类识别的实证标定。

第2步只说明“支持按什么猎物解释”。受伤、逃窜等有依据的状态在第3步形成；价值、可得程度与摄食意愿在第4步处理。已经用于支持类型的事实可以继续帮助描述状态，但不能再自动乘一份相同的“像不像奖励”。

## 27. 条束张合的数据来源，以及T尾与Jig对照表

### 27.1 先说明上一张表用了什么数据

第26.6节已包含Tube与鱼形拖尾裙饵的支持表。它应当保留在Markdown中，作为检查公式、输入与输出的设计算例，不是正式饵属性表或实测鱼类相似度。

其中O=0.25、O=0.03是人工样例输入，不是已经从项目物理或动画提取的结果。本轮未核实生产项目是否有相关接口，不能宣称“现有系统已经提供条束张合”。

“条束张合”在这里特指指定柔性部分整体展开宽度的变化，不要求计算每一根丝；也不能把T尾的左右尾摆振幅直接当作裙丝展开变化。

### 27.2 三种来源的取舍

| 来源 | 怎样得到O | 当前取舍 |
|---|---|---|
| 动画／少量标记点 | 在饵的局部坐标中，按统一尺度读取指定条束／裙丝的展开宽度，取窗口内最大值减最小值，再除以L | 若已有相关动画或宽度曲线，可以使用；需要核实接口与骨骼／标记口径 |
| 配置曲线代理 | 用实际相对水速等输入驱动展开程度与恢复过程，再从生成序列取宽度变化 | 首版优先候选，独立于细致软体物理；仍需配置与接入 |
| 完整柔性物理 | 计算各条束受力与运动，再提取同一个宽度量 | 当前不作为前置要求 |

来源应显式记录。代理值不是测量值；无论用哪种来源，都不能一边从动画算一次O，一边再把代理O作为额外奖励重复计入。

来源尚未实现时，不能默默补O=0。若已知b=0.40、路径可能提高到0.75，但B、X足以成立而O未知，则该类型结果是未决，范围[0.40,0.75]。如果B、X已经明确让路径为0，则无需读取O也能确定该路径没有增强。

也可以显式选择一版更粗的规则、完全不读取O，但那属于替换机制，须重新检查输出表；不能沿用原规则却伪造输入。

### 27.3 一版具体的代理生成示例

此例只说明数据可以怎样产生，不把它当成真实水动力定律。将整个条束或裙丝的展开宽度除以L，记为w。策划配置：

```text
u = |饵速度 - 当前水流速度| / L，单位体长/秒

u到目标展开宽度w_target的曲线：
u=0 → 0.35
u=2 → 0.20
u=5 → 0.10
中间线性插值，区间外先按端点限幅

展开恢复时间tau_spread = 0.20秒

每步：
w_next = w_target + (w_current-w_target) × exp(-dt/tau_spread)

在完整1秒窗口内：
O = max(w) - min(w)
```

这里的u是相对水速，不是收线档位。停收线后饵可能仍在下落，或仍受到水流，因此不能直接设置u=0。每件具体装配可引用自己的曲线；不必给每根丝单独配置。

受控例：长时间u=5，代理已稳定在w=0.10；随后真实相对水速降为0，保持0.50秒。此时：

```text
w = 0.35 + (0.10-0.35)×exp(-0.50/0.20)
  = 0.329479

O = 0.329479-0.10 = 0.229479
```

在同一个1秒窗口包含降速前后记录的前提下，这份O足以使第26节的O/0.15项达到1。如果窗口内一直处于稳定展开状态，O可能接近0，即使裙丝当时非常展开。

这也暴露了原规则的一项限制：它奖励展开变化，而不是展开状态本身。稳定展开是否同样能提供小龙虾线索，需要独立检验，不能因O小就断言不像小龙虾。本轮先把它作为一条可选动态证据路径，b仍保留；该路径尚未证明是必要机制。

### 27.4 T尾与Jig先按具体装配区分

T尾描述软饵形状；Jig可能指铅头钩装配，也可能特指带裙丝的Jig。它们不是互斥类别。以下分别定义：

- 鱼形T尾＋无裙丝铅头钩：本例有明确鱼体轮廓，没有裙丝与小龙虾形拖尾。
- 无拖尾裙丝Jig：有裙丝，但本例没有明确鱼体或小龙虾轮廓。
- 裙丝Jig＋鱼形T尾：有明确鱼形装配轮廓，也保留裙丝线索。
- 裙丝Jig＋明确小龙虾拖尾：有小龙虾轮廓，裙丝仍可支持其他解释。

这不是给整个T尾类别固定唯一猎物。具体形态、拖尾与装配改变后，配置需要随之改变。

### 27.6 表中的相同值与当前规则缺口

鱼形T尾的三行都为小鱼0.90，是因为这一步只输出猎物类型解释支持，明确鱼形在本例没有消失；不表示三种操作同样有效。尾摆、速度、停顿与下沉可在第3步状态及第4步鱼侧评价中产生差异。

T尾左右摆动应单独称为尾摆等运动量，不能把它写入裙丝张合O。如果后续确有需要让尾摆增强某些较弱形态的小鱼解释，须增加具体路径并说明数据来源；本轮不因“T尾应该有动作”就临时增加倍率。

同理，无拖尾裙丝Jig直线游动停在0.40／0.40，暴露的是当前规则还没有游动组合增强路径，不能据此判断真实swim jig吸引力弱。若某个真实策略需要在第2步形成更强的小鱼或小龙虾解释，应补相应机制；若类型已足够明确而差异主要是状态，则留在后续节点处理。

这张表的用途是暴露这些差异与缺口，不能把解释支持当作所有饵与操作的强弱排名。
