# 方案 C：从路亚实际呈现到猎物解释

日期：2026-10-23  
状态：设计提案。规则与数值为可检查的设计假设，尚未完成生产接入与效果验证。  
相关提案：[方案B](lure-feeding-target-interpretation.md)。两份提案独立；本页只定义方案C当前讨论的机制。

## 1. 目标与范围

本提案集中处理“1实际呈现 → 2猎物解释”：一件具体饵装配提供哪些证据，当前操作与环境让哪些动态证据成立，最后分别支持哪些猎物解释。

整体主线如下。本页展开前两步，后续节点只保留职责边界。

| 节点 | 回答的问题 |
|---|---|
| 1 实际呈现 | 当前装配实际提供了什么形态、运动及环境关系？ |
| 2 猎物解释 | 这些证据分别在多大程度上支持不同猎物类型？ |
| 3 类型条件状态 | 按该猎物理解，它表现为怎样的移动、停留、失衡或逃窜状态？ |
| 4 鱼侧评价 | 对这条鱼，食物价值、捕获要求与摄食意愿如何？ |
| 5 响应 | 上述评价怎样形成行动响应？ |

第2步输出猎物支持map，各项不要求之和为1，也不强制选择唯一类型。支持值表示“有多少依据可以按该猎物理解”，不是整体动作逼真度、食物偏好、可得程度或咬口概率。

运动可以参与第2步解释，也可参与后续状态与捕获评价，但同一作用不能重复结算。第2步不读取diet shift、feeding motivation或鱼的追赶能力来改写目标身份。

### 猎物范围

以下是工作分类，不直接等于七个固定计算通道。是否细分，以判断机制或鱼侧评价是否存在重要差异为依据。

| 猎物家族 | 包含哪些对象 | 需要检验的判断差异 |
|---|---|---|
| **鱼类** | 小型饵鱼、较高体型的小鱼、底栖鱼、细长鱼等 | 轮廓、摆动、反光；游动、悬停、下落、失衡等呈现 |
| **甲壳类** | 虾、小龙虾、蟹等 | 身体与附肢线索；游动、爬行、弹跳、逃逸与底部关系 |
| **两栖类** | 蛙、蝌蚪等 | 不同发育形态；水面、水下运动与停留 |
| **蠕虫、水蛭类** | 蚯蚓、水生蠕虫、水蛭等 | 柔软细长的形态、弯曲、蠕动、漂移等 |
| **昆虫类** | 水生幼虫、若虫、成虫，以及落水陆生昆虫 | 发育阶段、漂流、上浮、水面挣扎等差异 |
| **头足类** | 鱿鱼、章鱼等 | 海水路亚中的躯体、触腕与运动呈现 |
| **特殊猎物，暂作扩展** | 鼠、幼鸟、蜥蜴等 | 特定鱼种与场景下的较大猎物呈现 |

首批设计对象为小型饵鱼、小龙虾、蛙。鱼类与Shad等子类不能重复当作独立的响应机会；具体层级仍待确定。贴底爬行、走停、抽停是呈现方式或过程，不与猎物家族并列。

## 2. 两类逻辑与数据分工

### 饵侧呈现逻辑

饵侧接收已有的实际运动与环境记录，生成或提取这件饵特有的表现，例如下落轨迹、尾摆、裙丝展开变化。实现可以使用现有动画、配置曲线代理或必要的物理记录；不要求先自动识别Mesh或模拟每根柔性条束。

同样的操作指令，对不同装配未必产生同样呈现。停收线也不等于饵停止运动。判断应读取实际记录或明确的代理结果。

### 猎物解释逻辑

猎物侧读取形态证据与本次呈现，运行适用的解释路径，输出支持map。不同猎物可以使用不同条件、时序模式与特征，不要求共用一个几维距离公式。

### 配置关系

配置明确：这件装配选择哪些证据，证据针对哪类猎物，读取哪个对象或部位，使用哪条解释路径与参数。

| 内容 | 负责什么 | 例子 |
|---|---|---|
| 装配配置 | 选择可用证据与来源；声明已评价的猎物范围 | 裙丝Jig＋鱼形T尾，选择裙丝证据与鱼形证据 |
| 饵侧呈现配置 | 定义如何产生饵特有的运行时数据 | 相对水速到裙丝展开程度的代理曲线 |
| 解释证据配置 | 保存该份证据自己的形态基值、动态路径和上限 | 裙丝的小鱼证据基值0.40，下落偏摆路径上限0.75 |
| 运行时呈现 | 提供本次实际发生的数据 | 位移轨迹、近底比例、绑定裙丝的变化 |
| 猎物解释器 | 评价每份证据，按猎物汇总 | 分别得到小鱼、小龙虾、蛙的支持 |

来源可默认整饵。只有某条路径实际需要局部数据时，才绑定对应部位。部位组、后腿伸收等精细信息不是统一必填项。

本页算例固定形态线索可见、可辨认。遮挡、水色与距离如何改变可获得线索，尚未接入；配置基值不冒充这些效果的实时计算结果。

## 3. 配置与计算规则

### 3.1 每份证据拥有自己的基值与上限

配置与计算的基本单元是一份“针对某种猎物的证据”。它可以来自某个部件，也可以来自装配后的整体轮廓。装配需要明确选择适用证据，不机械地把所有部件分数合并；例如拖尾被遮挡或组合轮廓改变后，应检查相应证据是否仍适用。

每份证据e保存：

| 字段 | 含义 |
|---|---|
| prey_type | 该证据支持的猎物类型 |
| base_support，记为b_e | 形态证据的支持基值，0～1，由策划配置并说明依据 |
| routes | 该证据允许使用的动态解释路径，可以为空 |
| pattern | 动态路径引用的判断机制 |
| support_ceiling，记为u_ej | 该路径可达到的支持上限，满足b_e≤u_ej≤1 |
| sources | 该证据和路径读取的装配、轨迹、环境或部位来源 |

b_e是人工形态近似，不是已实现的视觉分类器输出。0.40、0.75、0.90等数值均为设计值，不是生物标定。

不额外设置一个独立的“整装配基值”。需要表达整体轮廓时，将它配置为一份整体证据，与其他证据采用同一计算接口。整装配只负责选择与汇总证据。

### 3.2 动态路径匹配

每条路径按自己的机制输出f_ej∈[0,1]。路径内部可以使用连续条件、离散条件或时序关系；具体读取哪些数据由该路径决定。

匹配为0表示这条动态组合未提供增强，不自动改换猎物类型。部分匹配提供部分增强。负证据压低形态基值的机制不在本版中；若需要否定已有类型线索，必须说明具体依据。

### 3.3 统一评价与汇总

```text
动态路径分数：
s_ej = b_e + (u_ej-b_e) × f_ej

一份证据的结果：
s_e = max(b_e, s_e1, s_e2, ...)

某类猎物的装配结果：
S_k = max(所有针对猎物k、适用证据的s_e)
```

没有动态路径时，s_e=b_e。这里的乘法只是在该份证据的基值与路径上限之间插值。max用于组合替代证据，不规定第5步响应也必须取max。

装配中更强的其他证据不会改写本证据的b_e或u_ej。例如T尾提供0.90小鱼支持，裙丝证据仍可在自己的0.40～0.75范围内计算，装配最后取最强结果。

同一份证据重复登记不会数值叠加。若两种线索确实需要联合判断，应明确配置联合证据或路径，不能靠重复枚举获得额外奖励。不同证据共用路径时，只共享机制与适用参数，不要求来源相同。

### 3.4 执行过程

```text
读取装配声明的评价范围与证据绑定
对每份适用证据：
    读取自己的形态基值
    获取已启用路径需要的本次呈现数据
    运行路径，得到匹配与该份证据的支持
按猎物类型分别汇总证据
输出每种猎物的状态、支持值与可检查的依据
```

统一执行器调用不同pattern，而非为每种商品写一个专属函数。饵侧的数据生产逻辑与猎物侧的解释规则各自复用。

### 3.5 零、缺失与覆盖范围

装配须声明本模型已经评价哪些猎物。明确声明覆盖某类型、且确认没有适用证据时，才可以输出该模型下的已知零。未配置、未评价的类型标记为未覆盖，不自动填零。

必要运行时事实缺失、且可能改变结果时，保留Unknown。例如b_e=0.40、上限0.75的路径未决，则该证据结果范围为[0.40,0.75]。若另一份已知证据达到0.90，这份未决路径不影响该类型支持闭合；相应历史状态仍可能未知。

绑定引用不存在的部件属于配置错误。来源存在但必要记录未取得属于数据缺失，两者分开。

不能因为b_e=0就提前剪掉动态路径；只有最终类型支持已解析为0，才跳过该类型后续评价。首版不设置任意低支持裁剪阈值。Unknown如何影响完整响应，留到响应阶段明确。

## 4. 配置、输入与结果对照

以下算例用于检查机制与数据关系。全部数值均为人工设计；运行时特征由样例直接提供，尚未从项目物理或动画提取。

### 4.1 两条示例动态路径

观察窗取完整1秒，L为该装配参考长度，sat(x)=min(1,max(0,x))。

| 特征 | 样例定义 | 数据来源 |
|---|---|---|
| D | 向下净位移的非负值/L | 窗内实际位置轨迹 |
| W | 轨迹到起终点连线的最大最短距离/L | 窗内实际位置轨迹；起终点重合时按距起点最大距离 |
| B | 离底间距≤0.50L的累计时间/1秒 | 轨迹与局部底部参照 |
| X | 窗内水平路程/L | 实际位置轨迹 |
| O | 指定柔性部分的展开宽度变化范围/L | 动画记录或配置代理，来源需明确 |

**小鱼下落偏摆：**

```text
f_fall = min(sat(D), sat(W/0.50))
```

直线斜落的W=0，不会仅因存在横向位移而通过偏摆路径。该路径不直接产生受伤或濒死标签。

**小龙虾近底附属部分运动：**

```text
f_bottom = min(
    sat((B-0.20)/0.50),
    sat(X/0.50),
    sat(O/0.15)
)
```

min是本示例的连续AND：一项很强不能无限补偿另一项不足。不要求所有猎物或所有路径都采用min。

O在这里仅用于展示“一条规则读取饵特有数据”的案例，不是所有小龙虾呈现的必要条件，也不要求首版建设精细条束系统。它测量变化而非稳定展开形态，该限制应随此示例保留，不由此推定O越大越好。

如果选择保留这条路径，O可由“实际相对水速→目标展开程度”的配置曲线与恢复时间生成，也可读取已有动画。未实现来源时，保留未决；不能补O=0，或把T尾的左右摆动振幅冒充裙丝张合。更粗的近底路径可以另行定义，但应同步重算结果。

### 4.6 计算追溯

**Tube＋P1：**

```text
f_fall = min(1,0.40/0.50) = 0.80
tube_fish = 0.40+(0.75-0.40)×0.80 = 0.68
f_bottom = 0，tube_cray = 0.40
输出：小鱼0.68，小龙虾0.40，蛙0
```

**裙丝Jig＋鱼形T尾＋P1：**

```text
skirt_fish = 0.40+(0.75-0.40)×0.80 = 0.68
tail_fish = 0.90
小鱼支持 = max(0.68,0.90) = 0.90
```

此处裙丝仍用自己的b=0.40、上限0.75，不拿整件装配的0.90代入裙丝路径。添加T尾不改变裙丝定义。

**Tube＋P4：**

```text
f_bottom = min(1,1,0.03/0.15) = 0.20
tube_cray = 0.40+(0.75-0.40)×0.20 = 0.47
```

若P3的O未取得，tube_cray为Unknown、范围[0.40,0.75]；不能把表中的0.75当作已算出的生产结果。

后续需要收敛：

1. 形态支持值如何配置得一致，具体装配怎样选择适用证据。
2. 哪些动态路径足以解释需要的策略差异，哪些仅保留为示例。
3. 已选路径的数据来源、观察窗口、可见性与记录缺失怎样接入。
4. 类型支持如何与第3步状态衔接；不同状态再怎样影响鱼侧评价。腿部精细结构不是前置条件。

第2步的max仅汇总类型证据，后续响应聚合另行确定。已用于类型支持的事实可继续用于描述状态，但不能自动重复乘一份相同的“像不像奖励”。
