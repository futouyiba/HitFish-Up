# 方案 C：按猎物类型分层解释与评价路亚呈现

日期：2026-10-23  
状态：独立设计提案，沿本轮对话继续推导；不是生产规范，已有首轮局部条件规则与案例推导，尚无方案C的完整公式或实现。  
方案B：[线索支持、呈现状态与鱼的响应](lure-feeding-target-interpretation.md)。方案B的原型、数值和失败记录继续保留，不在本文件中改写。

## 1. 为什么单独提出方案C

方案B用有限的类型支持规则、共同状态距离，以及激励相乘后扣除行动代价的形式，快速做出了可执行探针。轨迹推算暴露了状态切换的响应跳变，也让我们重新检查：不同猎物的解释与鱼侧评价，是否被过早压成了一套共同计算形式。

方案C保留“同一呈现可以支持多种猎物解释”的方向，先展开每类猎物自身的判断逻辑，以及解释、状态、捕获评价和摄食评价之间的关系。共同接口可以统一，内部判断机制不必相同。

方案B的 B=H×S×p×F×g 中各符号确实是相乘。方案C不继承统一乘法、最近状态距离、固定状态激励倍数，也不默认继承跨路径max。需要共用的规则，待案例推导后逐项确认；不能把方案B的数值结果当作方案C已经成立的证据。

## 2. 暂定主线

以下是讨论所需的语义节点，不是五个已经冻结的数据结构，也不要求实现成五个严格串行模块。

| 节点 | 回答的问题 | 暂定输出 | 主要边界 |
|---|---|---|---|
| 实际呈现 | 接收者可感知到什么？ | 轮廓、大小、物理特性、运动过程、水层、反光、振动等事实 | 商品名称不直接指定猎物身份；未观测不补零 |
| 猎物解释 | 各种猎物解释分别得到多少支持？ | 按猎物类型组织的支持map及依据 | 不因鱼更爱吃某食物，就把饵解释成该食物 |
| 类型条件下的呈现状态 | 如果按这种猎物理解，它当前表现如何？ | 正常移动、停留、失衡表现、逃窜表现等中间判断 | 状态定义与证据可以随猎物类型不同 |
| 鱼侧评价 | 对当前这条鱼，食物价值如何、捕获要求如何、是否愿意行动？ | 捕获评价与摄食评价，必要时再细分 | 可得程度与摄食意愿分开；不提前合成匿名总分 |
| 响应 | 这些评价如何激发行动？ | 各猎物解释下的响应，以及后续聚合 | 响应强度不反写目标身份；尚不等于中鱼概率 |

实际运动过程同时向猎物解释、呈现状态和捕获要求提供输入。不能先只凭静态外形永久定类，再禁止运动参与解释。相同事实可以有不同作用，但同一后果不能在多处重复扣罚或加分。

鱼种的感官差异可以影响可获得的线索；食物偏好、摄食意愿和运动能力不能代替线索证据。当前先讨论感知事实已经提供的情况，不在此冻结感官模型。

## 3. 猎物支持map

本轮保留一个显式的中间结果，例如：

```text
小型饵鱼：0.9
甲壳类：  0.5
蛙类：    0.0
```

这只是说明输出形态的示意值，不是已算出的结果。

暂定含义是“该解释获得的支持程度”。各项不要求加起来为1；也尚未规定它等于响应保留比例，或必须与后续响应相乘。0.9与0.5的尺度、跨类型可比性、证据组合及校准方式均待推导。

不同类型允许不同判断机制，例如必要线索、若干充分组合、条件规则、连续匹配或时序模式。不能先规定所有类型必须使用同一组维度与距离，再去填不同中心。

确认没有支持的分支可以停止后续计算。缺失事实或尚未覆盖的规则不等于0。低支持阈值的裁剪属于后续决策：需要说明是否可能丢掉重要响应，不能仅凭方便设一个统一阈值。未决分支如何影响最终输出也需明确，不自动照搬方案B的全局阻断规则。

## 4. 类型、运动与状态各放在哪一层

| 例子 | 适合放置的层次 |
|---|---|
| 小型饵鱼、甲壳类、蛙类 | 猎物类型，最终粒度待定 |
| Shad等更细猎物类别 | 可能的子类型；需要证明确实购买了不同判断或响应 |
| 米诺 | 若指拟饵商品类别，属于呈现来源；若指自然猎物类群，需另行定义 |
| 贴底爬行、水面游动 | 运动与环境关系，参与解释和状态判断 |
| 走停、抽停 | 一段实际运动序列，不直接获得固定响应倍率 |
| 失衡、疑似受伤、惊恐逃窜 | 依赖证据的状态解释，不是直接观测事实 |
| 速度、加速度、离底距离 | 呈现事实或提取特征，不必再包装成一个语义系数 |

不能把“蛙类”与“贴底爬行”作为同一层的平行猎物项。也不能把父类小鱼与其子类Shad重复当成两个独立响应机会；层级与去重方式尚待确定。

呈现状态不必是唯一标签，也不必各状态之和为1。比如“失衡表现”与“快速位移”可能同时成立；哪些状态互斥、哪些可共存，应由每类判断机制说明。

## 5. 鱼侧评价先分清两件事

### 捕获评价

猎物状态与实际几何提出了什么行动要求？鱼当前的速度、转向、加速等能力能否满足？由此得到对这条鱼而言的可得程度。

速度慢不必然更可得：位置、遮挡、逃逸路线和鱼的当前状态都可能改变结论。具体需要哪些输入，由首批案例推导，不先把所有可能因素列成必填字段。

### 摄食评价

鱼是否吃这类猎物、当前食物偏好与diet shift如何、这份食物的价值如何、当前feeding motivation是否支持行动？

食物偏好与feeding motivation保持不同含义。方案B的摄食动机专题可以作为候选参考，但其中的sigmoid、时段偏移与近期负荷公式并未因引用而自动成为方案C规则。

两种评价最后可以存在条件关系。例如容易捕获不代表想吃，很想吃也不代表愿意承担任何行动要求。大小也可能同时改变食物价值与捕获要求；若如此，应分别说明两条作用，而不是重复乘一个大小系数。

## 6. 从哪一端开始推

采用“最小语义约定 → 具体机制与案例 → 所需数据 → 下一案例修订”的循环。机制推导在前，完整数据契约在后；不先列完所有节点的字段，也不长期只画框架。

先约定每个节点回答什么、哪些含义必须分开。例如支持不等于偏好，可得不等于意愿，未知不等于零。接着推一个实际判断，写出条件、运算或明确比较结果；算不出来的地方标为缺口。只有当某项数据被规则实际读取、影响案例判断时，才把它提升为候选字段。

每轮形成一条小而完整的切片：输入事实、判断依据、中间结果、鱼侧变化、响应差异。允许早期数值是假设，但必须能检查；不能只留下函数签名，或为了得到预期排序事后随意改参。

### 首个切口：猎物解释到呈现状态

首批设计对象改为“小型饵鱼、小龙虾、蛙类”。先推小型饵鱼与小龙虾，用明确形态与同一Tube的不同呈现检查类型支持和状态判断；首版规则形成后立即加入蛙类，检查水面与停留逻辑。具体首轮推导见第8～12节；规则归属与配置展开见第13～17节。

首轮要回答：

1. 哪些线索足以支持该猎物解释，哪些仅用于判断状态？
2. 动作不匹配时，是支持减弱、状态改变，还是规则尚未覆盖？不能一概跳成另一猎物。
3. 同样处于停顿，近期运动与实际浮沉分别改变什么中间判断？
4. 各类型确实需要不同规则的地方是什么，哪些事实提取可以共享？

同一Tube的下落与近底移动在第一组案例中就参与检验多类型支持，防止把结构做成“一种饵只对应一种猎物”。

解释与状态的首版机制成立后，再固定同一份呈现，分别改变鱼的能力、偏好、feeding motivation，推捕获评价和摄食评价。最后才决定响应如何组合，以及跨类型的结果怎样聚合。上游案例需要的字段同步整理，不等到所有机制完成才补数据说明。

## 7. 首轮验收与未决问题

首轮至少应能检查以下结果：

- 同一呈现不因鱼的食物偏好变化而被重新解释。
- 明显鱼形饵仅因触底不会自动变成甲壳类；动态证据仍可支持本来就有依据的其他解释。
- 蛙类水面停留可以是合法呈现，不预设静止必然失效；异常水层如何影响支持与状态由规则明确。
- 抽后停顿与长期静止在证据充分时可以不同；缺失历史不伪装成已知没有动作。
- 状态与类型名称有具体规则支撑，不能只靠标签附赠倍率。
- 所需数据均能对应到某条实际判断，未知与已知零能够区分。

尚未裁定：猎物分类粒度、支持值尺度、各类型判断机制、状态集合及时间窗口、feeding motivation的具体参与方式、捕获评价公式、响应映射、跨类型聚合，以及后续行动与咬口结算。

本提案依据为当前项目对话及仓内方案B的推导与失败记录。猎物示例和机制建议属于设计假设，不作为新取得的生物学证据。

## 8. 路亚猎物范围与首轮选择

先整理六个主要家族；这是工作分类，不是完整生物分类，也不是已经冻结的六个计算通道。

| 猎物家族 | 包含哪些对象 | 需要检验的判断差异 |
|---|---|---|
| **鱼类** | 小型饵鱼、较高体型的小鱼、底栖鱼、细长鱼等 | 轮廓、摆动、反光；游动、悬停、下落、失衡等呈现 |
| **甲壳类** | 虾、小龙虾、蟹等 | 身体与附肢线索；游动、爬行、弹跳、逃逸与底部关系 |
| **两栖类** | 蛙、蝌蚪等 | 不同发育形态；水面、水下运动与停留 |
| **蠕虫、水蛭类** | 蚯蚓、水生蠕虫、水蛭等 | 柔软细长的形态、弯曲、蠕动、漂移等 |
| **昆虫类** | 水生幼虫、若虫、成虫，以及落水陆生昆虫 | 发育阶段、漂流、上浮、水面挣扎等差异 |
| **头足类** | 鱿鱼、章鱼等 | 海水路亚中的躯体、触腕与运动呈现 |
| **特殊猎物，暂作扩展** | 鼠、幼鸟、蜥蜴等 | 特定鱼种与场景下的较大猎物呈现 |

表中特殊猎物暂作扩展。浮游生物、鱼卵、贝类、植物等不是不存在，而是未列入本轮主动拟饵的优先设计集。后续兼容其他钓法时还需按目标范围补充，不能把这个表当作所有鱼的完整食谱。

第一组选择小型饵鱼与小龙虾，原因是既有不同的线索和行为，又有同一Tube用于两种模拟的现实案例。蛙类排在下一组，用于检验框架是否过度依赖游动或触底。

资料入口：

- [Minnesota DNR：大口黑鲈](https://www.dnr.state.mn.us/minnaqua/speciesprofile/largemouthbass.html)：列出食性随成长从浮游动物、水生昆虫转向小龙虾与鱼类，以及多种自然钓饵。
- [TPWD：Red Drum](https://tpwd.texas.gov/huntwild/wild/species/reddrum/)：鱼、虾、蟹仿生呈现的应用，说明海水扩展不能把所有甲壳类直接等同小龙虾。
- [Rapala：轻型Jig用途](https://blog.rapala.com/vmc/new-vmc-jigs-help-anglers-match-the-hatch/comment-page-1/)：拟饵覆盖水生昆虫、甲壳类与饵鱼。
- [Nomad：Striped Bass拟饵](https://www.nomadtackle.com/pages/striped-bass-lures)：包含Squidtrex等鱿鱼呈现。
- [Shaw Grigsby的Tube案例](https://www.bassmaster.com/how-to/news/be-a-better-tube-fisherman/)：同一Tube用于小鱼与小龙虾模拟，螺旋下落用于伤鱼呈现。

上述钓饵用途不等于测得鱼的识别机制。下面的条件、支持档位和解释边界均为方案C新提出的设计假设。

## 9. 首轮机制：有明确类型线索与只有部分线索时，走不同路径

本轮先处理接收者已获得的呈现事实。为了讨论判断机制，人工样例明确给出可见轮廓、可见柔性部分和实际运动；尚未实现从Mesh、材质、动画到线索的提取。下面使用的“明确鱼体轮廓”“前部成对粗大突出部分”等，是人工标注的可辨认证据，不是商品类别，也不是已经完成生产定义的字段。

这一步输出两个有范围的猎物支持项：小型饵鱼与小龙虾。其他家族尚未评价，不隐含它们为零。

### 支持值口径

本轮暂用三个人工档位，让案例能够明确比较：

| 数值 | 约定含义 |
|---:|---|
| 0.40 | 有部分类型线索，但单凭它仍缺乏区分力 |
| 0.75 | 部分类型线索与特定运动／环境形成一组支持组合 |
| 0.90 | 有本轮认可的较明确类型轮廓线索 |
| 0 | 所有本轮适用路径都已检查，均未提供支持 |

这些数值不是分类概率、整体逼真度或激励保留比例，不能直接乘入响应。0.90也不表示整体呈现九成像真实猎物：它可以同时伴随“有鱼体轮廓，但动作解释未闭合”。跨类型的0.90暂时只共用档位说明，尚无严格校准意义。

档位间距是设计占位；这一轮真正检验的是路径成立条件与输出排序，不声称算出了自然相似度。

### 小型饵鱼：首轮三条支持路径

| 路径 | 条件同时成立 | 支持 |
|---|---|---:|
| 较明确轮廓 | 可辨认的鱼体轮廓 | 0.90 |
| 柔性组合的动态解释 | 可见细长柔性部分／裙丝；主体在离底下落中表现出连续螺旋或侧向飘落 | 0.75 |
| 部分线索 | 可见细长柔性部分／裙丝，但尚未满足上面的运动组合 | 0.40 |

首轮只注册以上路径，不把普通下沉或任意反光直接判为小鱼。其他有效小鱼线索仍待补充。第二条根据Tube用途提出候选组合，不代表所有有丝状部分的螺旋物体在生物上都像伤鱼。

### 小龙虾：首轮三条支持路径

| 路径 | 条件同时成立 | 支持 |
|---|---|---:|
| 较明确轮廓 | 紧凑主体、前部成对粗大突出部分，以及可见的腹尾分区共同构成小龙虾轮廓 | 0.90 |
| 柔性组合的近底解释 | 可见细长柔性部分／裙丝；接近或接触底部；发生近底拖行或间歇位移，且柔性部分发生可见展开变化 | 0.75 |
| 部分线索 | 可见细长柔性部分／裙丝，但尚未满足上面的近底组合 | 0.40 |

完整轮廓只是其中一条充分支持路径，不是所有小龙虾解释的必要条件。没有完整螯、足或腹尾结构的裙饵，仍可经其他路径获得支持。

“接近底部”单独不提供小龙虾支持。也不把所有甲壳类收进本条规则：虾的游动、蟹的运动另需推导。

### 同类路径怎样组合

同一类型的多条路径是在提出替代证据，本局部候选暂取最强的已成立档位，不按路径数量相加。这里的取大只用于线索支持；不等于决定跨类型响应也取max。

任何未观测的必要条件都保留未决。若已有0.40路径成立，但决定能否升到0.75的运动事实缺失，则只知道支持至少为0.40，不能把最终值写成已解析0.40。如何编码这种未决结果，待数据契约整理。

## 10. 首轮案例：相同运动不能替代不同的类型证据

以下人工样例都明确提供本轮所需事实。名称只帮助阅读；判断实际读取表中的特征。为隔离机制，鱼形、小龙虾形样例均没有额外裙丝等其他支持线索。

| 呈现事实 | 小型饵鱼支持 | 小龙虾支持 | 为什么 |
|---|---:|---:|---|
| 明确鱼体轮廓，水中匀速游动 | 0.90 | 0 | 鱼体路径成立；没有本轮小龙虾线索 |
| 同样鱼体轮廓，贴底拖行 | 0.90 | 0 | 触底与拖行不能替代小龙虾路径需要的轮廓或柔性线索 |
| 明确小龙虾轮廓，近底间歇移动 | 0 | 0.90 | 小龙虾轮廓路径成立 |
| 同样小龙虾轮廓，被快速拉到离底位置 | 0 | 0.90 | 本轮仍有类型证据；动作是否合理需下一层判断 |
| 无明确鱼／小龙虾轮廓的Tube，柔性部分可见，螺旋下落 | 0.75 | 0.40 | 小鱼动态组合成立；小龙虾只保留部分线索 |
| 同一Tube，近底拖行且柔性部分展开变化 | 0.40 | 0.75 | 小龙虾近底组合成立；小鱼保留部分线索 |
| 同一Tube，离底悬停，已知近期无相关运动 | 0.40 | 0.40 | 两类均只有部分线索，本轮不强制选一个 |
| 同一Tube，运动历史未提供 | 未决，至少0.40 | 未决，至少0.40 | 不能用缺失历史代替“已知未运动” |

这些0只表示本轮规则集未提供支持，不等于证明鱼绝不把它解释成该猎物。若识别出其他可用线索，应补规则与反例，不靠偏好去补身份。

本轮出现的机制差异是：小鱼动态路径读取离底下落的轨迹形态；小龙虾动态路径读取底部关系与近底位移。它们不是对同一个统一运动距离换一组中心值。

## 11. 支持之后，下一层具体输出什么

同一份输入事实可以再次用于状态解释，但本轮不把支持值乘以“状态像不像”再重算一次相似度。支持与状态回答不同问题。

| 已支持的解释与事实 | 首轮可以输出的状态描述 | 仍不能直接推断 |
|---|---|---|
| 小鱼解释；持续稳定游动 | 稳定游动表现 | 鱼一定喜欢该速度 |
| 小鱼解释；短促位移后停止，历史已知 | 短促位移后停留；记录距停止多久 | 仅凭抽停确认受伤或惊恐 |
| 小鱼解释；螺旋／侧向飘落 | 下落中有非直线轨迹；可作为失衡样态的候选依据 | 已证明生物学受伤，或应该附赠固定倍率 |
| 小龙虾解释；近底拖行／间歇位移 | 近底移动；接触是否持续、是否离底可分别描述 | 所有移动越慢越好 |
| 小龙虾解释；离底快速拉动 | 离底快速位移，类型证据仍保留 | 自动判为逃逸；需进一步看方向、历时等证据 |
| 任一解释；当前停住但历史缺失 | 当前静止，历史状态未决 | 当作长期静止或“抽后停留” |

首轮先把状态中有依据的运动关系与时序关系写明。是否进一步形成失衡、逃窜等语义状态，必须追加证据规则。不能为了输出状态名而直接赋予0.8等系数。

尚不计算鱼侧的可得程度、摄食意愿或响应。这样可以保留一个重要反例：类型支持很强，但当前运动不协调、状态尚未解释，或者对某条鱼而言很难捕获。三者不再被同一支持标量包办。

## 12. 本轮得到的数据需求及下一步

规则实际用到了以下少量信息；这是需求清单，不是冻结schema：

| 信息 | 被哪条判断使用 | 尚需明确 |
|---|---|---|
| 可见主体轮廓与突出部分关系 | 两类的明确轮廓路径 | 人工标记或几何提取的口径、遮挡后的可见程度 |
| 可见柔性部分／裙丝 | 两类的部分线索及组合路径 | 可辨认尺度、材料与运动如何影响接收者侧可见线索 |
| 与底部的间距、接触 | 小龙虾近底组合 | 参照尺度、接触记录与时间范围 |
| 一段实际位移轨迹 | 下落、螺旋、拖行和短促位移后停留 | 采样、观察窗口与几何判据 |
| 记录是否完整 | 区分已知无事件与历史缺失 | 上游如何声明有效历史范围 |

主要缺口有三项：

1. 当前0.40／0.75／0.90是按证据档位赋值，不能冒充连续特征已推得的精确相似度。需要把轮廓强弱与运动组合的成立程度具体化，并检查支持尺度。
2. 轨迹的“螺旋”“近底移动”等仍需可检查判据，不能仅凭动画或操作名称赋标签。下一小步先展开Tube的下落与近底移动各需要什么事实、什么条件，不先添加响应倍率。
3. 已有线索是否真能区分猎物、组合是否过宽，需要更多对照案例。蛙类作为第三类紧接着加入，不能等两类框架固化后再兼容。

第9～12节为首轮条件规则的纸面推导。第14～17节补充配置示例，并对人工特征值执行了条件判断核算；尚未实现从轨迹提取特征的方案C识别器，也未运行生物识别或玩法效果验证。方案B的原型运行结果不计为本轮验证。

## 13. 待裁定：规则归属、饵侧配置与共享粒度

本节记录新的架构问题，不把上一轮回答中的分工建议当作已定结论。第9～12节是条件规则的案例草稿，尚不能证明规则应存放在哪一层，也不确定可复用的数据结构已经足够。

### 问题本身

Tube与裙饵都可能支持小鱼和小龙虾解释。需要确定：它们评价同一种猎物时，是否共用规则、只共用部分机制，还是需要各自的规则或参数？答案会直接决定配置表、规则引用关系和运行时计算，不能仅以“证据相同就共用”结束讨论。

### 已提出的候选，均待比较

| 组织方式 | 数据与逻辑的大致归属 | 必须检验的问题 |
|---|---|---|
| 按猎物类型 | 饵提供共同特征；每种猎物用自己的规则读取 | 共同特征是否丢掉了Tube与裙饵的重要差异？是否需要越来越多的专用特征？ |
| 按饵类型 | Tube、裙饵等各自评价可支持的猎物 | 是否重复维护小鱼／小龙虾规则？是否导致同样呈现因饵名不同而得到不一致结果？ |
| 按饵类型×猎物类型 | 每一对配置自己的评价规则或参数 | 能否表达真实差异，同时控制组合数量和配置成本？ |
| 按呈现机制共享，组合引用 | 将可复用机制与具体配置分开，由饵和猎物关系选择或组合 | 哪些机制确实可共享，如何证明组合有足够表达力，而不是换名字隐藏重复？ |

上一轮“猎物类型拥有多条证据路径、饵提供实际线索”的建议对应第一种为主、允许共享子机制的方向。它目前只是候选，不能直接据此冻结schema。

### 饵上配什么，同样尚未裁定

“明确类型线索／多样化类型线索”不必然适合做互斥枚举：同一饵可能同时具有较明确的鱼体轮廓和支持其他解释的柔性部分。但是否仍需要辅助的作者配置、多个猎物呈现配置或规则引用，应与上述组织方式一起比较。

饵侧数据可以由策划标注或配置，不要求先实现Mesh到线索的自动识别。需要明确的是每个配置值代表什么、参与哪项判断，以及它是物理／感知特征的近似，还是直接指定最终解释。不能用“实际呈现”四个字掩盖尚未解决的取值来源。

### 下一轮用同一组案例比较

1. 固定相同操作，比较Tube与带拖尾裙饵：差异先体现在哪些实际呈现数据上？
2. 对同一种小鱼解释，两种饵各自需要哪些条件与参数？逐项列出可共享与不可共享部分。
3. 再对同一种小龙虾解释重复比较，检验是否仍能使用同一套组织方式。
4. 若输入相同却声称必须得到不同结果，说明缺少了什么特征、历史或上下文；若选择用饵类型做代理，明确代理依据和适用边界。
5. 用鱼形硬饵与后续蛙类检查扩展成本，比较每种组织方式新增数据、规则与例外的数量。

架构裁定前应至少给出一版具体配置示例与计算过程，使差异能落在字段、引用关系或规则上。不能先裁定存放层级，再事后将所有反例塞进例外项。

## 14. 展开四个组合：不同在哪里

以下比较一件Tube装配与一件“裙丝Jig＋鱼形软拖尾”装配，不代表所有Tube或所有Jig。形态标记是策划对具体装配的人工配置，运行时还需考虑实际可见程度。物理与动画在本轮直接提供运动记录。

| 装配×猎物 | 可提供的证据 | 首选判断路径 | 需要绑定的对象 |
|---|---|---|---|
| Tube×小型饵鱼 | 本样例没有明确鱼体轮廓；有后部柔性条束 | 部分柔性线索；实际出现侧向下落时再检查动态组合 | 主体／整饵轨迹、后部条束 |
| 鱼形拖尾裙饵×小型饵鱼 | 头部与拖尾形成可辨认鱼体轮廓，同时有柔性部分 | 轮廓路径；满足条件时也可检查与Tube共用的下落路径 | 装配后轮廓、整饵轨迹、裙丝 |
| Tube×小龙虾 | 无明确小龙虾解剖轮廓；有后部柔性条束 | 近底移动与条束展开形成组合 | 整饵轨迹、底部关系、后部条束 |
| 鱼形拖尾裙饵×小龙虾 | 本样例不配置明确小龙虾轮廓；裙丝提供部分线索 | 近底移动与裙丝展开形成组合 | 整饵轨迹、底部关系、裙丝 |

因此，四个组合既不是四份完全独立算法，也不是只把同一组原始值交给一个万能评分式：

- 小鱼与小龙虾使用不同的证据组合。
- 两件饵对小鱼可以使用不同的主要路径；也可以共享其中一条路径。
- 两件饵对小龙虾暂时可以共用近底组合逻辑，但读取不同部位的变化。
- 饵的装配、配重与物理特性先改变实际轨迹；同样的操作指令并不保证产生同样的呈现。

后两条是不同的差异来源。不能把“Tube更容易产生某轨迹”与“该轨迹更支持某解释”重复配置成两份奖励。

## 15. 一版可供比较的配置形式

当前更值得继续检验的候选是：猎物侧保存可复用的规则集；具体装配为“装配×猎物”配置规则集引用和部位绑定。规则内部可以调用不同机制，暂不做允许任意写表达式的规则语言。

这意味着承认一层明确的二者关系配置。不是仅有一张猎物规则表，也不要求每个二者关系都新写算法。

| 配置对象 | 保存什么 | 本轮例子 |
|---|---|---|
| 装配描述 | 部件、装配后形态标记、物理／动画来源 | Tube主体与后部条束；Jig头、裙丝与鱼形拖尾 |
| 猎物规则集 | 该猎物有哪些支持路径、路径条件与默认参数 | 小鱼轮廓／柔性下落；小龙虾轮廓／近底附属部分运动 |
| 装配×猎物绑定 | 使用哪个规则集、各规则读取哪个部位或组合 | Tube读取rear_bundle，裙饵读取skirt |
| 运行时呈现 | 当前及窗口内的可见轮廓、轨迹、底部关系、部位运动 | 本次是否真的下落、触底和展开 |

示意配置如下。字段名只用于比较结构，尚未冻结为生产contract：

```yaml
tube_rig:
  prey_bindings:
    small_baitfish:
      rule_set: small_baitfish_v0
      outline_source: tube_body
      flexible_source: rear_bundle
      trajectory_source: whole_rig
    crayfish:
      rule_set: crayfish_v0
      outline_source: whole_rig
      appendage_source: rear_bundle
      trajectory_source: whole_rig

jig_with_fish_trailer:
  prey_bindings:
    small_baitfish:
      rule_set: small_baitfish_v0
      outline_source: assembled_head_and_trailer
      flexible_source: skirt
      trajectory_source: whole_rig
    crayfish:
      rule_set: crayfish_v0
      outline_source: whole_rig
      appendage_source: skirt
      trajectory_source: whole_rig
```

本例两件饵没有使用不同阈值。若之后确有差异需要按二者关系配置参数，可在绑定中显式引用参数组；必须说明对应了哪个可检查差异，不能仅凭饵名加一个隐形系数。

更换拖尾后，应更新装配轮廓及相应绑定，不能因为仍叫“裙饵”就永久保留鱼体支持。没有提供某种绑定只表示尚未评价或尚未实现，不自动证明该猎物支持为零。

### 与其他组织方式的具体比较

| 组织方式 | 四组合如何表达 | 本轮判断 |
|---|---|---|
| 只有猎物规则＋全局特征 | 把所有部位差异提前压成共同特征，再由两个规则集评价 | 可以实现；但部位选择与特征含义可能藏在上游，仍须明示这些关系 |
| 每种饵独立算法 | Tube、裙饵各自返回两个支持结果 | 可以实现；本例近底组合与部分小鱼路径会重复维护 |
| 四组合各自独立算法 | 四个组合拥有各自的规则正文 | 表达力充分；本例没有证据支持四份正文都必须不同 |
| 猎物规则集＋二者关系绑定 | 两个规则集、四个绑定，规则可共享 | 本轮优先候选；差异可定位到路径、部位或参数，仍需其他猎物验证 |

这不是靠计数证明架构最优：关系绑定仍可能随饵与猎物组合增加，配置成本没有凭空消失。只有当同一规则确实被多个组合复用时，共享才有收益。

## 16. 使用这套结构实际核算

为让结构可检查，先采用固定1秒观察窗，所有历史均完整。长度参照L为该装配的参考长度。人工样例直接提供以下特征值，本轮未实现特征提取：

| 特征 | 本例口径 |
|---|---|
| 明确轮廓标记 | 当前绑定对象可辨认的对应类型轮廓，布尔值；不是饵名 |
| 柔性部分可见 | 当前绑定的条束／裙丝可辨认，布尔值 |
| 下落量 | 窗末相对窗初向下位移的正值除以L |
| 侧向范围 | 窗内水平投影轨迹的最大两点间距除以L |
| 近底时间比例 | 窗内离底间距不大于0.5L的累计时长除以1秒 |
| 水平路程 | 窗内水平运动路程除以L |
| 展开变化 | 绑定柔性部分的可见展开宽度最大值减最小值，再除以L |

本轮条件：

```text
小鱼轮廓路径：
  明确鱼体轮廓 → 0.90

柔性下落路径：
  柔性部分可见 AND 下落量≥1 AND 侧向范围≥0.5 → 0.75

小龙虾近底路径：
  柔性部分可见 AND 近底时间比例≥0.70
  AND 水平路程≥0.5 AND 展开变化≥0.15 → 0.75

柔性部分线索：
  可见 → 0.40
```

两类仍分别具有自己的明确轮廓路径。下面两件装配都没有明确小龙虾轮廓，因此该路径为已知未成立。每类取自身已成立路径的最高支持档位，尚不计算响应。

这是对首轮近底组合的细化：只有接近底部且移动还不够，本轮加上可见柔性部分的展开变化。这样“读哪个部位”开始实际改变计算。这个新增条件是待检验假设，不是已有资料证明的必要条件。

| 人工呈现 | 鱼体轮廓 | 下落量／侧向范围 | 近底比例／水平路程／展开变化 | 小鱼支持 | 小龙虾支持 |
|---|---|---|---|---:|---:|
| Tube侧向下落 | 无 | 2／0.7 | 0.1／0.8／0.20 | 0.75 | 0.40 |
| Tube近底移动，条束张合 | 无 | 0／0.1 | 0.9／1.2／0.25 | 0.40 | 0.75 |
| 鱼形拖尾裙饵离底游动 | 有 | 0／0.1 | 0.1／2.0／0.10 | 0.90 | 0.40 |
| 同裙饵近底移动，裙丝张合 | 有 | 0／0.1 | 0.9／1.2／0.30 | 0.90 | 0.75 |
| Tube近底移动，条束几乎不展开 | 无 | 0／0.1 | 0.9／1.2／0.03 | 0.40 | 0.40 |
| 同裙饵近底移动，裙丝几乎不展开 | 有 | 0／0.1 | 0.9／1.2／0.03 | 0.90 | 0.40 |

例如，第二行Tube绑定rear_bundle，读到近底比例0.9、水平路程1.2、展开变化0.25，三个门槛全部成立，小龙虾路径给0.75。第五行只把该部位的展开变化改为0.03，组合不成立，只留下0.40。裙饵绑定skirt，同一算法读到的部位事实不同，但无需复制判断正文。

第四行同时支持小鱼与小龙虾不是计算冲突，也不因小鱼支持更高而删除小龙虾解释。后续如何响应仍待推导。

上述六行已经按所列条件执行数值核算。它验证的是示意配置和条件能给出所写结果，不验证阈值合理性或鱼类识别准确率。

## 17. 本轮架构结论与尚未解决的问题

本轮建议采用“猎物规则集＋装配×猎物绑定”作为下一轮工作结构，尚不作为生产裁定。规则组织在猎物一侧；饵与猎物之间有明确的配置关系，负责选择、绑定和必要参数引用。新机制是否属于某个猎物规则集或值得共享，应由实际复用情况决定。

这比“统一放在猎物类型上”多了一项明确承诺：饵侧不能只有一组来源不明的像鱼／像虾分数，还要知道每种解释具体读取哪些对象、使用哪些路径。也不要求先做自动几何识别；人工形态标记与曲线来源可以作为早期实现。

仍有四个实质缺口：

1. 柔性部分本身支持两类的0.40仍过宽，需要检查假阳性与缺失的关键形态。不能因配置结构清楚就把它当成已成立的生物机制。
2. 当前“下落量＋侧向范围”并不能区分螺旋／失衡与普通斜向下降。它只是可执行的下落组合占位，不可直接输出“受伤小鱼”；应补轨迹反例后决定是否需要转向、摆动或姿态信息。
3. 固定1秒窗口与阈值尚未验证，启动、停止、长时间静止及窗口边界可能改变结果。不能沿用方案B的轨迹测试作为本方案通过。
4. 蛙类尚未加入，不能宣称这套规则与绑定足以覆盖所有猎物。下一轮用蛙类检查：是否只需增加水面呈现规则与部位绑定，还是需要改变节点结构。
