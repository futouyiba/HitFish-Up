# Proposal C｜轨迹预测困难必要性审查

状态：Working Review / Candidate。不是 Current，不是生产参数。

## 1. 结论

“轨迹预测困难”暂不删除，但从已闭合主体变量降级为**待证明的独立负担**。

当前已有按“转向幅度 + 时间衰减”计算预测困难的 Candidate 算法，不足以继续作为主体契约。原因是：

- 转向本身不等于不可预测；
- 平滑弧线可以很好预测；
- 稳定、规律的左右摆动也可能逐渐变得可预测；
- 仅按每次方向变化刷新惩罚，会把“改变方向”和“打破预期”混为一件事。

如果保留这一项，它只能表达：

> 目标突然偏离鱼刚刚已经形成的短时运动预期，使当前攻击时机更难把握。

它不拥有“运动复杂”“转向多”“动作花”“速度快”“看起来不自然”等泛化语义。

## 2. 删除它以后，哪里可能出错

先控制其它变量：

- 食物价值相同；
- 攻击诱因相同；
- 速度和追赶负担相同；
- 风险顾虑相同。

比较两种运动：

```text
A. 目标以稳定方向 / 平滑曲线移动
B. 目标在鱼即将形成攻击时机时突然改变运动趋势
```

如果系统没有任何“预测困难”路径，则 A 与 B 的 Response 完全相同。

但目标体验可能要求：

```text
B
→ 短时间更难把握攻击时机
→ 出手成功倾向暂时下降
```

这是它目前唯一比较清楚的独立购买点。

因此它与追赶负担不同：

```text
追赶负担
→ 能不能追上 / 追起来多费劲

预测困难
→ 已经追得上，但当前能不能抓住攻击时机
```

存在概念上的独立性。

## 3. 但它目前没有形成很强的独立玩家策略

从玩家侧看，当前最明显的策略只是：

```text
突然强变向
→ 可能提高攻击诱因
→ 同时短时破坏攻击时机

随后稳定 / 停顿
→ 预测困难恢复
```

这更像“强刺激动作的自然代价”，而不是与食性、活性、摄食意愿、警惕度同等级的主策略轴。

当前尚未证明玩家会围绕“预测困难”本身独立选饵、选钓组或调整长期打法。

因此：

> 保留它作为 Response 中可能存在的局部成本，不把它提升成第五个鱼情策略轴。

## 4. 现有 TurnStrength 算法的问题

现有 Candidate：

```text
TurnStrength(delta_psi)
= (1 - cos(delta_psi)) / 2

PredictionChallenge(t)
= max_recent[
    TurnStrength * exp(-age / tau_recover)
  ]
```

该算法实际回答的是：

> 最近发生过多大的方向变化？

而不是：

> 最近发生过多大的“超出已有运动预期”的变化？

反例：

### 平滑圆周运动

目标持续沿弧线运动，每个短窗口都在转向。

如果近期转向趋势稳定，鱼可以形成“它还会继续沿这个弧度转”的预期。

仅按方向变化幅度计算会持续处罚，语义错误。

### 稳定蛇形 / 周期摆动

如果运动逐渐形成稳定节奏，重复左右摆动不一定始终保持同样的不可预测性。

仅靠 `max_recent` 刷新会把规律本身忽略。

### 单次急转后稳定

真正需要处罚的是急转发生时对已有预期的破坏；随后新趋势稳定后应恢复，而不是因为“曾经转过大角度”本身继续承担抽象惩罚。

因此原 `TurnStrength → PredictionChallenge` 只能作为历史 Working Probe，不应继续被当成已闭合主体算法。

## 5. 如果保留，最低成本定义应是什么

不做运动模式识别，不识别“之字形”“圆弧”“逃逸模式”。

只建立一个极简单的短时运动预测：

```text
近期实际运动
→ 得到短时预测运动

下一小段实际运动
vs
短时预测运动
→ 预测偏差
```

预测困难只来自“预测偏差”，而不是转向本身。

第一版甚至可以只使用简单趋势预测，例如：

- 平滑后的近期速度方向；或
- 近期速度 + 很短的转向趋势。

如果实际下一步明显偏离预测，产生短时预测困难；如果连续运动逐渐稳定，预测器会自动跟上。

这样可以自然得到：

```text
平滑转弯
→ 预测器跟随
→ 不持续高罚

突然急转
→ 短时预测误差大
→ 短时处罚

急转后稳定
→ 预测器重新跟上
→ 处罚恢复
```

无需机器学习。

## 6. 与攻击诱因的关系

同一个动作可以同时产生正负两条后果，但不能用同一个“转向强度”直接乘两个系数。

例如一次急窜：

```text
猎物状态解释
→ 可能形成攻击诱因

短时运动预测
→ 可能产生预测偏差
→ 预测困难
```

两条路径问的是不同问题：

- 攻击诱因：这个猎物状态是不是更容易让我想出手？
- 预测困难：当前这一瞬间是不是更难抓住攻击时机？

只有这样，强刺激才可能形成真正的收益—代价：

```text
刺激太弱
→ 攻击诱因不足

适度刺激
→ 正向诱因 > 短时预测代价

过度、频繁地打破趋势
→ 预测代价持续存在
→ 净收益下降
```

但这一排序必须靠后续案例验证，不能先当事实。

## 7. 与主体策略轴的关系

当前主体策略仍以四个鱼情轴为主：

```text
食物价值 / 食性
→ 选什么

活性
→ 搜多快

摄食意愿
→ 正常鱼口够不够，是否需要反应口

警惕度
→ 能不能露馅
```

预测困难不新增第五个鱼情轴。

它更适合作为：

> 某些强刺激、突然变向操作在 Response 内部自然产生的局部成本。

如果未来找不到控制其它变量后仍然需要它的真实策略案例，应直接删除，而不是因为“鱼理论上需要预测猎物”继续保留。

## 8. 当前决策

1. 保留“预测困难”概念，但降级为待验证局部成本。
2. 不再把“转向幅度”直接等同于预测困难。
3. 旧 `TurnStrength + max_recent` 算法标记为需要替换 / 重新验证的 Working Probe。
4. 若继续实现，优先尝试极简短时预测误差，而不是运动模式识别。
5. 下一轮用具体玩家操作案例验证：删掉该项是否造成稳定、可感知的策略排序错误。

## 9. 验证门槛

只有满足以下条件，才保留为生产主体项：

- 控制速度、食物价值、攻击诱因和风险顾虑后，仍存在稳定独立效果；
- 玩家能够通过可理解的操作影响它；
- 它改变至少一个重要策略排序，而不是只让数值更“真实”；
- 极简算法能够实现，不需要运动模式识别或机器学习；
- 它与攻击诱因、追赶负担不存在重复结算。

否则应删除。
