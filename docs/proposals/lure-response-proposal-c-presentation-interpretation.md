# Proposal C｜呈现解释与状态契约

状态：Working Design / Candidate。本文写清第 1 到第 3 层：实际呈现如何变成猎物支持，以及按某个解释看，当前呈现处于什么状态。不是 Current Contract，也不是生产参数。

来源：`docs/lure-response-joint-evaluation` 的 `lure-feeding-response-proposal-c.md`（按 `311ae70d` 快照核对）。示例数值是设计值，不是生物标定。

## 1. 范围

```text
ActualPresentation
→ 装配绑定的证据
→ 每份证据的形态基值与动态路径
→ 按猎物汇总 support
→ 按猎物解释提取状态、事件与时序
```

第 2 层不读食物偏好、摄食动机或鱼的追赶能力来改写目标身份。第 3 层不提前算可得程度或响应强度。

## 2. 装配与证据

### 证据字段

| 字段 | 含义 |
|---|---|
| prey_type | 该证据支持的猎物类型 |
| base_support `b_e` | 形态证据的支持基值，0~1，由作者配置并说明依据 |
| routes | 该证据允许使用的动态路径，可为空 |
| support_ceiling `u_ej` | 该路径可达到的上限，满足 `b_e ≤ u_ej ≤ 1` |
| sources | 该证据与路径读取的装配、轨迹、环境或部位来源 |

不另设“整装配基值”。需要表达整体轮廓时，把它配置成一份整体证据，走同一接口。

### 适用性

证据是否适用由装配配置显式给出，每个绑定带适用标记与来源。看到部件名称不等于自动加入。

- 组合后轮廓仍可辨认 → 启用对应证据；
- 轮廓被破坏 → 不启用或显式标为不适用；
- 已启用却引用不存在的部件 → 配置错误，不当作不适用。

### 基值锚点

| 情况 | 锚点 |
|---|---:|
| 静态形态未提供该类型支持 | 0 |
| 有相关但区分力有限的形态线索 | 0.40 |
| 形态线索已较明确 | 0.90 |

中间值允许，但要说明相对哪件同类参考更强或更弱。配置依据不能写“更爱吃”“更容易抓”或“某种操作中鱼更多”。

动态上限只按该证据自己的表达能力配置。别的证据有 0.90，不会抬高本证据的上限。

## 3. 动态路径与插值

```text
路径匹配 f_ej ∈ [0,1]

路径分数 s_ej = b_e + (u_ej - b_e) × f_ej

一份证据 s_e = max(b_e, s_e1, s_e2, ...)

某类猎物 S_k = max(所有适用证据的 s_e)
```

- `f=0` 表示这条动态组合没有提供增强，不自动改换猎物类型；
- 路径内部若有超出 `[0,1]` 的中间量，先 `sat(x)=min(1,max(0,x))` 截断，再作为 `f_ej` 输出；
- 这里的乘法只在本证据的基值与上限之间插值；
- 同一证据重复登记不叠加；需要联合判断时配置联合证据或路径；
- 负证据压低基值的机制不在本版；若需要否定已有线索，要说明依据；
- 汇总的 `max` 只用于类型证据，不规定响应阶段也取最大值。

## 4. 缺失、零与区间

- 装配必须声明已评价的猎物范围；声明覆盖且确认没有适用证据，才可输出该模型下的已知零；
- 未配置或未评价的类型是 `NotConfigured` / 未覆盖，不自动填零；
- 必要事实缺失且可能改变结果时保留 `Unknown`；
- 绑定引用不存在的部件是配置错误；来源存在但记录未取得是数据缺失，两者分开；
- `b_e=0` 不能提前剪掉动态路径；只有类型支持最终解析为 0 才跳过后续评价；
- 首版不设任意低支持裁剪阈值。

缺失路径用匹配区间继续算支持上下界：

```text
路径下界 = b_e + (u_ej - b_e) × f_min
路径上界 = b_e + (u_ej - b_e) × f_max

证据边界：对本证据的基值与各路径边界分别取 max
类型边界：对适用证据边界分别取 max

上下界相同 → Resolved；否则 Unknown
```

区间是缺失输入导致的可能范围，不是置信区间或分类概率。连续 AND 中某项已知为 0，就能确定路径为 0，不必因另一项缺失而整体阻断。

## 5. 状态提取

### 输入与输出

状态层同时读实际记录和类型支持，不能只拿支持 map 继续算。输出保留：

| 内容 | 例子 |
|---|---|
| 共用实际事实 | 世界速度、相对水体速度、离底或离水面距离、已低位移时长 |
| 按类型的状态维度 | 蛙：水面、低位移、姿态正常 |
| 时序关系 | 低位移前有 0.60 秒移动，距该段结束 0.40 秒 |
| 有依据的状态假设 | 失衡样下沉：匹配 / 不匹配 / Unknown |
| 独立的类型支持 | 沿用第 2 层结果，不乘进每个状态标签 |

多个维度可以同时成立，不压成一个好坏分。同一装配可以保留小鱼与小龙虾两套解释，但引用同一段实际记录。

### 共用事实

先提取可复用事实，再由各猎物规则组织。共用事实不含“受伤”“惊恐”“容易抓”等结论。

| 事实 | 可直接描述 | 不能单独推出 |
|---|---|---|
| 轨迹与时间 | 速度、加速度、方向变化、下落、低位移 | 自然、疲惫、受伤 |
| 相对水流的运动 | 随流漂移，或相对水体仍有运动 | 主动游动意图 |
| 底部与水面关系 | 近底、接触、水面、进入水下 | 近底必然爬行；下沉必然异常 |
| 实际姿态 | 侧翻、姿态恢复、持续失衡样表现 | 真实受伤或濒死 |
| 局部动作与信号 | 尾摆、裙丝变化、反光、振动、声音 | 变化都表示挣扎或逃窜 |

速度必须区分世界速度与相对水体速度。近底判断另读底部关系。缺水流时仍能描述世界位移，但不能断言相对水体静止。

### 分段示例参数

水流为零、轨迹同一参考系、记录视为分段线性。以下数值是可替换的设计示例：

```text
连续速度 ≥ 0.04 m/s 达 0.10 秒：确认移动段，起点为本次连续满足条件的起点
连续速度 ≤ 0.02 m/s 达 0.15 秒：确认低位移段，起点同上
两阈值之间：保持已确认状态，避免抖动
初始无已确认状态：保持未决，直到满足任一持续条件

已确认低位移，且最近移动段结束距今 ≤ 3 秒：保留“移动后停留”
```

- 确认需要等待，时长从条件开始满足时算，不从确认时刻重新计时；
- “停留”只指低位移，不要求裙丝或腿完全停止；
- 记录开始时已在移动或低位移的，时长只表示已观测下界；
- 运动记忆跨评价窗口保存，避免连续停留超过 1 秒就丢失前史。

垂直趋势示例：以向上为正，垂直速度 ≥ 0.02 m/s 持续 0.15 秒确认上升；≤ -0.02 m/s 持续 0.15 秒确认下落；绝对值 ≤ 0.01 m/s 持续 0.15 秒确认垂直低运动。三个判定都要求同样时长，阈值之间保持已确认趋势。

失衡样下沉示例：下沉速度 ≥ 0.02 m/s 且主体侧翻角绝对值 > 60 度（绕前后轴的滚转，不用俯仰角），共同持续 ≥ 0.20 秒才匹配。缺姿态记录且可能改变结论时保留 Unknown；已确认没有下沉则可直接排除。

短促提速后停留示例：速度 0.15 秒内从 ≤ 0.04 升到 ≥ 0.20，随后在到达高速阈值后 0.50 秒内降到 ≤ 0.02，再维持低速 0.15 秒才确认。该规则必须声明使用哪条速度通路：可用相对水体速度，但要求该来源记录完整；不能中途悄悄换成世界速度。必须保存有序事件，不能用窗口平均速度替代。

### 过程规则的状态

- 配置了规则且已知条件排除 → 不匹配；
- 必要数据缺失且可能改变结论 → Unknown；
- 没有注册相应规则 → NotConfigured，不猜结论。

## 6. 记忆、缺口与装配变化

| 情况 | 处理 |
|---|---|
| 正常连续更新 | 按时间顺序处理，保留候选计时、分段与必要事件 |
| 重复或重叠输入 | 按时间游标去重，不重复计时或生成事件；同源同时刻冲突报输入错误 |
| 乱序记录 | 首版报输入错误，不悄悄重排并改写历史 |
| 数据中断 | 需要连续性的计时中断；相关状态保持 Unknown，直到新记录足以重新确认 |
| 缺口后恢复 | 可恢复当前移动或低位移判断；跨缺口的前后关系仍 Unknown，除非已知排除条件使结果闭合 |
| 某类 support 暂时为零 | 共用运动记录与分段不因此停止维护；该类型稍后恢复时读取仍在保留期内的事实 |
| 换拖尾或装配版本变化 | 重新绑定证据；旧装配绑定的局部计时与事件失效；同一主体连续轨迹可以保留，但跨装配变化的类型过程默认不沿用，除非规则明确与装配无关 |
| 新抛投、瞬移、实例更换 | 开始新的呈现连续段，旧段事件不跨入 |
| 坐标重定位跳变 | 先恢复同一参考系或声明连续段中断；不识别成爆发运动 |

上游必须声明哪些区间有有效连续记录。不凭长间隔两端位置相等就认定中间静止。

## 7. 交给第 4 层什么

交付类型支持、共用事实、分类型状态、时序关系和依据。鱼侧再结合食物价值、鱼的追赶能力与摄食意愿评价这些呈现。

- 已确认的速度下降可以在追赶负担中体现，不必再给“移动后停留”自动奖励；
- 同一事实可以被多层读取：近底运动支持小龙虾解释、描述近底移动、影响追赶负担；重复读取允许，重复加成不允许；
- 类型支持不再乘进速度、时长或每个状态标签。

## 8. 最小数据契约

| 数据组 | 最少包含 | 约束 |
|---|---|---|
| 帧标识 | 饵实例、连续段 ID、装配版本、评价时刻 | 记录与支持必须对应同一实例、版本、时刻 |
| 共用事实 | 值、单位 / 参考系、有效时段、来源、解析状态 | 速度标明世界或相对水体；时长标明精确起点或已观测下界 |
| 类型结果 | 猎物键、支持与状态、是否执行状态评价 | 已知零可跳过；未覆盖仍为未覆盖；支持未决时状态条件性计算 |
| 状态维度 | 空间关系、移动状态、垂直趋势、按需姿态 | 一项未知不抹掉其他已知项 |
| 过程结果 | 模式 ID、规则版本、匹配状态、事件起止或关键时刻、来源 | 缺规则不写成不匹配；缺记录不写成零 |
| 持续记忆 | 最后处理时刻、各来源最后有效样点、候选转换起点、已确认分段、近期事件及有效期 | 执行所需数据，不是额外吸引力参数 |

“水面 / 水下”与“近底 / 离底”分开表示，浅水中可以同时成立。连续值同时保留，避免后续只剩标签。

## 9. 未决

- 遮挡、水色、距离对可见线索的影响；
- 猎物分类粒度与子类是否值得拆分；
- 各路径阈值与锚点的生产标定；
- 姿态、水流、局部动作的实际数据来源。
