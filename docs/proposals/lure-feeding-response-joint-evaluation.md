# 路亚摄食响应：目标、大小与运动的联合评价

日期：2026-10-21  
状态：设计提案，供继续推敲；尚非生产算法或已标定参数。  
依据：本轮项目对话；既有策略故事研究提供问题背景。本文示例不作为生物学证据。

## 1. 要解决的问题

玩家选择饵和操作时，需要同时判断：这个呈现像什么食物、大小是否合适、运动方式如何改变目标解释，以及当前鱼是否适合采取行动。算法应保留这些条件之间的关系，同时避免每个鱼种穷举全部组合。

当前先讨论摄食内部的目标评价。护巢等防御行为另有目的与评价逻辑。“反应口”暂作为观察标签，不直接新增一种独立驱动力。追逐、伏击也不据此各设一个高层 pathway。

本文局部数值记为 R，用于比较结构的表达能力；不是个体咬口概率。生产接入仍须闭合完整响应，遵守 Interaction 的 captureRetention 语义，不能直接把本例 R 当作最终输出。

## 2. 已明确的设计要求

- 运动与节奏承担两项职责：帮助解释目标类型与行为状态；形成当前行动要求，与鱼的能力比较。
- 目标解释本身不等于吸引力。识别为食物后，还需要该鱼在当前情境下的价值判断。
- 不预设越慢越好、越逼真越好，也不预设目标偏好是一个固定响应上限。
- 不要求各因素独立加分、相乘或取最小值；组合方式须能表达实际策略差异。
- 原始呈现由实际运动、形态、尺寸和情境解释；饵商品类别、钓法名称没有直接设置目标或响应的权限。
- 资料缺失是 Unknown，不能用“弱匹配”或数值零代替。

## 3. 当前候选算法

在鱼种与摄食情境已确定、目标解释足够明确的范围内：

1. 结合目标、大小和实际运动，确定适用的响应曲线。
2. 根据当前功能能力、实际运动与鱼相对几何等条件，解析行动要求并判断行动适配。
3. 按适配结果从选中的曲线取值。

示意：

```text
curve = selectCurve(fishProfile, feedingContext, target, size, motionFacts)
affordance = compare(resolvedCapacity, resolvedTaskDemand)
R = lookup(curve, affordance)
```

这是局部算法草案，不是完整 Runtime 接口。行动适配在示例中暂分低、中、高，不能与正式 Feasible / Constrained / Infeasible 状态直接画等号；档位定义仍待确定。Unknown 不进入数值查表。

这里仍保留“目标与呈现”和“行动适配”两种解释，但不先把前者压成一个通用的匹配强度。曲线编号仅用于复用配置，不新增行为目的、Mode 或 Pathway。

### 为什么不只保留两个评分

先把目标呈现压成弱、中、强，再把行动适配压成低、中、高，可能把需要不同响应的情况压到同一格。例如，持续游动和抽动后停留都被归成“强匹配、高适配”，就无法继续表达二者的响应差异。

这是给定设计锚点时的信息损失问题，并非证明真实鱼必然偏好其中一种。是否需要保留差异，须由策略案例或明确的玩法设计要求支持。

## 4. 可复查的数值示例

以下固定同一种鱼、同一摄食情境、大小合适，且所列目标具有摄食支持。数值为人为构造的结构测试锚点，不是经验规律。

### 目标与运动选择曲线

| 被识别的目标 | 持续游动 | 抽动后停留 | 贴底缓移 |
|---|---|---|---|
| 小鱼 | A | B | C |
| 底栖甲壳类 | D | A | B |

运动名称仅是阅读简写，后续须落实到实际运动事实及所需的时间语义，不能用 TechniqueId 直接代入。

### 行动适配确定曲线上的取值

| 曲线 | 低 | 中 | 高 |
|---|---:|---:|---:|
| A | 0.15 | 0.45 | 0.70 |
| B | 0.20 | 0.60 | 0.90 |
| C | 0.05 | 0.20 | 0.40 |
| D | 0.05 | 0.20 | 0.35 |

例如，小鱼持续游动、高适配得到 0.70；小鱼抽动后停留、高适配得到 0.90；后者若变为中适配，得到 0.60。同一种操作在不同目标解释下也可以得到不同结果。

当前按离散档位查值，未定义档位之间的连续距离或插值规则。示例各行单调不等于所有响应必须采用此形状。

## 5. 如何共享配置

上述六个“目标 × 运动”组合原本各有三个数值，共 18 个数值锚点。完全相同的行复用后，剩四条曲线、12 个数值锚点，另保留六个曲线绑定。

已逐格核对 18 个取值，共享前后完全一致。该检查只证明示例等价；绑定、条件选择与例外的维护成本也须记账，不能只按数值数量宣称总体配置成本下降。

共享以响应关系相同为条件，不以名称相近为条件。不需要先给每条鱼各建一套全表，也不能未经验证把同一套曲线推广给所有鱼。跨鱼种共享及例外比例尚未验证。

本例 C、D 只在高适配处相差 0.05，目前无证据支持这项差异；保留它只是展示精确共享的边界。后续可明确约束二者相同，但不能将人工 tying 描述为自然规律。

## 6. 大小与鱼状态如何接入

| 变化的实际后果 | 进入哪里 |
|---|---|
| 大小改变食物偏好或价值判断 | 目标与呈现的响应关系；必要时选择不同曲线 |
| 大小改变攻击、追逐的行动要求 | TaskDemand 与行动适配 |
| 当前功能能力改变 | Capacity 与 TaskDemand 的比较 |
| 当前摄食意愿改变 | 摄食响应关系，不能冒充能力变化 |

同一变化只有在产生不同语义后果时才进入两处。能力下降已经使行动适配降低，不额外乘匿名“状态惩罚”。已经解析的功能后果不再通过温度、溶氧等原始原因重复扣减。

大小对攻击选择的作用与吞入口、操控、挂钩的物理限制也须分开，不能把后者统一提前变成摄食响应惩罚。

状态变化若只改变能力，优先复用原曲线。如果它改变了动作的相对价值或最佳操作，须保留这种条件差异，不能强行解释为所有动作一律下降一档。

## 7. 验收条件与待解问题

本提案的检验重点：

- 相同动作在不同目标解释下能够产生不同响应。
- 行动能力变化与摄食意愿变化可以分别表达和解释。
- 共享配置后保留原有关键取值与最佳操作关系。
- 不重复结算同一后果，不把 Unknown 填成零。
- 两种情况若必须产生不同响应，却被压入相同曲线与适配档，能够定位丢失的条件并修订表示。

仍待解决：

1. 从形态、大小与实际运动到目标解释、再到曲线选择的具体规则。本文示例给出了绑定结果，尚未完成一般生成算法。
2. 行动适配的具体计算与档位含义。速度、方向变化、相对位置如何共同形成行动要求，尚未闭合。
3. 单一行动适配量是否足够；若不同任务约束导致操作排序反转，需要保留哪些条件。
4. 多个目标解释同时成立时如何评价；不能默认对它们取最大值。
5. 真实案例支持哪些曲线形状、哪些条件可共享；当前示例不能提供这项证据。
6. 摄食意愿、风险、其他感官证据及完整响应的闭合方式。本局部草案不能替代完整 Interaction 设计。

下一轮优先用具体策略故事核对第 1、2 项，再决定配置结构；不因查表示例已经可运行就宣布核心算法完成。
