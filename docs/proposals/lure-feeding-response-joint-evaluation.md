# 路亚摄食响应：阶段讨论记录与计算缺口

更新：2026-10-22  
状态：讨论记录。已补有限目标字典下的可执行局部链路；曲线共享、一般目标解释与完整响应仍待验证。  
依据：本轮项目对话及对原提案的审视。数值示例为人工构造，不作为生物学证据。

## 1. 当前进展与缺口

目前明确了需要解释的因果关系：鱼把呈现识别为什么目标、如何评价这份食物，以及当前是否适合采取行动。已补[有限目标解释与响应探针](lure-feeding-target-interpretation.md)，从明确的感知几何和运动事实生成局部结果；一般目标覆盖、感知解析与完整响应仍未完成。

此前的“选曲线 → 判断行动适配 → 查表”只组织了响应结果。选哪条曲线、行动适配怎么算，恰好仍是未解决的核心。不能将这套组织方式当成可交付开发的算法。

具体案例见[黑鲈局部计算](lure-feeding-response-bass-worked-case.md)与[目标解释探针](lure-feeding-target-interpretation.md)。这些候选公式尚未标定，下一步先用策略反例检验，再决定是否采用及如何共享配置。

## 2. 保留的设计要求

- 运动与节奏承担两项职责：帮助解释目标类型与行为状态；形成当前行动要求，与鱼的能力比较。
- 目标解释本身不等于吸引力。识别为食物后，还需要该鱼在当前情境下的价值判断。
- 目标、大小与运动须保留有策略意义的相互作用。不预设越慢越好、越逼真越好，也不预设目标偏好是固定响应上限。
- 不预设各因素独立相加、相乘或取最小值。运算方式应由需要表达的关系决定。
- 目标解释来自形态、尺寸、实际运动及情境，不能由饵商品类别或钓法名称直接设置。
- 功能能力、行动要求与摄食意愿分别解释；同一后果只结算一次。已解析的功能后果不通过温度、溶氧等原始原因重复扣减。
- Unknown 保持未解决状态，不能填成弱匹配或零。

当前范围是摄食内部的目标评价。护巢防御具有不同目的；“反应口”暂作为观察标签。尚不按追逐、伏击或操作快慢新增高层 Pathway。

大小对攻击选择的影响，与吞入口、操控、挂钩的物理限制须分开。局部示例结果也不能直接当作个体咬口概率或完整 captureRetention。

## 3. 必须解决的计算问题

| 问题 | 需要补出的内容 |
|---|---|
| 呈现像什么目标 | 从具体形态、尺寸、运动及情境得到目标解释的规则；处理不确定解释 |
| 这份食物有多值得攻击 | 鱼的食物偏好、目标大小与呈现行为如何共同影响价值判断 |
| 当前行动要求是什么 | 实际运动与鱼相对几何如何形成可检查的要求 |
| 鱼的能力如何影响行动 | 用能力与要求的比较解释响应变化，避免混入摄食意愿 |
| 各项判断怎样得到响应 | 明确计算规则和参数含义，而非再调用一个未定义的综合函数 |

“行动适配低、中、高”目前没有共同、可检查的含义。例如短距离急加速和持续追逐都被称为“中适配”，可能掩盖不同能力限制。是否需要保留多个条件，要由反例决定；不能先把所有要求压成一个分数。

## 4. 曲线查表：保留为候选表示

此前尝试的表示为：

```text
curve = selectCurve(fishProfile, feedingContext, target, size, motionFacts)
affordance = compare(resolvedCapacity, resolvedTaskDemand)
R = lookup(curve, affordance)
```

这里的 selectCurve 与 compare 仍未定义。这段伪代码只说明一种结果组织方式，不提供从输入到结果的生成算法。它也未证明行动适配可以用一个标量或三档充分表示。

此前两个粗评分的反例同样只说明：若需要不同响应的情况被分到同一格，那种具体分档会丢信息。它不能证明所有两评分模型都失败，也不能证明必须改用多条曲线。

若后续采用曲线，曲线编号只服务配置复用，不新增行为目的、Mode 或 Pathway。

## 5. 原数值示例及其证明范围

以下保留原例，便于核对已经讨论的内容。它假定同一种鱼、同一摄食情境、大小合适，且所列目标具有摄食支持；尚未指定真实鱼种或对应的策略案例。

### 人为设置的曲线绑定

| 被识别的目标 | 持续游动 | 抽动后停留 | 贴底缓移 |
|---|---|---|---|
| 小鱼 | A | B | C |
| 底栖甲壳类 | D | A | B |

运动名称仅为阅读简写。实际运动到这些类别的判定，以及抽动与停留的时间关系，均未在本例中计算。

### 人为设置的响应取值

| 曲线 | 假定适配低 | 假定适配中 | 假定适配高 |
|---|---:|---:|---:|
| A | 0.15 | 0.45 | 0.70 |
| B | 0.20 | 0.60 | 0.90 |
| C | 0.05 | 0.20 | 0.40 |
| D | 0.05 | 0.20 | 0.35 |

R 只是本例的局部输出，未定义生产测量语义。适配档位、档间距离与插值规则也未定义，不能直接等同于正式的可行性状态。

在相同适配档内始终有 B > A > C ≥ D。该表通过人为绑定展示了不同目标可对应不同动作排序；它没有计算同一目标在不同鱼状态下如何改变最佳操作。

不同动作若进入不同适配档，结构上可能出现排序反转，但本例未提供生成这些档位的规则。大小固定为合适，因此本例也未验证大小的作用。

### 配置共享核对

六个组合、每组三个取值，共 18 个数值锚点。相同行复用后成为四条曲线、12 个数值锚点，另保留六个绑定；原 18 个格子已逐一核对，共享前后取值一致。

这仅证明对本例重复行的精确复用。重复本身来自人工设置，不能据此估计真实鱼种的共享率或配置成本，也不能回答新饵、新动作如何获得响应。绑定、条件选择及例外均需计入维护成本。

C、D 的 0.05 差异没有独立依据，不作为必须保留的设计要求。曲线是否合并、是否采用其他计算形式，留待具体案例推导后决定。

## 6. 大小与状态的职责边界

| 实际后果 | 后续推导需要解释的关系 |
|---|---|
| 大小改变食物偏好或价值 | 目标大小与当前摄食价值的关系 |
| 大小改变攻击、追逐要求 | 大小与实际行动要求的关系 |
| 当前功能能力改变 | 能力与行动要求的比较 |
| 当前摄食意愿改变 | 意愿与摄食评价的关系 |

该表分配解释责任，尚未给出数值算法。不能将所有变化都处理成“换一条曲线”，也不能将状态变化统一处理成适配降一档。一个大小变化只有确实产生不同后果时，才进入多处判断。

## 7. 可计算案例与后续验收

已补充[大口黑鲈 × 小鱼目标的局部推导](lure-feeding-response-bass-worked-case.md)：用收益与行动代价竞争生成四格响应，并扩展目标大小。公式与参数为人工设计假设；固定了目标身份与感知，尚未闭合任意呈现的目标解释或整段节奏。该案例不采用本页的曲线绑定作为生成算法。

后续案例仍按以下要求推进：选择一个明确鱼种和一种有证据支持的食物目标，固定位置、可感知性和其他背景条件，比较两种有实际运动描述的呈现、两种明确的鱼状态，共四个组合。鱼状态先单独改变能力或意愿之一，避免两者一起变化后无法解释结果。

每个组合必须列出：

1. 已知输入及来源：实际运动、相对位置、目标形态和大小、鱼的状态。证据与人工设计假设分别标明。
2. 目标解释与食物评价：每步使用的条件、规则及参数。
3. 行动要求与能力比较：不能直接填“适配中”等结论。
4. 响应计算：将上述结果代入明确规则，得到可复算结果。
5. 操作比较：说明玩家是否应该换操作，以及差异由哪个原因产生。

若案例证据或明确玩法要求支持状态变化造成最佳操作反转，应检查模型能否产生反转；若不支持，不人为要求反转。先闭合一个目标的四个组合，再加入第二种目标大小，检查它改变食物价值、行动要求还是两者都有。

案例通过后，再比较直接函数、条件规则或曲线查表等表示。只有明确共享不会抹掉需要的操作差异，才进行配置压缩。

完成标准：从已知输入到响应可以逐步复算；决定结果的函数没有空缺；能力、意愿及大小的后果可分别解释；Unknown 和未验证假设明确可见。单一案例通过也不代表多目标解释、其他感官证据或完整 Interaction 已闭合。
