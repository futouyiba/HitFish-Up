# Proposal C｜响应主体聚合拓扑审查

状态：Working Closure / Candidate。不是 Current，不是生产参数。

## 1. 结论

第一版继续采用“加性出手余量”，但需要明确一个重要原则：

> 顶层聚合保持简单；真正的非线性、状态交互和装备/操作交叉，放在各自负责的机制内部完成。

因此主体保持：

```text
出手余量
= 食物价值
+ 攻击诱因
- 追赶负担
- 风险顾虑
- 摄食意愿对应的出手门槛
```

“预测困难”暂不作为主体必选项，只保留为待证明的局部代价；只有它在控制其它因素后仍能产生稳定、独立的策略排序，才重新加入主体。

这里的“相加”不表示这些量天然具有相同物理单位。它表示：各子机制先把自己的结果换算到同一个“出手余量标尺”，顶层只负责比较正向价值、负向负担与当前门槛。

---

## 2. 为什么顶层相加仍然有意义

主体真正回答的是：

> 对当前这个目标，值得出手的理由，扣掉需要承担的负担和当前鱼口要求之后，还剩多少余量？

因此：

```text
更高的食物价值
可以补偿一部分追赶负担或风险顾虑

更强的攻击诱因
可以帮助边缘案例跨过出手门槛

更低的摄食意愿
通过抬高门槛，使同一呈现更难触发出手
```

这种“可补偿”本身就是当前希望得到的策略语义。

例如：

```text
非常喜欢的猎物
+ 稍微有些难追
→ 仍可能值得出手

普通猎物
+ 同样追赶负担
→ 可能不值得
```

或者：

```text
摄食意愿较低
+ 普通猎物状态
→ 过不了线

摄食意愿较低
+ 合法的强攻击诱因
→ 可能刚好跨线
```

如果改成多个因子相乘，任何一个低值都可能把其它原因近似抹掉，反而很难表达这种策略补偿。

---

## 3. 顶层不负责制造交互

第一版不建议在总公式继续加入大量交叉项，例如：

```text
食物价值 × 摄食意愿
攻击诱因 × 摄食意愿
速度 × 活性
自然度 × 警惕度
```

需要的交互应由各自的 owner 在下层产生。

### 活性 × 速度

属于追赶负担：

```text
目标运动速度 / 鱼的追赶能力
+ 当前活性
→ 追赶负担
```

活性低时，同样速度产生更高负担；活性高时，同样速度更容易接受。

顶层只看到最终“追赶负担”。

### 警惕度 × 异常暴露

属于风险顾虑：

```text
装备暴露 / 运动反常 / 其它合法异常线索
+ 当前警惕度
→ 风险顾虑
```

高警惕时，同样异常暴露产生更强抑制；低警惕时影响弱。

顶层只看到最终“风险顾虑”。

### 猎物状态 × 攻击诱因

属于猎物状态解释：

```text
当前猎物类型
+ 当前猎物状态
→ 攻击诱因
```

不是把“转向幅度”“急窜速度”等原始运动量直接放进主体公式。

因此第一版总体结构是：

```text
复杂交互在下层求值
        ↓
换算成少数几个有明确语义的结果
        ↓
顶层做简单加减
```

---

## 4. 摄食意愿为什么更适合作为门槛

第一版不采用：

```text
食物价值 × 摄食意愿
```

也不采用：

```text
(食物价值 + 攻击诱因) × 摄食意愿
```

原因是摄食意愿描述的是：

> 当前这条鱼需要多强的理由，才愿意为了食物出手。

它不改变：

- 这个目标本身是什么食物；
- 目标鱼平时有多喜欢这种食物；
- 当前状态是否具有额外攻击诱因；
- 追赶本身有多费劲；
- 呈现本身有多可疑。

因此最自然的作用方式是移动最低可接受门槛：

```text
摄食意愿高
→ 出手门槛低

摄食意愿低
→ 出手门槛高
```

这会自然产生：

```text
同一个 Good 食物
高摄食意愿 → 容易出手
低摄食意愿 → 可能不够

同一个低摄食意愿
普通状态 → 不够
强合法攻击诱因 → 可能跨线
```

这正好保留“鱼口差，但存在反应口”的设计空间。

---

## 5. 为什么暂时不让摄食意愿再调制其它项

当前不建议同时再做：

```text
摄食意愿低
→ 追赶负担额外放大
```

因为这与活性开始重叠。

也不建议：

```text
摄食意愿低
→ 攻击诱因效果额外放大或缩小
```

因为这样会让“攻击诱因能否帮助低鱼口越线”从顶层可解释关系，变成一个难以校准的交叉倍率。

同样不建议：

```text
摄食意愿低
→ 风险顾虑额外放大
```

这与警惕度重叠。

因此第一版保持：

```text
活性
→ 主要调制追赶负担

警惕度
→ 主要调制风险顾虑

摄食意愿
→ 主要移动出手门槛
```

三种鱼情变量分别购买不同策略，不在顶层互相复制职责。

---

## 6. 加性公式成立的前提

顶层相加只有在以下条件下成立：

### 6.1 各项必须已经完成语义归一化

例如“追赶负担 0.1”不是速度 0.1，也不是能量 0.1；它表示：

> 在当前 Response 标尺上，这种追赶困难应减少多少出手余量。

风险顾虑、攻击诱因同理。

因此生产标定不是“查到真实物理单位后直接相加”，而是用目标策略排序把各项映射到同一决策标尺。

### 6.2 各项必须允许软补偿

进入主体公式的项必须允许：

```text
更高收益
↔
部分抵消更高代价
```

如果一个条件语义上绝不能被补偿，则不能伪装成一个很大的数字。

例如：

```text
明确拒食
→ 类型化的硬零
```

而不是：

```text
拒食成本 = 999
```

未来如果真正存在“物理上不可能截击”的情况，也应作为硬边界，而不是无限增大追赶负担。

### 6.3 同一原因不能重复结算

例如一次强烈逃窜可能同时：

```text
形成合法攻击诱因
```

并且：

```text
提高速度
→ 增加追赶负担
```

这是两个不同后果，可以同时存在。

但不能再因为“动作很大”额外创建一个匿名“刺激成本”。

同样，低猎物支持度不能自动再变成风险顾虑；高速度不能自动再变成运动反常。

---

## 7. 这种结构已经产生足够的非线性

顶层公式虽然是加性的，整体系统并不线性。

因为下层可以具有阈值、曲线和状态交互，例如：

```text
活性 × 速度
→ 非线性的追赶负担

警惕度 × 异常暴露
→ 非线性的风险顾虑

摄食意愿
→ 非线性的出手门槛

出手余量
→ 截断 / 饱和映射为最终响应强度
```

因此没有必要为了“更真实”再把顶层改成复杂乘法或多项式。

第一版应优先保持：

> 下层负责机制，顶层负责竞争。

---

## 8. 三个关键策略回归

### A. 高活性、低警惕

```text
追赶负担较低
风险顾虑较低
→ 快速搜索方案可行
```

不需要给“快速搜索”直接加奖励。

### B. 低活性、高警惕

```text
高速 → 追赶负担高
粗糙 / 暴露 → 风险顾虑高
→ 慢、自然、隐蔽的方案相对受益
```

这是两个独立代价共同改变策略排序。

### C. 低摄食意愿，但活性仍高

```text
出手门槛高
普通呈现不够

合法攻击诱因 ↑
同时可能产生一定追赶负担
→ 是否值得取决于净余量
```

这形成“强刺激有收益，但不是免费解法”的策略。

## 9. 当前 Working 裁定

主体第一版暂定：

```text
出手余量
= 食物价值
+ 攻击诱因
- 追赶负担
- 风险顾虑
- 摄食意愿门槛
```

保留原则：

```text
活性 → 调制追赶负担
警惕度 → 调制风险顾虑
摄食意愿 → 移动出手门槛
```

暂不加入：

```text
食物价值 × 摄食意愿
攻击诱因 × 摄食意愿
顶层 cross-term
全局乘法 ResponseDrive
```

“预测困难”继续保持待证明状态；不因历史 Candidate 已有公式就自动进入主体。

---

## 10. 下一步需要验证的真正问题

主体拓扑已经可以暂时闭合。后续需要的是反例验证，而不是继续增加公式复杂度：

1. 是否存在必须让摄食意愿改变攻击诱因效果、而单纯移动门槛无法表达的关键策略案例；
2. 是否存在风险顾虑无法被高食物价值部分补偿、但又不属于硬警报 / 硬拒绝的案例；
3. 是否存在追赶负担与食物价值之间必须非线性交互的稳定策略；
4. 在真实参数范围内，加性余量能否保持目标的策略排序；
5. 预测困难是否有足够独立案例值得重新加入主体。

没有这些反例之前，不新增顶层自由参数。
