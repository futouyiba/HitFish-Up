# 姿态浅水有效性判定机制

## 希望解决的问题

玩家把饵抛到近岸等**水深明显不足的地方**时，如果姿态系统仍将其判为有效，就可能按正常中鱼流程产生鱼口。玩家会在明显不具备正常作钓空间的位置钓到鱼，违背直觉，也可能形成利用极浅水反复触发中鱼的玩法漏洞。

本机制希望：**水深过浅时不产生有效姿态；达到最低水深后仍按其他现有规则判断姿态是否有效。** 此处不区分钓法或鱼种，大鱼能否进入浅滩由鱼的行为处理。

> 决策：全部钓法、全部鱼种共用一个最低水深条件；它只是姿态有效性的必要条件之一。大鱼能否抵达浅滩，由鱼行为处理。

## 1. 机制目的

避免饵所在位置的水深明显不足时，仍能触发**有效姿态**和对应中鱼机会。

本机制只处理**姿态是否有效**，不按鱼种、鱼体大小、钓法、鱼饵或具体运动类型区别配置。也不调整 Bake / DEF 的鱼类空间分布、环境权重、Response 适配系数或圆桌候选权重。

## 2. 核心规则

姿态系统统一读取当前作钓位置的实际水深，与一个全局最低水深阈值比较：

```text
waterDepth < poseMinWaterDepth   → 浅水条件不通过
waterDepth >= poseMinWaterDepth  → 浅水条件通过
```

水深条件是最终姿态有效性的一项**新增必要条件**。现有姿态内部可能采用不同的组合规则，保持不变：

```text
最终姿态有效 = 浅水条件通过 AND 既有姿态整体有效性判定通过
```

- **低于阈值**：姿态无效，不发出该姿态的有效中鱼机会。
- **达到阈值**：仅通过浅水条件，仍须走完原有姿态有效性判断；不能直接宣告姿态有效。
- **深度未知**：不能默认通过，也不能伪装成“水深为零”。记录数据不可用的原因，按现有异常处理通路阻断错误的有效态。

不要求浅水检查在代码执行顺序上必须位于第一项，但必须参与**统一的最终姿态有效性判定**。任何姿态识别结果、默认运动类型或评分结果都不得绕过它。

## 3. 配置应放在哪里

### 3.1 对 `pose.xlsx` 的核对

| 工作表 | 当前实际承担的职责 | 本次结论 |
| --- | --- | --- |
| `PoseBasic` | 全局姿态参数。现有 `POSE_SCORE_RANGE`，值为 `0\|60\|80\|100` | **新增统一阈值的建议位置** |
| `PoseLureEntities` | 路亚运动姿态的识别条件与评分。含运动类型、适用饵、水层类别、动作、持续时间、优先级、基础分与累积分 | **不加水深列**，避免按具体姿态重复配置 |
| `PoseFloatEntities` | 真饵浮钓的静漂、无规则运动及其评分与中断参数 | **不加水深列**，避免出现第二份阈值 |
| `PoseEffects` | 按路亚饵配置光、声、水花效果倍率 | 不适合放姿态有效性规则 |
| `Readme` | 解释姿态类型编号、同类配置优先级和时间口径 | 可补充规则说明，不放数值真值 |

**选择 `PoseBasic` 的理由：** 该表用“一个参数一行”的方式保存全局规则；`PoseLureEntities` / `PoseFloatEntities` 按具体运动或饵类型组织，含匹配、覆盖和默认配置语义。统一阈值应只配置一次，不参与姿态条目的筛选、继承或优先级竞争。

`Readme` 说明“100x–900x 为类型”“类型相同时优先取 ID 更大的配置”。这些是具体姿态行的匹配/覆盖规则，不应作用于统一最低水深阈值。

### 3.2 建议新增的配置行

`PoseBasic` 原表 A 列为数据类型、B 列参数 ID、C 列中文说明、D 列特殊值编码说明、E 列参数值。建议在现有 `POSE_SCORE_RANGE` 下新增一行：

| A：类型 | B：参数 ID | C：说明 | D：编码 | E：值 |
| --- | --- | --- | --- | --- |
| `INT32` | `POSE_SCORE_RANGE` | 技法评分区间 | `segment` | `0\|60\|80\|100`（原有） |
| **`FLOAT`** | **`POSE_MIN_WATER_DEPTH`** | **姿态最低有效水深** | **空（单值）** | **待标定的单个数值** |

`POSE_MIN_WATER_DEPTH` 是建议名称，**不是已有字段**。它不区分鱼种、饵、钓法或运动类型。单位应与实际水深查询保持一致；若水深接口采用米，表中同样填写米数。

**不要把“待定”写入生产表的 `FLOAT` 值。** 阈值标定完成后填写合法数值，由程序确认 `PoseBasic` 读取链路支持新增参数 ID、`FLOAT` 类型与单位。D 列的 `segment` 表示分段值编码，不在 D 列另写单位。

### 3.3 不选择的配置方式

- 不在 `PoseLureEntities`、`PoseFloatEntities` 每行重复增加 `minWaterDepth`。
- 不用 `PoseLureEntities.layer`（沉底、浮水、水层 1/2/3）代替实际水深；水层类别并非以米计的水深。
- 不修改 `POSE_SCORE_RANGE`，也不用 60/80 等评分档位代替有效性判定。**有评分不等于姿态有效**。
- 不在 `PoseEffects` 的光、声、水花效果中隐藏浅水禁用逻辑。

## 4. 运行时接入方式

```text
抛竿后进入既有姿态计算 / 更新时机
              ↓
    取得当前姿态求值位置及实际水深
              ↓
       统一水深条件判定
          ├─ 不通过 ───────────────────┐
          │                           ↓
          └─ 通过 → 既有姿态整体判定 → 最终姿态有效性汇总
                                         ├─ 无效 → 不触发有效中鱼机会
                                         └─ 有效 → 既有正常中鱼流程
```

实施建议：将水深检查接在**所有姿态共同经过的最终有效性判定出口**，而不是某个具体运动识别器、评分器或饵类型分支。如果代码中没有统一出口，应识别实际有效态发布路径，确保每条路径都受这一条件约束。工作簿没有运行时代码，不能断言已有统一节点；具体函数与数据接口待核实。

`PoseLureEntities` 有 `1001 静止`、`2001 无规则运动`；`PoseFloatEntities` 也有静漂和无规则运动。即使没有命中精细姿态规则，或进入默认/无规则路径，浅水条件仍必须生效。这里**不假定**默认运动类型在现有程序中必然等价于有效姿态。

现有识别流程仍可判断运动状态，但发出有效姿态或中鱼机会之前必须完成最终判定。水深不通过时，不得由评分、重新抽姿态、保底鱼或环境权重下限恢复该次机会。

## 5. 位置变化及职责边界

- 水深按**当前姿态求值位置**查询，不把初次落点固定为整次抛竿的永久依据。
- 沿用既有姿态更新时机重新评价：由浅入深可恢复水深条件通过，由深入浅可使条件失败；通过后仍要执行原有姿态整体判定。
- 不新增每帧强制刷新要求；位置取样、刷新频率和接入点需核实。
- 本机制不读取鱼种、品质或鱼体尺寸。若圆桌抽到大鱼，而鱼无法游入浅滩，由鱼行为与移动机制处理；姿态层不增加按鱼筛选。
- 如果阈值附近发生频繁抖动，先查明来源；本稿暂不增加迟滞区间或第二个阈值。

## 6. 验收用例

| 场景 | 预期行为 |
| --- | --- |
| 水深低于 `POSE_MIN_WATER_DEPTH` | 浅水条件失败，最终姿态无效 |
| 水深恰好达到阈值 | 水深通过，仍须执行既有整体判定 |
| 水深通过，但既有姿态整体判定失败 | 最终姿态仍无效 |
| 水深与既有整体判定均通过 | 姿态有效，沿用既有中鱼流程 |
| 同一水深，不同钓法、鱼饵、运动类型 | 使用相同阈值，水深判定结果相同 |
| 路亚使用 `1001/2001` 等默认运动类型 | 不绕过统一水深检查 |
| 真饵进入静漂或无规则运动 | 不绕过统一水深检查 |
| 评分很高，但水深不足 | 不能靠评分形成有效姿态 |
| 水深合格，饵处于沉底/浮水/水层 1/2/3 | 仍按既有姿态规则评价，不以水层类别代替实际水深 |
| 位置由浅到深或由深到浅 | 按既有姿态求值时机更新水深判定，不锁死整次抛竿 |
| 无水体或深度查询失败 | 不误判为通过，异常原因可诊断 |
| 抽到无法进入浅滩的大鱼 | 姿态层不重新按鱼体筛选；交由鱼行为处理 |
| 水深失败但存在保底鱼 | 不触发该姿态的中鱼机会 |

## 7. 待确认项

1. **阈值与量纲**：最低有效水深需要标定；核对水深查询使用米、厘米还是引擎单位。
2. **`PoseBasic` 读取**：配置解析是否支持新增 `FLOAT` 全局参数和参数 ID 注册。
3. **采样点**：现有姿态使用哪个位置坐标，是否可在同一坐标取得水深。
4. **有效性总判定**：代码的有效态发布点在哪里，有无默认姿态或其他入口绕过。
5. **异常反馈**：缺失水深的日志/错误码沿用哪条现有通路。
6. **配置单一真值**：优先在 `PoseBasic` 统一配置，避免临时硬编码与表内值冲突。
