# 姿态浅水有效性判定机制

> 状态：待审核的机制设计稿，尚未成为现行契约。原稿记载用户已确认机制边界；配置结构、字段与运行时接入点仍待独立核实。
>
> 日期：2026-11-04。来源与核实范围见第 8 节。

## 1. 问题与范围

玩家把饵抛到近岸等水深明显不足的地方时，如果姿态系统仍将其判为有效，就可能产生不合直觉的鱼口，甚至被用于反复触发中鱼。

本机制为姿态有效性增加一个全局最低水深条件，全部钓法、鱼种、鱼体大小、鱼饵和运动类型共用同一阈值。它不改变既有姿态内部的组合规则，也不调整烘焙（Bake）、派生环境场（DEF）的鱼类空间分布、环境权重、响应（Response）适配系数或圆桌候选权重。大鱼能否进入浅滩由鱼行为处理。

## 2. 核心规则

姿态系统读取当前姿态求值位置的实际水深，与全局最低水深阈值比较。阈值必须先通过第 3.2 节的配置校验，才可使用以下比较：

```text
waterDepth < poseMinWaterDepth   → 浅水条件不通过
waterDepth >= poseMinWaterDepth  → 浅水条件通过
```

水深条件是最终姿态有效性的一项新增必要条件。既有姿态内部的组合规则保持不变：

```text
最终姿态有效 = 浅水条件通过 AND 既有姿态整体有效性判定通过
```

- 低于阈值时，姿态无效，不发出该姿态的有效中鱼机会。
- 达到阈值时，仅通过浅水条件，仍须走完原有姿态有效性判断。
- 深度未知时，不能默认通过，也不能伪装成“水深为零”。记录数据不可用的原因，阻断该次有效态；具体日志或错误码通路待核实。

浅水检查不必在代码执行顺序上位于第一项，但必须参与最终姿态有效性判定。任何姿态识别结果、默认运动类型或评分结果都不得绕过它。

## 3. 配置建议

### 3.1 工作簿信息与配置落点

原稿作者称曾核对 2026-11-04 会话上传版 `pose.xlsx`。下表仅保留作者对工作表的描述及据此提出的建议，均未由本轮审查独立核实，不代表生产表事实。

| 工作表 | 作者转述的职责（待核） | 配置建议 |
| --- | --- | --- |
| `PoseBasic` | 以一个参数一行的方式保存全局姿态参数，含 `POSE_SCORE_RANGE` | 优先在此配置统一阈值 |
| `PoseLureEntities` | 路亚运动姿态的识别条件与评分，含匹配、覆盖和默认配置语义 | 不按具体姿态重复增加水深阈值 |
| `PoseFloatEntities` | 真饵浮钓的静漂、无规则运动及其评分与中断参数 | 不增加第二份阈值 |
| `PoseEffects` | 路亚饵的光、声、水花效果倍率 | 不放姿态有效性规则 |
| `Readme` | 姿态类型编号、同类配置优先级和时间口径 | 可补规则说明，不存阈值数值 |

若上述表结构经核实成立，建议选用 `PoseBasic`。统一阈值只配置一次，不参与具体姿态行的筛选、继承或优先级竞争。

### 3.2 建议新增的配置行与校验

原稿转述的 `PoseBasic` 列布局为：A 列数据类型、B 列参数 ID、C 列中文说明、D 列特殊值编码、E 列参数值。下表是按该布局提出的新增行建议，列布局与解析能力均待核实。

| A：类型 | B：参数 ID | C：说明 | D：编码 | E：值 |
| --- | --- | --- | --- | --- |
| `FLOAT` | `POSE_MIN_WATER_DEPTH` | 姿态最低有效水深 | 空（单值） | 待标定的单个数值 |

`POSE_MIN_WATER_DEPTH` 是建议名称，不是已确认存在的字段。阈值单位必须与实际水深查询一致；若接口采用米，表中同样填写米数。原稿将 `segment` 描述为分段值编码，此解释仍待核实，不能据此把单位写入 D 列。

阈值必须是有限正数，大于零，不能为 `NaN` 或正负无穷。配置缺项、无法解析或数值不合法时，记录配置错误并阻断依赖该配置的姿态有效态发布；不得以零、负数、旧缓存值或无条件通过作为兜底。具体加载与报错接口待核实。

**不要把“待定”写入生产表的 `FLOAT` 值。** 标定并统一单位后才能填写数值；程序还须确认新增参数 ID 的注册与 `FLOAT` 读取能力。

### 3.3 配置边界

- 不在 `PoseLureEntities`、`PoseFloatEntities` 每行重复增加 `minWaterDepth`。
- 不用水层类别代替实际水深。原稿将 `PoseLureEntities.layer` 描述为沉底、浮水、水层 1/2/3，字段及枚举仍待核实。
- 不修改 `POSE_SCORE_RANGE`，不以评分档位代替有效性判定。有评分不等于姿态有效。
- 不在 `PoseEffects` 的光、声、水花效果中隐藏浅水禁用逻辑。

## 4. 运行时接入方式

```text
抛竿后进入既有姿态计算 / 更新时机
              ↓
    取得当前姿态求值位置及实际水深
              ↓
       统一水深条件判定
          ├─ 不通过 ───────────────────┐
          │                           ↓
          └─ 通过 → 既有姿态整体判定 → 最终姿态有效性汇总
                                         ├─ 无效 → 不触发有效中鱼机会
                                         └─ 有效 → 既有正常中鱼流程
```

建议将水深检查接在所有姿态共同经过的最终有效性判定出口。如果代码中没有统一出口，应找到全部有效态发布路径，确保每条路径都受约束。具体函数、数据接口及统一出口是否存在，均待运行时代码核实。

原稿将 `PoseLureEntities` 的 `1001`、`2001` 分别描述为静止、无规则运动，并称 `PoseFloatEntities` 也有静漂和无规则运动。这些编号与配置职责仍待核实。无论具体编号如何，即使没有命中精细姿态规则，或进入默认、无规则路径，浅水条件仍必须生效；默认运动类型不必然等价于有效姿态。

现有识别流程仍可判断运动状态，但发出有效姿态或中鱼机会之前必须完成最终判定。水深不通过时，不得由评分、重新抽姿态、保底鱼或环境权重下限恢复该次机会。

## 5. 位置变化及职责边界

- 水深按当前姿态求值位置查询，不把初次落点固定为整次抛竿的永久依据。
- 沿用既有姿态更新时机重新评价：由浅入深可恢复水深条件通过，由深入浅可使条件失败；通过后仍须执行既有姿态整体判定。
- 不新增每帧强制刷新要求；位置取样、刷新频率和接入点需核实。
- 若圆桌抽到无法游入浅滩的大鱼，由鱼行为与移动机制处理；姿态层不读取鱼种、品质或鱼体尺寸来筛选。
- 如果阈值附近发生频繁抖动，先查明来源；本稿暂不增加迟滞区间或第二个阈值。

## 6. 验收用例

以下为设计验收要求，尚未执行运行时验证。除配置异常用例外，均以阈值配置合法且单位一致为前提。

| 场景 | 预期行为 |
| --- | --- |
| 阈值为有限正数且单位一致 | 配置校验通过，进入水深比较 |
| 阈值为零或负数 | 记录配置错误，阻断依赖该配置的有效态发布 |
| 阈值为 `NaN`、正无穷或负无穷 | 记录配置错误，不执行放行比较 |
| 阈值缺项、填入“待定”或无法解析 | 记录配置错误，不以默认值或旧缓存值放行 |
| 水深低于 `POSE_MIN_WATER_DEPTH` | 浅水条件失败，最终姿态无效 |
| 水深恰好达到阈值 | 水深通过，仍须执行既有整体判定 |
| 水深通过，但既有姿态整体判定失败 | 最终姿态仍无效 |
| 水深与既有整体判定均通过 | 姿态有效，沿用既有中鱼流程 |
| 同一水深，不同钓法、鱼饵、运动类型 | 使用相同阈值，水深判定结果相同 |
| 路亚使用默认运动类型（原稿举例 `1001/2001`，编号待核） | 不绕过统一水深检查 |
| 真饵进入静漂或无规则运动 | 不绕过统一水深检查 |
| 评分很高，但水深不足 | 不能靠评分形成有效姿态 |
| 水深合格，饵处于不同水层类别 | 仍按既有姿态规则评价，不以水层类别代替实际水深 |
| 位置由浅到深或由深到浅 | 按既有姿态求值时机更新水深判定，不锁死整次抛竿 |
| 无水体或深度查询失败 | 不误判为通过，异常原因可诊断 |
| 抽到无法进入浅滩的大鱼 | 姿态层不重新按鱼体筛选；交由鱼行为处理 |
| 水深失败但存在保底鱼 | 不触发该姿态的中鱼机会 |

## 7. 待确认项

1. 最低有效水深的具体数值及量纲，水深查询使用米、厘米还是引擎单位。
2. 工作簿原件、版本、表结构、字段与枚举；`PoseBasic` 是否支持新增 `FLOAT` 参数及参数 ID 注册。
3. 现有姿态使用哪个位置坐标，是否可在同一坐标取得水深。
4. 代码的有效态发布点，有无默认姿态或其他入口绕过。
5. 缺失水深和配置错误使用的日志、错误码及阻断接口。
