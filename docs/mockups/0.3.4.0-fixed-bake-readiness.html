这八步里，只有第 2 步和第 7 步在概念上容易搞错——上一版文档把它们写成了"门控封顶"，现行是"门控换路"。下一页专门讲这个差别。

最容易搞错的一处

门控失败 ≠ fit 归零，也 ≠ 封顶

旧模型说：门控失败就先算 RawEnvCoeff，再 min(Raw, cap) 压一下。现行契约说：失败就换路，聚合公式根本不执行。两者在"fit 恰好为 0"时结果相同，但在fit 很小却非 0 时不一样。

✕ 旧模型（已废）：封顶
Final = min(RawEnvCoeff, cap)

语义是"最多给到 cap"。Gate 永远只能压低，不能抬高。

✓ 现行：换路（分支）
背景鱼 → envCoeffMin；非背景鱼 → 0

语义是"这条路不存在"。对背景鱼而言，它仍然被保底到下限——这是设计意图，不是副作用。

水温门控：失败区比"超出可接受区间"更宽

以 Bass Q3 为例：可接受 [2, 35]、偏好 [24, 29]、LINEAR、temp_threshold = 0.05。判据是 fit 低于 0.05，不是"fit 等于 0"——所以在 [2, 3.1) 这段爬坡区里，鱼已经"不在这里"了。3℃ 失败、4℃ 通过，只差 1 度。

温度适配值 TemperatureFit 门控阈值线 斜纹区 = 门控失败

这条路径我在参考实现里用反事实测试钉住了：把 temp_threshold 调到 0 让门控永不触发，同一组 fit 下的结果只会更高或相等——所以"门控只会压低、不会抬高"这个不变量在现行契约下仍然成立（保底鱼那条路由 floor 兜住了）。

4 条已裁决：裁决内容与理由

GAP-001
已裁决
四个组件的习性表字段名统一走 snake_case。它不是"两页写得不一致、随便挑一个"——delta 7 早已把温度那 6 个参数在解析后 payload 里钉成 snake_case，所以另外三个组件跟同一层走：structure_affinity、foraging_surface_affinity / _middle_ / _bottom_、time_period_activity_coefficient。条件开关页的 camelCase 是过时写法。
GAP-002
已裁决
三个死键直接删掉，不保留为 null；并新增 gateFailureBranch。判据：没有存量数据、没有已实现的消费方、删了不丢信息（这些键的内容已由 secondaryProduct / secondaryFactor / gateFailureBranch 完整表达）。留着的代价是自相矛盾——一张以「可解释性」为唯一职责的字段表里躺着已废概念的字段。同时留一条 negative knowledge 注记，写明是哪次裁决删的、不要再加回来。
GAP-003
已裁决
显式 "aggregationRole": null = 显式忽略。只有整条 binding 行缺失才算「应配而缺」报错。这一条同时满足了两处现行权威的说法：Bass fixture 的 null 读成 IGNORED，而「缺配置 ≠ 忽略」仍然管着"整行缺失"。
GAP-004
已裁决
gatePolicy 从未上线，所以不存在迁移通道——出现即报错。我原先把它写成"两条权威互相矛盾"，重新细读后更正：Schema §5.1 管的是迁移读取通道，Bass 切片 V6 管的是校验通道。但既然没有存量数据，迁移通道根本没有对象，只剩"字段不存在"这一条。另外：把某条鱼的水温从 CORE 改成 SECONDARY 是普通编辑，烘焙永远按当前角色算，不需要任何迁移逻辑。

自我审查

写完之后反查：代码里有没有"文档没说我就自己定了"的地方

有 8 处。其中 3 处已由 2026-09-18 的裁决变成正式契约（不再算"隐式"）；剩 5 处仍未决。没有一处是偷偷做的——每处都写进了 Gap Log；这里列出最要紧的三条。

▲ 故意不夹紧

超出 [0,1] 的手填值原样透传，会让环境系数冲过 1.0。

这是刻意不做决定：一夹紧，GAP-005 就被藏起来了。

▲ 换路时聚合字段置空

门控失败时 Trace 报 null 的乘积字段，但仍报各条件的 fit（判门控本来就得先算出来）。

文本只写了"不计算公式"，没写 Trace 报什么。

✓ null 当忽略、缺行当错

null → IGNORED；整行缺失 → 报错。

已裁决（GAP-003）：这是两条现行权威折中后的正式读法，不再是隐式决定。

另外 5 处仍未决：appliedFit == rawFit（现行无 0.05 夹紧，属陈述而非决定）、CORE fit 为 0 时 coreLoss 置 null 以免 −inf、空积 = 1、换路时聚合字段置空、故意不夹紧。已由裁决转正的另两处：死键已删（不再保留 null）、gatePolicy 一律报错（不再有惰性读透）。
