Proposal C · Response Model

这条鱼，为什么这一刻会咬

把鱼的一次出手拆成五笔账，再合成一个数。

状态 Candidate / Working 设计 基线 main bbb21201 日期 2026-11-05 档位标尺 tier-v2

这套模型只回答一个问题：给定这条鱼、这个拟饵、这一刻的动作，它现在有多强的出手倾向？ 它输出的是响应强度，不是咬口概率；也不从商品名称推断猎物身份，不决定奖励。

三条硬规矩

未知不等于零。缺数据就是 Unknown，不能当成“没有吸引力”。

同一作用只结算一次。同一个事实可以被多处读取，但同一个效果只能在一处加成。

时间不进余量。停留多久、扫过多少空间，由机会侧结算，不在这里加分。

01一条链：从画面到出手

输入是这条鱼实际看到、听到、感觉到的东西。每一层只做一件小事，输出交给下一层。

呈现事实轨迹、速度、水层关系，带时间与来源
→
猎物解释这条鱼把它当成什么，有多确定
→
猎物状态它在逃、在停，还是受伤；催不催出手
→
鱼况快照活跃度、食欲、食性偏移、警戒，每竿一份
→
五项评价食物、诱因、追赶、风险、门槛
→
出手余量加减成一个数
→
响应 C压到 0 到 1

快照在抛竿那一刻冻结。整竿沿用同一份鱼况，不因为中途换时段而重算。

02五笔账

出手余量就是一张账本：两项往里加，三项往外扣。所有项都先换算到同一把尺子上，顶层只做加减。

出手余量 = 食物价值 + 攻击诱因 − 追赶负担 − 风险顾虑 − 摄食意愿门槛
项用大白话说工作范围
食物价值这个猎物，对现在的它值多少0 ~ 1
攻击诱因它的动作有多催鱼出手0 ~ 0.15
追赶负担追上去要花多少力气0 ~ 1.52（q∈[0,2] 时）
风险顾虑这次呈现看起来有多可疑0 ~ 1
摄食意愿门槛现在要多想吃的理由才值得动嘴0.1 ~ 0.6

五项可以互相补偿。食物足够好，可以抵消一部分追赶代价；动作足够催，可以让边缘目标跨过门槛。 但补偿有上限，成本再大也不能冒充“根本不可能”。

表中的范围是 Working 边界，不是硬上限。追赶负担在 q 或活跃度越界时还会继续增大，不设硬 cap。

03食物价值：从基础食性到此刻的偏移

先问“这类鱼本来觉得这种猎物值多少”，再问“现在的季节、近期食谱让它偏了多少”。 两部分分开存，最后在同一个档位标尺上合并。

基础食性 BaseDietAffinity

鱼种 × 猎物家族的静态值。参考鱼况、参考尺寸下的“本来值多少”，不随当天变化。

食性偏移 DietTierShift

按猎物家族分别给出，单位是“档”。当前工作域是 [-1, +1]，一档以内，允许小数档。

公共档位标尺

四个锚把 0 到 1 的分数切成三段。锚由 Owner 定，同一标尺版本内所有猎物家族共用。

0Poor
0.25Marginal
0.60Good
1.00Preferred

档位坐标是 0、1、2、3，锚之间按分段直线插值。把分数换成坐标叫 T，换回来叫 U。

u   = T(BaseDietAffinity)                  # 分数 → 档位坐标
u'  = clamp(u + s, 0, 3)                   # 加减偏移，停在两端
ShiftedDietAffinity = U(u')                # 档位坐标 → 分数
FoodValue = clamp(
    ShiftedDietAffinity + 尺寸调整, 0, 1
)
三个具体例子
基础 0.40，加 1 档0.40 → 0.771
基础 0.70，加 0.1 档0.70 → 0.74
基础 1.00，加 1 档，再减尺寸 0.201.00 → 1.00 → 0.80
两条端点规则

基础 0 可以被抬起来。0 只表示“目前基本不把它当食物”，不是“绝不接受”。加一档就能抬到 Marginal(0.25)，饮食偏移才有意义。

顶档不存余额。已经是 1.00 再加一档，结果还是 1.00。多出来的部分丢掉，不能回头抵消尺寸扣分。鱼“更想吃这类”和“这个尺寸不在它偏好的范围内”是两件事。 再大、已经超出可食范围的尺寸属于另一条硬边界，不靠这项软调整表达。

版本必须跟着走

“加一档”没有绝对含义，它只相对于某张锚表。锚表一改，同样的 +1 就会落到别处。 所以每个鱼况块与快照都带 tierScaleVersion，当前是 tier-v2。 消费端只认已知版本；旧版本 tier-v1 读到就直接返回 ResolutionIncomplete，不会被按新锚重解释。

04攻击诱因：它的动作在催你

只有目标已经被解释成“可接受的猎物”，才谈得上诱因。这一项表达猎物的状态是否额外促发出手， 不承载领地、护巢、烦躁、调查这些别的动机。

攻击诱因 = TriggerBudget × TriggerIntensity
TriggerBudget ≈ 0.10 ~ 0.15        # 预算上限，防止诱因压过一切
TriggerIntensity ∈ [0, 1]          # 由猎物状态解释器给出

TriggerIntensity 不是把转向角度、爆发速度、事件次数直接相加。 一次逃逸冲刺往往同时包含转向和加速，按特征相加会把同一个动作奖励两遍。 现在的做法是先按猎物类型判断“这是不是一次逃逸样动作”，再用转向强度与爆发强度合成。

05追赶负担：追上去有多累

q = 拟饵相对水体的水平速度 / InterceptSpeedLimit
追赶负担 = K_close × q² × ActivityCostMultiplier(Activity)

K_close = 0.19
ActivityCostMultiplier(A) = clamp(1 / A, 0.5, 2)     # A = 0 时按 2 处理
Activity ∈ [0, 2]，常规不超过 1，极活跃才越过 1

q 是速度需求比，按“鱼在追拟饵”这一个方向估算，不模拟相对方位。 速度越快，负担按平方上升。鱼种与体型决定它能追多快；活跃度决定它此刻愿意为追赶付出多少。

算一笔
q = 0.40，Activity = 1.00.19 × 0.16 × 1.0 = 0.0304
q = 0.80，Activity = 0.50.19 × 0.64 × 2.0 = 0.2432

活跃度只改“愿不愿意花力气”，不改“能追多快”。低活跃不能表现为鱼突然失去运动能力。

06风险顾虑：这次看起来可疑吗

风险顾虑 = K_wary × Wariness × SuspicionLoad
K_wary = 1.0（Working 尺度）

Wariness 是这类鱼对风险线索有多敏感，SuspicionLoad 是这次呈现里有多少已解析的可疑证据。

  • 没有已解析的线索，两个警觉值都不产生风险顾虑；
  • 支持度不足不算可疑，高速和频繁转向也不算，它们已经在追赶负担里结算；
  • 钓压提高警戒度，不能再塞进可疑证据，否则会平方放大；
  • 首版装备显眼度还没有生产字段，所以 RiskCost 目前恒为 0。

07摄食意愿门槛：要多少理由才动嘴

M ≤ 0.80:  threshold = 0.60 − 0.40 × M
M > 0.80:  threshold = 0.60 − 0.40 × M − 0.50 × (M − 0.80)

M = 0.5  →  threshold = 0.40

动机不乘食物价值，也不放大其它负担，它只移动门槛。普通区间保持固定斜率； 只有极高的动机进入额外下降区，让很差的猎物也出现一条窄窗口。

一个容易混的点

门槛的数字 0.40 和档位锚里的 Marginal 曾经是同一个数。现在不是了：Marginal 是 0.25，门槛仍是 0.40。 两者互相独立：档位锚由 Owner 设定，不参与标定；门槛仍是 Working 参数。改锚不会带着门槛一起走。

08从余量到响应：压成一个数

C = clamp((出手余量 − M0) / (M1 − M0), 0, 1)
M0 = 0.00
M1 = 0.40

余量小于等于 0，响应为 0。余量到 0.40 就满了。中间线性。 这个截断既是设计选择，也是标定工具：它把不同量级的因素拉到同一个可比区间。

余量响应 C读法
≤ 00不值得动
0.200.50半推半就
≥ 0.401.00满响应

09多个猎物、多个模式：怎么合

一个拟饵可能被解释成好几种猎物。每种猎物各自算一份响应，最后取最大值。

  • 已解析的分支取最大，不求和；
  • Reject 的分支贡献 0，但不会被最大值复活；全部已解析分支都是 Reject，整体就是 Reject；
  • Unknown、NotConfigured 的分支不参与比较，但必须记录在结果里，不能当作 0；
  • 没有已解析分支时，整体返回 ResolutionIncomplete；
  • InvalidInput 会阻断整个结果，不能靠其它分支救回来。

同一竿里如果有多个 EngagementMode，各自独立计算自己的鱼况与响应，不互相平均。

10状态：三种“零”不能混

状态含义能不能当 0 用
Resolved，值 0算出来了，结果就是没有响应可以
Unknown必要事实缺失，结果可能改变不可以
NotConfigured没有适用的规则或配置不可以
Reject类型上的硬边界，根本不接受当作 typed zero，不进连续公式
InvalidInput配置或输入错误不可以，不可修复后继续
ResolutionIncomplete归约阶段仍形不成最终标量不可以

数值里出现 NaN 或 Infinity 一律按 InvalidInput 处理，不先 clamp 再继续。

11完整算一笔

假设：猎物支持度 1.0，食物价值 0.70，诱因强度 0.80，活跃度 1.0，q = 0.40，无风险线索，动机 0.50。

食物价值0.70
攻击诱因0.10 × 0.80 = 0.08
追赶负担0.19 × 0.40² × 1.0 = 0.0304
风险顾虑0
摄食意愿门槛0.60 − 0.40 × 0.50 = 0.40
出手余量0.3496
响应 C0.3496 / 0.40 = 0.874
乘上支持度 1.00.874

如果这一季食性偏向这种猎物，加 0.1 档，食物价值从 0.70 升到 0.74，余量变成 0.3896， 响应升到 0.974。这就是食性偏移在链条里的实际效果。

12机会与圆桌：响应只走到这里

响应返回的是 C_feed，一个 0 到 1 的标量。它不乘停留时间，也不乘空间覆盖。

Response  →  C_feed
Opportunity →  L = r × τ               # L 是机会侧内部量
圆桌接口   →  SpatialDistributionWeight × AdaptationCoeff

L × C 只在 Opportunity 内部使用，不是候选贡献公式。圆桌按 FCF 通用公式计算； L 如何并入空间分布权重，仍由 Opportunity 线决定。

13边界与还没定的

  • Prediction 不在第一版，列为 Deferred Research；
  • 装备显眼度 TackleConspicuousness 还没有生产字段，风险项暂为 0；
  • Wariness 的运行时叠加（事件来源、衰减、有效期）尚未闭合；
  • Escape 样诱因的阈值仍是 Working，缺独立审核与数据依据；
  • L 的遭遇几何、档位时间粒度和重复手法衰减 K(n) 仍待定；
  • 非摄食行为（防御、调查）是否归入独立 Engagement Mode，尚未裁定；
  • 所有系数都是 Working / Probe，不是生产参数。
