## 冲突清单

### C1｜GPT 线「卡5 Impact Preview」组与本批「共用N2」组并存
- **事实**：画布现有 GPT 线组「PROJECTION｜卡5 Impact Preview · Source Rebase / Shared Template」（figma-current.md §二 GPT 线登记），已画两块影响预览面板（四统计、消费者分类、确认标签「确认切换 Source」「确认模板变更」）。本批新增「共用N2」组后，同一文件将有两套确认面投影。
- **张力点**：①内容面重叠（四统计／分类／确认）；②GPT 线确认按钮串是分场景串，契约共享N2 的统一动作串是「确认变更」——两形并存。③「卡5」这个编号与 A①-卡5（Provenance Display）编号空间不同（GPT 清单另一套），figma-current.md §二已声明「与本清单不是同一批」，但读者仍可能混。
- **不动手理由**：两线并存是登记过的现状；GPT 组不在本批写集内。是否给 GPT 组加分工注记／降级／保持，由编排线裁。

### C2｜四统计词形变体
- **事实**：汇编 §14 写「直接引用数／**Effective consumers 数**／最终结果变化数／新增 Error·Warning」；卡12 Must show 写「直接引用数／**Effective consumer 数**并列」。两处冻结文本不同形（consumers／consumer）。
- **本稿处置**：帧内统一取卡12 形「Effective consumer 数」；在此登记差异，供下次契约修订对齐（属 Editorial Delta，不自行改卡）。

### C3｜示例数值 12／31／24／2E·3W 的多处归属
- **事实**：同一组示例数值现行出现在三处：GPT 卡5 组（通用示例）、卡12 态2（**旧候选示例**——其 annotation 已声明「只有 Direct/Effective 两数可作当前读数」，且 `#60` 将按「日常列表不显示虚构 candidate 全局四数」修订）、本批 N2 态3／卡11 态2（候选变更场景，四数**合法**）。
- **张力点**：`#60` 修订卡12 时若把「候选场景不得显示四数」读宽，可能误伤本批两组；反之本批落地后读者会看到卡12 两数 vs N2/卡11 四数并存。
- **本稿处置**：本批各组 annotation 均写明上下文句（「四项统计属候选变更场景…后两项归卡10/11场景——汇编§14」）。`#60` 执行方需带本条上下文读「不显示虚构 candidate 全局四数」——它约束的是**无候选输入的只读列表**，不是候选面板。

### C4｜EffectiveConsumerSet 是否计入「IGNORED＋空底板」组件
- **事实**：汇编 §14 定义 EffectiveConsumerSet＝「Resolve 后当前 Effective Source 为 A 的全部最终 Recipe」；§11（ADJ-11 §3.7 第三臂）规定 `Authoring Profile 为空 且 Effective Role=IGNORED` 的组件「根本不进入 evaluator」、不产生 Component Profile projection。
- **张力点**：一个直接绑定了 A 但处于 IGNORED＋空底板的组件，**算不算 A 的 Effective consumer**，两节合起来没有唯一答案（按「最终 Recipe」算则算；按「不进 evaluator」算则不算）。
- **本稿处置**：示例数据避开该形态（所有消费者均非 IGNORED＋空底板）；统计口径待裁，不改卡。

### C5｜「取消候选」（N2）与「丢弃未保存的改动」（卡7）措辞互核
- **事实**：两动作都作用于未确认候选，分工有契约（N2 只弃本次候选；卡7 弃全部未 durable 本地态，显式含「未确认的 staged Source candidate」）。`#59`（F2.3）将修订卡7 组的「两窗口」投影并已涉「取消候选」边界。
- **要求**：`#62` 批落 N2 态4 前，writer 应 fresh 读 `#59` 之后的卡7 组现状（它先落）；两处措辞不得把对方的动作吞并（N2 不得写成「丢弃未保存的改动」的局部版；卡7 不得写成「等于取消所有候选」）。列出不裁，执行时互核。

### C6｜卡10 编辑面标题格式无契约逐字
- **事实**：态1 标题「模板 · 水温 · 类型名 T（示意）」为示例串；契约只规定「从模板库进入（中栏切到模板上下文）」与卡上以模板名显示，无逐字标题格式。
- **处置**：标示意；不改行为。若后续 `#51` 系 UI 细则落页，以页为准。

### C7｜UNIMPL 记号口径
- **事实**：`#54`／`#62`／`#63` 正文令「状态明确UNIMPL」；画布记号体系要求 ⚑UNIMPL 挂 GAP 号，缺号标「待补」（`figma-mockup-write` skill §六）。当前未取得模板改值／Replace 的 GAP 编号（实现未核，OPEN-ITEMS §6）。
- **处置**：三组统一 `⚑UNIMPL（GAP 号待补）`。实现线后续给出 GAP 号时只补号、不改文案。

### C8｜Replace 的 B 是否可为 SPECIES_CONCRETE
- **事实**：卡11 标题逐字「批量换绑（模板 A → 模板 B）」，Actions 只写「候选 B」未限定类型。汇编 §8 矩阵禁止「任何层 pin 非当前物种的 Concrete」；跨物种直引写 Concrete 必违，但同物种水温直引在 §8 矩阵内合法。
- **本稿推定**（非引文）：B 侧只列 ACTIVE 模板——依据＝卡11 标题限定「模板 B」＋ §8 矩阵。**此为推导不是逐字裁定**；若 Owner 认为同物种 Concrete 可作 B，只需改态1 `[b]`/`[bl]` 两行文案，其余不动（翻转点：态1 的 B 侧枚举范围）。
