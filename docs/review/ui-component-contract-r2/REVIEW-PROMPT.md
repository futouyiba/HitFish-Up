# REVIEW-PROMPT — 审什么、怎么报、什么算通过

## 一、这份材料要审的是什么

**审「实现投影是否忠实于当前契约」，不是审机制设计本身。**

三样东西的关系：

- **汇编** ＝「现在是什么」（逐条带出处的合并视图）
- **冻结卡** ＝「实现按这个做」（执行投影）
- **Figma** ＝「图上现在画了什么」（视觉投影；**是目标态投影，不代表已实现**）

**判据**：一个实现者**只读**这三样＋Current，能不能**唯一**地做出来；一个审阅者**只读**本目录，能不能判断**投影是否忠实**。

## 二、四个聚焦问题（请逐条回答）

1. **语义丢失**：投影里有没有把 Current 的某个判据、阈值、值域、阻断性、执行顺序、owner/consumer、验收向量**改弱或改没了**？
2. **竞争权威**：同一事实在**两处**都自称定义？（Current 侧的真问题在 `OPEN-ITEMS.md` 里列了；本目录内若发现新的，照报。）
3. **压缩层歧义**：为了变短而把**不同层**的规则压成一句（最典型：「物种层」与「桶层」的语言混用、「同值」与「同意图」混用）？
4. **实现歧义**：一个实现者按这份投影，会不会在**两个都说得通**的读法之间无从选择？

## 三、输出格式

每条给出：

```
ID:      <自选前缀>-<序号>（**请带前缀**，不同报告的裸序号会撞车）
SEVERITY: BLOCKER | MAJOR | MINOR | NOTE
HEAD:    <你审的 exact head SHA —— 必须给>
LOCATION: <文件 + 节/行 + 引文（≤2 句）>
REASON:  <逐字给出理由；**不要只给结论**>
```

**⚠️ 两条关于「为什么」的纪律**：

- **理由是最容易被就地替换的东西。** 复核方**只认最新那条理由**，所以**同一条若改判，请连同理由一起重发**，不要只改 ID。
- **ID 不是身份。** 本族历史上同一个 ID 曾被关→开→关，且不同报告用过相同的裸序号。**判「还是不是那条」要读当前理由，不要只看 ID。**

## 四、四条纪律

1. **不裁定** —— 你报的是**投影与契约是否一致**；机制该不该这样，归 Owner。发现契约本身可疑，用 `NOTE` 标出，不要就地改判。
2. **不确定就说不知道** —— 写 `NOTE: 不足以判` 比给一个猜的结论有用。**假证明比没有证明更贵。**
3. **不为了清空清单制造劳动** —— 已关的项不必复述；**只为仍开的重开**。
4. **自陈缺口要读成阻塞** —— 材料里若写「X 尚无稳定形态 / 待裁」，那**就是一条成立的 finding**，请照报；但**先看 `OPEN-ITEMS.md`**，那里已列的不要重复报。

## 五、通过判据（两层门）

- **开发门**：在**同一个 exact head** 上**至少一位**审阅者通过 ⇒ 即可驱动实现侧工作。
- **合并门**：(a) **全部**审阅者通过 **＋** (b) 自**最后一次「提意见的评论」**起**连续 2 小时无新评论**。

**⚠️ 两条前提**：

- **approve 没有 GitHub 状态位** ⇒ 门是从**评论文本**读的。请写 **`REVIEW: APPROVE @ <sha>`**，否则机器读不出来。
- **「没说话」不算通过。** 上一版材料里有一条与之相抵的旧写法，**以本节为准**。

## 六、审 Figma 那一半时

`figma-current.md` 是**文字与图像**；图上的 **annotation 对读本目录的人不可见**（本目录只有文字与图像）。该文件给的是**对外可见的摘要**。

- **图与包必须同批** —— 若你怀疑图旧，核 `figma-current.md` §六 的判图纪律：**「字节变了」≠「内容变了」**；**比字节前先确认是同一条导出管线**（两条管线的同内容产物差约 1.5%）。
- **判「图上有没有某个记号」要给作用域** —— 「这几帧没被标」与「这个体系没人用」是两件事。
