# REVIEW-PROMPT — 审什么、怎么报、什么算通过

## 一、这份材料要审的是什么

**审「实现投影是否忠实于当前契约」，不是审机制设计本身。**

三样东西的关系：

- **汇编** ＝「现在是什么」（逐条带出处的合并视图）
- **冻结卡** ＝「实现按这个做」（执行投影）
- **Figma** ＝「所登记版本的图上画了什么」（视觉投影；**是目标态投影，不代表实时画布或已实现**）

**判据**：一个实现者**只读**这三样＋Current，能不能**唯一**地做出来；一个审阅者**只读**本目录，能不能判断**投影是否忠实**。

## 二、四个聚焦问题（请逐条回答）

1. **语义丢失**：投影里有没有把 Current 的某个判据、阈值、值域、阻断性、执行顺序、owner/consumer、验收向量**改弱或改没了**？
2. **竞争权威**：同一事实是否存在多个独立维护的规范性副本？非规范性摘要与可识别来源的生成投影按 [README 的维护边界](README.md#projection-maintenance)判断；区分 Product Authority 与 Repository Projection Owner。
3. **压缩层歧义**：为了变短而把**不同层**的规则压成一句（最典型：「物种层」与「桶层」的语言混用、「同值」与「同意图」混用）？
4. **实现歧义**：一个实现者按这份投影，会不会在**两个都说得通**的读法之间无从选择？

## 三、输出格式

每条给出：

```
ID:      <自选前缀>-<序号>（**请带前缀**，不同报告的裸序号会撞车）
SEVERITY: BLOCKER | MAJOR | MINOR | NOTE
HEAD:    <你审的 exact head SHA —— 必须给>
LOCATION: <文件 + 节/行 + 引文（≤2 句）>
REASON:  <逐字给出理由；**不要只给结论**>
```

同一批缺陷使用稳定编号，并写明通过条件。改判时保留理由及证据变化，不能只改 ID；跨批次不靠同号判断是不是同一问题。首次独立审核同时声明范围与回归边界；后续按 §五逐项关闭。

## 四、四条纪律

1. **不裁定** —— 你报的是**投影与契约是否一致**；机制该不该这样，归 Owner。发现契约本身可疑，用 `NOTE` 标出，不要就地改判。
2. **不确定就说不知道** —— 写 `NOTE: 不足以判` 比给一个猜的结论有用。**假证明比没有证明更贵。**
3. **不为了清空清单制造劳动** —— 已关的项不必复述；**只为仍开的重开**。
4. **缺口按范围判定** —— 先读 `OPEN-ITEMS.md`，区分产品未裁、投影缺失与实现未核；只有阻碍本批通过条件的缺口才阻断，不把已登记的实现未核自动变成设计包门禁。

## 五、风险分级、通过判据与审核收口

本节适用于仓内 Markdown 收敛；不修改产品机制，不迁移上游产品权威。

| 改动类别 | 边界 | 验证要求 |
|---|---|---|
| Editorial Delta | 不改语义、不改仓内投影 Owner | diff、回读、链接及现有 lint 检查 |
| Authority Topology Delta | 语义不变，改变仓内唯一维护位置 | 必须独立检查定义、条件、例外、来源、锚点、消费者是否承接完整，旧位置是否真正降为引用或摘要 |
| Semantic Delta | Contract 本身改变 | 从收敛批次拆出，单独设计裁决与语义审核 |

纯重复删除、链接替换、普通 History 删除，若不改变 Owner／状态／证据边界且无独有语义删除风险，局部验证即可，**不默认完整独立 Review**。涉及仓内投影 Owner 迁移、独有语义删除风险、状态变化、证据范围变化或 Semantic Delta，必须独立审核；混合批次按最高风险处理。

**Diff Hygiene**：同批不混入无关全文 reflow、大表重排、大规模改名／搬迁或普通润色。真实变化很小而 diff 很大时，先缩小 diff 再 Review；必要的大规模结构调整单独成批。

**Review Scope Freeze**：

1. 首轮完整审核明确 exact head、文件及事实范围，尽量一次形成 bounded defect set：稳定编号、必修项通过条件、不得改变的行为／证据边界。
2. 后续主要回答 `R1 PASS / FAIL` 等缺陷关闭结果，并检查修复引入的 regression；不重新扩大卫生搜索范围。新 head 的结论须说明增量及继承的审核范围，不把旧 APPROVE 自动套到新 head。
3. 本次修复引入的阻塞回归在本批处理。首轮漏检的既存问题，仅在实质影响正确性、迁移完整性或证据可信度时新增阻塞，并说明不能延后的理由；普通既存卫生问题进入 follow-up，不阻断本批。
4. 主动扩展事实范围或引入 Semantic Delta 另开批次。已有阻塞意见须逐项关闭，不以换 reviewer 绕过。

**通过与合并**：低风险批次在 PR 记录局部验证结果；需要独立审核的批次，在最终 exact head 上关闭全部必修项、无阻塞回归并获得独立 APPROVE 后合并。开发侧使用该投影不等于实现验收通过。**不设“全部历史审阅者通过”或“两小时无新评论”条件；沉默不算批准。**

独立结论沿既有机器可读格式：`REVIEW: APPROVE @ <sha>` 或 `REVIEW: REQUEST_CHANGES @ <sha>`，附委派来源、实际模型／推理强度及范围；PR 链接审核证据和被审 exact head。低风险局部验证不得冒称独立 REVIEW。

## 六、审 Figma 那一半时

`figma-current.md` 是**文字与图像**；图上的 **annotation 对读本目录的人不可见**（本目录只有文字与图像）。该文件给的是**对外可见的摘要**。

- **按逐资产版本核图** —— 以[图像登记](figma-current.md#image-evidence)的版本、证明范围和比较方法为准；不因导出参数相同断言同批，也不把原实验结果当本轮实测。
- **判「图上有没有某个记号」要给作用域** —— 「这几帧没被标」与「这个体系没人用」是两件事。
