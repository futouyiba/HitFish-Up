## 三、⚠️ 撤回「Persistence 未闭」的表述，并按页重述

`REVISION-12` §一 撤回了 `REVISION-10` 的「Persistence Contract: CLOSED」。**它举的三条理由，在《编辑器持久层契约》现文里都不成立：**

| REV-12 说的 | 页上现文 |
|---|---|
| §3.1 的字段表没有 source binding、没有 durable shape | **§3.1 已是完整字段表**：`policy_source_binding`（必填）＋ `roles`（四组件 Role op，必填）＋ `fail_env_coeff`（op）＋ 四组件值列；并逐字写明内含 **`Component Recipes`（＝ `Species Recipe`）** 与 **`Species Policy Recipe`** 两条子结构 |
| §3.3 的表里**没有 `sourceOverride` 行** ⇒ 物理落点未闭 | `sourceOverride` **落在桶层 patch 上**：逐字「桶层的 patch ＝ `AffinityAuthoringPatch`（owner ＝ `FishEnvAffinityRef`）：**每组件可选 `sourceOverride`** ＋ 逐字段 operationPatches」。§3.3 那张表是**逐 (component, member) 行**，本就不承载"每组件一个 source pin" |
| §3.3 表被钉在 bucket 级 ⇒ **不可能**承担 species 级 Recipe | **那不是缺口，是裁定** —— 逐字「`scope_kind` Current 固定为 `bucket`；**numeric override 不允许 row-level**」。物种级的东西住 §3.1，并不要求住这张表 |

- 另：**§3.4 整节**就是两条 row-level 轨道（键、op、唯一约束逐字齐），并逐字「**Role 不允许 ADD**」。
- ⇒ **本版不写「CLOSED」。** 改为**按页重述现状**，并指向该页 **§3.1／§3.3／§3.4／§3.10**。
- ⇒ **理由**：**包里写「未闭」是包的判断，不是页的事实**；反过来，包里写「CLOSED」同样不能代替页。**这条两边都成立**，所以本版只做「指向页 ＋ 说明我读到了什么」。
- `README` 的 `REVISION-10` 行 ⚠️ 同步改。
