## 八、卡上 Role 角标 —— 为什么它是"三态下拉"，以及为什么它**不做成白场**

**图上的角标**：每张 `ComponentCard` 上有一枚 Role 角标（**74×16**，角色色淡底 `#e3edfb` ＋ 角色色描边 `#2e63b8`，圆角 8），**内含一个矢量三角 `roleCaret`（7×4）**，标签 TEXT 为 `CORE` / `SECONDARY` / `IGNORED`。
⇒ **它是一个三态下拉控件，不是纯状态徽标。**

**依据（页 §1.1 逐字）**：「**AggregationRole｜每个组件卡一个三态下拉：CORE / SECONDARY / IGNORED**」。

**与顶部 `sel_*`（来源选择器）对照 —— 两者都是"入口"、形态**有意**不同**：

| | 顶部 `sel_*`（来源选择器） | 卡上 Role 角标 |
|---|---|---|
| 容器 | 126×20 | 74×16 |
| 填充 | `#ffffff`（白场） | `#e3edfb`（角色色淡底） |
| 描边 | `#d4dbe5`（中性灰） | `#2e63b8`（角色色） |
| 圆角 | 5 | 8 |
| 下拉记号 | 文字字形 `▾`（advance **6px**） | 矢量三角 `roleCaret`（**7×4**） |
| 读起来是 | 输入字段 | 状态角标 |

**⚠️ 一处"可辨识度"与一条已裁规矩的相抵 —— 刻意保留现状**：

让角标「**更读得出是下拉**」的**做法是白场 ＋ 中性描边**；但那会**抹掉角色色区分**，而**角色色是已裁的** —— **记录页 §104 四**逐字：「**角标色保留：CORE 蓝 / SECONDARY 琥珀 / IGNORED 灰 —— 满足 Owner 那条『非常重要信息』的要求**」。

⇒ **当前保留角色色**；**下拉记号以矢量三角承载**。

**量纲对照（两种记号不是同一把尺子 —— 别混比）**：**矢量三角的包围盒 `7×4`** vs **顶部字形 `▾` 的 advance `6px`**（**字形的墨宽不超过 advance，故更小** —— ⚠️ **后半句是排版推导、不是实测**）。
⇒ **无论按 advance 还是按墨宽比，卡上那个都不更小**（这一句的两种读法都成立）。
