路亚 Response：把鱼情变化转成玩家策略变化

这次会议不审批所有数值，也不设计完整鱼类 AI。目标是先对齐：我们想让玩家根据什么鱼情改变什么打法，以及这些差异至少要明显到什么程度，才值得建设对应机制。

本轮重点：路亚 后续带回：台钓 / 浮钓 先定策略差异，再定参数 不定最终 Fish Condition 数量

1. Response 是共同问题，但三种钓法的重点不同

共同问题是：当前这个食物目标，以当前方式呈现给当前状态的鱼，鱼有多愿意出手。不同钓法只是输入重心不同。

路亚｜本轮重点
更偏运动与呈现

拟饵形态、运动、速度、停顿、贴底、水层、猎物状态。

共同仍要解决：选什么饵。
台钓｜后置
更偏食物组合与窝点

成分、味型、混合、物性、雾化/残留、窝点，同时也有钩饵位置和状态。

共同仍要解决：食物是否匹配。
浮钓｜后置
更偏钩饵、水层与漂流

钩饵 / 天然饵、水层、漂流、状态；具体玩法也可能涉及味型、混合或窝料。

共同仍要解决：食物与鱼情匹配。
本轮策略：先用路亚把 Response 的评价骨架闭合，再把可复用的 Takeaway 带回台钓和浮钓。

2. 先定体验验收：要出现“策略翻转”，不是几个百分点的微调

我们真正要买到什么差异？ 体验目标，不是生产数值
在典型的两端鱼情里，玩家应该能从反馈中学到“这时换另一种打法明显更合适”。中间状态允许两边都可用；两端则至少要出现清楚的相对优势变化。现在先对齐这种排序和幅度等级，不先承诺具体百分比。
策略轴 状态一端 此时希望看到 状态另一端 此时希望看到 护栏
食性 / 食物价值 偏好不强 / 广适 泛用饵保持竞争力；专攻饵不是必选 明确偏好某类猎物 高匹配饵应明显更值得，足以让玩家考虑换饵 不能把泛用饵整体做废；Reject 仍是硬边界
追赶状态 适合追 快速搜索的局部 Response 仍可接受，玩家可以用覆盖换信息 不适合追 高速呈现要明显吃亏；在已知鱼区，慢速 / finesse 应成为清楚的更优选择 “适合追”不等于快钓单次 Response 必须高于 finesse
摄食意愿 高 普通优质呈现已经足够，额外强刺激只是可选增益 低 普通口应明显变弱；合法攻击诱因能把部分边缘机会救回到可用区间 强刺激不能成为万能按钮，也不能救活 Reject
警惕度 低 直接、强势、相对暴露的方案仍然可用，隐蔽收益有限 高 暴露 / 机械感要产生明显损失；隐蔽自然应值得玩家付出代价 本轮不要求把所有暴露直接硬判失败
验收口径：如果状态从一端走到另一端，只让同一打法从 1.00 变成 0.95，但玩家的最佳策略没有改变，这个 Fish Condition 就还没有购买到足够的玩法价值。这里的 1.00 / 0.95 只是说明“微差”的例子，不是目标参数。

→

快速搜索的收益
空间覆盖 / 信息效率

更快知道哪里值得继续投入时间。

快速搜索的代价
局部 Response 质量可能下降

局部停留更短，高速呈现还可能提高追赶负担。

希望出现的循环：快速搜索 → 找到信号 → 降速 / finesse 深挖。Response 不需要额外给“搜索速度奖励”。

7. Capacity + Activity：上游可分，Response 端可合

两者语义不同，但玩家侧主要都影响“当前应该把拟饵放多快”。因此可以把它们折叠成一个追赶状态倍率。

Capacity｜能力
客观能调用多少运动能力

能力下降后，同样拟饵速度会占用更高比例的能力。

追赶状态倍率
= ActivityCostMultiplier / Capacity²
关键点：这只是 Response 端的聚合。它不要求删除 Capacity 或 Activity 的上游来源。如果 Capacity 未来还被搏鱼、逃逸、迁移等系统消费，可以保留；如果它只服务这里且能直接推导，就没必要为了名字而 Bake 成一级 Fish Condition。

8. 三个会议案例：不只证明方向，还要证明差异足以改变选择

Case A｜追赶状态

快速搜索 vs 慢速 finesse

  • 追赶状态好：高速负担较低，快搜的局部 Response 仍可接受。
  • 追赶状态差：高速负担应明显拉开，已知鱼区里慢速呈现成为更优选择。
  • 验收不是“快饵扣一点分”，而是玩家会因为鱼情主动改变搜索速度。
Case B｜摄食意愿

普通口 vs 反应口

  • 摄食意愿高：普通优质猎物已经够，没必要强行刺激。
  • 摄食意愿低：普通呈现明显变弱，合法攻击诱因才开始有明显价值。
  • 验收是“反应口成为条件性策略”，不是“刺激永远更强”。
Case C｜警惕度

直接强势 vs 隐蔽自然

  • 低警惕：暴露成本有限，直接方案有竞争力。
  • 高警惕：暴露方案应明显掉档，隐蔽自然值得付出操作 / 装备成本。
  • 验收是“是否值得为了隐蔽做取舍”，不是审批完整 Naturalness。

10. 这次要对齐什么，刻意不闭合什么

需要对齐
  • 本轮先集中路亚，后续再回到台钓 / 浮钓。
  • 四个策略方向是否成立。
  • 每个策略轴两端要达到怎样的可感知差异和排序翻转。
  • 是否认可“状态 → 评价项 → 玩家策略翻转”。
  • 是否认可加性出手余量主体。
  • Capacity / Activity 是否允许在追赶消费端聚合。
  • Fish Condition 数量由消费需求反推。
刻意不闭合
  • 这些策略差异的最终百分比 / 生产参数。
  • 台钓 / 浮钓味型、混饵、窝料算法。
  • 完整 Naturalness / 异常暴露模型。
  • 最终 Fish Condition 数量。
  • Functional Capacity 是否最终独立 Bake。
  • 轨迹预测困难是否保留。
  • 非摄食攻击与完整单位时间中鱼效率。
会议主旨
我们不是在增加一组更复杂的中鱼系数，而是在建立一层把鱼情变化转译成玩家策略变化的 Response。第一步先对齐“鱼情从一端变化到另一端时，玩家的合理策略应该怎样明显翻转”；算法、状态量和参数随后都服务于这些体验目标，而不是反过来。
