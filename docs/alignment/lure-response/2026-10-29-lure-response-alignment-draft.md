# 路亚 Response 对齐稿｜会议草案

状态：Meeting Alignment Draft / Candidate。不是 Current Contract，不是生产参数。

基线：`docs/lure-response-joint-evaluation` 分支，起草前 HEAD 为 `862388c03fa4eed972441656e395f077d47008db`。

用途：用于一次路亚 Response 方向对齐。目标是先统一体验目标、策略轴、算法骨架和第一版范围；不在这次会议里完成生产参数、完整自然度、最终 Fish Condition 数量或台钓/浮钓细节。

## 0. 这次会议要回答什么

这次不是评审一套完整鱼类行为模拟，也不是审批所有数值。

希望对齐四件事：

1. 不同钓法的 Response 有哪些共同问题，路亚第一版重点解决什么；
2. 我们希望鱼情变化带来哪些可学习的玩家策略变化；
3. 为了得到这些策略变化，鱼侧评价需要拆成哪些独立问题；
4. 哪些状态值得成为 Fish Condition，哪些更适合作为派生中间量。

如果这四件事对齐，再继续做数值标定和 Bake 状态量设计。

# 1. Response 不是只服务于路亚，但这次先集中路亚

不同钓法都要回答一个共同问题：

> 当前这个食物目标，以当前方式呈现给当前状态的鱼，鱼有多愿意出手？

但不同钓法的输入重点不同。

| 钓法 | 更重的输入 | 共同关心 |
|---|---|---|
| 路亚 | 拟饵形态、运动、猎物状态、速度、停顿、贴底/水层等呈现 | 饵 / 猎物选择，鱼当前状态 |
| 台钓 | 饵料成分、味型、混合、物性、雾化/残留、窝点，以及钩饵位置与状态 | 食物选择，鱼当前状态 |
| 浮钓 | 钩饵 / 天然饵选择、水层、漂流与状态；具体玩法也可能涉及味型、混合或窝料 | 食物选择，鱼当前状态 |

因此本轮的范围是：

> **先用路亚把 Response 的评价骨架和策略关系闭合；随后把可复用的 Takeaway 带回台钓和浮钓。**

本轮不尝试把路亚的“猎物运动解释”硬套给台钓 / 浮钓，也不提前解决味型、混饵和打窝聚合。

# 2. 我们想购买的不是更多参数，而是策略翻转

Response 值得复杂化的前提是：鱼情变化能改变玩家不同打法的相对收益。

当前希望购买四个主要策略方向：

| 鱼侧评价轴 | 玩家选择 A | 玩家选择 B | 状态变化后希望发生什么 |
|---|---|---|---|
| 食物价值 / 食性匹配 | 广谱 / 泛用拟饵 | 高匹配 / 专攻拟饵 | 食性越明确，高匹配方案越值得 |
| 追赶状态 | 快速搜索 | 慢速 / finesse | 当前越不适合追，慢速呈现相对越值 |
| 摄食意愿 | 普通自然呈现 | 强攻击诱因 / 反应口 | 摄食意愿越低，普通口越差，合法诱发状态越重要 |
| 警惕度 | 直接 / 强势 | 隐蔽 / 自然 | 警惕越高，暴露和机械感的代价越高 |

可以把四行理解成四个“跷跷板”：

```text
食性匹配
广谱 / 泛用      <────────────>      高匹配 / 专攻
                            食性越明确，右侧越值

追赶状态
快速搜索         <────────────>      慢速 / finesse
                            越不适合追，右侧越值

摄食意愿
普通呈现         <────────────>      强诱因 / 反应口
                            摄食意愿越低，右侧越重要

警惕度
直接 / 强势      <────────────>      隐蔽 / 自然
                            警惕度越高，右侧越值
```

这里不是给玩家四个固定正确答案，而是让鱼情改变各策略的相对收益。

# 3. 快速搜索的收益是什么

这里需要避免一个误解：

```text
快速搜索
≠ 系统额外发更多抽奖机会
```

从姿态颗粒和空间探索角度，更合适的体验解释是：

```text
更快的收线 / 移动
→ 单位时间覆盖更多空间
→ 尝试更多位置、结构、水层或局部条件
→ 更快排除无效区域
→ 更快收敛“鱼在哪、哪里值得继续精钓”的判断
```

因此快速搜索的收益首先是：

> **空间覆盖和探索收敛效率。**

它的代价可能是：

```text
局部停留更短
+ 高速呈现的追赶负担更高
→ 单个局部位置的 Response 质量下降
```

于是形成完整策略：

```text
快速搜索
→ 更快获得区域信息
→ 找到信号
→ 降速 / finesse 深挖
```

鱼的追赶状态越好，快速探索时付出的 Response 代价越小；追赶状态越差，玩家为了获得可靠反馈就需要更慢地搜索。

本轮只对齐这条体验关系，不在 Response 中增加“快速搜索奖励”。

# 4. 为了达到这些策略目标，鱼的评价标准需要细化

为了达到上面的策略性目标，我们需要把鱼对当前拟饵的评价拆细。

第一版的基本逻辑是：

```text
值得出手的理由
  食物价值
+ 攻击诱因

需要承担的代价
- 追赶负担
- 风险顾虑

当前出手要求
- 摄食意愿门槛

        ↓
      出手余量
        ↓
      Response
```

Working 主体：

```text
出手余量
= 食物价值
+ 攻击诱因
- 追赶负担
- 风险顾虑
- 摄食意愿门槛
```

这里的加减不是把真实物理量硬相加，而是各子机制先把结果换算到统一的“出手余量”标尺，再由顶层比较收益、代价和门槛。

第一版坚持：

> **下层负责机制和非线性，顶层只负责竞争。**

例如：

```text
当前追赶状态 × 拟饵速度
→ 追赶负担

警惕度 × 异常暴露
→ 风险顾虑

当前猎物 × 当前猎物状态
→ 攻击诱因

摄食意愿
→ 出手门槛
```

不在顶层继续堆大量交叉项。

# 5. 五个评价项分别回答什么

## 5.1 食物价值：这个目标本身值不值得吃

它主要购买“选什么”的策略。

```text
鱼种 / 当前食性
× 猎物类型 / 大小
→ 食物价值
```

目标是区分 Preferred / Good / Marginal / Poor；明确拒食仍是硬边界，不靠大惩罚模拟。

这条逻辑未来也最容易带回台钓和浮钓，只是那边“食物是什么”的输入会增加成分、味型、混合等维度。

## 5.2 攻击诱因：现在这个猎物状态是否额外促使捕食出手

攻击诱因不是“动作越大越加分”。

正确边界是：

```text
实际呈现
→ 按猎物解释当前状态
→ Fish × Prey × PreyState 评价
→ 攻击诱因
```

候选状态可以包括逃逸样、受伤 / 挣扎样、虚弱停顿等，但第一版只准入少量有策略价值、能低成本识别的状态。

它主要购买：

```text
摄食意愿低
→ 普通呈现过不了线
→ 合法攻击诱因有机会帮助越线
```

领地、防御、烦躁、护巢等非摄食攻击不塞进这条路径。

## 5.3 追赶负担：当前这个速度对这条鱼有多难接受

这一项是当前最值得进一步收敛的地方。

前面曾拆成：

```text
Capacity
→ 客观能调用多少运动能力

Activity
→ 对能力调用的行为容忍
```

但两者从玩家策略上都主要改变：

> **当前应该把拟饵放多快。**

所以第一版可以考虑：

> **上游来源分开，Response 消费端聚合。**

设：

```text
BaseAbility
= 鱼种 / 体型的基础追赶能力

Capacity
= 当前生理能力修正

ActivityCostMultiplier
= 当前对主动追赶负荷的容忍倍率
```

若基础追赶负担近似按相对速度平方增长：

```text
追赶负担
= K
× (拟饵径向远离速度 / (BaseAbility × Capacity))²
× ActivityCostMultiplier
```

则可以等价写成：

```text
追赶负担
= K
× (拟饵径向远离速度 / BaseAbility)²
× 追赶状态倍率

追赶状态倍率
= ActivityCostMultiplier / Capacity²
```

这意味着：

```text
Capacity 下降
→ 同样速度需要调用更高比例的能力

Activity 下降
→ 对同样能力调用更不愿意承担

二者最终
→ 共同提高同一份追赶负担
```

从 Response 和玩家策略看，可以只消费一个派生的“追赶状态倍率”。

### 这不等于把 Capacity 和 Activity 的来源语义删除

如果未来 Capacity 还被搏鱼、逃逸、迁移等多个系统消费，可以继续保留为共享派生状态；Activity 也可以继续有独立上游来源。

但若 Capacity 只服务于这一个追赶 Response，并且能由温度、溶氧等直接算出，则没有必要仅为了“多一个状态量”而 Bake 成一级 Fish Condition。

当前建议：

```text
上游是否保留 Capacity
→ 后续再定

Response 端
→ 优先收成一个追赶状态 / 追赶负担倍率
```

## 5.4 风险顾虑：当前呈现有多容易“露馅”

第一版最低语义：

```text
异常暴露
× 警惕度
→ 风险顾虑
```

希望购买：

```text
低警惕
→ 更直接、更强势的方案可用

高警惕
→ 隐蔽、自然方案相对受益
```

但本轮刻意不闭合完整 Naturalness / 自然度算法。

第一版只需要确认：

- 装备暴露属于这条路径；
- 呈现异常也属于这条路径；
- 具体做到“静态装备代理”“实际呈现结果”还是更深的操作 × 物理耦合，后续按体验价值和实现成本决定。

## 5.5 摄食意愿：现在需要多强的理由才愿意为了食物出手

摄食意愿更适合作为门槛，而不是全局乘数。

```text
摄食意愿高
→ 出手门槛低

摄食意愿低
→ 出手门槛高
```

它不改变食物本身的价值，也不直接放大追赶负担或风险顾虑。

这样可以自然形成：

```text
低摄食意愿
+ 普通呈现
→ 过不了线

低摄食意愿
+ 合法攻击诱因
→ 可能跨线
```

# 6. 三个会议案例

## Case A｜追赶状态：快速搜索还是慢速 finesse

同一拟饵、同一食物价值：

```text
追赶状态好
→ 同样高速产生的追赶负担较低
→ 可以较快搜索，快速收敛鱼位判断

追赶状态差
→ 同样高速的追赶负担明显上升
→ 快速扫过一个有效区域也可能得不到可靠反馈
→ 降速 / finesse 相对受益
```

要对齐的不是“高 Activity 必须快钓”，而是：

> **鱼的当前追赶状态改变快速探索的代价。**

## Case B｜摄食意愿：普通口还是反应口

```text
摄食意愿高
→ 普通 Good / Preferred 食物已经足够
→ 不需要刻意制造强刺激

摄食意愿低
→ 普通呈现可能低于出手门槛
→ 合法的逃逸 / 受伤 / 挣扎等猎物状态提供攻击诱因
→ 有机会跨线
```

但强诱因不是免费按钮：更强动作可能同时增加追赶负担和风险顾虑。

## Case C｜警惕度：直接强势还是隐蔽自然

```text
警惕度低
→ 同样异常暴露带来的风险顾虑低
→ 更直接、更强势的装备和操作方案可用

警惕度高
→ 同样暴露更容易形成风险顾虑
→ 隐蔽、自然方案的相对收益提高
```

本轮只对齐策略方向，不审批完整自然度算法。

# 7. Fish Condition 不应该先按“听起来重要”定数量

Response 先提出消费需求，再反推 Bake 到底需要产出几个鱼侧动态参数。

每个候选状态都要问：

1. Response 中有哪个独立消费职责？
2. 它是否购买了新的玩家策略？
3. 能否由已有输入确定性推导？
4. 是否被多个系统共同消费？
5. 如果删除它，是否真的丢失独立表达能力？

因此要区分：

```text
一级 Fish Condition
→ 需要长期表达、生产、调试的鱼侧动态状态

派生中间量
→ 可以由已有状态 / 环境确定性计算，只服务算法消费
```

Functional Capacity 当前更适合作为“候选派生状态”讨论，而不是预设必有的第四个 Fish Condition。

如果它最终只和 Activity 一起决定拟饵速度容忍，并且没有其它独立消费者，则 Response 端甚至可以只保留一个派生的“追赶状态倍率”。

# 8. 这次会议建议明确对齐什么

## 需要对齐

1. 本轮先集中路亚 Response，之后再把共同骨架带回台钓 / 浮钓；
2. 四个主要策略方向是否成立：
   - 选什么；
   - 搜多快；
   - 普通口还是反应口；
   - 能不能露馅；
3. 是否认可“鱼状态 → Response 评价项 → 玩家两种策略相对收益改变”的设计方式；
4. 是否认可第一版主体：

```text
食物价值
+ 攻击诱因
- 追赶负担
- 风险顾虑
- 摄食意愿门槛
→ 出手余量
```

5. 是否认可 Capacity / Activity 在追赶 Response 端允许聚合成一个派生追赶状态，而不提前决定 Bake 是否分别产出；
6. 是否认可 Fish Condition 数量最后由 Response 与其它消费者反推，而不是先列生物学名词。

# 9. 这次会议刻意不闭合什么

以下问题明确后置，不应阻止本轮对齐：

- 台钓 / 浮钓的味型、混饵、窝料具体聚合算法；
- 完整自然度 / 异常暴露模型；
- 最终 Fish Condition 数量；
- Functional Capacity 是否最终成为独立 Bake 状态；
- 生产数值和最终曲线参数；
- 轨迹预测困难是否值得保留为独立局部成本；
- 非摄食咬击，如护巢、领地、防御、烦躁；
- 完整“打法 → 单位时间最终中鱼效率”模型。

尤其：快速搜索的价值先按“覆盖更多空间、尝试更多条件、更快收敛探索结果”理解；不在 Response 内人为增加搜索奖励。

# 10. 会前必须闭合到什么程度

为了让稿件不自相矛盾，会前只要求四处进一步收紧：

### A. 追赶状态的最小公式

确认是否接受：

```text
追赶状态倍率
= ActivityCostMultiplier / Capacity²
```

或其它等价的单轴聚合方式。

重点是策略排序，不是最终系数。

### B. 攻击诱因第一版准入范围

至少选出 1~3 个具名猎物状态，能支持会议案例；不需要完整状态库。

### C. 风险顾虑最低实现层

确认第一版至少承接装备暴露与呈现异常，但不展开完整 Naturalness。

### D. 三个 worked cases

每个案例只证明：

```text
鱼状态变化
→ 某个评价项变化
→ 玩家两个方案的相对结果发生变化
```

不追求生产数值。

# 11. 一句话会议主旨

> **我们不是在增加一组更复杂的中鱼系数，而是在建立一层把鱼情变化转译成玩家策略变化的 Response：让玩家根据鱼的食性、追赶状态、摄食意愿和警惕程度，改变选饵、搜索速度、刺激方式与隐蔽程度。第一版先用路亚把这个骨架闭合，再反推需要哪些 Fish Conditions，并把可复用的框架带回台钓和浮钓。**
