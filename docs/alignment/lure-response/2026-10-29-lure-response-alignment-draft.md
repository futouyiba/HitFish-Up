# 1. Response 是共同阶段，本轮主要深入路亚的即时呈现

现行术语将 Response 分成两条路径：

```text
Response
├─ 持久响应 Persistent Response
│  → 打窝、补窝等持续生效的玩家行为
│
└─ 姿态响应 Pose Response
   → 当前饵、姿态、位置与即时操作
```

不同钓法都要回答一个共同问题：

> 当前这个食物目标，以当前方式呈现给当前状态的鱼，鱼有多愿意出手？

但不同钓法的输入重点和两条 Response 路径的占比不同。

| 钓法 | 更重的输入 | Response 重心 | 共同关心 |
|---|---|---|---|
| 路亚 | 拟饵形态、运动、猎物状态、速度、停顿、贴底 / 水层等呈现 | **即时姿态响应更重** | 饵 / 猎物选择，鱼当前状态 |
| 台钓 | 饵料成分、味型、混合、物性、雾化 / 残留、窝点，以及钩饵位置与状态 | 即时钩饵 + **持久窝点响应** | 食物选择，鱼当前状态 |
| 浮钓 | 钩饵 / 天然饵、水层、漂流与状态；具体玩法也可能涉及味型、混合或窝料 | 即时呈现为主，部分玩法有持久响应 | 食物选择，鱼当前状态 |

因此本轮范围是：

> **先用路亚闭合“即时呈现如何被鱼评价”的 Response 骨架；随后把可复用的评价原则带回台钓和浮钓。**

复用的是：

```text
原始玩家输入
→ 先解析成有领域语义的状态
→ 再由鱼侧评价
→ 最后进入 Response
```

不是把路亚公式复制到台钓 / 浮钓。

Groundbait Candidate 已采用同一原则：Food、Flavor、Particle Size、Physical Release 分别拥有自己的因果职责，不把配方字段直接做成四个并列 Bonus；持续窝点影响优先进入 Persistent Response 相关状态，而不是直接改 Fish Condition。

# 2. 先定体验目标：我们要购买四种策略差异

Response 值得复杂化的前提是：条件变化能够改变玩家不同打法的相对收益。

这里的四行是**玩家策略轴**，不是四个 Fish Condition，也不是要求一一对应。

| 玩家策略轴 | 玩家选择 A | 玩家选择 B | 主要输入 / Response 评价 | 希望发生什么 |
|---|---|---|---|---|
| **选什么** | 广谱 / 泛用拟饵 | 高匹配 / 专攻拟饵 | 基础食性 + **食性偏移** + 当前猎物 → 食物价值 | 当前食性越明确，高匹配方案越值得 |
| **搜多快** | 快速搜索 | 慢速 / finesse | **活跃度** + 基础追赶能力 + 必要能力修正 → 追赶负担 | 当前越不适合追，高速代价越大 |
| **普通口还是反应口** | 普通自然呈现 | 强攻击诱因 / 反应口 | **摄食动机** → 门槛；猎物状态 → 攻击诱因 | 摄食动机越低，普通口越弱，合法诱因边际价值越高 |
| **能不能露馅** | 直接 / 强势 | 隐蔽 / 自然 | **警戒度** + 异常暴露 → 风险顾虑 | 警戒度越高，暴露和机械感的代价越高 |

体验验收不是“系数有变化”就算完成。

在典型的两端条件下，玩家应当能从反馈中学到：

> **这时换另一种打法明显更合适。**

中间状态允许两边都可用；两端至少要出现清楚的相对优势变化。当前先对齐排序和差异等级，不承诺最终百分比。

### 2.1 四个策略轴的两端目标

| 策略轴 | 条件一端 | 希望看到 | 条件另一端 | 希望看到 | 护栏 |
|---|---|---|---|---|---|
| 选什么 | 偏好不强 / 广适 | 泛用饵保持竞争力；专攻饵不是必选 | 当前明确偏好某类猎物 | 高匹配饵明显更值得，足以让玩家考虑换饵 | 不能把泛用饵整体做废；Reject 仍是硬边界 |
| 搜多快 | 适合追 | 快搜的局部 Response 仍可接受，可以用覆盖换信息 | 不适合追 | 高速呈现明显吃亏；已知鱼区慢速 / finesse 成为更优选择 | 适合追不等于快钓单次 Response 必须高于 finesse |
| 普通口 / 反应口 | 摄食动机高 | 普通优质呈现已经足够，强刺激只是可选 | 摄食动机低 | 普通口明显变弱；合法攻击诱因能把部分边缘机会救回可用区间 | 强刺激不能成为万能按钮，也不能救活 Reject |
| 能不能露馅 | 警戒度低 | 直接、强势、相对暴露的方案仍可用 | 警戒度高 | 暴露 / 机械感产生明显损失；隐蔽自然值得玩家付出成本 | 不要求所有暴露直接硬失败 |

如果条件从一端走到另一端，只让同一打法从 1.00 变成 0.95，而合理策略没有发生变化，这个机制就还没有购买到足够的玩法价值。这里的数字只是“微差”的示意，不是生产目标。

# 3. 快速搜索：收益在探索，Response 不额外发奖励

需要避免两个误解：

```text
快速搜索
≠ Response 内直接获得额外奖励
≠ Opportunity 与速度 / 位置无关
```

从玩家体验看，更快的收线 / 移动可以：

```text
单位时间覆盖更多空间
→ 尝试更多位置、结构、水层或局部条件
→ 更快排除无效区域
→ 更快收敛“鱼在哪、哪里值得继续精钓”的判断
```

因此快速搜索的主要收益是：

> **空间覆盖和探索收敛效率。**

但单个姿态颗粒仍然同时有两部分：

```text
Response
→ conditional response C
→ 这次局部呈现，鱼有多愿意出手

Spatial / Opportunity
→ native opportunity support L
→ 这个姿态颗粒实际提供了多少有效局部机会

Candidate join
→ q = L × C
```

`L × C` 只乘一次。时间、停留、穿越有效区域、覆盖范围不进入 DecisionMargin，也不在 Candidate 后段再次乘同一份 Response。

快速呈现的局部代价可以来自：

- 更高的追赶负担；
- 更明显的暴露带来的风险顾虑；
- 姿态颗粒在有效空间中的 `L` 变化。

于是形成策略循环：

```text
快速搜索
→ 更快获得区域信息
→ 找到信号
→ 降速 / finesse 深挖
```

本轮不在 Response 中增加“快速搜索奖励”。

# 4. 为了达到这些策略目标，鱼的评价标准需要细化

基本逻辑是：

```text
值得出手的理由
  食物价值
+ 攻击诱因

需要承担的代价
- 追赶负担
- 风险顾虑

当前出手要求
- 摄食动机对应的出手门槛

        ↓
      出手余量
        ↓
      Response C
```

第一版 Working 主体：

```text
出手余量
= 食物价值
+ 攻击诱因
- 追赶负担
- 风险顾虑
- 摄食动机门槛
```

各子机制先把结果换算到统一的“出手余量”标尺，顶层只做竞争。

> **下层负责机制和非线性，顶层只负责竞争。**

第一版主体**不包含 Prediction / 轨迹预测困难**。Prediction 只保留为待证明的局部代价或诊断候选；只有在控制其它因素后仍能证明独立、稳定的策略排序，才重新打开是否进入主体的问题。

# 5. 五个评价项分别回答什么

## 5.1 食物价值：这个目标本身值不值得吃

```text
基础食性
+ 当前食性偏移 Diet Shift
+ 猎物类型 / 大小
→ 食物价值
```

它主要购买“选什么”的策略。目标是区分 Preferred / Good / Marginal / Poor；Reject 是连续轴外的硬边界。

## 5.2 攻击诱因：当前猎物状态是否额外促使捕食出手

```text
实际呈现
→ 按猎物解释当前状态
→ Fish × Prey × PreyState 评价
→ 攻击诱因
```

攻击诱因不是“动作越大越加分”。第一版只准入少量有策略价值、能低成本识别的状态，例如逃逸样、受伤 / 挣扎样、虚弱停顿等。

它主要购买：

```text
摄食动机低
→ 普通呈现过不了线
→ 合法攻击诱因有机会帮助越线
```

领地、防御、烦躁、护巢等非摄食攻击不塞进这条路径。

## 5.3 追赶负担：当前这个速度对这条鱼有多难接受

现行 Fish Condition 中有 **活跃度 Activity**。追赶能力还来自鱼种、体型，以及未来如果确有必要的“当前可用运动能力修正”。

这里不恢复一个正式的 `FunctionalCapacity` Fish Condition。

`90048b35` 的 joint baseline 是：

```text
q = horizontal lure speed relative to water / InterceptSpeedLimit
u_close(theta) = max(0, q * cos(theta))

ClosingCost(theta)
= K_close × u_close(theta)^2 × ActivityCostMultiplier(Activity)
```

其中：

- `InterceptSpeedLimit` 表达鱼种 / size cohort 的基础追赶能力；
- Activity 只调制 soft Closing cost，不修改物理能力上限；
- `u_close >= 1` 不 hard-zero；
- 没有追赶负荷时，低 Activity 不应凭空降低 Response。

### CapacityModifier：本轮新增 Working Hypothesis

如果当前可用运动能力确实需要随温度、溶氧等动态修正，可以讨论一个派生中间量：

```text
环境 / 生理输入
→ CapacityModifier（OPEN，未确认需要）
```

若它存在，可以在追赶消费端与 Activity 汇合。例如：

```text
追赶状态倍率
= ActivityCostMultiplier / CapacityModifier²
```

但这不表示：

- 已经确认需要 `CapacityModifier`；
- `CapacityModifier` 是第五个 Fish Condition；
- `90048b35` 已经认可这条新公式。

### 垂直运动的第一版边界

第一版已经有明确分工：

```text
Closing
→ 只处理水平径向分离

垂直运动
→ 不硬塞进 Closing
→ 通过“处在可交互垂直区域多久”影响 Opportunity 的 L
```

仍未闭合的是：垂直可交互窗口的正式 owner、具体数据形态和 reducer 接口，而不是“要不要把垂直速度塞进 Closing”。

## 5.4 风险顾虑：当前呈现有多容易“露馅”

最低语义：

```text
异常暴露
× 警戒度 Wariness
→ 风险顾虑
```

希望购买：低警戒时直接 / 强势方案仍可用；高警戒时隐蔽 / 自然方案相对受益。

本轮不闭合完整 Naturalness。`SuspicionLoad` 只能来自具名、独立拥有的风险线索；高速、频繁转向、低 prey support 不能自动生成匿名 Suspicion。

## 5.5 摄食动机：现在需要多强的理由才愿意为了食物出手

摄食动机 `Feeding Motivation` 更适合作为门槛，而不是全局乘数。

```text
摄食动机高 → 出手门槛低
摄食动机低 → 出手门槛高
```

它不改变食物本身的价值，也不直接放大追赶负担或风险顾虑。

# 6. Fish Condition 与策略轴不是一回事

main 当前术语将 **鱼况 Fish Condition** 定义为鱼侧动态参数，当前使用：

```text
活跃度 Activity
摄食动机 Feeding Motivation
食性偏移 Diet Shift
警戒度 Wariness
```

这四个状态不是“四条玩家策略轴”的另一种叫法。

```text
鱼侧动态参数 / 静态配置 / 当前呈现
        ↓
Response 子机制求值
        ↓
食物价值 / 攻击诱因 / 追赶负担 / 风险顾虑 / 门槛
        ↓
玩家策略的相对收益发生变化
```

| 上游输入 | 主要被哪个 Response 子机制消费 | 主要购买的策略 |
|---|---|---|
| 基础食性 + 食性偏移 | 食物价值 | 选什么 |
| 活跃度 + 基础追赶能力 + 可选能力修正 | 追赶负担 | 搜多快 |
| 摄食动机 | 出手门槛 | 普通口是否够用 |
| 猎物状态 | 攻击诱因 | 是否值得制造反应口 |
| 警戒度 + 异常暴露 | 风险顾虑 | 能不能露馅 |

本次会议不重新发明 Fish Condition 名单。后续专门讨论 Bake 时，再检查现行状态如何生成、是否存在可派生量以及是否有重复职责。

# 7. 三个会议案例

## Case A｜追赶条件：快速搜索还是慢速 finesse

同一拟饵、同一食物价值：

```text
当前适合追
→ 同样高速产生的追赶负担较低
→ 可以较快搜索，更快收敛鱼位判断

当前不适合追
→ 同样高速的追赶负担明显上升
→ 快速扫过一个有效区域也可能得不到可靠反馈
→ 降速 / finesse 相对受益
```

护栏：

```text
ClosingLoad ≈ 0
+ Activity 低
→ Activity 不应凭空降低 Response
```

也就是说，Activity 购买的是“追赶要求出现时，玩家应该把饵放多快”，不是泛化的“鱼懒，所以什么都不咬”。

## Case B｜摄食动机：普通口还是反应口

```text
摄食动机高
→ 普通 Good / Preferred 食物已经足够
→ 不需要刻意制造强刺激

摄食动机低
→ 普通呈现可能低于出手门槛
→ 合法的逃逸 / 受伤 / 挣扎等猎物状态提供攻击诱因
→ 有机会跨线
```

强诱因不是免费按钮，但它的代价必须来自已有机制：

- 更高的 Closing；
- 更明显暴露带来的 Risk；
- Opportunity 的 `L` 变化。

**不额外发明统一的 `StrongStimulusPenalty`。**

## Case C｜警戒度：直接强势还是隐蔽自然

```text
警戒度低
→ 同样异常暴露带来的风险顾虑低
→ 更直接、更强势的装备和操作方案可用

警戒度高
→ 同样暴露更容易形成风险顾虑
→ 隐蔽、自然方案的相对收益提高
```

本轮只对齐策略方向，不审批完整自然度算法。

# 8. 台钓 / 浮钓随后带走什么 Takeaway

不是带走路亚的具体公式，而是带走三条原则：

1. **先解析，再评价。** 原始配方、轨迹、动作、味型百分比都不应直接成为最终 Response Bonus。
2. **每个机制拥有自己的因果职责。** 同一事实不在多个 Response 路径重复结算。
3. **持续世界状态与即时呈现分开。** 打窝 / 补窝等持续影响优先进入 Persistent Response 相关状态；当前钩饵 / 拟饵呈现进入即时 Response。

Groundbait 当前 Candidate 已给出一个可复用范式：

```text
Recipe Facts
→ Physical Release
→ Feeding Place State(place, t)
→ Feeding Event / 可摄食机会
→ Response 的候选输入
```

窝料产生的状态不能为了方便直接写成 `Feeding Motivation +X` 或 `Activity +X`。如果未来持续摄食确实改变 Fish Condition，必须单独定义时间、记忆、衰减与状态更新机制。

# 10. 这次会议刻意不闭合什么

以下问题后置，不应阻止本轮对齐：

- 台钓 / 浮钓的味型、混饵、窝料具体聚合算法；
- 完整自然度 / 异常暴露模型；
- 现行 Fish Condition 的 Bake / 动态生成算法；
- 是否需要额外的 `CapacityModifier`；
- 生产数值和最终曲线参数；
- Prediction 是否未来凭独立策略证据重新进入主体；
- Opportunity / Spatial 侧 `L` 的正式 owner、垂直可交互窗口的数据形态与 reducer；
- 真实 encounter geometry、reaction window、strike reach；
- 非摄食咬击，如护巢、领地、防御、烦躁；
- 完整“打法 → 单位时间最终中鱼效率”模型。

已经不再开放的问题：

- 第一版 DecisionMargin 主体**不含 Prediction**；
- 垂直运动**不塞进 Closing**，第一版通过 Opportunity 的垂直可交互窗口影响 `L`；
- Response 内不增加搜索奖励。

# 11. 会前还需要闭合到什么程度

为了让稿件不自相矛盾，会前只要求三处进一步收紧：

### A. 追赶负担的最低实现

确认第一版是否沿用 joint baseline：

```text
基础追赶能力
+ 活跃度
+ 当前水平径向运动要求
→ ClosingCost
```

`CapacityModifier` 作为新增 Working Hypothesis 单独评估，不要求会前决定长期存在。

### B. 攻击诱因第一版准入范围

至少选出 1~3 个具名猎物状态，能支持会议案例；不需要完整状态库。

### C. 风险顾虑最低实现层

确认第一版至少承接装备暴露与呈现异常，但不展开完整 Naturalness。

三处都只需要闭合到可以做 worked cases 和策略回归，不需要生产数值。

# 12. 一句话会议主旨

> **我们先用路亚回答一个核心问题：当前的鱼况、食性和拟饵呈现，为什么会让不同玩家打法的相对收益发生明显变化。Response 把这些输入转成食物价值、攻击诱因、追赶负担、风险顾虑和出手门槛，形成单次局部响应 `C`；Opportunity 侧提供该姿态颗粒的有效机会 `L`，再通过一次 `L × C` 接入 Candidate。第一版先让“选什么、搜多快、要不要刺激、能不能露馅”稳定成立，再闭合 Fish Condition 的生成逻辑，并把同一套分层原则带回台钓和浮钓。**
