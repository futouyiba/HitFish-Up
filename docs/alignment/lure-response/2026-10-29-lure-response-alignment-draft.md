## 0. 这次会议要回答什么

这次不是评审一套完整鱼类行为模拟，也不是审批所有数值。

希望对齐四件事：

1. Response 的共同问题是什么，本轮为什么主要深入路亚；
2. 我们希望不同鱼况和食性条件带来哪些可学习的玩家策略变化；
3. 为了得到这些策略变化，Response 需要拆成哪些独立评价问题；
4. 哪些量是现行 Fish Condition，哪些只是 Response 内的派生中间量。

如果这四件事对齐，再继续做数值标定和 Fish Condition / Bake 生成逻辑。

# 1. Response 是共同阶段，本轮主要深入路亚的即时呈现

现行术语将 Response 分成两条路径：

```text
Response
├─ 持久响应 Persistent Response
│  → 打窝、补窝等持续生效的玩家行为
│
└─ 姿态响应 Pose Response
   → 当前饵、姿态、位置与即时操作
```

不同钓法都要回答一个共同问题：

> 当前这个食物目标，以当前方式呈现给当前状态的鱼，鱼有多愿意出手？

但不同钓法的输入重点和两条 Response 路径的占比不同。

| 钓法 | 更重的输入 | Response 重心 | 共同关心 |
|---|---|---|---|
| 路亚 | 拟饵形态、运动、猎物状态、速度、停顿、贴底 / 水层等呈现 | **即时姿态响应更重** | 饵 / 猎物选择，鱼当前状态 |
| 台钓 | 饵料成分、味型、混合、物性、雾化 / 残留、窝点，以及钩饵位置与状态 | 即时钩饵 + **持久窝点响应** | 食物选择，鱼当前状态 |
| 浮钓 | 钩饵 / 天然饵、水层、漂流与状态；具体玩法也可能涉及味型、混合或窝料 | 即时呈现为主，部分玩法有持久响应 | 食物选择，鱼当前状态 |

因此本轮范围是：

> **先用路亚闭合“即时呈现如何被鱼评价”的 Response 骨架；随后把可复用的评价原则带回台钓和浮钓。**

这里要复用的是：

```text
原始玩家输入
→ 先解析成有领域语义的状态
→ 再由鱼侧评价
→ 最后进入 Response
```

不是把路亚公式直接复制到台钓 / 浮钓。

main 最新 Groundbait Candidate 也采用同一原则：Food、Flavor、Particle Size、Physical Release 分别拥有自己的因果职责，不把配方原始字段直接做成四个并列 Bonus；窝料持续影响优先落在 Persistent Response 相关状态，而不是直接改 Fish Condition。

# 2. 先定体验目标：我们要购买四种策略差异

Response 值得复杂化的前提是：条件变化能够改变玩家不同打法的相对收益。

这里的四行是**玩家策略轴**，不是四个 Fish Condition，也不是要求一一对应。

| 玩家策略轴 | 玩家选择 A | 玩家选择 B | 主要输入 / Response 评价 | 希望发生什么 |
|---|---|---|---|---|
| **选什么** | 广谱 / 泛用拟饵 | 高匹配 / 专攻拟饵 | 基础食性 + **食性偏移** + 当前猎物 → 食物价值 | 当前食性越明确，高匹配方案越值得 |
| **搜多快** | 快速搜索 | 慢速 / finesse | **活跃度** + 基础追赶能力 + 必要的能力修正 → 追赶负担 | 当前越不适合追，高速代价越大 |
| **普通口还是反应口** | 普通自然呈现 | 强攻击诱因 / 反应口 | **摄食动机** → 门槛；猎物状态 → 攻击诱因 | 摄食动机越低，普通口越弱，合法诱因边际价值越高 |
| **能不能露馅** | 直接 / 强势 | 隐蔽 / 自然 | **警戒度** + 异常暴露 → 风险顾虑 | 警戒度越高，暴露和机械感的代价越高 |

体验验收不是“系数有变化”就算完成。

在典型的两端条件下，玩家应当能从反馈中学到：

> **这时换另一种打法明显更合适。**

中间状态允许两边都可用；两端至少要出现清楚的相对优势变化。当前先对齐排序和差异等级，不承诺最终百分比。

### 2.1 四个策略轴的两端目标

| 策略轴 | 条件一端 | 希望看到 | 条件另一端 | 希望看到 | 护栏 |
|---|---|---|---|---|---|
| 选什么 | 偏好不强 / 广适 | 泛用饵保持竞争力；专攻饵不是必选 | 当前明确偏好某类猎物 | 高匹配饵明显更值得，足以让玩家考虑换饵 | 不能把泛用饵整体做废；Reject 仍是硬边界 |
| 搜多快 | 适合追 | 快搜的局部 Response 仍可接受，可以用覆盖换信息 | 不适合追 | 高速呈现明显吃亏；已知鱼区慢速 / finesse 成为更优选择 | 适合追不等于快钓单次 Response 必须高于 finesse |
| 普通口 / 反应口 | 摄食动机高 | 普通优质呈现已经足够，强刺激只是可选 | 摄食动机低 | 普通口明显变弱；合法攻击诱因能把部分边缘机会救回可用区间 | 强刺激不能成为万能按钮，也不能救活 Reject |
| 能不能露馅 | 警戒度低 | 直接、强势、相对暴露的方案仍可用 | 警戒度高 | 暴露 / 机械感产生明显损失；隐蔽自然值得玩家付出成本 | 不要求所有暴露直接硬失败 |

如果条件从一端走到另一端，只让同一打法从 1.00 变成 0.95，而合理策略没有发生变化，这个机制就还没有购买到足够的玩法价值。这里的数字只是“微差”的示意，不是生产目标。

# 3. 快速搜索的收益：空间覆盖与探索收敛

需要避免一个误解：

```text
快速搜索
≠ 系统额外发更多抽奖机会
```

从姿态颗粒和空间探索角度，更合适的体验解释是：

```text
更快的收线 / 移动
→ 单位时间覆盖更多空间
→ 尝试更多位置、结构、水层或局部条件
→ 更快排除无效区域
→ 更快收敛“鱼在哪、哪里值得继续精钓”的判断
```

因此快速搜索的收益首先是：

> **空间覆盖和探索收敛效率。**

代价则可能来自：

```text
局部停留更短
+ 高速呈现的追赶负担更高
→ 单个局部位置的 Response 质量下降
```

于是形成策略循环：

```text
快速搜索
→ 更快获得区域信息
→ 找到信号
→ 降速 / finesse 深挖
```

鱼当前越适合追，快速探索时付出的 Response 代价越小；越不适合追，玩家为了获得可靠反馈就需要更慢地搜索。

本轮只对齐这条体验关系，不在 Response 中增加“快速搜索奖励”。

# 4. 为了达到这些策略目标，鱼的评价标准需要细化

基本逻辑是：

```text
值得出手的理由
  食物价值
+ 攻击诱因

需要承担的代价
- 追赶负担
- 风险顾虑

当前出手要求
- 摄食动机对应的出手门槛

        ↓
      出手余量
        ↓
      Response
```

Working 主体：

```text
出手余量
= 食物价值
+ 攻击诱因
- 追赶负担
- 风险顾虑
- 摄食动机门槛
```

这里的加减不是把真实物理量硬相加，而是各子机制先把结果换算到统一的“出手余量”标尺，再由顶层比较收益、代价和门槛。

第一版坚持：

> **下层负责机制和非线性，顶层只负责竞争。**

例如：

```text
当前运动要求
+ 活跃度
+ 基础追赶能力 / 必要能力修正
→ 追赶负担

警戒度 × 异常暴露
→ 风险顾虑

当前猎物 × 当前猎物状态
→ 攻击诱因

摄食动机
→ 出手门槛
```

不在顶层继续堆大量交叉项。

# 5. 五个评价项分别回答什么

## 5.1 食物价值：这个目标本身值不值得吃

它主要购买“选什么”的策略。

```text
基础食性
+ 当前食性偏移 Diet Shift
+ 猎物类型 / 大小
→ 食物价值
```

目标是区分 Preferred / Good / Marginal / Poor；明确拒食仍是硬边界，不靠大惩罚模拟。

这条评价原则未来可以带回台钓和浮钓，但那边“食物是什么”的解析方式不同。Groundbait 最新 Candidate 已明确：Food、Flavor、Particle Size、Physical Release 不应先压成一个原始 RecipeFit，再直接给 Response 加分。

## 5.2 攻击诱因：当前猎物状态是否额外促使捕食出手

攻击诱因不是“动作越大越加分”。

正确边界是：

```text
实际呈现
→ 按猎物解释当前状态
→ Fish × Prey × PreyState 评价
→ 攻击诱因
```

候选状态可以包括逃逸样、受伤 / 挣扎样、虚弱停顿等，但第一版只准入少量有策略价值、能低成本识别的状态。

它主要购买：

```text
摄食动机低
→ 普通呈现过不了线
→ 合法攻击诱因有机会帮助越线
```

领地、防御、烦躁、护巢等非摄食攻击不塞进这条路径。

## 5.3 追赶负担：当前这个速度对这条鱼有多难接受

现行 Fish Condition 中有 **活跃度 Activity**。同时，真实追赶能力还来自鱼种、体型，以及未来如果确有必要的“当前可用运动能力修正”。

这里不恢复一个正式的 `FunctionalCapacity` Fish Condition。

第一版只保留一个 Working 问题：

> **如果当前可用运动能力确实需要动态修正，它是否应当作为可直接计算的派生中间量，与活跃度一起在 Response 消费端汇合？**

概念上可以写成：

```text
鱼种 / 体型
→ BaseAbility 基础追赶能力

环境 / 生理输入
→ CapacityModifier 可用运动能力修正（OPEN，未确认需要）

活跃度 Activity
→ ActivityCostMultiplier 主动追赶负担倍率
```

若基础追赶负担近似按相对速度平方增长，一个 Working 表达可以是：

```text
追赶负担
= K
× (拟饵径向远离速度 / (BaseAbility × CapacityModifier))²
× ActivityCostMultiplier
```

等价整理为：

```text
追赶负担
= K
× (拟饵径向远离速度 / BaseAbility)²
× 追赶状态倍率

追赶状态倍率
= ActivityCostMultiplier / CapacityModifier²
```

这只说明：**如果两类影响都存在，它们可以在追赶消费端聚合成一个玩家可感知的速度轴。**

它不表示：

- 已经确认需要 `CapacityModifier`；
- `CapacityModifier` 是第五个 Fish Condition；
- Activity 与能力来源在上游必须合并。

若能力修正只服务这一处且可由温度、溶氧等直接计算，它更适合作为派生中间量；若以后刺鱼、搏鱼、逃逸、迁移等多个系统都需要同一动态能力状态，再讨论是否提升其持久化地位。

另外，当前追赶算法主要围绕**水平径向分离**验证。垂直抽停、快速上提 / 下落、vertical jigging 等垂直主导呈现的适用边界，本轮刻意不闭合。

## 5.4 风险顾虑：当前呈现有多容易“露馅”

第一版最低语义：

```text
异常暴露
× 警戒度 Wariness
→ 风险顾虑
```

希望购买：

```text
低警戒度
→ 更直接、更强势的方案可用

高警戒度
→ 隐蔽、自然方案相对受益
```

但本轮刻意不闭合完整 Naturalness / 自然度算法。

第一版只需要确认：

- 装备暴露属于这条路径；
- 呈现异常也属于这条路径；
- 具体做到“静态装备代理”“实际呈现结果”还是更深的操作 × 物理耦合，后续按体验价值和实现成本决定。

## 5.5 摄食动机：现在需要多强的理由才愿意为了食物出手

摄食动机 `Feeding Motivation` 更适合作为门槛，而不是全局乘数。

```text
摄食动机高
→ 出手门槛低

摄食动机低
→ 出手门槛高
```

它不改变食物本身的价值，也不直接放大追赶负担或风险顾虑。

这样可以自然形成：

```text
低摄食动机
+ 普通呈现
→ 过不了线

低摄食动机
+ 合法攻击诱因
→ 可能跨线
```

# 6. Fish Condition 与策略轴不是一回事

main 当前术语将 **鱼况 Fish Condition** 定义为鱼侧动态参数，当前使用：

```text
活跃度 Activity
摄食动机 Feeding Motivation
食性偏移 Diet Shift
警戒度 Wariness
```

这四个状态不是“四条玩家策略轴”的另一种叫法。

更准确的层级是：

```text
鱼侧动态参数 / 静态配置 / 当前呈现
        ↓
Response 子机制求值
        ↓
食物价值 / 攻击诱因 / 追赶负担 / 风险顾虑 / 门槛
        ↓
玩家策略的相对收益发生变化
```

具体映射：

| 上游输入 | 主要被哪个 Response 子机制消费 | 主要购买的策略 |
|---|---|---|
| 基础食性 + 食性偏移 | 食物价值 | 选什么 |
| 活跃度 + 基础追赶能力 + 必要能力修正 | 追赶负担 | 搜多快 |
| 摄食动机 | 出手门槛 | 普通口是否够用 |
| 猎物状态 | 攻击诱因 | 是否值得制造反应口 |
| 警戒度 + 异常暴露 | 风险顾虑 | 能不能露馅 |

因此本次会议**不重新发明一套 Fish Condition 名单**。现行四个鱼况继续作为已存在的上游语义；后续专门讨论 Bake 时，再检查它们各自如何生成、是否存在可派生量以及是否有重复职责。

# 7. 三个会议案例

## Case A｜追赶条件：快速搜索还是慢速 finesse

同一拟饵、同一食物价值：

```text
当前适合追
→ 同样高速产生的追赶负担较低
→ 可以较快搜索，更快收敛鱼位判断

当前不适合追
→ 同样高速的追赶负担明显上升
→ 快速扫过一个有效区域也可能得不到可靠反馈
→ 降速 / finesse 相对受益
```

要对齐的不是“高 Activity 必须快钓”，而是：

> **鱼当前追赶条件改变快速探索的代价。**

## Case B｜摄食动机：普通口还是反应口

```text
摄食动机高
→ 普通 Good / Preferred 食物已经足够
→ 不需要刻意制造强刺激

摄食动机低
→ 普通呈现可能低于出手门槛
→ 合法的逃逸 / 受伤 / 挣扎等猎物状态提供攻击诱因
→ 有机会跨线
```

但强诱因不是免费按钮：更强动作可能同时增加追赶负担和风险顾虑。

## Case C｜警戒度：直接强势还是隐蔽自然

```text
警戒度低
→ 同样异常暴露带来的风险顾虑低
→ 更直接、更强势的装备和操作方案可用

警戒度高
→ 同样暴露更容易形成风险顾虑
→ 隐蔽、自然方案的相对收益提高
```

本轮只对齐策略方向，不审批完整自然度算法。

# 8. 台钓 / 浮钓随后带走什么 Takeaway

不是带走路亚的具体公式，而是带走三条原则：

1. **先解析，再评价。** 原始配方、轨迹、动作、味型百分比都不应直接成为最终 Response Bonus。
2. **每个机制拥有自己的因果职责。** 同一事实不在多个 Response 路径重复结算。
3. **持续世界状态与即时呈现分开。** 打窝 / 补窝等持续影响优先进入 Persistent Response 相关状态；当前钩饵 / 拟饵呈现进入即时 Response。

Groundbait 当前 Candidate 已给出一个可复用范式：

```text
Recipe Facts
→ Physical Release
→ Feeding Place State(place, t)
→ Feeding Event / 可摄食机会
→ Response 的候选输入
```

而不是：

```text
Food + Flavor + Particle + Physical
→ 直接得到一个万能 Recipe Bonus
```

同样，窝料产生的状态不能为了方便直接写成 `Feeding Motivation +X` 或 `Activity +X`。如果未来持续摄食确实改变 Fish Condition，必须单独定义时间、记忆、衰减与状态更新机制。

# 9. 这次会议需要对齐什么

1. 本轮主要深入路亚即时 Response；持久 Response 和台钓 / 浮钓机制后续承接；
2. 四个玩家策略方向是否成立：
   - 选什么；
   - 搜多快；
   - 普通口还是反应口；
   - 能不能露馅；
3. 每个策略轴两端要达到怎样的可感知差异和排序翻转；
4. 是否认可“上游状态 / 呈现 → Response 评价项 → 玩家策略翻转”的设计方式；
5. 是否认可第一版主体：

```text
食物价值
+ 攻击诱因
- 追赶负担
- 风险顾虑
- 摄食动机门槛
→ 出手余量
```

6. 是否允许在追赶消费端，把活跃度与“若确有必要的可用运动能力修正”聚合成一个追赶负担结果，而不把能力修正预设成第五个 Fish Condition；
7. 是否认可台钓 / 浮钓复用的是 Response 分层原则，而不是路亚具体公式。

# 10. 这次会议刻意不闭合什么

以下问题明确后置，不应阻止本轮对齐：

- 台钓 / 浮钓的味型、混饵、窝料具体聚合算法；
- 完整自然度 / 异常暴露模型；
- 现行 Fish Condition 的 Bake / 动态生成算法；
- 是否需要额外的可用运动能力派生量；
- 生产数值和最终曲线参数；
- 轨迹预测困难是否值得保留为独立局部成本；
- 垂直主导呈现的完整追赶算法与真实截击几何；
- 非摄食咬击，如护巢、领地、防御、烦躁；
- 完整“打法 → 单位时间最终中鱼效率”模型。

尤其：快速搜索的价值先按“覆盖更多空间、尝试更多条件、更快收敛探索结果”理解；不在 Response 内人为增加搜索奖励。

# 11. 会前还需要闭合到什么程度

为了让稿件不自相矛盾，会前只要求三处进一步收紧：

### A. 追赶负担的最低实现

明确第一版是否只需要：

```text
基础追赶能力
+ 活跃度
+ 可选的派生能力修正
+ 当前水平径向运动要求
→ 追赶负担
```

不要求先决定 `CapacityModifier` 是否长期存在。

### B. 攻击诱因第一版准入范围

至少选出 1~3 个具名猎物状态，能支持会议案例；不需要完整状态库。

### C. 风险顾虑最低实现层

确认第一版至少承接装备暴露与呈现异常，但不展开完整 Naturalness。

三处都只需要闭合到可以做 worked cases 和策略回归，不需要生产数值。

# 12. 一句话会议主旨

> **我们先用路亚回答一个核心问题：当前的鱼况、食性和拟饵呈现，为什么会让不同玩家打法的相对收益发生明显变化。Response 负责把这些上游输入转成“食物价值、攻击诱因、追赶负担、风险顾虑和出手门槛”，再形成一次出手评价。第一版先让“选什么、搜多快、要不要刺激、能不能露馅”稳定成立；随后再闭合 Fish Condition 的生成逻辑，并把同一套分层原则带回台钓和浮钓。**
