# 0. 先讲 4 个钓鱼策略故事

我们不是为了做一个“更像真实鱼脑”的模型而增加复杂度。响应（Response）值得存在，是因为它要让玩家在不同鱼情、不同饵和不同操作下，真的换策略。

## 故事一：今天它到底想吃什么？

玩家手里有两类方案：

- 一个比较泛用，很多鱼都能吃，但不是任何一种猎物的极致模仿；
- 一个明显在模仿当前鱼正在追的猎物，例如小鱼、小龙虾或蛙。

当鱼的当前食性没有明显偏转时，泛用饵应该仍有竞争力；当鱼明显偏向某类猎物时，高匹配方案应该明显更值得换上去。

这个故事要求系统回答：

```text
这个拟饵现在像什么猎物？
×
这条鱼当前有多想吃这种猎物？
→ 食物价值
```

它最终购买的是玩家策略：**换不换饵、换成什么饵。**

## 故事二：现在该快搜，还是慢下来精钓？

玩家还不知道鱼在哪时，会想快速覆盖更多水域；一旦已经知道鱼区，或者当前鱼不适合追高速目标，就应该有理由降速、停顿、精细操作。

我们希望：

- 鱼当前适合追时，快速搜索的局部响应仍可接受，玩家可以用覆盖换信息；
- 鱼当前不适合追时，高速呈现明显吃亏，慢速 / 精细慢钓（finesse）方案更值得。

这个故事要求系统回答：

```text
当前拟饵跑得多快？
鱼种 × 体型档的基础追赶能力是多少？
当前活跃度让它愿意承担多少追赶负担？
→ 追赶负担
```

快速搜索本身不获得额外“搜索奖励”。它的收益来自真的覆盖了更多空间，由机会量（Opportunity）承接。

它最终购买的是玩家策略：**什么时候快搜，什么时候降速。**

## 故事三：鱼不开口时，反应口能不能把它“激”出来？

有时鱼并不积极摄食。一个普通、自然、很合理的呈现可能仍然缺少“现在就出手”的理由。

这时某些猎物状态，例如突然逃窜，可能额外促发捕食动作，让一部分原本处在边缘的机会重新进入可用区间。

但我们不希望得到：

> 抽得越乱、动作越多，奖励越高。

所以要先区分：

```text
游得更像猎物
→ 提高猎物表达支持度

猎物当前处于逃逸 / 脆弱等状态
→ 才可能形成攻击诱因
```

当前第一版正式准入的攻击诱因只有 **逃逸样（Escape-like）**。

它最终购买的是玩家策略：**普通自然呈现和反应口什么时候分别有价值。**

## 故事四：高警戒鱼，值不值得换更隐蔽的终端钓组？

同一个拟饵、同一个操作，在低警戒鱼面前，前导线、钩、别针等终端钓组可以比较直接；在高警戒鱼面前，暴露更明显的钓组应该有更高代价。

这个故事要求系统把两件事分开：

```text
鱼有多警戒
→ 警戒度（Wariness）

这次终端钓组有多显眼
→ 可疑负荷（Suspicion Load）
```

两者结合才形成风险顾虑。

它最终购买的是玩家策略：**什么时候值得为了隐蔽付出成本。**

## 0.1 四个故事如何推出五项评价

四个故事最后都汇到同一个问题：

> **这个机会已经摆在鱼面前时，这种鱼、这种体型档、这种中鱼习性模式，对当前呈现到底有多适配？**

第一版响应评价因此收成五项：

```text
出手余量（Decision Margin）
= 食物价值（Food Value）
+ 攻击诱因（Attack Trigger）
- 追赶负担（Closing Cost）
- 风险顾虑（Risk Cost）
- 摄食意愿门槛（Willingness Threshold）
```

然后把出手余量投影成最终 **适配系数（Adaptation Coefficient）C**。

核心理解：

> **拟饵不是猎物类型。一个拟饵可以同时表达多个猎物类型。系统先并行解释“像什么、现在是什么状态”，再让鱼分别评价这些解释，最后同级猎物解释取最大值。**

猎物解释器（Prey Interpreter）是这层语义的负责模块；实现可以使用类（class）、策略模式（Strategy）或数据规则，但契约不要求一定使用继承树。

# 2. 猎物解释器做两件事

每个猎物类型（Prey Type）对同一份实际事实做两层解释：

```text
共同事实
  ↓
① 表达支持度解释（Support Interpretation）
   现在有多像这种猎物？
  ↓
② 状态解释（State Interpretation）
   如果按这种猎物理解，它现在是什么状态？
```

也就是说，同一段轨迹可以同时：

- 让一个拟饵“更像小鱼”；
- 在“小鱼”这个解释下，又被识别为“正在逃逸”。

前者影响猎物表达支持度，后者才可能进一步形成攻击诱因。两者不能混成一个“动作越多奖励越多”的总分。

# 3. 第一版猎物证据：四类就够

| 证据类型 | 英文名 | 回答什么 | 典型输入 | 边界 |
|---|---|---|---|---|
| **外观证据** | `Appearance` | 它看起来像什么 | 整体轮廓、比例、颜色 / 反光、部件布局 | 不读整体运动 |
| **整体运动证据** | `WholeBodyMotion` | 整体怎么运动像什么 | 速度模式、方向变化、游 / 爬 / 跳 / 漂 / 下沉 | 不重复局部部件动作 |
| **局部动作证据** | `Articulation` | 局部部件怎么动像什么 | 尾摆、腿踢、裙丝动作、局部摆动 | 不重复整体轨迹 |
| **空间关系证据** | `SpatialRelation` | 出现在哪里更符合什么猎物 | 水面、近底、中层、触底、离底高度 | 默认弱证据，不能单独把不相干外观变成强猎物身份 |

声音、振动、压力信号（Sound / Vibration / Pressure）第一版不单列为猎物证据。只有未来证明它们具有明确的特定猎物身份语义时再准入，避免滑成“刺激越强越容易咬”。

## 3.1 证据如何聚合

同一份证据内部可以有动态表达规则（Dynamic Expression Rule）：

```text
基础支持度 = b
动态表达匹配程度 = f，范围 0~1
支持度上限 = u

证据得分 = b + (u-b) × f
```

同一份证据有多种动态表达方式时取最强；同一猎物类型有多份替代证据时也默认取最强：

```text
单份证据得分 = max(基础值, 动态规则1, 动态规则2, ...)
猎物表达支持度 = max(所有适用证据得分)
```

不默认相加。只有 A+B 同时存在才形成新语义时，才显式配置联合证据（Joint Evidence / Joint Expression）。这样可以避免作者把一个事实拆得越细，支持度反而越高。

原来的动态路线（Dynamic Route）不再作为独立业务模块。它现在只是猎物解释器内部的一条**动态表达规则**。

# 4. 姿态：一个当前原子姿态 + 最多一个主导分子姿态

为了避免姿态标签爆炸，当前运动姿态收成两层。

```text
原子姿态（Atomic Pose）
= 当前这一刻是什么
移动 / 停顿 / 上升 / 下落 / ...

分子姿态（Composite Pose）
= 当前原子姿态 + 必要前史形成的过程
移动→停顿
抽动→停顿
爆发→停顿
爆发→转向→停顿
...
```

每个猎物解释在某个时刻最多保留：

```text
1 个当前原子姿态
+ 0 或 1 个当前主导分子姿态
```

若多个分子姿态同时满足，猎物解释器选择更具体、解释力更强的一个，不把多个过程标签同时变成奖励。

水面、近底、侧翻角、离底距离等继续作为正交事实 / 状态维度，不算额外“姿态”。

停顿（Pause）因此是有用的原子姿态，但没有通用的 `PauseBonus`。它可以：

- 组成“抽动→停顿”“爆发→停顿”等猎物特定的分子姿态；
- 让当前速度下降，从而改变追赶负担；
- 让机会量重新评价当前机会。

**不预设“停留越久，L 必然越大”。** 停留时间只是机会量的输入；在错误水层、无效窗口或覆盖效率下降时，多停不一定更好。

# 5. “游得更像”与“额外促发攻击”分开

```text
游得更像某种猎物
→ 猎物表达支持度

当前猎物状态额外促发捕食动作
→ 攻击诱因
```

例如自然匀速游、正常尾摆，可以明显增强小鱼表达，但本身不必产生攻击诱因。

攻击诱因的问题更窄：

> 已经接受“这是可吃的猎物”以后，当前状态有没有额外制造“现在扑上去”的理由？

当前第一版正式准入只有 **逃逸样（Escape-like）**。受伤 / 挣扎（Injured / Struggling）和失衡脆弱状态仍是后续候选；停顿本身不自动成为攻击诱因。

```text
状态攻击值（StateTriggerValue）
= 诱因预算（TriggerBudget） × 诱因强度（TriggerIntensity）
```

攻击诱因只增加出手余量。最终适配系数始终经过 0~1 投影：

```text
C = clamp((Margin - M0) / (M1 - M0), 0, 1)
```

所以攻击诱因再强也只能把适配系数推到 1，不会出现 `C > 1`，也不会反过来放大基础强度。

# 6. 鱼侧：先用体型档，不先生成具体鱼

响应计算允许读取：

```text
鱼种（Species）
× 中鱼习性模式（Engagement Mode）
× 体型档（Size Cohort）
```

不要求先抽出一条“47.3cm / 2.08kg”的具体鱼。

两个地方会明显使用体型档：

```text
捕食鱼体型档 + 猎物大小
→ 猎物尺寸偏好修正（SizePreferenceAdjustment）

鱼种 × 体型档
→ 追赶能力基线（InterceptSpeedLimit）
```

因此可以先按体型档计算候选权重；最终选中候选后，再在体型档内部生成具体长度、重量和品质。

这保留了“先算鱼权重，再抽具体个体”的生产顺序，同时允许大鱼和小鱼对猎物尺寸、追赶能力表现不同。

# 7. 第一版响应：五项评价，并去掉 θ

第一版主公式：

```text
出手余量（Decision Margin）
= 食物价值（Food Value）
+ 攻击诱因（Attack Trigger）
- 追赶负担（Closing Cost）
- 风险顾虑（Risk Cost）
- 摄食意愿门槛（Willingness Threshold）
```

## 7.1 追赶负担简化

首版**不再模拟隐藏方位角 θ（latent bearing）**，统一采用产品假设：

> 当前形成摄食机会时，鱼正在追拟饵。

因此：

```text
速度需求比 q
= 拟饵相对水体水平速度 / 追赶能力基线（InterceptSpeedLimit）

追赶负担（ClosingCost）
= K_close × q² × 活跃度成本倍率
```

不考虑“虽然很快，但刚好迎面朝鱼游过来，所以不用追”的特殊情况。现实中当然可能发生，但没有真实鱼世界坐标时，第一版不为二阶遭遇几何（Encounter Geometry）伪造精度。

如果未来真的拥有鱼距、相对方向、攻击距离、反应窗口等稳定事实，再单独重开完整遭遇几何。

## 7.2 运动可预测性第一版刻意不做

曾考虑独立的运动可预测性成本（Prediction Cost），第一版刻意不要。

因为大部分玩家可感知效果已经被其它机制承接：

- 游得更像谁 → 猎物表达支持度；
- 是不是逃逸 / 脆弱 → 攻击诱因；
- 是否太快难追 → 追赶负担；
- 有效交互窗口 / 覆盖 → 机会量；
- 是否露馅 → 风险顾虑。

只有控制这些因素后，纯“可预测性”仍稳定改变策略排序，才值得重开。会议中应把它作为“考虑过但主动删掉的复杂度”。

# 8. 风险第一版：终端钓组显眼度简单聚合

风险侧只计算目标饵以外、鱼能感知的终端钓组部件。

每个逻辑部件配置显眼度：

```text
c_i = 部件显眼度（Conspicuousness），范围 0~1
```

第一版候选公式：

```text
终端钓组显眼度（TackleConspicuousness）
= 1 - Π(1-c_i)
```

例如前导线 0.20、钩 0.30：

```text
1 - 0.8 × 0.7 = 0.44
```

首版可以先直接：

```text
可疑负荷（SuspicionLoad）≈ 终端钓组显眼度
风险顾虑（RiskCost）= K_wary × 警戒度（Wariness） × 可疑负荷
```

拟饵主体不计入终端钓组显眼度：拟饵主体属于猎物表达，目标饵之外的终端钓组才属于“是否露馅”。后续若确有必要，再加入水体透明度、光照等可见性环境修正。

# 9. 鱼况：一竿一个快照

鱼况基线（baseline）不做在线有效期（TTL）状态机。首版采用**本竿鱼况快照（Cast Fish Condition Snapshot）**：

```mermaid
flowchart LR
    A[抛竿开始\nCast Start] --> B[解析当前派生环境场 DEF / 环境条件组]
    B --> C[读取鱼况基线\nFish Condition Baseline]
    C --> D[生成本竿鱼况快照]
    D --> E[本竿所有响应只读]
    E --> F[下一竿重新解析]
```

例如 05:59 抛竿，06:00 时段切换，本竿仍使用 05:59 形成的快照；下一竿才读取新的 DEF。

因此鱼况基线的核心失败情况变成：

- 抛竿开始时找不到对应 DEF / 环境条件组；
- 鱼况数据块（block）缺必要值或来源；
- 值非法；
- 版本不一致，无法形成快照。

警戒度如果未来真的需要运行时累积，再在本竿快照之上做单独授权的运行时叠加（Runtime Overlay）；不要因此把活跃度、摄食动机、食性偏移都做成持续刷新状态机。

# 10. 适配系数 C 与机会量 L

术语统一：

```text
C = 适配系数（Adaptation Coefficient）
L = 机会量（Opportunity Support）
```

适配系数回答：

> **这个机会已经摆在鱼面前时，这个中鱼习性模式对当前呈现有多适配？**

机会量回答：

> **这个机会实际上有没有形成、形成多少、在哪个时间 / 空间窗口有效？**

最终：

```text
候选贡献 q = L × C
```

`L × C` 只乘一次。

同一个物理目标的多个同级猎物解释：

```text
C_final = max(C_小鱼, C_小龙虾, C_蛙, ...)
```

这个 `max` 只用于同一摄食路线下的替代猎物解释，不自动授权其它互动类型也使用通用最大值规则（universal max）。

# 11. 这版会议应明确讲出的“刻意简化”

| 刻意不做 | 第一版为什么不做 |
|---|---|
| 运动可预测性（Prediction） | 与猎物表达、攻击诱因、追赶负担、机会量高度重叠，尚未证明残余策略价值 |
| θ / 鱼与拟饵相对方位积分 | 没有鱼的真实位置，不伪造遭遇几何；首版按“鱼在追拟饵”统一估算 |
| 通用停顿奖励（PauseBonus） | 停顿已经能进入猎物姿态、追赶负担和机会量，不再匿名加分 |
| “停越久 L 越大” | 机会量应根据有效窗口求值，停留时间不是单调奖励 |
| 具体鱼个体先生成 | 响应先用体型档，选中后再抽具体个体 |
| 复杂视觉显眼度模型 | 先用终端钓组部件简单饱和聚合，数据不足时不提前模拟 |

这些不是“少做”，而是要求每个复杂度只有在购买独立玩法价值时才进入系统。
