# 台钓配方与作钓策略：算法实验

> Candidate / Working Experiment，2026-11-04。不是 Current，也不是生产参数。总体提案仍由 [proposal.md](proposal.md) 承担；本页负责槽位配方的策略推演与可执行比较。

## 1. 玩家为什么要换配方

玩家先选目标，再选配方与钩饵，最后根据窝点变化决定补不补。目标至少有两个：提高目标鱼的有效作钓响应，减少非目标鱼的干扰。两者不保证同时改善。

例如，一份谷物与动物料混合的窝料，可能对食物接受范围广的鱼更有效，却稀释只接受谷物的鱼所需的谷物份额。大颗粒钩饵可以阻断某些小鱼的处理路径，也可能牺牲目标鱼自身的摄食成功。快速释放适合较早产生可接触对象；慢释放把同一批物料留到较晚。它们不应分别领取“速效加分”与“持久加分”。

这些都是待验证的玩法假设。真实鱼种的食性、动作能力和签名关系需要独立证据；以下数字只来自 [工作样本](../fixtures/float-strategy-v1.json)。

## 3. 离散槽位保留什么数量

候选界面让玩家选择原料，不填连续百分比。模板为每个槽位保存固定批次用量 `m_i`，玩家选择批次数量或投放总量 `D`。内部保留真实用量，不能把“一个槽”当成所有原料等质量。

```text
模板槽位与固定批次用量 → 原料质量 m_i
share_i = m_i / Σ m_i
投放时总量 D × 配方份额 → 各原料库存
```

小药可用独立剂量单位，不强行与固体质量相加。工作 JSON 中的 0.001 只用于攻击“任意微量签名存在”问题，不是批准玩家自由输入的剂量。标准用量、可空槽位、重复原料、解锁与价格仍需产品选择。

| 角色 | 购买的候选价值 | 支付的代价 | 不给的奖励 |
|---|---|---|---|
| Base 主料 | 基础 Food、颗粒载体和物理基底 | 批次主体质量、库存与价格 | 单独的 Base Bonus |
| Target 主攻饵 | 改变食物目标构成 | 替换其它可用份额，可能扩大杂鱼响应 | 对所有目标必涨 |
| State 状态饵 | 改变对象形成、释放与水层路径 | 可食份额、制作/材料成本，可能更快流失 | 固定留鱼倍率 |
| Attractant 小药 | 改变签名集合 | 有限槽位、剂量与材料成本 | 新增实体食物或固定加分 |

主料不需要额外隐藏价值。有 Food、物理与经济差异就足够；如果两种主料这些事实全部相同，应允许它们机制等价，而不是靠角色标签强造区别。

## 4. 食物混合的比较结果

公式和算子比较由 [food-aggregation.md](food-aggregation.md) §10 维护。固定总固体质量与 20% 载体，比较谷物专精、动物料专精、各半混配。样本里的“专食型”“广食型”是合成测试鱼，不是欧鳊、鲫鱼或鲤鱼的真实配置。

同目标 `S(E)=E/(1+E)` 仅为工作样本。广食型对两目标偏好均为 0.8；专食型对谷物为1、动物料为0。

| 测试鱼与配方 | max | Noisy-OR | 总和后全局饱和 |
|---|---:|---:|---:|
| 专食型：谷物专精 | 0.4444 | 0.4444 | 0.3077 |
| 专食型：混配 | 0.2857 | 0.2857 | 0.2222 |
| 广食型：谷物专精 | 0.3556 | 0.3556 | 0.2623 |
| 广食型：混配 | 0.2286 | 0.4049 | 0.3137 |

额外枚举四份等量食物槽位（每份0.2，另有0.2载体）：专食型在三种算子下均选4份谷物；广食型在 max 下选全谷物或全动物料，在另两种算子下选2份谷物加2份动物料。在后两种算子下，两种鱼没有共同最优配方；max 下全谷物却能同时最优，暴露了策略退化风险。这个小空间不能证明真实全空间不存在万金油。

结论不是“混配应该赢”。max 会让本例的广食型也偏向专精；另两种算子支持有限混配，但依赖固定目标字典，拆分目标仍会套利。优先继续研究全局饱和，不选生产公式。三个算子尺度不同，不能跨列按数值大小判断谁更合理。

## 5. 味型目前能形成的策略有限

[flavor-and-avoidance.md](flavor-and-avoidance.md) §11 负责槽位味型边界。当前只能改变签名身份，不能改变浓度或相对组成。同味背景与钩饵不会自动增加匹配奖励；不同味也不自动产生对比奖励。

一种值得保留的选择是：有限小药槽位改变对不同鱼的正向/中性/排斥标签。它能形成选鱼策略，但还不足以形成剂量策略。若玩家期望“少量蒜有效、多了过量”，必须先过 C-02，不能用投放量、槽位数或时间系数伪装浓度。

排斥标签不自动等于 Reject。Probe 只验证标签，未为 POSITIVE/AVOID 配置数值倍率。因此本轮不能声称已验证味型对中鱼排序的数值效果。

## 6. 颗粒与状态饵购买不同路径

Probe 用动作窗口和加权成功率代替免费 `max`：

```text
F = 满足水层、尺寸窗口等前提的唯一动作集合
p_m = action_weight_m / Σ_F action_weight
U = Σ_F p_m × success_m
```

动作按机制身份去重，重复注册同一动作不能加奖；同身份不同定义是错误。权重只表示动作选择成本/倾向的工作代理，不读取 Food、Cue 或鱼况。成功率只测试对象处理，不包含遇见概率。

工作小鱼只能处理 0.1–2 尺寸单位，大鱼有 0.1–6 和 0.1–8 的路径。相同4单位钩饵让小鱼 U=0，大鱼 U>0；改变底层到表层可让底层动作全部不可行。这不是“大鱼一定喜欢大颗粒”。

真实形状、硬度、团聚不能合并成尺寸。首版建议先用有证据的少量对象状态与动作可行条件；没有独立反例前不购买四条自由曲线。慢释放也不是高黏度的必然结果，Probe 只直接输入释放率，不臆造原料到释放率的映射。

## 7. 钩饵必须独立成立

具体组合由 [hookbait-groundbait-combination.md](hookbait-groundbait-combination.md) 维护。工作式让钩饵自身价值乘一个有界背景作用，而不是背景与钩饵简单相加。这样强窝料不会救活不可处理、非法或明确 Reject 的钩饵。

钩饵额外拥有钩体、持钩、入口和呈现前提。本 Probe 只暴露合法/拒绝、尺寸和水层边界，没有证明完整钩饵模型已经实现。

## 8. 六组完整对照

| 玩家选择 | 期待与产生差异的机制 | 实验结果与限制 | 更简单的替代与攻击 |
|---|---|---|---|
| 欧鳊：蒜面团/奶渣面团 × 不同背景 | 若鱼侧对两签名关系不同，可改变解释；背景不能替换钩饵适合性 | 科学和RF4原帖本轮均未取到可核正文。只做假设关系的标签对照，真实排序不输出 | 同味奖励没有独立依据，删除；不能用其它鱼类味觉外推欧鳊 |
| 鲫/鲤场景：谷物/动物主攻/混配 | 固定预算替换目标份额；专食与广食可有相反排序 | 上表用合成鱼运行，不声明鲫/鲤的真实偏好 | max 更简单但本例丢混配；总和饱和仍有字典套利 |
| 小鱼/大鱼用同一钩饵颗粒 | 动作能力和水层条件筛选，不改 Food 偏好 | 4单位小鱼不能处理，大鱼可处理；重复动作不增益 | 单一最大嘴宽无法覆盖过滤等动作；真实窗口待证 |
| 同点不打窝/适量/连续补/过量 | 可用食物先提供有限背景收益，过剩后与钩饵竞争 | 时间输出包含四种情况；无摄食事件时压力始终0 | 不用“投得多=鱼吃饱”；竞争项是需裁定的假设 |
| 同配方快释放/慢释放 | 相同库存，不同时间可用曲线 | 早期快释放高，后期慢释放可能高；见时间表 | 无须独立速效/长效加成；没有证明原料如何生成率 |
| 下线/重登/另一玩家加入 | 保存库存、时点、事件去重；同作用域共享输入 | 在线与重登状态相等，第二玩家增量不复制；跨房间拒绝 | 无额外离线摄食模拟；公共水域归属仍需Owner决定 |

每组结果都限定在已执行的测试条件。Probe 不模拟真实鱼群迁移，不输出生产候选概率，也没有证明全配方空间不存在万金油。
