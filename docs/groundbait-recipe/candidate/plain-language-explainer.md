# 台钓窝料 / 混饵机制：深入浅出说明

> 状态：Candidate Explainer
> 
> 日期：2026-10-28
> 
> 用途：帮助设计者、程序和后续 Agent 快速理解当前提案。机制细节以 `proposal.md` 和子模块文档为准。

## 一句话

这套设计不是“把几个饵料加分项相加”。

更接近：

> 玩家调出一团真实的饵。饵在水里释放食物、气味和颗粒；不同鱼根据自己的食性、体型和摄食方式，对这团东西产生不同反应。

## 1. 一份配方同时包含四类信息

假设玩家调：

```text
60% 谷物基础饵
25% 虾粉
10% 红虫粉
5% 状态粉
+ 少量草莓小药
```

系统不直接算：

```text
谷物 +0.3
虾粉 +0.4
红虫 +0.2
小药 +0.1
= 总分 1.0
```

而是先拆成四个问题：

```text
这团饵里有什么食物？
→ Food

闻起来是什么？
→ Flavor / Chemical Cue

颗粒有多大？
→ Particle Size

这些东西如何在水里散开和持续？
→ Physical Release
```

四者职责不同。

## 2. Food：鱼到底想吃什么

例如：

```text
谷物
虫
甲壳类
植物
藻类
```

鲤鱼可能同时喜欢谷物和甲壳类。

如果把所有主攻预算都放进虾粉，前面增加虾粉的收益很高；当甲壳类信号已经很强以后，再加一点的收益会变小。

这时，如果鲤鱼也喜欢虫类，少量红虫粉可能比继续堆虾粉更值。

但如果这条鱼根本不喜欢虫，那么混红虫没有理由更强。

所以当前思路不是“混得越多越好”，而是：

> 同一种有效食物堆太多后会边际递减；只有第二种食物本身也对目标鱼有效，混配才可能有价值。

## 3. Flavor：整团饵最终闻起来是什么

Flavor 不能做成：

```text
腥 Bonus
+ 奶 Bonus
+ 果香 Bonus
+ 蒜香 Bonus
```

否则玩家最优策略会很自然地变成“每种都来一点”。

当前设计把味型看成整体画像：

```text
腥    40%
谷香  30%
果香  20%
奶香  10%
```

再加一个“味道有多强”的 Intensity。

鱼评价的是整个 Flavor Profile。

因此，加草莓小药不是在原有配方上免费多拿一个 Bonus，而是把整团饵的味型往果香方向推。

如果目标鱼喜欢果香，可能变好；如果不喜欢，原来的腥味和谷香还会被稀释，结果可能变差。

## 4. 小药：不是 Buff 药水

当前更合适的理解是：

> 小药是低剂量、高强度的 Chemical Cue Modifier。

它主要改变：

```text
Flavor Composition
Flavor Intensity
```

而不是：

```text
基础配方效果 + 小药固定加成
```

这样“小药加不加”才是选择，而不是固定必选。

## 5. Particle Size：筛选谁能有效利用实体食物

颗粒大小和拟饵大小筛选很像，但不是简单比较“颗粒 < 鱼嘴”。

鱼侧先看：

```text
鱼有多大
+ 口部 / 过滤结构相对有多大
+ 它用什么方式吃东西
```

例如同样是 30 cm 的鱼：

- 大口吞食型可以处理更大的食物对象。
- 小口啄食型高效区间更小。
- 滤食鱼即使嘴很大，也不能直接推出偏好大颗粒，它需要看过滤结构和悬浮颗粒截留能力。

所以鱼侧不直接配置“最佳 5 mm”。

而是生成一条 Size Response Curve。

### Groundbait

窝料输入是一组粒径分布：

```text
Fine    20%
Small   40%
Medium  30%
Coarse  10%
```

小鱼可能只能高效利用 Fine / Small；大鱼可以利用更宽范围。

当配方变粗以后，小鱼可利用份额下降，大鱼仍可利用，于是自然形成体型筛选。

不需要额外写：

```text
大颗粒 → 大鱼概率 +30%
```

### Hookbait

以后钩上饵球也可以直接复用这套 Size Response：

```text
饵球大小 × Fish Size Response → Size Fit
```

## 6. 多种摄食方式不是多份 Bonus

一条鱼可能会：

```text
底吸
也会啄食
```

当前第一版不会把两个 Fit 加起来。

更像：

> 面对同一颗食物，鱼使用自己最有效的一种处理方式。

因此先取 best available path。

这样不会出现“会的摄食方式越多，Size Fit 就越高”的奇怪套利。

## 7. 雾化、黏度：决定信号怎么传播，不直接加中鱼

高雾化不等于“更强”。

它更像：

```text
解体快
→ 细颗粒和化学线索更快释放
→ 更快形成明显信号
→ 可能更容易开窝
```

但也可能：

```text
释放快
→ 消耗快
→ 更需要补窝

扩散广
→ 更容易招到非目标鱼
```

高黏度则可能让：

```text
解体更慢
→ 释放更慢
→ 局部更集中
→ 持续更久
```

所以最终希望形成：

```text
快速开窝
vs
长期守窝
```

以及：

```text
快速扩散、容易发现
vs
集中、持久、筛选更强
```

这才是玩法，而不是“雾化值越高越好”。

## 8. Food 和 Flavor 的关系

Food 和 Flavor 相关，但不是一回事。

例如虾粉同时带来：

```text
甲壳类实体食物
+ 腥 / 海产类化学线索
+ 自己的颗粒和释放性质
```

草莓小药可能几乎不贡献实体食物，但提供很强的果香 Chemical Cue。

因此：

```text
Food
→ 有什么可以吃

Flavor
→ 鱼感知到什么食物线索
```

如果后续证据支持，可以进一步把它们映射到“发现 / Attraction”和“摄食 / Retention”之类的不同响应阶段；目前不提前锁死总公式。

## 9. “不喜欢”和“排斥”不同

如果一条鱼对蒜味只是没有兴趣：

```text
蒜味没有正向帮助
```

如果它对强蒜味存在 Avoidance：

```text
蒜味出现反而降低响应
```

当前只计划稀疏配置少数这种关系，不给所有 Fish × Flavor 填满正负矩阵。

## 10. 天气暂时不直接决定“今天喜欢什么味”

当前更稳的链是：

```text
天气 / 时段 / 水温等
→ Activity / Feeding Readiness
→ 今天愿不愿意积极摄食
```

而不是：

```text
下雨 → 一定喜欢腥
晴天 → 一定喜欢果香
```

如果以后保留 Diet Shift，更倾向：

```text
长期基础食性
+ 较慢的生态 Context
+ 少量有界、连续的世界漂移
```

它不应该每杆随机。

## 11. 玩家最终应该在想什么

后台机制可以复杂，但玩家心智最好仍然简单：

```text
目标鱼吃什么？
今天鱼口怎么样？
我现在想筛小鱼还是筛大鱼？
我要快开窝还是长时间守？
现在的味型需要往哪个方向调？
```

好的配方不应该是“把所有好东西全塞进去”，而应该有明确目的和代价。

## 12. 当前最重要的下一步

不是继续发明更多参数。

先用 `Edible Size Response` 做一个小型 Gold Fixture，验证：

- 同物种长大后尺寸响应自然变化；
- 不同口部形态产生差异；
- 啄食、吸食、吞食、滤食不是简单倍率；
- 粗颗粒能筛小鱼；
- 细颗粒不会无依据地强烈排斥大鱼；
- 多摄食方式不会叠加套利。

这条链跑通以后，再接 Groundbait Particle Distribution 和 Physical Release。
