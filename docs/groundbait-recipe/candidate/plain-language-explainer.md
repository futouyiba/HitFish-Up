# 台钓配方机制：中文说明

> 状态：Candidate Explainer
> 日期：2026-10-29
> 用途：帮助快速理解当前机制骨架。完整机制、状态和未收口问题以 [`proposal.md`](proposal.md)、[`system-object-model.md`](system-object-model.md)、[`working-decisions.md`](../decisions/working-decisions.md) 和 [`conflict-register.md`](../decisions/conflict-register.md) 为准；尺寸结构验证见 [`edible-size-gold-fixture.md`](edible-size-gold-fixture.md)。

## 一句话

这套设计不是把几种饵料的加分项相加。玩家调出一团饵，饵在水中释放食物、化学线索和颗粒；鱼再根据食性、体型、摄食结构和当前状态解释这些信号。

## 1. 配方包含四类事实

例如：

```text
60% 谷物基础饵
25% 虾粉
10% 红虫粉
5% 状态粉
+ 少量草莓小药
```

系统不直接计算：

```text
谷物 +0.3
虾粉 +0.4
红虫 +0.2
小药 +0.1
= 总分 1.0
```

它先分别回答四个问题：

```text
这团饵里有什么可吃的东西？
→ Food

释放什么化学线索？
→ Flavor / Chemical Cue

实体颗粒有多大？
→ Particle Size

这些东西如何在水中解体、扩散、沉降和持续？
→ Physical Release
```

四者职责不同。

## 2. Food：鱼想吃什么

Food Target 可以包括谷物、虫、甲壳类、植物和藻类。鲤鱼可能同时喜欢谷物和甲壳类。

当前候选是：先合并同一 Food Target 的有效 Exposure，再做边际递减。甲壳类信号已经很强时，继续堆虾粉的边际收益可能变小；如果目标鱼也喜欢虫类，转一部分预算给红虫粉可能更有价值。目标鱼不喜欢虫时，加入红虫没有理由自动变好。

## 3. Flavor：由 Cue Exposure 形成，而不是按原料质量计算

Flavor 不应做成腥、奶、果、蒜各自领取一份 Bonus，否则玩家容易把每种味型都放一点。

当前候选先计算：

```text
Ingredient amount / dose
× 该 Ingredient 对某味型的 Cue Potency
→ 该味型的 Cue Exposure
```

再得到：

```text
Flavor Composition
→ 各味型在总 Cue Exposure 中的相对组成

Flavor Intensity
→ 总体化学线索强度
```

例如：

```text
腥    40%
谷香  30%
果香  20%
奶香  10%
```

这里的 40% 表示腥味占当前 Chemical Cue Exposure 的比例，不表示配方质量中有 40% 是腥味原料。少量高 Potency 小药因此可能显著改变味型画像。

## 4. 小药：不是固定加成

小药更适合定义为低剂量、高 Potency 的 Chemical Cue Modifier，主要改变：

```text
Cue Exposure
Flavor Composition
Flavor Intensity
```

它不应被写成：

```text
基础配方效果 + 小药固定加成
```

新味型可能改善响应，也可能稀释原有组成，让结果变差。

## 5. Particle Size：筛选谁能有效利用实体食物

颗粒大小不能简化为“颗粒小于鱼嘴”。鱼侧还要考虑线性体尺、口部或过滤结构，以及摄食方式：

```text
线性体尺
+ 口部 / 过滤结构
+ 摄食方式
→ Size Response
```

体长等线性尺度可以和口部比例生成长度 Reference。鱼重不能直接乘 Mouth Ratio 得到颗粒毫米数，量纲不成立。FILTER 也不强迫使用“体长 × 嘴比例”，它可能主要由鳃耙或其他过滤结构决定有效截留粒径。

### Groundbait

窝料配方给出一组投放粒径分布：

```text
Fine    20%
Small   40%
Medium  30%
Coarse  10%
```

这组比例不是鱼实际遇到的对象份额。物理释放、沉降、解体和消耗会改变当前地点可接触的对象集合，鱼侧看到的是后者的分布。

还要区分可食颗粒和载体颗粒。状态粉、黏结料、泥和不提供营养的颗粒也可以有粒径，也参与释放和沉降，但不能因为尺寸合适就算成可食质量。只有可食颗粒进入尺寸响应。

小鱼对大颗粒的可利用性可能快速下降，大鱼通常可以利用更宽的尺寸范围。粗颗粒配方让小鱼的可利用份额下降，就能形成体型筛选，不必额外写成“大颗粒 → 大鱼概率 +30%”。

当前模型也不默认大鱼会因为嘴大而强烈排斥小颗粒。细颗粒的利用效率应由摄食方式决定，而不是统一降到 0。

### Hookbait

钩上饵球以后可以复用“尺寸是否适合摄食”这一层：

```text
饵球大小 × 鱼侧尺寸约束 → 可利用程度
```

但 Hookbait 还受形状、硬度、钩体阻碍、持钩和姿态影响。复用的是尺寸语言，不是把 Groundbait 的完整响应直接搬过去。

## 6. 尺寸响应描述一次摄食能否成立

颗粒尺寸不是一条独立的鱼种加分。它约束的是一次摄食事件：鱼能否捕获、吸入、留住、处理并吞下这个对象。

一条鱼可能有多种摄食方式。它们是处理同一对象的替代路径，不是多份 Bonus。动作是否可行，还取决于当前水层、底质、流态和对象状态。因此尺寸响应不能脱离 Feeding Place 单独宣布最终结果。

`max` 可以作为“动作总能自由切换、没有切换代价”的简化上界，但不是机制真理。需要保留的更一般表达是：

```text
Edible Size Usability
= 对当前地点可行的摄食路径的受限聚合
```

## 7. 雾化、黏度：影响信号传播，不直接增加中鱼

高雾化可能带来：

```text
解体更快
→ 细颗粒和 Chemical Cue 更快释放
→ 更快形成明显信号
→ 可能更快开窝
```

代价也可能是消耗更快、需要更频繁补窝，或扩散更广而更容易招来非目标鱼。黏度、比重等也应先进入解体、沉降、扩散和持续过程。

当前没有确认“高黏度必然更集中、更持久”的硬公式。需要验证的是能否稳定形成“快速开窝”和“长期守窝”等有代价的策略，而不是让雾化值越高越好。

## 8. Food 和 Flavor 的关系

Food 和 Flavor 相关，但不是同一件事。虾粉可能同时带来：

```text
甲壳类实体食物
+ 腥 / 海产类 Chemical Cue Potential
+ 自身的颗粒和物理性质
```

草莓小药可能几乎不贡献实体食物，但会提供果香 Chemical Cue。因此：

```text
Food
→ 有什么可以吃

Flavor / Chemical Cue
→ 水中释放了什么可被鱼感知的化学线索
```

它们以后可能分别影响发现、趋近、摄食和留鱼，但这些中间语义尚未闭合，不提前锁成一条总公式。

## 9. “不喜欢”和“排斥”不同

鱼对蒜味没有兴趣，表示蒜味没有正向帮助；如果强蒜味触发 Avoidance，则会主动降低响应。当前只计划稀疏配置少数有证据的关系，不给所有 Fish × Flavor 填满正负矩阵。

## 10. 天气不直接决定味型

当前边界是：

```text
天气 / 时段等环境输入
→ 现有 Fish Condition
→ 当前响应积极程度变化
```

`Feeding Readiness` 不是术语表定义的独立状态；未裁定前只作为描述性说法，不落 Schema。

不采用：

```text
下雨 → 一定喜欢腥
晴天 → 一定喜欢果香
```

Diet Shift 是否需要、由什么驱动仍是 Open。较慢生态 Context 或有界随机漂移只能作为后续候选，不能提前写成既定机制；“每杆随机改食性”已经排除。

## 11. 玩家最终应该在想什么

后台机制可以复杂，但玩家心智应保持简单：

```text
目标鱼吃什么？
今天鱼口怎么样？
我现在想筛小鱼还是筛大鱼？
我要快开窝还是长时间守？
现在的味型需要往哪个方向调？
```

好的配方不应是把所有好东西塞进去，而应有明确目的和代价。

## 12. 当前机制重点

下一步不是继续堆鱼种和数字，而是按同一条主脊推清：

```text
配方事实
→ 物理释放
→ 当前地点可接触的对象与线索
→ 一次摄食事件
   → 是否遇见
   → 哪些动作可行
   → 选择哪条动作
   → 动作是否成功
   → 对象如何更新
→ 现有 Response Stage 的候选输入
```

需要先回答的是：

- 每个量由谁产生、谁消费；
- 粒径、形状、硬度和团聚分别进入哪一步；
- 释放改变的是鱼遇到什么，还是对象本身如何被处理；
- 多动作是互斥路径还是被错误地相加；
- Groundbait 如何进入现有 `Response Condition` / `Persistent Response Field`，而不越权定义 Current 公式。

数字 Fixture 只用来暴露这些边界是否自洽，不能替代机制本身。
