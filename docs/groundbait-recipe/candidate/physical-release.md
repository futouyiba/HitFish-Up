# Physical Release｜物理释放 Candidate

> 状态：Candidate / Working Design
> 日期：2026-10-29
> 权威边界：本页不是 FCF Current Contract；它只描述配方状态如何成为 Feeding Place 状态。

## 1. 职责

Physical Release 不是“窝料的强弱分”。它是一个状态转换：

```text
Recipe / Ingredient Facts
        ↓
投放后物理过程
        ↓
Feeding Place State(place, t)
```

它回答：

- 哪些实体对象在什么时候出现；
- 这些对象位于什么空间 / 水层；
- 对象是完整、解体、悬浮、沉降还是已失去可处理状态；
- 化学线索和实体食物分别以什么时间形状可被感知。

它不直接回答鱼会不会被吸引、会不会留下或会不会吞食。

## 2. 状态与账本

最小 Feeding Place 状态不压成一个 `release_score`：

```text
FeedingPlaceState(place, t)
├─ available_physical_bins
├─ available_edible_bins
├─ chemical_cue_field
├─ location / layer
├─ object_state
└─ persistence / turnover
```

对每个账本分别记录四份：

```text
A(t)  当前地点可用
L(t)  已离开地点（沉降到别处、漂移出接触范围）
C(t)  已被摄食
U(t)  已不可处理（解体到阈值以下、溶解、失去实体状态）
```

初始 `A(0) = 1`，`L(0) = C(0) = U(0) = 0`。

守恒：

```text
A(t) + L(t) + C(t) + U(t) = 1
```

物理账本、可食账本和载体账本分别成立。可食账本不混入载体。

化学线索单独记账：

```text
Q(t) = 累计已释放的线索比例
0 ≤ Q(t) ≤ 1
```

`Q` 与实体账本不共享守恒式。线索可以释放得比实体食物快，也可以更慢。

## 3. 离散时间状态转移

用离散时间步 `t = 0, 1, 2, ...`。每个步长的转移：

```text
A(t+1) = A(t) - B(t) - S(t) - E(t)
L(t+1) = L(t) + S(t)
U(t+1) = U(t) + B(t)
C(t+1) = C(t) + E(t)
Q(t+1) = Q(t) + R(t)
```

其中：

| 符号 | 含义 | 读取 |
|---|---|---|
| `B(t)` | 本步解体到不可处理 | 黏结、硬度、水作用 |
| `S(t)` | 本步离开当前地点 | 比重、水流、沉降、漂移 |
| `E(t)` | 本步被摄食 | 当前鱼侧事件，不是释放本身 |
| `R(t)` | 本步线索释放 | 线索潜力、黏结、水作用 |

约束：

1. `B, S, E ≥ 0`；
2. `B + S + E ≤ A(t)`；
3. `R(t) ≥ 0`，且 `Q(t) ≤ 1`；
4. `E(t)` 只能来自已经发生的 Feeding Event，不能由释放模块自行设定；
5. 各账本分别守恒。

`B`、`S`、`R` 如何由物理性质和环境计算，仍是 OPEN。本页只固定状态变量、转移结构和守恒。

## 4. 输入与过程映射

候选输入：

```text
RecipePhysicalFacts
├─ cohesion / binder tendency
├─ water interaction
├─ density relation
├─ particle object distribution
├─ dose / amount
└─ environmental conditions
```

当前只保留方向性假设，不写生产公式：

| 输入 | 可能影响 | 不能直接写成 |
|---|---|---|
| 黏结 / binder | 解体速度、团聚、初始粒径 | `+Retention` |
| 水作用 | 解体、溶解、线索释放 | `+Attraction` |
| 比重 | 沉降、所在水层、离开地点速度 | `+Bite` |
| 粒径 | 沉降、解体、暴露时间 | 鱼侧尺寸成功 |
| 剂量 | 可用总量 | 固定倍率 |

同一个物理变化可能同时扩大暴露、缩短留存、改变水层或降低可处理性。方向取决于地点、时间和鱼，不由单个属性决定。

结构行为：

- FAST_OPEN 的可用食物下降最快，线索释放也最快；到 t3 只剩 0.10 可用。
- LOCAL_HOLD 的可用食物下降最慢，t3 仍有 0.70；线索释放也最慢。
- STATE_HEAVY 的可用食物保持较高，但线索释放比 LOCAL_HOLD 快，t1 已有 0.50。这说明实体食物和线索可以错位。
- 每个时点 `A + L + C + U = 1.00`，三份 Profile 都满足守恒。

这些数字只用于检查结构，不是生产参数。

## 6. 退化测试

1. **守恒**：任一时点，`A + L + C + U = 1`；物理、可食、载体账本分别成立。
2. **时间方向**：`A(t)` 单调不增，`L(t)`、`C(t)`、`U(t)` 单调不减。
3. **线索有界**：`Q(t)` 在 `[0,1]`，不因步长增加超过 1。
4. **状态隔离**：只改变 `location / layer`，不直接改写 `B`、`S`、`E` 的账本。
5. **状态材料成本**：增加状态材料必须占配方固体预算，不能既保持所有可食份额不变又额外获得释放效果。
6. **不单调偏好**：不能由释放 Profile 单独推出最终 Response 单调上升；必须经过 Feeding Place 和鱼侧解释。
7. **粒径分责**：改变粒径可以影响 `B`、`S`，但不得绕过 Size Response 直接改写鱼侧尺寸利用。
8. **线索与食物分离**：`Q(t)` 与 `A(t)` 可以不同步，模型不能强迫二者相等。
9. **摄食来源**：`E(t)` 只能来自 Feeding Event，不能由释放模块凭空设置。

## 7. 机制边界

### 不属于本模块的直接结论

- 高雾化必然更容易中鱼；
- 高黏度必然更集中或更持久；
- 释放量越大最终 Response 越高；
- 状态饵可以在不占用 Food / Flavor 预算的情况下免费增强配方。

### Working Hypothesis

- 释放首先改变 Feeding Place 中鱼能遇到什么，而不是改变鱼的固有偏好；
- 快速释放与长期局部留存是不同的时间空间策略，不能用一个总分替代；
- 状态材料占据配方资源，应通过物料与释放状态进入，而不是固定 Bonus；
- 实体食物与化学线索的释放可以错位，这种错位可能是机制的一部分。

### OPEN

- `B`、`S`、`R` 如何由黏结、水作用、比重、粒径和环境计算；
- Feeding Place 需要多细的空间、时间和水层分辨率；
- 哪些物理量可由现有 Ingredient Facts 取得，哪些需要实验或 Owner 输入；
- “可接触”和“可处理”是否应分开建模；
- 线索场是否需要单独的衰减和空间扩散；
- 颗粒团聚和解体是否需要显式对象生命周期。

## 8. Overfeeding 与局部鱼群

外部研究记录 RF4 存在 overfeeding：population 下降、咬口频率降低、需要休息和补窝。该研究是外部证据，不是本仓 Current。

当前只保留问题边界：

- Overfeeding 是否首版纳入；
- 若纳入，放在 Feeding Place（对象与线索状态）还是 Fish Condition（饱食 / 警戒）；
- 是否需要历史累积、非单调结果、补窝频率和跨 session 语义；
- 局部鱼群 / 招募是否需要显式建模，还是只体现为机会权重变化。

在本仓没有证据和位置前，不写具体惩罚公式。

## 9. 最小验证要求

1. `FeedingPlaceState(place, t)` 只产生接触机会、对象状态、位置和线索场；不能直接产生最终 Response。
2. 同一总物料只改变释放速度时，改变的是时间分布，不是凭空增加物料。
3. 只改变空间位置时，改变的是接触机会，不直接改写鱼的尺寸曲线。
4. 只改变对象状态时，若影响摄食，必须经对象处理约束进入，不能伪装成化学吸引。
5. 线索释放与食物释放可以不同步，模型不能强迫二者相等。
6. 改变物理释放不能绕过 Feeding Place 直接生成最终 Response。
