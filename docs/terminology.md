## 2. 权重的分类

### 2.1 基础权重

**基础权重（Base Weight，基础机会强度）**：在环境影响介入之前，某投鱼条目的基础数量 / 中鱼机会量级。来源（简述）：投鱼条目。

当前对应：

| 名称 | Identifier |
|---|---|
| 基础权重 | `Base Weight` |
| 基础机会强度 | `Base Opportunity Intensity` |
| 配表字段 | `probWeightIdeal` |
| 既有机制字段 | `baseOpportunityIntensity` |

**投鱼条目（Stocking Entry）**：某钓场中对一种鱼 / Fish Quality 的投放配置，负责表达这条鱼在该钓场中的基础权重及相关钓场级配置。

**鱼品质（Fish Quality / FishQualityRef）**：既有的鱼品质身份，用于表达同一鱼种下的品质 / 个体规格差异。

### 2.2 环境权重（＝空间分布权重）

**空间分布权重（SpatialDistributionWeight）**

Identifier：`SpatialDistributionWeight`。业务上也可称**环境权重**。

定义：基础权重经过环境评价后得到的未归一化权重。

```text
BaseWeight × EnvCoeff
→ SpatialDistributionWeight
```

即：

```text
基础权重 × 环境系数
→ 空间分布权重（环境权重）
```

`SpatialDistributionWeight` 不是 Probability；只有与其它候选项共同归一化 / 抽样后，才进入概率意义上的结果。存储形态：派生环境场 DEF（见 §4）。

### 2.3 圆桌权重（表）

**圆桌权重 / 圆桌权重表**：圆桌抽鱼阶段，由空间分布权重 × 适配系数等各路权重组装形成的最终候选权重列表；是抽鱼和生成的直接输入。详细输入输出与圆桌四件见框架文档《中鱼中层框架》"圆桌权重表"一节。

### 2.4 模式基础强度、模式权重与模式分布

**模式基础强度（Mode Base Intensity）**：配置在中鱼习性模式（Engagement Mode）上的相对量，例如一个模式 6.0、另一个 3.0；用作该模式在当前上下文中参与权重计算的起始值。注意量级差异：基础强度是相对量，最终权重可达十万、百万量级。

环境侧条件、鱼况以及后续响应逻辑可以在各自阶段影响该模式最终参与计算的权重；具体求值公式由对应 Contract 定义。

**模式权重（Mode Weight）**：某个中鱼习性模式（Engagement Mode）在某一计算阶段所具有的权重。模式权重贯穿权重链，可以分别处于基础、环境、圆桌等阶段；阶段名称说明“权重算到哪一步”，模式名称说明“这份权重属于哪个 Engagement Mode”。模式基础强度是否直接等价于基础阶段的模式权重，由对应 Contract 进一步确定。

**模式分布（Mode Distribution）**：某个鱼种（Species）在某个具体求值上下文与计算阶段下，各个中鱼习性模式（Engagement Mode）及其模式权重组成的整体分布；权重是计算结果，不是新的鱼群实体。

```text
模式分布 Mode Distribution
├─ 小个体模式 → 300
├─ 大个体模式 → 100
└─ 其它模式   → 50
```

模式分布可以贯穿不同计算阶段，并在后续阶段被归一化、继续调整或参与跨模式聚合；是否以及何时归一化由对应 Contract 决定。

**模式分布条目（Mode Distribution Entry）**：模式分布中的单个条目，表达某个中鱼习性模式（Engagement Mode）在当前阶段和上下文中的模式权重。

```text
Mode Distribution Entry
├─ EngagementModeRef
└─ ModeWeight
```

模式分布条目是运行 / 求值结果，不是独立长期业务身份。

### 2.5 归一化与候选概率

**归一化（Normalization）**：将同一候选集合中的权重转换为相对份额的过程。归一化改变数值尺度，但不改变候选之间的相对权重关系；具体在哪个阶段归一化，由对应 Contract 决定。

**候选概率（Candidate Probability）**：同一候选集合中的权重经过归一化后得到的相对抽取概率。权重本身不是概率；只有在明确候选集合和归一化规则后，才具有概率意义。

## 3. 重要相关：系数

系数的计算围绕因子进行：各因子独立计算，再把结果聚合成更高层系数。因子举例：水温、气压、溶氧、食物浓度。

### 3.1 系数族（环境评价）

| 中文正式名 | 英文 / Identifier | 定义 |
|---|---|---|
| 习性配置 | `Profile` | 一个中鱼习性组件（Engagement Component）内用于描述偏好 / 响应规则的结构化配置。 |
| 亲和度 | `Affinity` | 鱼侧静态配置中，对某个离散环境项的偏好值。 |
| 适配值 | `Fit` | 当前条件代入某个环境习性组件后得到的单组件评价结果。 |
| 环境系数 | `EnvCoeff` | 多个环境习性组件评价结果聚合后的整体环境倍率。 |
| 门槛判定 | `Gate` | 对某项条件是否满足最低要求进行的离散判定。 |
| 门控结果 | `GateResult` | Gate 对当前条件的离散判定结果（通过 / 失败；是否需要更丰富枚举由 Contract 决定）。 |
| 聚合角色 | `AggregationRole` | 某环境习性组件在环境权重计算中的角色。当前使用 `CORE / SECONDARY / IGNORED`。 |
| 忽略 | `IGNORED` | 当前环境权重计算不消费该组件；不表示组件数据不存在。 |
| Gate 失败环境系数 | `fail_env_coeff` | 普通 Gate fail 路径下使用的环境系数。 |
| 最小环境系数 | `envCoeffMin` | 保底鱼（Background Fish）兜底路径下使用的最低环境系数。 |
| 保底鱼 | `Background Fish` | 在具体钓场投鱼配置中承担兜底供给职责的鱼。环境 Gate 失败时可进入专门的最低环境系数路径，以避免该类鱼在不利环境下完全失去基础供给；具体标记位置与数值规则由对应 Contract 定义。 |
| 环境条件组 | `ConditionGroup` | 一组可以共同求值的环境侧条件组合 / 等价类。 |
| 适配系数 | `Adaptation Coefficient` | 响应阶段产生的最终系数，表达当前 Engagement Mode 对本次玩家刺激 / 呈现的响应强弱；按鱼种聚合为鱼适配系数集（鱼种 × 中鱼习性模式 → 适配系数）。公式见 §5.2。 |

单因子层输出两个量：门控结果（GateResult，离散判定）与适配值（Fit，连续评价）；多因子聚合后得到更高层系数（环境系数、适配系数）。“亲和系数”“因子结果”不再作为正式术语（无机制证据表明它们与 Fit 是不同量）。

### 3.2 维度：因子

**因子（Factor）**：对鱼而言具有独立评价语义、可独立产生评价结果的评价维度。

```text
Environment Entity / Terrain / Material（环境实体 / 地形 / 材质）
        ↓
Raw Condition（原始条件）
        ↓
Derived Condition（派生条件）
        ↓
Factor Input / Value（因子输入 / 值）
        ↕
Environment Component（环境习性组件）
        ↓
Fit（适配值）
```

判别：

> **实体（Entity）是世界里有什么；条件（Condition）是当前事实是什么；因子（Factor）是鱼评价什么；环境习性组件（Environment Component）是这条中鱼习性模式（Engagement Mode）如何评价它。**

因子、条件、习性组件与系数的关系可以概括为：

```text
条件（输入数据：环境 / 配置 / 玩家策略 / 运行时状态）
  ↓
因子（独立评估、计算的计算对象）
  ↓ 读取该因子对应的条件
习性组件（该中鱼习性模式下的评价规则：门控 / 亲和度 / 响应曲线）
  ↓ 产出
输出（门控结果 / 适配值）
  ↓ 多因子聚合
更高层系数（如环境系数、适配系数）
```

因此，条件是输入数据，因子是计算对象。例如，当前饵的速度值属于条件；"饵速度因子"是对该条件进行独立评估的运算对象。

### 3.3 输入A：条件

条件有两个相互独立的分类维度：按派生前后，和按使用模块。

按派生前后：

| 中文正式名 | 英文 | 定义 | 示例 |
|---|---|---|---|
| 原始条件 | `Raw Condition` | 直接编辑、采样或由世界状态提供的事实。 | 实体类型、位置、形态、地形高度、材质、天气 |
| 派生条件 | `Derived Condition` | 从原始条件或其它派生条件确定性计算得到的事实。 | 水深、距 Structure、Cover 密度、光照、局部流速、溶氧 |

按使用模块（轴心统一：均按消费该条件的模块命名；来源信息写入定义作属性描述）：

| 中文正式名 | 英文 | 定义 | 示例 |
|---|---|---|---|
| 烘焙条件 | `Bake Condition` | 被烘焙阶段消费的条件，来自世界侧（时段、天气、水温、光照、溶氧、水流、结构体、底质、深度等钓场环境）。 | 时段、天气、水温 |
| 响应条件 | `Response Condition` | 被响应阶段消费的条件，来自玩家侧（饵、姿态、窝料、线组、玩家位置与操作等）；该步骤固定称为响应，响应最终产出的系数称适配系数。 | 饵、姿态、窝料 |

两个分类维度相互独立，不应混在同一个列表里。为避免"一级条件 / 二级条件"只表达层级而不表达语义，按派生前后采用"原始条件 / 派生条件"的名称。

条件的来源（世界侧，简述）：

**环境实体（Environment Entity）**：世界中实际存在、具有位置 / 形态并可参与环境计算的对象。例：水草、石块、沉木、树桩、桥墩、码头构件。环境实体主要提供类型、位置、形态、尺寸、材质等原始条件数据；影响系数为实体直接配置的原始条件，点级实际值（实际光照强度、实际溶氧、局部流速、掩蔽程度）为派生条件（详见《Environment Entity Raw Condition Schema》）。

### 3.4 输入B：习性

| 中文正式名 | 英文 / Identifier | 定义 |
|---|---|---|
| 鱼种 | `Species` | 鱼种本身的稳定定义，包含名称、体长与体重关系和可用的中鱼习性模式。 |
| 中鱼习性模式 | `Engagement Mode` | 某鱼种可复用的一套中鱼习性定义，描述这类鱼在环境和玩家刺激下如何表现。可包含模式自身的基础强度，以及环境习性、响应习性等配置。 |
| 基础习性 | `Species Base` | 一个 Species 的默认中鱼习性模式。当前 Production 中由一条特殊 `FishEnvAffinity` 承载。 |
| 习性档案 | `FishEnvAffinity` / `FishEnvAffinityRef` | 当前 Production 中承载中鱼习性模式（Engagement Mode）的持久记录 / 引用。 |

推荐关系：

```text
Species
├─ Species Base
└─ Engagement Mode(s)
   ├─ Mode Base Intensity
   ├─ 环境习性组件（Environment Components）
   └─ 响应习性组件（Response Components）
```

判别：

> **Species（鱼种）说明鱼是什么；Engagement Mode（中鱼习性模式）说明鱼怎么表现；Stocking Entry（投鱼条目）说明这个钓场投了什么、投多少。**

**中鱼习性模式（叙述）**：一个鱼种在本质上行为由其脑部神经网络驱动，不同情况下会做不同的取舍，过于复杂。为解决此问题，我们将鱼的习性分为几种习性模式，从而简化问题。

- **伏击模式下**：鱼伏在掩蔽物附近（水草边缘、石缝、倒木旁），活动范围小、节省体力；对进入攻击半径的饵果断出击，对远距离或快速掠过的饵保持警戒；偏好泳姿自然、动作逼真的活饵型呈现。
- **开放游弋模式下**：鱼在开阔水域主动巡游觅食，活动范围大，跟随食物与水温分布移动；搜索半径大，对饵的响应相对平缓但持续，愿意追踪并试探。
- **护巢护卵模式下**：鱼守卫巢穴与卵块，活动范围收缩到巢区附近；对靠近巢区的饵反应剧烈，但以驱逐入侵者为主、进食意愿低；越过巢区边界的饵容易被攻击。

一个中鱼习性模式由一组习性组件构成：每个因子对应一个组件（含门控规则、亲和度规则、响应曲线、聚合参数）。框架文档文首"一图流"画板中的"习性模式1"就是这张配置表的示意。存储时不必按嵌套树，可平铺成表格：每行一个"中鱼习性模式 × 因子"的组件条目，查询时按模式和因子直接定位行。平铺示意：

| 中鱼习性模式 | 因子 | 门控规则（配置区间） | 亲和度规则 | 响应曲线 |
|---|---|---|---|---|
| 鲈鱼的伏击模式 | 水温 | 水温 22~30℃ | … | … |
| 鲈鱼的伏击模式 | 光照 | 光照 220~10000 | … | … |
| 鲈鱼的开放游弋模式 | 水温 | 水温 18~26℃ | … | … |
| 鳡鱼的伏击模式 | 饵速度 | 0.2~0.8 m/s | … | … |

**中鱼习性组件（Engagement Component）**：一条中鱼习性模式（Engagement Mode）中，围绕一个相对独立的评价或响应语义组织的一组鱼侧配置。

```text
中鱼习性组件（Engagement Component）
├─ 环境习性组件（Environment Component）
└─ 响应习性组件（Response Component）
```

**环境习性组件（Environment Component）**：一条中鱼习性模式（Engagement Mode）针对某个环境因子（Factor）的完整鱼侧评价配置。典型环境因子包括：水温（Temperature）、结构类型（Structure Type）、遮蔽物类型（Cover Type）、底质类型（Substrate Type）、觅食生态水层（Feeding Layer）、时段（Period）、光照（Light）、水流（Flow）、溶氧（Oxygen）。

**响应习性组件（Response Component）**：一条中鱼习性模式（Engagement Mode）中，针对玩家输入、饵料、窝料、呈现方式或其它刺激的独立响应配置单元。它的内部配置不默认复用环境侧的 `Profile → Affinity → Fit` 结构。

习性组件表按两个维度组织：行是因子，列是中鱼习性模式（Engagement Mode）。每个格子是一个组件的配置，可以包含门控规则、亲和度规则、响应曲线以及聚合参数，对应"计算条目 × 模式 × 因子"的交叉点。示意（列＝隶属鱼种的模式，行＝因子，单元格＝该习性组件的配置区间）：

| 因子 ＼ 模式 | 鲈鱼/伏击模式 | 鲈鱼/开放游弋模式 |
|---|---|---|
| 水温 | 水温 22~30℃ | 水温 18~26℃ |
| 光照 | 光照 220~10000 | 光照 5000~30000 |
| 饵速度 | 0.2~0.8 m/s | 0.3~1.5 m/s |

例如，饵速度、震动、闪光都可以作为因子。它们的当前值属于条件；不同计算条目在不同中鱼习性模式下如何评价这些值，由对应的习性组件定义。

### 3.5 关键点：算法逻辑

**因子聚合**：多个适配值（Fit）按聚合角色（CORE / SECONDARY / IGNORED）合成为更高层系数（如环境系数）的过程。

**分模式逻辑（Per-mode Evaluation）**：同一鱼种（Species）的多个中鱼习性模式分别参与计算，并保留各自模式身份和阶段权重的计算方式。它描述“同一种鱼为什么可以同时存在多套可区分的行为 / 习性计算路径”，不等同于把鱼拆成多个长期鱼群实体。

**跨模式聚合（Cross-mode Aggregation）**：同一鱼种的多个 Engagement Mode 分别得到阶段结果后，根据当前路由 / 聚合规则把这些模式结果汇合、选择或继续传递到下一阶段的过程。具体算子和发生阶段由对应 Contract 定义。

**计算通道（Calculation Channel）**：某个计算域内部，被组织成同一条独立计算 / 聚合路径的计算项集合；框架文档模块表称"烘焙通道聚合"，通道一（环境侧）是当前实现重点。

硬边界：**因子聚合处理单个模式内多个因子的合成；跨模式聚合处理同一 Species 下多个模式结果之间的关系；计算域划分“算什么问题”；计算通道划分“这个问题内部沿哪条独立路径算”。**

## 5. 逻辑模块

### 5.1 烘焙（预烘焙）

**烘焙（Bake）**：已解析的鱼配置 + 环境事实 → 环境评价输出。

**预烘焙（Pre-bake）**：烘焙派生环境场之前，先把原始条件烘焙成派生条件的过程。

### 5.2 响应（持久响应 ｜ 姿态响应）

**响应阶段（Response Stage）**：环境权重形成之后，系统按中鱼习性模式（Engagement Mode）的响应习性、当前鱼况和玩家刺激，调整候选权重。它分两路：持久响应处理持续生效的玩家行为（如打窝）；姿态响应处理当前姿态、饵和操作的即时计算。

**持久响应（Persistent Response）**：响应阶段中处理持续生效玩家行为的计算路径，例如打窝。其结果以持久响应场等形式保留，在有效范围和持续时间内影响后续响应计算。

**姿态响应（Pose Response）**：响应阶段中针对当前姿态、饵和玩家即时操作进行的即时计算路径。它读取当前呈现信号，并可叠加持久响应影响，形成当前中鱼计算所需的适配结果。

```text
空间分布权重（SpatialDistributionWeight）
+ 鱼况（Fish Condition）
+ 响应习性组件（Response Components）
+ 当前刺激 / 呈现信号（Presentation Signal）
→ 响应评价
→ 下游候选权重
```

当前可表达为：

```text
空间分布权重（SpatialDistributionWeight）× 适配系数（AdaptationCoeff）
→ 下游候选权重
```

**鱼况（Fish Condition）**：鱼侧动态参数。随天气、时段等输入变化，描述鱼当前的活跃、摄食与警觉状态，供后续响应（Response）等计算使用。

| 中文 | 英文 / Identifier | 说明 |
|---|---|---|
| 活跃度 | `Activity` | 当前整体活跃程度；除参与响应（Response）外，也可向刺鱼、搏鱼等后续模块提供输入。 |
| 摄食动机 | `Feeding Motivation` | 当前摄食意愿 / 驱动力。 |
| 食性偏移 | `Diet Shift` | 当前相对于基础食性的动态偏移。 |
| 警戒度 | `Wariness` | 当前警觉程度；随过程累积变化，影响后续响应。 |

基本关系：

```text
天气 / 时段 / 其它动态输入
        ↓
      鱼况（Fish Condition）
        ↓
     响应（Response）计算
        ↓
后续中鱼、刺鱼、搏鱼等模块
```

鱼况各参数的更新公式、时间粒度与下游消费关系由对应机制 Contract 定义。

**呈现信号（Presentation Signal）**：玩家如何把饵 / 钓组呈现给鱼的当前输入，例如速度、姿态、深度、距离、运动方式等。

### 5.3 圆桌抽鱼

**圆桌抽鱼（Roundtable Selection）**：使用圆桌权重表作为直接输入，在当前候选集合中完成最终抽取并决定本次进入生成 / 中鱼流程的候选对象的阶段。

圆桌阶段当前使用以下四类职责概念；具体先后顺序、公式和相互作用由对应框架 / Contract 定义：

- **品质抽取调整（Quality Share Adjustment）**：由中鱼习性模式等因素对不同鱼品质在候选集合中的份额进行调整。
- **硬保底（Hard Guarantee）**：独立于普通相对权重竞争的尾部保护 / 保底控制层，用于满足明确的最低体验约束。
- **动态权重调整（Dynamic Weight Adjustment）**：根据运行时玩家标签、鱼标签或其它明确控制信号，对圆桌候选权重进行动态干预的机制；具体规则仍由对应 Contract 定义。
- **挤占（Crowding-out）**：圆桌抽鱼中，候选按权重竞争抽取机会的关系；某些候选权重上升时会相对压低其它候选的抽取份额。

### 6.2 计算域

**计算域（Calculation Surface）**：一套配置、角色或规则所作用的计算问题范围。它回答：

> **"这个配置在哪一类计算中生效？"**

当前主要包括：

- **环境权重计算域（Environment Weight Surface）**
- **响应计算域（Response Surface）**

计算域不是数据传输通道，也不是 Pipeline。与计算通道的边界见 §3.5：计算域划分“算什么问题”；计算通道划分“这个问题内部沿哪条独立路径算”。

### 6.3 配置与工作流

| 中文 | 英文 | 定义 |
|---|---|---|
| 配方 | `Recipe` | 描述一个配置对象如何由来源（Source）+ 操作（Operations）形成。 |
| 来源 | `Source` | 为组件（Component）/习性配置（Profile）提供原始配置值的上游来源。 |
| 操作 | `Operation` | 在来源值（Source value）上表达继承、调整或设置等作者意图的操作。 |
| 解析 | `Resolve` | 来源 + 操作 + 覆盖 → 生效后的解析结果（effective resolved truth）。 |
| 物化 | `Materialize` | 生效后的配置 → 完整的生产行（Production rows）。 |
| 校验 | `Validate` | 对编辑态（Authoring）/解析态（Resolved）/生产态（Production）约束进行检查。 |
| 发布 | `Publish` | 将通过发布条件的结果写入生产环境（Production）。 |

（烘焙 / 预烘焙作为工作流步骤见 §5.1。）
