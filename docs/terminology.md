## 0. 术语地图

术语地图表达概念关系，不表达来源与流向。

```text
权重
├─ 分类：基础权重 ｜ 环境权重（＝空间分布权重）→ 派生环境场 ｜ 圆桌权重表
├─ 模式维度：模式基础强度 ｜ 模式权重 ｜ 模式分布
├─ 重要相关：系数
│   ├─ 系数族：环境系数（单因子层：门控结果/适配值）｜ 适配系数
│   ├─ 维度：因子
│   ├─ 输入A：条件
│   │   ├─ 分类A（派生前后）：原始条件 ｜ 派生条件
│   │   └─ 分类B（使用模块）：烘焙条件 ｜ 响应条件
│   ├─ 输入B：习性
│   │   ├─ 鱼种
│   │   ├─ 中鱼习性模式 → 伏击 ｜ 开放游弋 ｜ 护巢护卵
│   │   │      ├─ 基础习性（默认模式）
│   │   │      └─ 习性档案（持久化载体）
│   │   └─ 中鱼习性组件 → 环境习性组件 ｜ 响应习性组件
│   └─ 关键点（算法逻辑）：因子聚合 ｜ 分模式逻辑 ｜ 跨模式聚合

```

## 2. 权重的分类

### 2.1 基础权重

**基础权重（Base Weight）**：投鱼条目配置的基础数量或中鱼机会量级，尚未计入环境影响。

当前相关名称 / 字段：

| 名称 | 标识 / 字段 | 当前关系 |
|---|---|---|
| 基础权重 | `Base Weight` | 推荐业务术语 |
| 基础机会强度 | `Base Opportunity Intensity` | 既有机制名 / 兼容名；是否与基础权重逐值等价由对应契约确认 |
| 配表字段 | `probWeightIdeal` | 既有字段；与上述量的精确映射由对应契约确认 |
| 既有机制字段 | `baseOpportunityIntensity` | 既有字段；与上述量的精确映射由对应契约确认 |

不要仅因名称接近就把上述标识或字段自动实现为多个独立基础量，也不要在没有契约证据时假定它们逐值完全等价。

**投鱼条目（Stocking Entry）**：某钓场中对一种鱼 / Fish Quality 的投放配置，负责表达这条鱼在该钓场中的基础权重及相关钓场级配置。

**鱼品质（Fish Quality / FishQualityRef）**：既有的鱼品质身份，用于表达同一鱼种下的品质 / 个体规格差异。

### 2.2 环境权重（＝空间分布权重）

**空间分布权重（SpatialDistributionWeight）**：基础权重经过环境评价后得到的未归一化权重，业务上也称**环境权重**。标识为 `SpatialDistributionWeight`。

```text
BaseWeight × EnvCoeff
→ SpatialDistributionWeight
```

中文对应关系：

```text
基础权重 × 环境系数
→ 空间分布权重（环境权重）
```

空间分布权重不是概率。只有在明确候选集合并进行归一化或抽样后，才得到概率意义上的结果。空间分布权重保存在派生环境场中，见 [§4](#4-中间数据)。

### 2.3 圆桌权重表

**圆桌权重表（Roundtable Weight List）**：圆桌抽鱼阶段，由空间分布权重 × 适配系数等各路结果组装形成的最终候选权重列表；是抽鱼和生成的直接输入。

单个候选的数值可称“圆桌阶段权重”或“圆桌权重值”；正式集合名为“圆桌权重表”。“圆桌权重表构建”只描述过程，不与单值或集合混用。详细输入输出与圆桌职责由对应框架或契约定义。

### 2.4 模式基础强度、模式权重与模式分布

**模式基础强度（Mode Base Intensity）**：配置在中鱼习性模式（Engagement Mode）上的相对量，例如一个模式 6.0、另一个 3.0；用作该模式在当前上下文中参与权重计算的起始值。基础强度是相对量，最终权重可达十万、百万量级。

环境侧条件、鱼况以及后续响应逻辑可以在各自阶段影响该模式最终参与计算的权重；具体求值公式由对应契约定义。

**模式权重（Mode Weight）**：某个中鱼习性模式（Engagement Mode）在某一计算阶段所具有的权重。模式权重贯穿权重链，可以分别处于基础、环境、圆桌等阶段；阶段说明权重算到哪一步，模式说明权重属于哪个中鱼习性模式。模式基础强度是否直接等价于基础阶段的模式权重，由对应契约进一步确定。

**模式分布（Mode Distribution）**：某个鱼种（Species）在某个具体求值上下文与计算阶段下，各个中鱼习性模式（Engagement Mode）及其模式权重组成的整体分布；权重是计算结果，不是新的鱼群实体。

```text
模式分布 Mode Distribution
├─ 小个体模式 → 300
├─ 大个体模式 → 100
└─ 其它模式   → 50
```

模式分布可表达不同计算阶段的模式权重。是否在每个阶段物化、何时归一化、模式身份保留到何处，以及何时进行跨模式聚合，均由对应契约决定。

**模式分布条目（Mode Distribution Entry）**：模式分布中的单个条目，表达某个中鱼习性模式（Engagement Mode）在当前阶段和上下文中的模式权重。

```text
Mode Distribution Entry
├─ EngagementModeRef
└─ 当前阶段模式权重值
```

模式分布条目是运行时的求值结果，不是独立的长期业务身份。运行时或物理表结构是否固定使用字段名 `ModeWeight`，仍由对应契约决定。

### 2.5 归一化与候选概率

**归一化（Normalization）**：将同一候选集合中的权重转换为相对份额的过程。归一化改变数值尺度，但不改变候选之间的相对权重关系；具体在哪个阶段归一化，由对应契约决定。

**候选概率（Candidate Probability）**：同一候选集合中的权重经过归一化后得到的相对抽取概率。权重本身不是概率；只有在明确候选集合和归一化规则后，才具有概率意义。

## 3. 重要相关：系数

系数的计算围绕因子进行：各因子独立计算，再把结果聚合成更高层系数。因子举例：水温、气压、溶氧、食物浓度。

### 3.1 系数族（环境评价）

| 中文正式名 | 英文 / 标识 | 定义 |
|---|---|---|
| 习性配置 | `Profile` | 一个中鱼习性组件（Engagement Component）内用于描述偏好 / 响应规则的结构化配置。 |
| 亲和度 | `Affinity` | 鱼侧静态配置中，对某个离散环境项的偏好值。 |
| 适配值 | `Fit` | 当前条件代入某个环境习性组件后得到的单组件评价结果。 |
| 环境系数 | `EnvCoeff` | 多个环境习性组件评价结果聚合后的整体环境倍率。 |
| 门槛判定 | `Gate` | 对某项条件是否满足最低要求进行的离散判定。 |
| 门控结果 | `GateResult` | 门槛判定对当前条件的离散判定结果（通过 / 失败；是否需要更丰富枚举由契约决定）。 |
| 聚合角色 | `AggregationRole` | 某环境习性组件在环境权重计算中的角色。当前使用 `CORE / SECONDARY / IGNORED`。 |
| 忽略 | `IGNORED` | 当前环境权重计算不消费该组件；不表示组件数据不存在。 |
| Gate 失败环境系数 | `fail_env_coeff` | 普通门控失败路径下使用的环境系数。 |
| 最小环境系数 | `envCoeffMin` | 保底鱼（Background Fish）兜底路径下使用的最低环境系数。 |
| 保底鱼 | `Background Fish` | 在具体钓场投鱼配置中承担兜底供给职责的鱼。环境门控失败时可进入专门的最低环境系数路径，以避免该类鱼在不利环境下完全失去基础供给；具体标记位置与数值规则由对应契约定义。 |
| 环境条件组 | `ConditionGroup` | 一组可以共同求值的环境侧条件组合 / 等价类。 |
| 适配系数 | `Adaptation Coefficient` | 响应阶段产生的最终系数，表达当前中鱼习性模式对本次玩家刺激 / 呈现的响应强弱；按鱼种聚合为鱼适配系数集（鱼种 × 中鱼习性模式 → 适配系数）。公式见 [§5.2](#52-响应持久响应--姿态响应)。 |

单因子层输出两个量：门控结果（GateResult，离散判定）与适配值（Fit，连续评价）；多因子聚合后得到更高层系数（环境系数、适配系数）。“亲和系数”“因子结果”不再作为正式术语（无机制证据表明它们与 Fit 是不同量）。

### 3.2 维度：因子

**因子（Factor）**：对鱼而言具有独立评价语义、可独立产生评价结果的评价维度。

```text
Environment Entity / Terrain / Material（环境实体 / 地形 / 材质）
        ↓
Raw Condition（原始条件）
        ↓
Derived Condition（派生条件）
        ↓
Factor Input / Value（因子输入 / 值）
        ↕
Environment Component（环境习性组件）
        ↓
Fit（适配值）
```

实体（Entity）说明世界里有什么；条件（Condition）说明当前事实；因子（Factor）说明鱼评价什么；环境习性组件说明该模式如何评价这个因子。

通用评价关系：

```text
条件（输入数据：环境 / 配置 / 玩家策略 / 运行时状态）
  ↓
因子（独立评估、计算的计算对象）
  ↓ 读取该因子对应的条件
习性组件（该中鱼习性模式下的评价规则；具体结构由组件类型决定）
  ↓ 产出
输出（如门控结果 / 适配值 / 响应评价结果）
  ↓ 多因子聚合
更高层系数（如环境系数、适配系数）
```

例如，当前饵的速度值是条件；饵速度因子是对速度进行独立评价的维度。

### 3.3 输入A：条件

条件有两个相互独立的分类维度：按派生前后，和按使用模块。

按派生前后：

| 中文正式名 | 英文 | 定义 | 示例 |
|---|---|---|---|
| 原始条件 | `Raw Condition` | 直接编辑、采样或由世界状态提供的事实。 | 实体类型、位置、形态、地形高度、材质、天气 |
| 派生条件 | `Derived Condition` | 从原始条件或其它派生条件确定性计算得到的事实。 | 水深、距结构体的距离、遮蔽物密度、光照、局部流速、溶氧 |

按直接使用条件的模块分类，来源只作说明：

| 中文正式名 | 英文 | 定义 | 示例 |
|---|---|---|---|
| 烘焙条件 | `Bake Condition` | 被烘焙阶段直接消费的条件。常见来源为世界侧环境事实，例如时段、天气、水温、光照、溶氧、水流、结构体、底质、深度等。 | 时段、天气、水温 |
| 响应条件 | `Response Condition` | 被响应阶段直接消费的条件集合。可包含鱼侧动态输入，也可包含描述玩家呈现状态的输入；来源不是分类依据。 | 鱼况、饵、姿态、窝料、线组、位置与操作 |

两个分类维度应分开使用。派生前后称“原始条件 / 派生条件”，不用只表示层级的“一级条件 / 二级条件”。

**环境实体（Environment Entity）**：世界中实际存在、具有位置 / 形态并可参与环境计算的对象。例：水草、石块、沉木、树桩、桥墩、码头构件。环境实体主要提供类型、位置、形态、尺寸、材质等原始条件数据；影响系数为实体直接配置的原始条件，点级实际值（实际光照强度、实际溶氧、局部流速、掩蔽程度）为派生条件（见[环境实体原始条件规范](environment-entity-raw-condition-schema.md)）。

结构、遮蔽物与底质的对应关系：

| 中文对象 / 特征 | 世界侧表示 | 对应鱼侧因子 |
|---|---|---|
| 岬角（Point） | 地形 / 几何 | Structure Type |
| 水下隆起（Hump） | 地形 / 几何 | Structure Type |
| 陡坎（Drop-off） | 地形 / 几何 | Structure Type |
| 台坎（Ledge） | 地形 / 几何 | Structure Type |
| 沟槽（Channel） | 地形 / 几何 | Structure Type |
| 平坦区（Flat） | 地形 / 几何 | Structure Type |
| 水草（Weed） | Environment Entity | Cover Type |
| 灌木（Brush） | Environment Entity | Cover Type |
| 树桩（Stump） | Environment Entity | Cover Type |
| 倒木（Laydown） | Environment Entity | Cover Type |
| 码头（Dock） | Environment Entity / 场景构筑物 | Cover Type |

| 岩脊（Rock reef） | 地形 / 几何 | Structure Type |
| 沙 / 砾石 / 泥（Sand / Gravel / Mud） | Surface / Material Property | Substrate Type |

### 3.4 输入B：习性

| 中文正式名 | 英文 / 标识 | 定义 |
|---|---|---|
| 鱼种 | `Species` | 鱼种本身的稳定定义，包含名称、体长与体重关系和可用的中鱼习性模式。 |
| 中鱼习性模式 | `Engagement Mode` | 某鱼种可复用的一套中鱼习性定义，描述这类鱼在环境和玩家刺激下如何表现。可包含模式自身的基础强度，以及环境习性、响应习性等配置。 |
| 基础习性 | `Species Base` | 一个鱼种的默认中鱼习性模式。当前生产环境中由一条特殊 `FishEnvAffinity` 承载。 |
| 习性档案 | `FishEnvAffinity` / `FishEnvAffinityRef` | 当前生产环境中承载中鱼习性模式（Engagement Mode）的持久记录 / 引用。 |

推荐关系：

```text
Species
├─ Species Base
└─ Engagement Mode(s)
   ├─ Mode Base Intensity
   ├─ 环境习性组件（Environment Components）
   └─ 响应习性组件（Response Components）
```

鱼种说明鱼是什么；中鱼习性模式说明鱼怎么表现；投鱼条目说明钓场投了什么、投多少。

模型用不同的中鱼习性模式简化鱼在不同情境下的行为取舍，例如：

- **伏击模式下**：鱼伏在掩蔽物附近（水草边缘、石缝、倒木旁），活动范围小、节省体力；对进入攻击半径的饵果断出击，对远距离或快速掠过的饵保持警戒；偏好泳姿自然、动作逼真的活饵型呈现。
- **开放游弋模式下**：鱼在开阔水域主动巡游觅食，活动范围大，跟随食物与水温分布移动；搜索半径大，对饵的响应相对平缓但持续，愿意追踪并试探。
- **护巢护卵模式下**：鱼守卫巢穴与卵块，活动范围收缩到巢区附近；对靠近巢区的饵反应剧烈，但以驱逐入侵者为主、进食意愿低；越过巢区边界的饵容易被攻击。

一个中鱼习性模式由一组习性组件构成。组件围绕一个相对独立的评价或响应语义组织；环境习性组件与响应习性组件可以拥有不同的内部配置结构，不要求同时具备 Gate、Affinity、Response Curve 等字段。

[中鱼中层框架](../feishu-module-framework.md)文首“一图流”中的“习性模式1”展示了这种配置组织方式。存储不必使用嵌套树，也可平铺成表格：每行对应一个“中鱼习性模式 × 因子”，按模式和因子定位；字段由组件类型决定。例如：

| 中鱼习性模式 | 因子 | 组件类型 | 适用配置（示意） |
|---|---|---|---|
| 鲈鱼的伏击模式 | 水温 | Environment Component | Gate / Affinity / Aggregation |
| 鲈鱼的伏击模式 | 光照 | Environment Component | Affinity / Aggregation |
| 鲈鱼的开放游弋模式 | 水温 | Environment Component | Gate / Affinity / Aggregation |
| 鳡鱼的伏击模式 | 饵速度 | Response Component | Response Curve / Response Parameters |

**中鱼习性组件（Engagement Component）**：一条中鱼习性模式（Engagement Mode）中，围绕一个相对独立的评价或响应语义组织的一组鱼侧配置。

```text
中鱼习性组件（Engagement Component）
├─ 环境习性组件（Environment Component）
└─ 响应习性组件（Response Component）
```

**环境习性组件（Environment Component）**：一条中鱼习性模式（Engagement Mode）针对某个环境因子（Factor）的完整鱼侧评价配置。典型环境因子包括：水温（Temperature）、结构类型（Structure Type）、遮蔽物类型（Cover Type）、底质类型（Substrate Type）、觅食生态水层（Feeding Layer）、时段（Period）、光照（Light）、水流（Flow）、溶氧（Oxygen）。

**响应习性组件（Response Component）**：一条中鱼习性模式（Engagement Mode）中，针对玩家输入、饵料、窝料、呈现方式或其它刺激的独立响应配置单元。它的内部配置不默认复用环境侧的 `Profile → Affinity → Fit` 结构。

习性组件可以按“因子 × 中鱼习性模式（Engagement Mode）”的二维关系理解：列是隶属鱼种的模式，行是因子，交叉点是该模式针对该因子的组件配置。不同组件类型使用各自适用的字段集合，不要求同一个交叉点同时存在门控规则、亲和度规则和响应曲线。

| 因子 ＼ 模式 | 鲈鱼/伏击模式 | 鲈鱼/开放游弋模式 |
|---|---|---|
| 水温 | Environment Component：22~30℃ | Environment Component：18~26℃ |
| 光照 | Environment Component：220~10000 | Environment Component：5000~30000 |
| 饵速度 | Response Component：0.2~0.8 m/s | Response Component：0.3~1.5 m/s |

例如，饵速度、震动、闪光都可以作为因子。它们的当前值属于条件；不同计算条目在不同中鱼习性模式下如何评价这些值，由对应的习性组件定义。

### 3.5 关键点：算法逻辑

**因子聚合**：多个适配值（Fit）按聚合角色（CORE / SECONDARY / IGNORED）合成为更高层系数（如环境系数）的过程。

**分模式逻辑（Per-mode Evaluation）**：同一鱼种（Species）的多个中鱼习性模式分别参与计算，并保留各自模式身份和阶段权重的计算方式。同一鱼种因此可以保留多条行为或习性计算路径，无需拆成多个长期鱼群实体。

**跨模式聚合（Cross-mode Aggregation）**：同一鱼种的多个中鱼习性模式分别得到阶段结果后，根据当前路由 / 聚合规则把这些模式结果汇合、选择或继续传递到下一阶段的过程。具体算子和发生阶段由对应契约定义。

**计算通道（Calculation Channel）**：框架中描述某个计算域内部独立计算或聚合路径的工作名称，例如总图中的“通道一”。

状态为工作名称、契约待定（Working / Contract Open）。目前没有足够证据证明通道具有稳定独立的输入、输出和生命周期，因此不构成独立领域身份，也不得仅凭该术语设计持久化对象或跨模块接口。是否保留为正式术语，见 [Issue #133](https://github.com/futouyiba/HitFish-Up/issues/133)及对应契约。

因子聚合处理单个模式内的多个因子；跨模式聚合处理同一鱼种的多个模式结果；计算域划分计算问题。计算通道只作路径分组说明，不具有同等的领域划分效力。

## 5. 逻辑模块

### 5.1 烘焙（预烘焙）

**烘焙（Bake）**：已解析的鱼配置 + 环境事实 → 环境评价输出。

**预烘焙（Pre-bake）**：烘焙派生环境场之前，先把原始条件烘焙成派生条件的过程。

### 5.2 响应（持久响应 ｜ 姿态响应）

**响应阶段（Response Stage）**：环境权重形成之后，系统按中鱼习性模式（Engagement Mode）的响应习性、当前鱼况和玩家刺激，调整候选权重。它分两路：持久响应处理持续生效的玩家行为（如打窝）；姿态响应处理当前姿态、饵和操作的即时计算。

**持久响应（Persistent Response）**：响应阶段中处理持续生效玩家行为的计算路径，例如打窝。其结果以持久响应场等形式保留，在有效范围和持续时间内影响后续响应计算。

**姿态响应（Pose Response）**：响应阶段中针对当前姿态、饵和玩家即时操作进行的即时计算路径。它读取当前呈现信号，并可叠加持久响应影响，形成当前中鱼计算所需的适配结果。

```text
空间分布权重（SpatialDistributionWeight）
+ Response Condition
  ├─ 鱼况（Fish Condition）
  └─ 呈现信号（Presentation Signal）等
+ 响应习性组件（Response Components）
→ 响应评价
→ 下游候选权重
```

当前可表达为：

```text
空间分布权重（SpatialDistributionWeight）× 适配系数（AdaptationCoeff）
→ 下游候选权重
```

**鱼况（Fish Condition）**：鱼侧动态参数。随天气、时段等输入变化，描述鱼当前的活跃、摄食与警觉状态，供后续响应（Response）等计算使用。

| 中文 | 英文 / 标识 | 说明 |
|---|---|---|
| 活跃度 | `Activity` | 当前整体活跃程度；除参与响应（Response）外，也可向刺鱼、搏鱼等后续模块提供输入。 |
| 摄食动机 | `Feeding Motivation` | 当前摄食意愿 / 驱动力。 |
| 食性偏移 | `Diet Shift` | 当前相对于基础食性的动态偏移。 |
| 警戒度 | `Wariness` | 当前警觉程度；随过程累积变化，影响后续响应。 |

基本关系：

```text
天气 / 时段 / 其它动态输入
        ↓
      鱼况（Fish Condition）
        ↓
     响应（Response）计算
        ↓
后续中鱼、刺鱼、搏鱼等模块
```

鱼况各参数的更新公式、时间粒度、存储所有权与下游消费关系由对应机制契约定义。

**呈现信号（Presentation Signal）**：响应条件中的一类运行时输入，描述玩家当前如何向鱼呈现饵或钓组，例如速度、姿态、深度、距离、运动方式等。它属于响应条件，不是与响应条件并列的完整输入分类。是否形成独立运行时接口，由对应契约决定。

### 5.3 圆桌抽鱼

**圆桌抽鱼（Roundtable Selection）**：使用圆桌权重表作为直接输入，在当前候选集合中完成最终抽取并决定本次进入生成 / 中鱼流程的候选对象的阶段。

以下名称描述圆桌阶段的职责方向，仍属框架工作名称（Working framework terms）。除挤占的相对竞争语义外，作用位置、先后顺序、公式和数据接口均由对应框架或契约定义，不能从术语反推实现结构：

- **品质抽取调整（Quality Share Adjustment）**：调整不同鱼品质最终抽取份额的职责。具体作用于候选权重、品质抽样还是其它步骤，由契约决定。
- **硬保底（Hard Guarantee）**：满足最低体验、最低供给或候选保护要求的控制概念。具体通过权重下限、概率约束、独立控制路径或其它方式实现，由契约决定。
- **动态权重调整（Dynamic Weight Adjustment）**：运行时控制信息可能动态影响候选权重的机制类别。具体输入、是否带状态 / 记忆以及算子由契约决定。
- **挤占（Crowding-out）**：圆桌抽鱼中候选按相对权重竞争抽取份额的关系；在候选集合和总量固定时，某些候选相对权重上升会压低其它候选的相对份额。与其它圆桌控制职责的先后关系由契约决定。

| 条件 ＼ 分级 | 原始条件（直接配置、编辑、采样或运行时得到） | 派生条件（预处理、预烘焙、采样或组合得到；如无特殊说明，指特定饵点 & 特定策划选择下的数据） |

### 6.2 计算域

**计算域（Calculation Surface）**：一套配置、角色或规则生效的计算问题范围，即它在哪一类计算中起作用。

当前主要包括：

- **环境权重计算域（Environment Weight Surface）**
- **响应计算域（Response Surface）**

计算域不是数据传输通道或流水线。计算通道的契约尚未闭合，不能作为与计算域同等的领域划分轴，见 [§3.5](#35-关键点算法逻辑)。

### 6.3 配置与工作流

| 中文 | 英文 | 定义 |
|---|---|---|
| 配方 | `Recipe` | 描述一个配置对象如何由来源（Source）+ 操作（Operations）形成。 |
| 来源 | `Source` | 为组件（Component）/习性配置（Profile）提供原始配置值的上游来源。 |
| 操作 | `Operation` | 在来源值（Source value）上表达继承、调整或设置等作者意图的操作。 |
| 解析 | `Resolve` | 来源 + 操作 + 覆盖 → 生效后的解析结果（effective resolved truth）。 |
| 物化 | `Materialize` | 生效后的配置 → 完整的生产行（Production rows）。 |
| 校验 | `Validate` | 对编辑态（Authoring）/解析态（Resolved）/生产态（Production）约束进行检查。 |
| 发布 | `Publish` | 将通过发布条件的结果写入生产环境（Production）。 |
